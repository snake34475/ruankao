01 / 先理解问题

资源不够所有人同时拿满，能不能轮流完成？

一间工作室共有 5 台同类设备，甲、乙两个任务共用。每个任务完成后，会归还自己占用的全部设备。

任务最多需要已经拿到还需要
甲3 台2 台1 台
乙2 台1 台1 台

目前已借出 2 + 1 = 3 台，所以空闲 5 − 3 = 2 台。假设先让甲完成，再让乙完成，逐步记账：

时刻与动作空闲甲持有乙持有核对总数
开始2212 + 2 + 1 = 5
借 1 台给甲1311 + 3 + 1 = 5
甲完成，归还手里的 3 台4014 + 0 + 1 = 5
借 1 台给乙3023 + 0 + 2 = 5
乙完成，归还手里的 2 台5005 + 0 + 0 = 5

甲、乙都能按这个顺序完成，因此 甲 → 乙 是一条安全序列。这里说的是“存在这样一种完成顺序”，不是要求系统必须按这个顺序运行。

留意借还的完整账：甲原来有 2 台，再借 1 台后手里有 3 台；完成时归还 3 台。空闲量从 2 变成 2 − 1 + 3 = 4。如果省略中间借出这一步，直接从最初状态算到完成后，也可以写成 2 + 2 = 4，加的是甲原先已持有的 2 台。
02 / 定义与步骤

安全序列怎么找

银行家算法是一种避免死锁的方法：资源分配前，先检查分配后的状态中，是否存在一种顺序，让所有进程都能依次获得所需资源、完成并归还资源。这样的顺序叫安全序列；存在安全序列的状态叫安全状态。

四个英文记号先认清

前两个通常由题目给出，后两个通常要算。Max、Allocation 和 Need 分别对应每一个进程；Available 对应整个系统当前空闲的资源。

英文记号中文含义如何得到
Max某进程的最大需求题目通常直接给出
Allocation某进程已经分配到的资源题目通常直接给出
Need某进程还需要的资源Max − Allocation
Available整个系统当前空闲的资源资源总量 − 所有进程的 Allocation 之和
两个计算公式：
Need = Max − Allocation
Available = 资源总量 − 所有进程的 Allocation 之和

代入上面的设备例子

这是前面讲解示例的初始状态，不是下面的练习题。工作室共有 5 台，甲最多需要 3 台、已拿 2 台；乙最多需要 2 台、已拿 1 台。

任务Max 最大需求Allocation 已分配Need 还需要
甲323 − 2 = 1
乙212 − 1 = 1

初始 Available = 5 − (2 + 1) = 2 台。比较甲的 Need = 1 和当前 Available = 2，即可判断现有空闲设备够甲完成。任务完成后，Available 会变化，下一轮要用更新后的数。

不要混淆：Allocation 是某个进程已经拿到的；Available 是系统还空着的。Need 要对每个进程分别算，不能把所有人的 Max 减去另一个人的 Allocation。
  1. 算出每个进程的 Need 和初始 Available。
  2. 在未完成的进程中，找一个 Need ≤ Available 的进程。
  3. 假设这个进程获得剩余所需资源并完成。简算时，让 Available = Available + 该进程完成前的 Allocation，再把它标记为已完成。
  4. 用更新后的 Available 继续找未完成进程。所有进程都能完成，就找到了安全序列；如果还有进程未完成，却没有任何一个满足条件，当前状态不安全。

为什么第 3 步可以直接加原先的 Allocation？先临时借出 Need，完成时归还的是 Allocation + Need，因此空闲量变为 Available − Need + (Allocation + Need)，化简后就是 Available + Allocation。

考试动作：算 Need 和 Available；从未完成进程里找 Need 不大于 Available 的；完成后更新 Available；重复直到全部完成或无人可选。找到一条安全序列就能证明安全，不要求序列唯一。
区分：不安全表示找不到保证所有进程完成的安全序列，可能发生死锁；它不等于当前已经发生死锁。

追加申请：先试分，再检查

进程再申请资源时，先检查申请量是否超过它的 Need；超过了就是超出最大声明需求。再看申请量是否超过当前 Available；超过了就先等待。两关都通过后，先假设资源已分给它，再检查是否能找到安全序列。

试分三项：Available 减去申请量；申请进程的 Allocation 加上申请量；申请进程的 Need 减去申请量。随后重新找安全序列：找到才批准；找不到就撤销试分，不批准这次申请。

04 / 多类资源

资源不止一种：数字变成向量

前面所有例子里只有一个数：空闲几台、还需要几台。考试题通常一次给三类资源（比如 A、B、C 三种），这时每个数变成一个三元组，规则本身不变，但比较和相加都要按位置一位一位来。

先看懂括号里的三个数

三类资源题里，一个格子里的数不是一个数量，而是一排数量。(4, 3, 2) 读作“4 个 A、3 个 B、2 个 C”，位置固定：第一位永远是 A，第二位 B，第三位 C，像坐标一样，不能换位。

它也不是“第几个阶段”或“第几步”，而是同一时刻三类资源各自的数目。所以 Need = Max − Allocation 要一列一列地算：(4, 3, 2) − (2, 1, 1) = (2, 2, 1)。

为什么必须逐位比，不能把三个数加起来算总账：假设 Available = (3, 2, 3)，某进程的 Need 是 (4, 1, 2)。按总数看，空闲 8 个、它只要 7 个，好像够；但 A 只有 3 个，它要 4 个 A，这一位永远不满，现在就做不了。三类资源不能互相顶替：内存条顶不了打印机。

四条规则怎么变

项目单一资源三类资源（A、B、C）
Max / Allocation / Need一个数三元组，如 Need = (2, 2, 1)
Need = Max − Allocation两个数相减三个位置各自相减，不能跨位
能否先完成Need ≤ Available每一位都 ≤ Available 的同一位
完成后更新Available + Allocation三个位置各自相加
Available 从哪来总量 − 各进程 Allocation 之和题目直接给出，不要自己拿总量减
最后一行最容易翻车：多类资源题一般直接把 Available 写给你。因为系统里有些资源不参与分配（内核占着、预留备件），“总量减已分配”算出来的数往往大于真正的空闲量。只在这题明确给了总量、且说明全部可分配时，才能那样算。

三个常见扣分点

  1. 只看一位就下结论。P4 的 Need 是 (4, 3, 1)，Available 是 (3, 3, 2)：B、C 都够，但 A 的 4 大于 3，不能选。必须三位全过。
  2. 完成后加错东西。只能加 Allocation。加 Need 或加 Max 都会让 Available 虚高，后面的判断全废。
  3. 以为答案唯一。本题最开始 P1 和 P3 都能先做，写出一条即可。

哈夫曼树：常用字符用短码

先纠正码长的误区，再看最小权值合并和 WPL 的计算；下面是自拟示范。

先想一想：为什么码长可以不同？

假设 A 出现 2 次、B 出现 5 次、C 出现 9 次。每次传一个字符，都要传出它的编码。

如果让出现更多的 C 用较短编码，每次发送 C 都可以少用一些位；出现较少的 A、B 可以用较长编码。这样可以减少所有字符编码后的总位数。

本次错因：不能认为哈夫曼编码的码长必须近似相等。码长由构造出的树决定；常出现的字符可以更短。

从权值构造一棵树

权值表示出现次数。规则：每轮挑当前最小的两个权值合并，把它们的和放回，再重新挑最小的两个。

轮次合并前可选权值合并合并后可选权值
12、5、92 + 5 = 77、9
27、97 + 9 = 1616（只剩一棵树）

最后一次合并产生根节点 16；它的两个孩子是 C（权 9）和节点 7。节点 7 的两个孩子是 A（权 2）和 B（权 5）。

约定左边为 0、右边为 1，例如把 C 放在根的左边、节点 7 放在右边；节点 7 的左边放 A，右边放 B，就得到：

字符权值从根走过的分支编码码长
C9左01
A2右、左102
B5右、右112

码长等于从根到字符所在叶子经过的边数。左右交换也可以，编码可能改变。

带绿边、有底色的圈是合并时造出来的中间节点；只有一圈灰边的是字符本身（叶子）。从根往下走一条边，码长就加 1，所以 C 只走 1 步，A、B 要走 2 步。

计算 WPL

WPL 是带权路径长度：把每个叶子的权值乘以它的路径长度，再相加。

WPL = 2×2 + 5×2 + 9×1 = 23

第二种算法：把合并时产生的非叶节点权值相加，即 7 + 16 = 23，两种算法一致。

注意：两种算法一致只能检查这棵树的 WPL 计算是否一致，不能单独证明每一轮都选了最小的两个；还要逐轮检查合并选择。

不同的合法哈夫曼树可能得到不同编码；遇到权值相同时，码长分布也可能不同，但它们的最小 WPL 相同。

五个权值：合并出的新数要放回候选池

三个权值只合并两轮，看不出真正的易错点。下面五个权值：3、5、6、9、12。关键动作是每合并一次，把和放回候选池，和剩下一堆数一起重新挑最小的两个，不是接着拿刚合并的结果往下凑。

轮次合并前候选挑最小的两个得到合并后候选
13、5、6、9、123 和 586、8、9、12
26、8、9、126 和 8149、12、14
39、12、149 和 122114、21
414、2114 和 213535（只剩一棵树）
第 3 轮是分水岭：候选里 14 是刚合并出来的，看起来最新，但 9 和 12 都比 14 小，所以必须挑 9 和 12。很多人顺手把 14 和 9 合并，从这一步起整棵树就错了。

树长这样：35 的两个孩子是 14 和 21；14 的两个孩子是 6 和 8（8 是 3+5）；21 的两个孩子是 9 和 12。所以 3 和 5 在最深处（路径长度 3），6、9、12 浅一层（路径长度 2）。

WPL = 3×3 + 5×3 + 6×2 + 9×2 + 12×2 = 78
验算：非叶节点权值之和 8 + 14 + 21 + 35 = 78，一致。

规律也在这里显出来了：越晚被合并的权值离根越近、码越短；先被合并的权值埋得最深、码最长。这就是“常用字符用短码”的由来。
