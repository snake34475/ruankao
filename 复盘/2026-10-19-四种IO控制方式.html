6 / 四种 I/O 控制方式 · 先抓判断线

只问两件事：怎样知道能传，谁来搬数据？

  1. CPU 如何知道可以传送？ CPU 反复检查是程序查询；设备发信号通知是中断；题设保证设备按约定时机就绪、无需检查或通知，是无条件传送。
  2. 数据到底由谁搬？ CPU 执行传送，还是 DMA 控制器直接搬运？这是区分中断与 DMA 的关键。
最容易混的地方：中断和 DMA 都可以让 CPU 在设备工作时处理其他任务；但中断方式仍由 CPU 响应并传送数据，DMA 才由控制器直接搬运一批数据。
02 / 四种方式对照

看等待方式和搬运者

方式CPU 是否等待设备设备就绪后谁搬数据记忆抓手
程序查询是。CPU 反复查询状态，未就绪时持续等待或轮询。CPUCPU 一直盯着设备。
无条件传送不查询状态，也不等设备通知；按预先约定的时机执行，前提是设备那时肯定已就绪。CPU没有通知；时机由程序和设备约定。
中断方式CPU 发出 I/O 请求后可继续执行其他工作；设备就绪后主动发中断通知。CPU 响应中断后传送数据。有通知；设备叫 CPU 来搬。
DMA 方式发出请求后可继续执行其他工作；传输结束后通常再通知 CPU。DMA 控制器直接在设备与内存间搬运一批数据。控制器自己搬一批。
一句话记忆：查询是 CPU 等；无条件是 CPU 按时搬；中断是设备叫 CPU 来搬；DMA 是控制器自己搬一批。

重点辨析：无条件传送与中断方式

比较点无条件传送中断方式
CPU 如何知道时机程序预先按固定时序安排；题设假定设备届时已就绪。设备就绪后发中断请求，通知 CPU。
CPU 是否查询状态不查询，也没有设备通知；如果设备未按时准备好，传送可能失败。不必反复查询；CPU 收到中断后再响应。
谁搬数据CPUCPU

自拟例子：假设一台设备每隔 1 秒必定产生一个数据。程序可以每秒到点直接读取，这是假定时序可靠的无条件传送；如果设备准备好时主动按铃，CPU 收到铃声后再读取，就是中断方式。两种方式都由 CPU 搬数据，区别在于“按约定时间去读”还是“等设备通知后再读”。

03 / 换角度也能辨认

题目反过来问时这样判断

  1. 题干说 CPU 不断检查设备是否就绪：选程序查询。
  2. 题干说题设保证设备按约定时刻就绪，CPU 不查状态、不等通知而直接传送：选无条件传送。
  3. 题干说设备就绪后发出中断，由 CPU 响应并传送数据：选中断方式。
  4. 题干说在内存和设备间直接成批传送，减少 CPU 对每个数据字的干预：选DMA 方式。

相邻概念：中断响应与 DMA 总线请求

中断是设备向 CPU 发信号，请 CPU 处理事件；DMA 传输期间需要使用总线，DMA 控制器会请求总线控制权。题目若问“谁通知 CPU 处理”和“谁请求总线搬数据”，问的是不同动作。

再往外一层：通道方式

通道可看作专门承担 I/O 控制工作的处理部件，适合管理多台外设、减轻 CPU 的 I/O 管理负担。辨认时抓“专门管理多个外设”这个场景，不要把它与单次 DMA 成块传送混为一谈。

7 / 编译阶段与中间代码

词法认记号，语法看结构，语义查含义

学习状态：学过但做错。记录显示曾把“检查语句含义”归给语法分析，也混淆了中间代码的作用。

自拟例子：一门假设的语言允许整数相加。程序写下 总数 = 数量 + 价格;。编译器先把字符分成标识符、等号、加号和分号；再检查它们是否组成合法赋值结构；最后检查变量是否声明、类型是否允许相加和赋值。

阶段看什么典型问题
词法分析字符流拆成记号，如标识符、数字、运算符。出现该语言不允许的字符。
语法分析记号按文法组织成结构，通常形成语法树。缺少操作数，或括号不配对。
语义分析检查结构的静态含义，如声明和类型是否匹配。把字符串与整数相加，而语言不允许这样做。
易错：语法合法只说明结构合规，类型仍可能不合法。比如按一门禁止字符串与整数相加的语言，“蓝” + 3 可以是结构完整的表达式，却会在类型检查时出错。

中间代码是翻译过程中的表达方式

常见编译流程是：词法、语法、语义分析，中间代码生成，代码优化，目标代码生成。中间代码通常尽量与具体机器无关，方便在共同表示上优化并针对不同机器生成目标代码；目标代码面向具体机器或目标平台。实际编译器的中间表示也可能包含平台相关信息。

以表达式 a + b × c 为自拟例子：

  • 后缀式：a b c × +，运算符放在对应操作数后面。
  • 三地址码：先写 t1 = b × c，再写 t2 = a + t1；每步用临时变量保存结果。
记忆：词法拆记号，语法查结构，语义查类型；中间表示便于优化与移植，目标代码面向目标平台。
合上讲解复述：缺操作数和类型不匹配分别由哪个阶段检查？后缀式里运算符放在哪里？
8 / 安全：攻击分类与检测

先看攻击者是否改变数据或服务，再看工具的任务

学习状态：学过但做错。曾把拒绝服务归到被动攻击，也混淆了入侵检测与漏洞扫描。

自拟例子：有人偷偷记录店铺与仓库之间的通信，但不修改内容，是被动窃听；如果他修改订单内容，或发大量请求让订单系统无法服务，就改变了数据或服务状态，是主动攻击。

区分关注点常见例子
被动攻击窃听或分析信息，不主动改变数据或服务。窃听通信内容、分析通信流量。
主动攻击篡改、伪造、重放信息或干扰服务。篡改订单、冒充用户、拒绝服务（DoS）。

“截获”如果指只窃听会话内容，按被动攻击处理；如果指劫持会话、冒用身份或篡改通信，就属于主动攻击。看题干实际行为。

安全工具：各自解决什么问题

工具主要职责好记的问法
防火墙按规则控制进出网络的流量。这次连接能不能通过？
入侵检测（IDS）分析网络或主机活动，发现可疑行为并告警。是否有人正在或曾经攻击？
漏洞扫描检查系统是否存在已知弱点或错误配置。哪里可能被利用？

安全目标与常用技术

目标或技术核心作用
机密性防止未授权者读懂信息；加密常用于保护机密性。
完整性发现信息是否被改动；摘要可用于校验，防恶意篡改需结合可信摘要或认证机制。
身份认证确认通信对象的身份；可用口令、证书等机制。
不可否认性为事后证明行为提供依据；数字签名可用于证明签名者与内容的关联。
对称加密加密和解密使用同一密钥，适合大量数据；需要安全地共享密钥。
非对称加密使用公钥和私钥；可用于加密、密钥交换或数字签名。
数字签名发送者用私钥签名，验证者用对应公钥验证；本身不负责隐藏消息内容。
记忆：偷看是被动；改、冒充、挡服务是主动。防火墙管通行，入侵检测找异常活动，漏洞扫描找弱点。
合上讲解复述：拒绝服务为什么是主动攻击？入侵检测和漏洞扫描分别在找什么？
9 / 观察者模式

谁维护名单，谁收到通知？

学习状态：学过但做错。记录中曾把维护观察者名单的职责放到观察者一侧；策略模式也有过薄弱记录。

自拟例子：图书馆的新书通知服务保存订阅者名单。有人订阅或取消订阅，服务就增删名单；新书到馆时，服务通知名单里的读者，每位读者自行决定如何处理通知。

角色例子中的对象职责
Subject（目标／主题）新书通知服务维护观察者名单；状态变化时逐个通知。
Observer（观察者）订阅的读者接收通知并执行自己的更新操作。
易错：观察者负责收到通知后的反应；维护订阅名单和发通知是主题的职责。一个主题可以通知多个观察者。

三个相邻模式不要串

模式解决的问题自拟例子
观察者一个对象变化时通知多个订阅者。新书到馆通知读者。
策略把可替换的算法封装起来，按需要选择。运费按普通或加急算法计算。
装饰器包裹对象，动态增加职责。给通知服务加一层记录发送日志的功能。
记忆：观察者看通知，策略换算法，装饰器加职责。
合上讲解复述：谁保存订阅名单？谁被通知？策略与装饰器各解决什么问题？
10 / 模块内聚、耦合与合并

先分清模块内部和模块之间

学习状态：内聚、耦合曾复习并有重做答对记录；“相似功能模块是否应合并”是待辨析的疑问，原题信息不足，未记为确认错误。

自拟例子：预约系统中，预约模块负责建立与取消预约，通知模块负责发送提醒。如果两处都有完全相同的日期格式化代码，可以抽取公共格式化功能；但把取消预约和发送通知硬塞进一个模块，会让模块承担不同职责。是否合并要看实际职责和依赖。

判断方向：内聚看一个模块内部的任务是否紧密围绕职责；耦合看不同模块之间依赖有多强。目标是高内聚、低耦合，“名字相似”本身不足以决定合并。

七种内聚：问“为什么放在一起”

从低到高放在一起的理由自拟例子
偶然没有实质关系，随意凑在一起。把打印日期和计算费用塞进杂项。
逻辑属于同一类操作，按标志选择其中一种。一个输入模块分别处理键盘、文件输入。
时间都在同一时段执行。启动时读取设置、初始化计时器。
过程按指定步骤先后执行。按流程核对身份，再显示使用须知。
通信操作同一份数据。读取、修改同一份预约记录。
顺序前一步输出交给下一步作为输入。读取原始预约数据，再计算统计结果。
功能各部分共同完成一个明确功能。计算一次预约的总费用。

方向：偶然 → 逻辑 → 时间 → 过程 → 通信 → 顺序 → 功能，内聚逐步增强。时间强调同时段，过程强调先后；顺序强调上一步的输出交给下一步。

三种常考耦合：看模块间传了什么

类型传递内容自拟例子
数据耦合必要的简单数据。传入预约人数。
标记耦合完整记录或数据结构，接收方使用其中部分字段。只需预约人数，却传入整条预约记录。
控制耦合传入控制标志，决定被调用模块的内部处理分支。传入操作码，让模块选择创建或取消。
记忆：内聚看内部为何聚，耦合看模块间传什么；重复实现可抽公共功能，不同职责强合并要警惕。
合上讲解复述：时间内聚与过程内聚差在哪里？只要一个字段却传整条记录属于哪种耦合？
11 / 配置管理边界

配置管理追踪“什么版本、如何变化”

学习状态：学过但做错。记录显示曾把版本控制排除在配置管理之外；风险管理属于项目管理中的另一项活动。

自拟例子：预约系统准备发布。团队把需求文档、源代码和测试计划确定为需要管理的对象；确认一版作为基准；之后有人提议修改，需要登记、评估、批准，再记录新的版本和状态。

概念要做什么在例子中
配置项被纳入管理的工作成果。需求文档、代码、测试计划。
基线经过正式评审或批准，用作后续工作的参照版本；之后通过变更流程修改。发布前确认的需求文档版本。
版本控制保存与识别不同版本。知道文档从第 1 版变为第 2 版。
变更控制提出、评估、批准或拒绝并实施变更。评估新增预约规则后决定是否批准。
配置状态报告记录并报告配置项、版本和变更处理状态。查看某项变更待审批还是已完成。
配置审计检查成果是否符合要求，配置项及其记录是否一致、完整。核对发布内容与批准的变更是否对应。

与相邻管理活动区分

风险管理识别、分析并应对不确定事件，如担心关键成员临时离岗；质量保证关注开发过程是否按既定标准执行；项目计划安排范围、进度和资源。它们可以与配置管理协作，但各自关注点不同。

记忆：配置管理认对象、定基线、管版本与变更、报状态、做审计；风险管理看不确定性。
合上讲解复述：基线是什么？状态报告与配置审计分别回答什么问题？
12 / DNS 解析顺序

先区分本机查找和 DNS 服务器查询

学习状态：有疑问，尚不能按原题确定做错。原题没有明确浏览器缓存、系统缓存、hosts 等层次，不能据此断言所有环境的固定先后。

自拟例子：浏览器要访问 shop.example.com，需要获得它的 IP 地址。本机可能先用已有缓存或本地名称映射；没有可用结果时，再向配置的 DNS 解析器请求。具体查找顺序可能因浏览器、操作系统和配置而异。

考场动作：题干明确给出查找层次或指定教材口径时，按题设判断；若未限定环境，不能把“hosts 一定在所有缓存之前”或“缓存一定在 hosts 之前”当成普遍规则。

没有缓存命中时，DNS 怎样找到答案？

参与者职责
本地递归解析器接受客户端请求；没有缓存答案时，代表客户端向其他 DNS 服务器查询。
根服务器指引解析器去查相应顶级域的服务器。
顶级域服务器指引解析器去查目标域名的权威服务器。
权威服务器提供其负责区域中的权威记录，如对应的地址记录。

常见路径是：客户端向递归解析器请求答案；解析器在没有可用缓存时，依次向根、顶级域、权威服务器查询或根据已有信息跳过部分步骤，最后把结果返回客户端。

递归与迭代：谁继续跑腿

递归查询：被询问的服务器负责进一步查找，向请求者返回最终结果或错误。迭代查询：服务器若不知道最终答案，可以给出下一步该问谁，由查询者继续询问。常见情况下客户端请求递归解析器，解析器再迭代查询其他服务器。

缓存与 TTL：DNS 记录的 TTL 通常规定结果可作为新鲜缓存使用的时间；到期后一般需要重新获取。某些系统在特殊故障条件下可按规则返回过期数据，因此实际实现还有例外。

记忆：递归是被问者帮忙查到底；迭代是查询者按指引继续问。先看题设，缓存可能使查询不必每层重走。
合上讲解复述：根、顶级域和权威服务器分别提供什么？递归与迭代中谁继续查？为什么不能给所有系统硬背一个本机查找顺序？
