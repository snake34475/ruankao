## 查清「构建后 git status 误报 24 个 M」

- **现象**：`npm run build` 后 `git status` 列出 24 个 `docs/**.html` 为 `M`，但 `git diff --numstat` 与 `git diff HEAD --numstat` **均为空**；`git update-index --refresh` 又报 `needs update`。三者互相矛盾。
- **诊断**：写 `.refs/diag-eol.py`——用 `git status --porcelain -z` 取文件名列表，再逐个比较**工作区字节** vs **`git cat-file blob HEAD:<path>` 的仓库内存储字节**。结果：**24 个全部字节完全相同**（"只有行尾不同" 0 个、"真实内容差异" 0 个）。
- **根因**：`core.autocrlf=true` + 仓库**没有 `.gitattributes`**。index 的 stat 信息假设工作区文件是 CRLF，而构建脚本把文件重写成 LF → size 不同 → `git status` 据 stat 报 M；`git diff` 走 CRLF→LF 归一化后判定无差异。所以两条命令都没说谎。
- **解法**：`git add --renormalize .`（只作用于已跟踪文件）——实测 24 个假 M 一次清净、`git diff --cached` 为空（无 blob 变化，纯刷新 stat）。**不要用 `git checkout -- .` 去"还原"**，那是对现象的误判，会白跑一遍构建产物。
- **顺带得到的结论**：构建是幂等的 → **远端提交的 136 个页面产物与本地重跑的结果内容一致**，可以用这个办法快速判断"产物有没有漏提交"。
