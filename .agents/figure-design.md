# 图示设计规范

适用于新增或修改讲义中的任何示意图（SVG、ASCII 字符画、交互页）。修改图示时除本文件外，还要遵守 `.agents/markdown-rendering.md` 与 `.agents/course-authoring.md`。

## 三层图示体系

按"信息复杂度 vs 维护成本"选层级，不要一律上重图：

| 层级 | 形式 | 什么时候用 | 维护方式 |
|---|---|---|---|
| L1 快图 | ASCII 字符画（围栏代码块） | 结构简单、需要随手复制、需要逐字改 | 直接改文本 |
| L2 精图 | **内联 SVG**（写进 md 正文） | 结构/空间关系有讲究：E-R 图、类图、状态图、树形、流程、坐标类图 | 改 md 里的 SVG 源码 |
| L3 交互 | `interactive/<名字>/` 独立页 | 需要动画、单步、可点击反查 | 改 `interactive/` 源码，构建时自动拷进 `docs/` |

**优先 L2 而不是落盘 PNG**：内联 SVG 能自动跟随主题切换深浅色、缩放不糊、可事后逐字修改；PNG 是位图，深色模式下会刺眼、改一个字也要重画。确需位图（如截图）时再落盘，并放进 `assets/`。

## 内联 SVG 硬性要求

1. **配色只用主题变量，禁止写死颜色**。可用 `var(--surface)`、`var(--surface-2)`、`var(--ink)`、`var(--ink-strong)`、`var(--muted)`、`var(--faint)`、`var(--line)`、`var(--line-strong)`、`var(--accent)`、`var(--accent-ink)`、`var(--accent-soft)`、`var(--gold)`、`var(--gold-soft)`、`var(--red)`、`var(--bg)`。写死 `#333` 一类颜色会导致深色模式不可读。
2. **必须是响应式的**：外层 `<svg>` 带 `viewBox` 与 `width="100%"`，并给 `style="max-width:<原宽>px"`，保证窄屏等比缩小。
3. **必须带无障碍信息**：`role="img"` + `aria-label="……"`，`aria-label` 要能独立说清这张图讲了什么（读屏用户只听得到这一句）。
4. **样式写在源码 SVG 内部的 `<style>` 里**，类名语义化（如 `.node`、`.edge`、`.hit`、`.dim`），不要污染页面全局样式。`prepare_vitepress.mjs` 会把它提取为按图作用域隔离的 `figures.css`；不要手改生成的 `site-src/`。
5. **字体用 `system-ui,"PingFang SC","Microsoft YaHei",sans-serif`**，不要引用 Web 字体（离线可读是仓库红线）。
6. 用 `<figure class="fig">` 包裹，图下可跟一行短说明；**图注不进 `<figcaption>` 之外的长段落**，正文解释放在图外。

## SVG 范本

以 `软考学习/01-数据结构与算法/04-查找.md` 的「分块查找」图为标准范本（`<figure class="fig">` + 内联 `<style>` + `var()` 变量 + `aria-label`）。新增图照此结构写。

## 图示必须验算

图里出现的每个数字、序号、坐标关系都要亲自核对，不能"看起来对"：

- **E-R 图**：联系类型（1:1 / 1:n / m:n）必须与正文业务描述一致；转换后的关系模式，主键/外键要能对上图上的矩形与菱形。
- **树 / 图**：节点数、深度、路径长度、入度出度按 `markdown-rendering.md` 的要求统一口径并复算。
- **流程 / 状态**：箭头方向与转换条件一一对应，不能有画了箭头却没有触发条件的边。
- **数据一致**：同一份数据在多张图、正文、答案里必须完全一致；改一处要全文搜索连带位置。
- **SVG 几何连接**：属性椭圆的中心要与所属实体／联系对齐（或用明确折线连接），每条连接线端点要落在图形边界上；调整节点坐标后同时重算相连的线段和文字位置，不只移动单个形状。
- **SVG 画布边界**：长说明文字不能只检查 `x`、`y` 起点，还要检查渲染后的文字右边缘与底边是否落在 `viewBox` 内；必要时拆行或移到图注。浏览器检查时排除 `<defs>` 内的箭头标记，它们使用独立坐标系。

## 图与正文的分工

- 图负责**空间结构**（谁连着谁、层级、位置关系），正文负责**为什么**和**怎么用**。
- 不允许出现"只有图、无文字解释"或"只有文字、图是装饰"两种情况；每张图在正文里要有明确引用（如"见下图"）。
- 图**不能替代反例**：机械规则的最常见错误写法仍按 `course-authoring.md` 用文字写清。

## 源码检查

构建后打开对应 `docs/**/*.html` 实渲染确认（`markdown-rendering.md` 要求以浏览器渲染为准，静态扫描只找候选问题）：

- 深浅两种主题下都可读（可用 `?theme=dark` / `?theme=light` 参数切换核对）；
- 窄屏（≤ 480px）下不溢出、不逐字竖排；
- SVG 内**不能残留字面的 `**`**（SVG 里不解析 Markdown，`**` 会原样显示成星号）；
- 检查正文是否残留 `<figure class="fig">` 未闭合。
