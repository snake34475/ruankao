# 概念扩讲方法论（通用提示词）

适用于：用户反馈某段讲义「笼统、不直观、太简单、没讲透」，或自检发现读者必须靠脑补才能建立画面时，对该概念的重讲与扩充。本文件回答三个问题：**哪些概念需要扩讲、按什么病因选讲法、按概念形态选什么图**。动笔时与 `course-authoring.md`（内容原则）、`figure-design.md`（图形实现规范）并用。

## 第 1 步 · 判断这个概念要不要扩讲（触发信号）

命中任何一条就应扩讲，不要只加两句注释：

1. **抽象记号先行**：定义用 X→Y、映射、寻址这类记号开场，但读者说不出「表里哪一列、哪一行」是它的载体；
2. **成组分级概念平铺**：一族有先后/包含关系的概念（范式阶梯、模式层次、协议分层、内聚耦合七级）挤在一张对比表或几行字里；
3. **机械判定规则易错**：规则能背但常判错，错误根源是把一个维度混进另一个维度（部分依赖 vs 传递依赖、聚合 vs 组合）；
4. **过程类知识缺中间态**：算法/变换/拆解步骤只写「先…再…最后…」，每步后的状态要读者心算；
5. **「一句话」概念**：讲义里出现只报术语、无示例无用途的句子。

## 第 2 步 · 诊断“为什么看不懂”，按病因选药

| 病因 | 典型症状 | 首选解药 |
|---|---|---|
| 抽象记号没有具体载体 | 读得懂定义，指不出表格里谁是谁 | 先摆一张带真实数值的最小示例表，把 X、Y、K 等代号**标注在表上**，再给一般定义 |
| 概念簇平铺、彼此不分 | 一族同根术语各自为政、互相混 | 嵌套/包含关系图（同心椭圆、集合表）：先讲「谁包含谁」再逐个定义；口诀必须给包含方向 |
| 逐级判定靠链式心算 | 问「到第几级/第几层」只能背流程 | 总览阶梯图 + **每一级一张「病灶→手术→结果」图**，全链只用一份示例数据 |
| 规则背过仍会错 | 反例缺席，或反例没说错在哪一步 | 反例前置：给出最常见的错误做法，指明错在哪条规则、造成什么后果；反例须验伪 |
| 过程无法在脑中定格 | 多步变换跟不上每步动了什么 | 单步状态快照图（L1 逐帧）；若 ≥3 步状态连续演化且值得亲手试，升级 L3 交互动画（一步一屏、病灶高亮、手术对比；实现与验收见 `figure-design.md` L3 要求） |
| 易混概念并排塞 | 名称相似的两者互相污染 | 拆独立段落 + 口径对照表，禁止「顺带记住另一条」 |

## 第 3 步 · 一次扩讲的标准结构（五件套）

1. **动机开场**：先说这个概念解决什么问题、不解决会得什么病——病要用带真实数据的小表「演」出来，不用形容词；
2. **一个例子贯穿全链**：开头定下示例数据（人名、数值、列名齐备），此后所有图、正文、反例、题目、交互页复用同一份数据；中途不换例子，每张图不各造一份数据；
3. **每级/每维一图**：图只负责空间结构（谁连着谁、谁包含谁、谁在哪一级），正文只负责为什么与怎么用；每张图在正文有明确引用；
4. **三类口诀**：认题口诀（题型特征→认它）、判定口诀（规则的执行顺序或分界判据）、动作口诀（考场第一步做什么）。口诀必须含判据不只含结论，每条都能指回某张图或表；
5. **应试动作收束 + 一个验伪过的反例**：以“看到 X 就 Y”结尾，最常见错误单独成段。

## 第 4 步 · 图式选型速查（概念形态 → 图形形态）

| 概念形态 | 推荐图式 |
|---|---|
| 层级 / 递进 / 流程分级 | 阶梯图（每级标「消什么病」）+ 每级细节图 |
| 集合包含（术语族谁属于谁） | 同心嵌套图，配右侧实例对照表 |
| 对象间定向关系（决定、依赖、引用） | 箭线图：方框=对象、箭头=关系、颜色区分正常/病灶，虚线框圈出成组对象 |
| 数据本身的性质 | 带真实数值的小表格（永远排在定义之前） |
| 变换前后对比 | 「病表 → 手术 → 净表」三连图，一步一箭头 |
| 多步动态过程 | L1 逐帧快照 → 值得动手试时升 L3 单步动画 |

## 第 5 步 · 扩讲完成的判据

- 合上讲义，读者能**独立复写**该概念的判定流程（不是背结论）；
- 全部图、正文、配套题目、交互页使用同一份示例数据，数字互查一致；
- 每个抽象记号首次出现处标明所指层级（表 / 字段 / 取值 / 组合）；
- 每个反例确实错、且错因与正文规则一一对应；
- 新增交互页时，核心流程在浏览器逐步点完并有 DOM 状态断言（见 `figure-design.md`）。

## 范围控制

- 扩讲只动该概念一节及其连带的答案/解析，不顺手重构其他小节；
- 超大纲内容只做「一句话了解」，不配重图不展开（大纲范围以 `软件设计师考点大纲.md` 为准）。
