# 课程拆分与迁移规范

适用于把过大的课程 Markdown 和 HTML 拆成目录子章节或独立路由。

## 设计目标

- 一个考点仍是一门课，但可由入口页和多个子章节文件组成。
- 每个子章节围绕清晰学习主题，能独立阅读，又能从课程入口按顺序到达。
- Markdown 继续作为唯一内容真源，HTML 路由全部由构建器生成。
- 拆分只改变组织方式，不丢内容、不改变题目答案、不修改学习进度。

## 推荐结构

```text
软考学习/
└── 01-数据结构与算法/
    ├── index.md
    ├── 01-基础与复杂度.md
    ├── 02-线性结构.md
    ├── 03-树与二叉树.md
    ├── 04-图.md
    ├── 05-查找与排序.md
    └── 06-练习与解析.md
```

实际文件名按内容决定，不为追求平均长度强行切断一个完整知识链。入口页承担课程介绍、章节目录、学习顺序和跨章提示；题目与解析可以单独成章，但答案仍放在对应题目体系的末尾，避免做题时提前看到。

## 迁移流程

1. 盘点原文件所有二级、三级标题，设计章节边界和稳定文件名。
2. 建立入口页和子章节，保持原有内容顺序；先迁移，不顺手大改知识内容。
3. 检查标题层级、题号、答案编号、代码块和表格没有在边界处截断。
4. 更新所有指向旧课程文件的相对链接；不得写页内锚点链接。
5. 扩展构建器，使目录 Markdown 映射为目录 HTML，例如 `课程/index.md` → `docs/课程/index.html`，子章节生成各自路由。
6. 导航中把课程作为父项、章节作为子项；课程入口和章节页面都应有明确的返回路径。
7. 更新 README 目录说明，但不复制一份会漂移的课程状态表。
8. 运行构建并检查旧入口兼容策略。若旧 URL 已公开，优先保留跳转或兼容入口，不静默制造死链。
9. 按 `verification.md` 完成内容完整性、链接和视觉验收。

## 边界选择

- 按学习任务拆，而不是按字符数机械拆。例如“树的概念—遍历—还原—哈夫曼”可作为连续章节体系。
- 强依赖的例题和解析放在知识点附近；综合练习可以集中放在课程末尾。
- 章节太短时合并，过长且包含多个独立学习目标时继续拆分。
- 入口页不重复粘贴每章正文，只提供摘要、导航和学习建议。

## 多课并行

只有用户明确要求一次生成或拆分多课时才并行。每个执行者只修改被分配的课程，不改进度表、不运行全局构建；共享导航、README、进度和构建由主任务统一处理，并做跨文件链接检查。
