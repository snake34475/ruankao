# 记忆声明规范

当用户说出「记住 xxx」「以后都这样」「帮我记一下」等表示要持久化的请求时，按本文档把记忆归入正确层级。记忆分四个落点，判定顺序自上而下。

## 四个落点

| 落点 | 位置 | 适用内容 | 生命周期/可见性 |
|---|---|---|---|
| ① 用户级个人偏好 | TRAE 全局 `user_profile.md`（不在本仓库） | 跨所有项目成立的习惯、偏好、背景、技术栈 | 全局、永久 |
| ② 项目级备忘 | `.workbuddy/memory/MEMORY.md`（随仓库入库） | 本仓库跨会话要记住、但**不适合写成强制规则**的状态/结论/事实/踩坑记录 | 本项目、长期 |
| ③ 任务级强制规则（全局） | `AGENTS.md` | 对所有任务都生效的约束与流程快照 | 本项目、强制 |
| ④ 单类任务细则 | `.agents/*.md` | 只在某类任务（如改讲义、构建、拆分）生效的详细规范 | 本项目、按任务 |

## 判定流程

按顺序判断，命中即止：

1. **是否跨所有项目成立？** → 是 → **落点 ①**（`user_profile.md`）。如「我习惯用简体中文交流」。
2. **是否属于本仓库需要记住、但写成强制规则会过份的内容？**（事实、结论、测量结果、个人决定、状态）→ 是 → **落点 ②**（`MEMORY.md`）。
3. **是否对所有任务都生效的强制约束？** → 是 → **落点 ③**（`AGENTS.md`）。
4. **是否仅在某一类任务生效的强规则？** → 是 → **落点 ④**（最匹配的 `.agents/*.md`）。

边界提示：

- **「规范类」一律以 AGENTS.md / .agents 为准**；MEMORY.md 只承载它们装不下的状态与结论（该约定已写在 MEMORY.md 头条）。
- 记忆若只是**本次会话内临时**、不涉及后续会话，则不落盘，口头确认即可。
- 不易判断时倾向「写进 MEMORY.md 的结论区」而非 AGENTS.md——AGENTS.md 尽量精简，避免规则堆砌。
- 不重复登记：同一条记忆只写一个落点，不跨文件复制（遵循「唯一真源」).

## 声明格式

用户给的是口语，写入目标文件时先翻译成结构化条目：

- **给条目标题**：一句话概括，能当目录锚点（如「双远端并存」「GitHub Pages 已启用」）。
- **写结论而非过程**：用「已确认/已实测/勿再试」等定性词，附日期撮要时给具体日期。
- **保留可复用判据**：若结论包含判断方法，把方法也写下，供后续复用。
- **反例、测量、否决过的尝试**同样值得记，避免重复踩坑。

## 示例

- 「我一直只用中文」→ **落点 ①**：`user_profile.md` 追加 `Communication language: Chinese`。
- 「本仓库两个远端 main 要保持同一提交」→ **落点 ③/④** 之间：因为它对所有提交任务生效，写进 AGENTS.md「提交与推送」。
- 「Gitee Pages 已被官方下线，在线阅读走 GitHub Pages」→ **落点 ②**：这是事实/状态，不是强制规则，写进 MEMORY.md「仓库与平台」。

## 规则维护

- 本文件由新增流程或踩坑教训时补充。
- 若某条记忆暴露新的通用错误类型，把对应检查规则补充到最匹配的 `.agents/*.md`；只有对所有任务都适用的才写回 AGENTS.md。
