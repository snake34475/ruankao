# 错题本数据结构与维护

错题本是一个**独立 HTML 看板**，不是 Markdown 讲义页。源码三件套在 `interactive/mistake-book/`，数据全在 `app.js` 顶部两个数组里；构建时整目录拷进 `docs/interactive/mistake-book/`。**只改 `app.js`，不动 `index.html` / `style.css`，不建新的 md 页，不手改 `docs/`。**

## 两个数组

### `MISTAKES` — 逐题/逐知识点记录

```js
{
  date: '2026-10-15',                    // 作答日 YYYY-MM-DD
  kind: '错题',                           // 错题 / 盲区 / 疑问
  title: '资源编号递增破坏的是循环等待',    // 一句话结论式标题，写得能当索引
  tags: ['死锁', '必要条件'],             // 考点名 + 上位概念，各一个为宜
  status: 'danger',                      // danger / warn / ok
  mine: '第 3 题选 B（不可剥夺）',          // 我的答案原话
  correct: 'D：循环等待',                  // 正确答案 + 一句要点
  cause: '…指向具体规则的错因…',           // 见下方「错因写法」
  next: '2026-10-17',                    // 下次回炉日
}
```

`kind` 的用法：
- **错题**：答错了。
- **盲区**：不知道自己不知道（如「某一步为什么这样走」）。
- **疑问**：答案对了但对某个辨析没把握、或两种说法间犹豫。用户明确表达过犹豫时优先记这类。

### `WEAK` — 薄弱点图谱

```js
{ name: '并发四类错误对号入座', errors: 3, status: 'ok', action: '…回炉动作…' }
```

- `errors` 是该知识点**累计出错次数**，图谱按它画条长（条越长越弱）；新错一次 +1，回炉答对**不归零**（保留累计强度），但把 `status` 降级。
- `status` 与 `MISTAKES` 同一套三态，表示**当前掌握程度**，与 `errors` 不矛盾：常见是 `errors` 高但 `status: 'ok'`（错过多次、现已过关）。
- `action` 写「下一步做什么」，要具体到重做哪几道题、默写哪条固定格式。
- **同一个知识点只留一条**，别为每次错误新建行；新错并入已有行的 `errors`，需要时改写 `action`。

## 状态三态的判定

| status | 标签 | 触发 |
|---|---|---|
| `danger` | 未过关 | 答错；或同一知识点多次出错、仍未独立答对 |
| `warn` | 待巩固 | 蒙对 / 犹豫 / 结论对但理由错；或已重做答对一次但还没稳 |
| `ok` | 已过关 | 回炉重做独立答对，在 `cause` 末尾补记「X 月 X 日重做答对」 |

状态只升不跳：`danger → warn → ok`。一轮里独立答对就可以直接升到 `ok`（现有条目就这么做的）。

## 错因写法（最容易敷衍的一项）

错因必须能回到**一条讲义规则**。反例与正例：

- ✗「粗心写错了」「没记住」「看错了」——只描述现象，复习时帮不上。
- ✓「把条件塞进聚合函数括号里：`HAVING COUNT(Cno>3)` 数的是真假值个数，把 ≥3 的门槛整个丢掉；正确结构是 `HAVING 聚合函数(列) 运算符 数值`」——有名有姓的规则 + 为什么错。

写错因的套路：**先说错误的想法是什么 → 再说正确规则是什么 → 再说两者差在哪个定义/公式上**。若同一轮多题同型（如两道题都把运算符写进括号），合并记一条并在 `title` 里点明「同一型错误」，`errors` 一次性加够。

## 维护动作清单

新增/更新错题时：

1. `MISTAKES` 追加对象（或改已有对象的 `status` / `cause` / `next`）。
2. `WEAK` 对应行的 `errors` +1（新簇则新增一行），必要时改 `status` 与 `action`。
3. 页面上「记录总数 / 未过关 / 待巩固 / 已过关」四个数字和进度条都是自动统计的，**不用手改**。
4. 完事在对话里报一句：新增几条、哪几条升级/降级、哪个薄弱点次数变了。
5. 不重建 `docs/`（用户没要求构建时）。下次构建会自然带上。

## 下次回炉日 `next`

默认取作答日 +2 天，与现有条目惯例一致（学习计划的回响节奏是「次日 → +3 → +7 → +14」，错题按 +2 起步）。用户若指定了回炉安排就按用户说的。日期用 `YYYY-MM-DD`。
