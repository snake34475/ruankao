# 考点出题 · 批改 · 归错题本

用户是软考中级·软件设计师的自考生，本仓库是唯一学习资料。这个技能管一整条闭环：
**指定考点 → 从题库选题出卷 → 用户作答 → 批改并罗列错题与知识点 → 更新错题本**。

## 铁律

1. **出卷不给答案，也不给来路。** 卷面上不出现原题号、不出现「这是课后题／精华题／案例题」，不出现出自哪个文件。理由：题目原文就存在仓库里、解析就在旁边，一旦写明来源和题号，用户翻两下就能对到答案，这次练习就废了。题干原文照抄（不改写），只抽掉来源与编号这两层外壳。
2. **出完卷就停，等作答。** 一轮只做一件事。用户把答案发回来才进入批改，绝不自己往下答。
3. **同一道题不重复出。** 出卷前查历史记录，已出过的题换掉。
4. **错因要落到规则上。** 错题本条目里「错因」必须指向一条可复述的规则（哪个定义用错、哪个公式套错、哪两个概念记串），只写「粗心」「没记住」等于没写。
5. **改错题本只动 `interactive/mistake-book/app.js`**，不建新的 md 页、不动 `docs/`（那是构建产物）。

## 触发与两种模式

| 用户说的话 | 进入 |
|---|---|
| 「死锁请出题」「出题：SQL」「考考我子网划分」 | **模式 A：出卷** |
| 发回一串答案（「1.A 2.C 3.B…」或逐题写） | **模式 B：批改** |

用户没说是哪个考点时，先看 `软考学习/00-总览与进度.md` 的进度，用最近学完或仍未过关的考点出卷，并说明选了哪个、为什么。

## 模式 A：出卷

### 第 1 步 定考点与检索词

把考点翻译成 2～4 个检索词：**考点名 + 讲义里用到的近义词或场景词**。例如「死锁」→ `死锁`、`资源编号`、`循环等待`、`进程资源图`；「SQL 分组」→ `GROUP BY`、`分组`、`HAVING`。检索词选错会导致漏题，`references/question-sources.md` 有各课的用词参考。

### 第 2 步 找题

用本技能自带的索引脚本（白名单目录、越界会报错）：

```bash
node .agents/skills/topic-quiz/scripts/question-index.mjs --any <词1> <词2> <词3>
node .agents/skills/topic-quiz/scripts/question-index.mjs --course 05 死锁
```

它按题块切开题库真源，输出「课 / 文件 / 题型 / 题号 / 行号 / 题干首行」，且**不会读答案文件**，所以检索阶段不可能被答案带偏。近义词之间用 `--any`，需要同时命中才用默认的 AND。

### 第 3 步 选卷：四类题源都要有

用户要求「至少包括课后题、案例题、精华和补充题」，所以每次出卷至少凑齐下表四类；某个考点确实没有对应类型（如纯计算考点常无案例题）就跳过并在卷末一句说明，其余情况不许缺项。

| 类型 | 位置 | 卷面标识用不用 |
|---|---|---|
| 课后题 | `软考学习/NN-*/90-课后考题.md` | 不用 |
| 案例题 | 90 文件里的「二、案例题」段、`07-案例题专攻.md`、`99-考前全真模拟卷/04\|05-下午卷*.md` | 不用 |
| 精华题 | `91-*.md` 前半（不带「补充题」小节标题的编号题） | 不用 |
| 补充题 | `91-*.md` 的「补充题／专项题」小节 | 不用 |
| 模拟卷（可选） | `99-考前全真模拟卷/01\|02\|03-*.md` | 不用 |

配比按考点性质定：有案例大题的考点（数据库、软件工程、面向对象、数据结构算法）至少 1 道案例题；纯选择题考点以 5～8 道选择为主。总量控制在 5～8 题、20 分钟以内，别把一节的所有题倒给用户。

### 第 4 步 落一份选题记录（用户看不到，但必须写）

写到 `.zcode/quiz/<日期>-<考点>.json`（`.zcode/` 已被 gitignore）。两个作用：批改时靠它把卷面题号对回原题，以及下次出卷时排除已出过的题。没有它，跨轮次一旦上下文被压缩就批改不了。

```json
{
  "topic": "死锁与并发控制",
  "date": "2026-10-15",
  "items": [
    { "no": 1, "course": "05-操作系统", "file": "90-课后考题.md", "kind": "课后题", "sourceNo": 9, "line": 32 }
  ]
}
```

### 第 5 步 出卷

卷首只给「考点 / 题量 / 建议时间」。题号从 1 重排，不显示原题号与来源。案例题保留它自带的「问题 1／问题 2」小问，因为那是题目本身的结构。**卷尾不许出现答案或解析区**。

```text
【本次练习】考点：死锁与并发控制　共 6 题　建议 20 分钟
（选择题直接作答；案例题按小问作答。答完把答案发我。）

第 1 题
采用给系统中所有资源统一编号、进程只能按编号递增顺序申请资源的方法
预防死锁，破坏的是死锁四个必要条件中的（　）。
A. 互斥条件　B. 占有且等待　C. 不可剥夺　D. 循环等待

第 2 题
某系统有互斥资源 R 共 10 个，3 个进程 P1、P2、P3 竞争 R，每个进程最多
申请 i 个 R。该系统可能发生死锁的最小 i 值为（　）。
…

第 5 题（案例）
【说明】…
问题 1：…
问题 2：…
```

然后停下等答案。可直接说「答完发我，我来批改并登记错题本」。

## 模式 B：批改 + 归错题本

### 第 1 步 取答案

读选题记录 `items` 拿到原题位置，再到对应课的 `99-答案与解析.md` 取标准答案与解析。**批改依据是仓库里的解析，不是自己现推**——两边不一致时以解析为准，同时按 `.agents/course-authoring.md` 复核是不是题目或解析本身有错，可疑就明确指出。

### 第 2 步 判对错，分三档

- **答错** → 记 `danger`（未过关）。
- **蒙对、犹豫、通篇对但理由错** → 记 `warn`（待巩固）。用户没说是否犹豫时，对题干沾边但答案明显是碰的，按 `warn` 处理。
- **回炉重做答对** → 把该知识点旧条目升级为 `ok`（已过关），并在 `cause` 末尾补记「X 月 X 日重做答对」。

### 第 3 步 在对话里列出来

先给一行结论（题量、对错数、正确率、本轮最该盯的点），再逐条列错题，每条含：我的答案、正确答案、错因、知识点、下次回炉日。最后单列一段「本轮涉及的知识点」，把分散的错题归到上位概念上（例如两道题都错在「候选键求解」，就点出这一簇）。

```text
## 批改结果 · 死锁与并发控制
共 6 题：对 4、错 2。正确率 67%。

### 错题
1. 第 3 题
   - 我的答案：B　正确答案：D
   - 错因：把「资源编号递增申请」当成破坏不可剥夺。这条规则让所有进程按同一顺序申请，
     成环的等待链不可能形成，破坏的是【循环等待】；不可剥夺指的是已占资源能被强行抢走。
   - 知识点：死锁四个必要条件的区分与破坏手段
   - 下次回炉：2026-10-17

### 本轮知识点
- 死锁四条件：互斥 / 占有且等待 / 不可剥夺 / 循环等待——四个破坏手段各自对应哪一个，是本轮唯一失分簇。
- 资源下限公式：m ≥ n×(w−1)+1，其中 n 为进程数、w 为单进程最大需求。
```

### 第 4 步 更新错题本

按 `references/mistake-book.md` 的字段规则，往 `interactive/mistake-book/app.js` 追加 `MISTAKES` 条目、同步 `WEAK`。改完在对话里报一句改了什么（新增几条、哪几条降级/升级、哪个薄弱点 `errors` 变化）。不要顺手重建 `docs/`。

字段最少取这几项，`tags` 用考点名与上位概念各一个：

```js
{
  date: '2026-10-15',
  kind: '错题',            // 错题 / 盲区 / 疑问
  title: '资源编号递增破坏的是循环等待，不是不可剥夺',
  tags: ['死锁', '必要条件'],
  status: 'danger',
  mine: '第 3 题选 B（不可剥夺）',
  correct: 'D：循环等待',
  cause: '…指向具体规则的错因…',
  next: '2026-10-17',
}
```

`next` 默认取作答日 +2 天，与现有条目惯例一致；用户若说了具体回炉安排就按用户说的。

## 收尾自检

- 卷面里搜不到原题号、来源文件名和答案（模式 A 交付前扫一遍）。
- 选题记录已写，`items` 的 `sourceNo` 与行号对得上。
- 错题本 `MISTAKES`、`WEAK` 两处都动了，`errors` 与 `status` 不矛盾。
- 对话里的「错因」能回到某条讲义规则，不是现象描述。
