# 02.2 E-R 模型 ★★★

E-R 模型（**Entity-Relationship Model**，实体-联系模型）是用图形描述现实世界的一种概念模型。案例题第 2 题的第一小问几乎固定考它。

### 三个基本要素与术语对照

| 中文名 | 英文全称 | 符号 | 定义 |
|---|---|---|---|
| 实体 | Entity | 矩形 | 客观存在、可相互区分的事物；能独立存在 |
| 属性 | Attribute | 椭圆 | 实体或联系所具有的性质；本身不能独立存在 |
| 联系 | Relationship | 菱形 | 实体之间的关联；依附于实体而存在 |

**三者的区分靠"能不能独立存在"**：实体是"名词性对象"，能单独拿出来说；属性是贴在实体上的"特征"，脱离实体就没有意义；联系是**连接两个（或多个）实体**的那条关联，它也有自己的属性（如"选修"上的成绩）。考试让你在图上补框时，先问自己"这个词是对象、是特征，还是关系"。

三个要素的举例：

- **实体 Entity**：一名学生、一门课程
- **属性 Attribute**：学号、姓名、成绩
- **联系 Relationship**：学生"选修"课程

### 联系的类型：1:1、1:n、m:n（必须会判）

判法只有一句：**站在这端的每一个个体上，问它对面那一端能对应几个**。两边都能对应"多个"才是 m:n。

**反例演示（易错）**：别看到"多个"就判 m:n——**只有两边都能是"多个"才是 m:n**。"一个班有多名学生"但"一名学生只属一个班"是 1:n，不是 m:n。反过来，"一个学生可以选多门课，而一门课只能有一个学生选"这种反常识设定，按定义仍是 1:n——**判定永远按题面给的定义走，不按现实经验**。

### 案例 A：图书馆借阅（判联系类型 + 找联系属性）

> **业务**：读者凭读者卡借阅图书。一名读者可以借多本书，一本书同时只能被一名读者借走；每笔借阅记录登记借出日期和应还日期。
>
> **要求**：画出 E-R 图，判断联系类型，并把联系上的属性标在正确位置。

**审题与推导**：

1. **找名词 → 实体**：读者、图书。二者都有能唯一标识自己的编号（读者编号、书号），是独立对象，所以都是实体。
2. **找动词 → 联系**："借阅"连接读者与图书。
3. **判类型**：站到**读者**这一端问"一个读者能对应几本书"→ 多本；站到**图书**这一端问"一本书能对应几个读者"→ **同时只能一个**。两端一边多一边单 → **1:n**，多端是读者。
4. **定属性归属**："借出日期、应还日期"不是读者的特征，也不是图书的特征——同一本书被不同读者借走时日期不同，同一个读者借不同书时日期也不同。它**只由"谁借了哪本书"这一个组合决定**，所以属于**联系"借阅"**，挂在菱形上。

```
              借出日期    应还日期
                  \        /
   ┌──────┐        ◇──────◇        ┌──────┐
   │ 读者 │───────◇ 借阅  ◇───────│ 图书 │
   └──────┘        ◇──────◇        └──────┘
       │                                  │
    读者编号                             书号
      1                                   n
```

**易错点**：把借出日期画到"图书"实体上。判断方法——**问"这个属性是随实体唯一确定，还是随'这对组合'确定"**：同一本书被两次借阅日期不同，说明它不由书号唯一决定，就不能挂在图书上。

### 案例 B：含弱实体的综合场景（考试综合题型）

> **业务**：一所学校有若干**系**，每个系有系编号和系名；一个系聘用多名**教师**，一名教师只属于一个系。一名教师可以讲授多门课，一门课可以由多名教师讲授，**授课**记录该教师讲这门课的课时数。此外，学校为每个系记录其**分教研室**，教研室按"所属系编号 + 本系内编号"区分，不同系的教研室可以同号。
>
> **要求**：画 E-R 图、判断联系类型、生成关系模式。

**审题与推导**：

1. **实体**：系、教师、课程；**弱实体**：教研室。
2. **联系与类型**：系—教师 = **1:n**（一个系多名教师，一名教师只属一个系）；教师—课程 = **m:n**（讲授）；系—教研室 = **1:n**（一个系有多个教研室，一个教研室只属一个系）。
3. **弱实体的识别**：题干说教研室按"**所属系编号 + 本系内编号**"区分，不同系可以同号——这说明它**离开"系"就无法被唯一标识**，且它的标识要借用"系"的主键。这就是**弱实体**（Weak Entity）。

### 弱实体与属性分类（选择题加分点）

**弱实体**：自身属性不足以唯一标识自己，**必须依赖另一个实体（强实体）才能被标识**的存在。画法与转换规则：

| | 强实体 | 弱实体 |
|---|---|---|
| 图形 | 普通矩形 | **双边矩形** |
| 与强实体的联系 | —— | **双边菱形**（标识联系） |
| 主键 | 自身码 | **强实体主键 + 自身区分属性**（组合键） |
| 典型例子 | 系、教师 | 教研室、订单明细、职工家属 |

**属性的五种分类**（选择题会问某个属性属于哪类）：

| 类别 | 含义 | 画法 / 例子 |
|---|---|---|
| 简单属性 | 不可再分 | 学号、年龄 |
| 复合属性 | 可再分为更小部分 | 姓名（姓 + 名）、地址（省 + 市 + 街） |
| 单值属性 | 一个实体只有一个值 | 学号、出生日期 |
| 多值属性 | 一个实体可有多个值 | 电话号码、兴趣；画成**双椭圆** |
| 派生属性 | 可由别的属性算出来 | 年龄（由出生日期算）；画成**虚线椭圆** |

**三种以上实体的联系**：当一条联系同时涉及三个及以上实体时叫**多元联系**（如"供应商—零件—项目"三者之间的"供应"联系），判类型时要把"其余实体都固定住"再看本端能有几个。软考以二元联系为主，多元联系了解概念即可。

### E-R 图转关系模式（案例题必考步骤）

| 联系类型 | 转换规则 |
|---|---|
| 1:1 | 联系并入任一端实体（加对方的主键作外键） |
| 1:n | 联系并入 **n 端**实体（加 1 端的主键作外键） |
| **m:n** | **联系必须单独建一张关系模式**，主键 = 两端主键的组合，联系自身的属性也放这张表 |
| 弱实体 | 单独建表，主键 = **强实体主键 + 自身区分属性** |

**反例演示（易错）**：学生-课程是 m:n，若把"选课"并入学生表（学生表加课程号、成绩列），一个学生选多门课就要占多行，学号、姓名重复存储，而且学号不再能作主键——错。**口诀：多对多，单独坐一桌**。

### E-R 集成时的三类冲突（选择题考过）

多个分 E-R 图合并时会撞车：

- **属性冲突**：同一属性在不同分图里**类型或单位不一致**（这边"重量"用克、那边用千克）。
- **命名冲突**：**同名异义**（都叫"编号"但一个指学生号一个指课程号）或**异名同义**（"教师"与"教员"指同一种人）。
- **结构冲突**：同一对象在**此图是实体、在彼图却成了属性**（这边"系"是独立实体，那边只是"教师"的一个属性）。

**没有"实体冲突"这种说法**——选项里出现即排除。三种冲突里，**最容易考的是结构冲突**，因为它必须改变 E-R 图的结构才能消除，而命名冲突只需统一命名。
