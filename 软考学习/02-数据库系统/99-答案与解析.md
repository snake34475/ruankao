# 02.10 答案与解析

### 课后考题答案

**1. B**
外模式就是某类用户看到的局部数据逻辑（典型实现即视图）。概念模式是全体逻辑，内模式/存储模式是物理层。★ 对应关系直接背。

**2. B**
存储结构变化发生在内模式，靠模式/内模式映像屏蔽 → 物理独立性。易错点：把"逻辑独立性"跟"存储"联想到一起——恰好相反，逻辑独立性屏蔽的是**逻辑结构**（表定义）的变化。

**3. B**
一门课只属一个教师、一个教师可授多门课 → 教师:课程 = 1:n。易错点：见到"多门"就选 m:n——必须**两边都可多**才是 m:n，这里课程一侧只能一个教师。

**4. C**
m:n 联系必须单独建关系模式，主键 = 学生主键 + 课程主键组合，联系自身的属性（成绩）也放这里。并入任一端都会造成学号重复存储、学号失去主键资格。

**5. D**
行数：自然连接行数取决于同名属性上相等的元组如何配对，**不能确定**（最少可能 0 行）；列数 = 4+6−1 = **9**。所以选"行数不确定、9 列"。易错点：列数算成 10（忘了去掉一份重复列）或行数答 15（那是笛卡尔积的行数）。

**6. B**
选择 σ 挑行，投影 π 挑列。口诀：σ 像筛子筛行，π 两条竖线切列。

**7. A**
能唯一标识元组且**无多余属性**正是候选键的定义。超键只要求"能唯一标识"（可含多余属性）；主属性是包含在任一候选键中的属性，不是属性集；外键是引用他表主键的属性。

**8. A**
右部出现过的属性：B（A→B）、C（B→C）、B（D→B）——即 B、C。从未出现在右部的：**A、D** → 先试 AD：A→B，B→C，D→B，闭包 = A、B、C、D 全部 → 候选键 = AD。再看其余三个为何只是超键：ABD 闭包虽也是 ABCD，但 B 可由 A 推出（A→B），去掉 B 剩 AD 仍能推全 → B 是多余属性；ACD 同理，C 可由 A→B→C 推出，去掉 C 剩 AD 仍推全 → C 多余；ABCD 显然更冗余。**候选键 = 无多余属性的"最小"超键，四个选项里只有 AD 满足**。

**9. B**
候选键 = 学号（单属性）→ 不存在部分依赖，直接满足 2NF；但学号→系→系主任是传递依赖 → 达不到 3NF。**最高 2NF**。易错点：因"有冗余"误判 1NF——单属性键的表第一步就不可能有部分依赖。

**10. D**
范式是逐级加严的包含链：1NF ⊃ 2NF ⊃ 3NF ⊃ BCNF。BCNF ⇒ 3NF 成立（C 对），反过来 3NF 不一定到 BCNF（D 错，反例：存在主属性被非主属性决定的情况）。A、B 是标准定义。

**11. B**
聚合条件只能写 HAVING：`GROUP BY 课程号 HAVING AVG(成绩)>=80`。WHERE 在分组前执行，彼时 AVG 还没算出来，A 语法错误。D 把成绩当分组列，会把每个分数各成一组，不符合"按课程"。

**12. B**
GRANT 授予、REVOKE 收回。DROP 是删除对象（DDL），DENY 不是软考教材标准关键词。

**13. C**
读到"未提交、随后被回滚"的数据 = 脏数据（读脏数据）。区分：不可重复读是"本事务两次读之间被**别人提交**的修改弄得不一致"；丢失修改是两个都提交导致一个写被覆盖。

**14. B**
两段锁协议：先统一加锁、后统一放锁 → 保证可串行化；但两个事务可能互相持有对方要的锁（T1 锁 A 等 B，T2 锁 B 等 A）→ **不能避免死锁**。A、C、D 均为典型错误表述。

**15. B**
故障恢复口诀：**已提交 REDO（重做），未提交 UNDO（撤销）**。未完成的事务做了一半，必须撤销抹掉。ROLLBACK 是事务运行期间的主动回滚操作，不是恢复策略本身。

**16. B**
先检验系别：01、03 留下，02 淘汰；再检验学号大于 01：01 淘汰，03 留下。选择保留整行，因此结果只有 `(03, 计算机)`。A 只看了系别却忽略学号条件；C 忘了第二次筛选；D 把选择误当成投影。

**17. D**
先投影 `系别` 一列，临时得到 `计算机、计算机、统计`；去掉重复的“计算机”，最终两行：`(计算机)`、`(统计)`，共 **2 行 1 列**。若不去重会误选 B；若保留学号则不是投影指定的一列。

**18. C**
笛卡尔积先产生 $2\times3=6$ 个配对；按同名属性“学号”相等筛选，R 的 01 分别配上 S 的 `(01, C1)` 和 `(01, C2)`，R 的 02 配不上，S 的 03 也配不上。因此留下 `(01, 小林, C1)`、`(01, 小林, C2)` 两行。列为“学号、姓名、课程号”，同名学号只保留一份，所以是 **2 行 3 列**。反向核对：01 在 R 出现一次、S 出现两次，贡献 $1\times2=2$ 行。

### 案例题答案

**问题 1（E-R 图描述）**：
实体三个：代表团、运动员、比赛项目。
- 代表团—运动员：**1:n** 的"组成"联系；
- 运动员—比赛项目：**m:n** 的"参赛"联系，联系属性：成绩。
（画图时：三个矩形 + 两个菱形；"参赛"菱形上挂"成绩"椭圆。）

**问题 2（关系模式）**：
- 代表团(**团编号**, 团名, 团所在地)
- 运动员(**运动员编号**, 姓名, **团编号**) ← 1:n 联系，把 1 端主键"团编号"并入 n 端作外键
- 比赛项目(**项目编号**, 项目名称)
- 参赛(**运动员编号, 项目编号**, 成绩) ← m:n 联系单独建表

**"参赛"表的主键 =（运动员编号，项目编号）组合键**——单靠任何一端都无法唯一标识一行（同一运动员参加多个项目、同一项目多名运动员）。

**问题 3（SQL）**：

```sql
-- (1) 建参赛表
CREATE TABLE 参赛 (
    运动员编号  CHAR(8),
    项目编号    CHAR(6),
    成绩        SMALLINT,
    PRIMARY KEY (运动员编号, 项目编号),
    FOREIGN KEY (运动员编号) REFERENCES 运动员(运动员编号),
    FOREIGN KEY (项目编号)   REFERENCES 比赛项目(项目编号)
);
```

```sql
-- (2) 各代表团总分，保留 300 分以上
SELECT 代表团.团编号, 代表团.团名, SUM(参赛.成绩) AS 总分
FROM 代表团
JOIN 运动员 ON 代表团.团编号 = 运动员.团编号
JOIN 参赛   ON 运动员.运动员编号 = 参赛.运动员编号
GROUP BY 代表团.团编号, 代表团.团名
HAVING SUM(参赛.成绩) >= 300;
```
（要点：三表连接取全路径代表团→运动员→参赛；GROUP BY 带上团编号防止两个代表团重名被并成一组；聚合条件进 HAVING。）

```sql
-- (3) 建视图
CREATE VIEW vHighScore AS
SELECT 运动员.运动员编号, 运动员.姓名, 比赛项目.项目名称
FROM 运动员
JOIN 参赛 ON 运动员.运动员编号 = 参赛.运动员编号
JOIN 比赛项目 ON 参赛.项目编号 = 比赛项目.项目编号
WHERE 参赛.成绩 >= 95;
```

**案例二答案**

**问题 1（联系名与联系类型）**：
- 门店—会员：联系名"**注册**"，**1:n**（门店端 1、会员端 n）——"每名会员只在一家门店注册，一家门店可注册多名会员"。
- 门店—团课：联系名"**开设**"，**1:n**（门店端 1、团课端 n）——"每家门店可开设多门团课，一门团课只在一家门店开设"。
- 会员—团课：联系名"**报名**"，**m:n**——"每名会员可报名多门团课，每门团课可被多名会员报名"；联系自身的属性是**报名日期**。

判法：每组都站到一端问"对面能对应几个"，只有**两端都能是"多个"**才是 m:n。

**问题 2（补全关系模式）**：
(a) = **门店编号**　(b) = **门店编号**
- "门店—会员"是 1:n，把 1 端（门店）的主键**并入 n 端**（会员）；
- "门店—团课"是 1:n，同理把门店编号并入 n 端（团课）。

"报名"关系模式的**主键 =（会员编号, 课程编号）组合键**。理由：单看会员编号，一名会员可以对应多门团课；单看课程编号，一门团课可以对应多名会员；只有"会员 + 团课"这个组合才能唯一标识一行。题面还明确"同一名会员在同一门团课上最多报名一次"，保证该组合不会重复。

全部外键：

| 关系模式 | 外键 | 来源 |
|---|---|---|
| 会员 | 门店编号 → 门店 | 门店—会员 1:n 并入 n 端 |
| 团课 | 门店编号 → 门店 | 门店—团课 1:n 并入 n 端 |
| 报名 | 会员编号 → 会员 | m:n 单独建表，两端主键都跟过来 |
| 报名 | 课程编号 → 团课 | 同上 |

**易错点**：只写"报名"表的两个外键，漏掉会员表、团课表里的**门店编号**。1:n 联系并入 n 端后，那个被并入的列**就是外键**，真题常年在这里挖空。

**问题 3（增补实体与联系）**：

(1) 新增实体：**教练**，属性为教练编号、姓名、等级。
新增两组联系：
- 门店—教练：联系名"**聘用**"，**1:n**（门店端 1、教练端 n）——"一家门店有多名教练，一名教练只属于一家门店"；
- 教练—团课：联系名"**讲授**"，**m:n**——"一名教练可以讲授多门团课，一门团课可以由多名教练讲授"；联系自身的属性是**课时数**。

(2) 转换后的关系模式：
- 教练(**教练编号**, 姓名, 等级, 门店编号)　主键：教练编号；外键：门店编号 → 门店（1:n 把 1 端主键并入 n 端）
- 讲授(**教练编号, 课程编号**, 课时数)　主键：(教练编号, 课程编号) 组合键；外键：教练编号 → 教练、课程编号 → 团课（m:n 单独建表，联系属性跟过来）

(3)"课时数"放在**讲授**关系模式中。理由：它不随教练唯一确定——同一名教练讲不同团课课时不同；也不随团课唯一确定——同一门团课由不同教练讲课时不同。它只由"**哪名教练讲哪门团课**"这一个组合决定，所以是联系"讲授"的属性；"讲授"是 m:n，单独建表后它就跟着落到这张表里。

**注意"聘用"不单独建表**：它是 1:n，已被"并入 n 端"消化成教练表里的门店编号列。如果为它单独建一张"聘用"表，那是错的。

**问题 4（弱实体判断与说明）**：

(1) **属于弱实体**。50 字以内作答：

> 联系人不单独编号，姓名可在不同会员间重复，离开会员无法唯一标识，必须借用会员主键。

作答模板（换成别的场景也照这个骨架写）：**是弱实体 → 它为什么不唯一 → 必须借用强实体主键**。三个成分缺一不可：只说"是弱实体"不给分，因为题目要的是原因；只描述现象不说"必须借用主键"也拿不全分。

判断依据（三条命中其一即可）：机构**不为它单独编号**；题干明说**不同会员可以有同名同电话的联系人**，即自身属性可能重复；它**不能脱离会员存在**——会员注销，其紧急联系人信息随之无效。

(2) 紧急联系人(**会员编号, 联系人姓名**, 与会员的关系, 联系电话)
- 主键：**(会员编号, 联系人姓名)** 组合键——自身属性（姓名、关系、电话）都不足以唯一标识一条联系人记录，必须**借用强实体"会员"的主键**，再加上自身区分属性"联系人姓名"（题面已保证同一名会员的联系人姓名不重复，所以这个组合不会重复）。
- 外键：**会员编号 → 会员（会员编号）**。

对照记忆：这与"邮件附件"是同一种结构——附件号只在一封邮件内唯一，所以附件的主键是（邮件号, 附件号），附件就是弱实体。

### 补充题答案

**1. A⁺={A,B,C,D,E}，A 是候选键；C⁺={C}，C 不是候选键。**

演算 A⁺：初始 `{A}`；A→BC，加入 B、C；B→D，加入 D；已有 C、D，可用 CD→E，加入 E；闭包达到全集。A 是单属性，无法再删，故为候选键。反向验证 C⁺：只有 C 时，CD→E 缺 D，其余依赖左部也不满足，没有新属性可加入，故停在 `{C}`。

**2. 候选键为 AB、AC；主属性为 A、B、C；最高为 3NF。**

`(AB)⁺=ABC`，且 A⁺、B⁺都推不全，所以 AB 是候选键。`(AC)⁺` 中由 C→B 得到 B，故为 ABC；A⁺、C⁺都推不全，所以 AC 也是候选键。全部属性都出现在某个候选键中，都是主属性，因此至少满足 3NF；但依赖 C→B 中，C 不是超键，违反 BCNF，故最高 **3NF**。这也反向验证了“全属性皆主属性不代表一定是 BCNF”。

**3. A。**

分解 A 的公共属性是 A，且 A→AB，所以公共属性能决定 R1，分解无损。分解 B 的公共属性是 B，而由 F={A→B} 推不出 B→AB 或 B→BC，不能用该条件判为无损。

**4. 4 行、3 列。**

公共值 x 在 R 中出现 2 行，在 S 中出现 2 行，产生 `2×2=4` 个组合；y、z 互相配不上。列数为 `2+2−1=3`，属性是 A、B、C。用实际枚举四个组合可反向核对行数。

**5. SQL 如下：**

```sql
SELECT S.Sname
FROM Student AS S
WHERE EXISTS (
    SELECT 1
    FROM SC
    WHERE SC.Sno = S.Sno
      AND SC.Cno = 'C02'
);
```

`SC.Sno = S.Sno` 把内层记录与“当前外层学生”绑定。若省略，只要全校任意一人选了 C02，子查询对每个学生都为真，会错误返回全校学生。

**6. A。**

S 与 S 相容，所以 T2 可再申请 S 锁；S 与 X 不相容，X 锁必须等待。矩阵中唯一的“相容”格就是 S-S。

**7. D。**

同一范围查询的结果集新增了满足条件的行，属于幻读。不可重复读通常指已存在的同一行字段值改变；脏读必须涉及未提交数据。

**8. 系统故障；REDO T1、UNDO T2。**

断电但磁盘未损坏属于系统故障。T1 已提交，其结果必须保留，故 REDO；T2 未提交，半成品必须消失，故 UNDO。反向检查：恢复后数据库只应体现已提交事务。

**9. 分片透明；可用性。**

“怎样水平切块”描述分片规则，属于分片透明；站点失效后仍能借助其他副本服务，描述系统抗单点故障，体现可用性。后者问的是特性，不是复制透明。

**10. C。**

$T_1$ 是选课表中课程号为 C1 的三行（01、02、05）的学号集合；$T_2$ 是课程号为 C2 的两行（01、03）的学号集合。逐项验：A 错——并把两边合并再去重，应得 {01,02,03,05}，选项写的只是 $T_1$ 自己；B 错——交只留两边共有，02 不在 $T_2$ 中，结果应为 {01}；D 错——并运算只要求结构相容（列数相同、每列同域），与行数无关；C 对——差是“左边有、右边没有”，01 在 $T_2$ 中被剔除，剩 {02,05}，问法“选了 C1 但没选 C2”与运算一致。

**11. A。**

$R-S$ 是 $R$ 中不属于 $S$ 的部分，从 $R$ 里再删掉这部分，剩下的就是既在 $R$ 又在 $S$ 的交集。代入第 10 题数据交叉验证：令 $R$={01,02,05}、$S$={01,03}，$R-S$={02,05}，$R-(R-S)$={01}，与 $R\cap S$ 结果一致。B 错——$S-R$={03} 与 $R$ 无公共元素，从 $R$ 中减它仍是 $R$；C 错——那是“各自独有部分”的对称差；D 错——$R-S$ 本含于 $R$，并回 $R$ 仍是 $R$。

**12. A。**
站在**医生**一端问：一名医生能负责几个科室 → 题面"最多负责一个"→ 至多 1；站在**科室**一端问：一个科室能由几名医生负责 → "最多由一名医生负责" → 至多 1。两端都至多 1，所以是 **1:1**。
B 错——1:n 读作医生端 1、科室端 n，即一名医生可负责多个科室，与"最多负责一个科室"矛盾；C 错——m:n 要求两端都可多，题面两端都限死了 1；D 错——n:1 读作医生端 n、科室端 1，即一个科室可有多名负责医生，与"最多由一名医生负责"矛盾。**判定只看题面给的定义，不看"现实中一个科室会不会有好几个医生"**。

**13. (1) B　(2) B。**
(1) 两个分图用"患者""病人"两个**不同名称指向同一对象**，属于命名冲突里的**异名同义**。A 错——属性冲突指同一属性的类型、取值范围或单位不一致，题面没有属性层面的不一致；C 错——结构冲突指同一对象在两图中的抽象不同或属性集合不一致，题面两边都是实体；D 错——**没有"实体冲突"这种说法**，选项里出现即排除。
(2) 命名冲突（异名同义）只需**统一命名**并合并为同一个实体。A 错——同一对象建成两个实体会让同一份数据两处存放；C 错——补充属性解决不了名称不统一；D 错——不处理，集成后仍有两个名字指向同一对象。**三类冲突里命名冲突的消除代价最小，只需统一命名**。

**14. (1) C　(2) A。**
(1) 同一对象（客房）在两个分图中**属性集合不一致**，属于结构冲突。A 错——属性冲突是同一属性的类型、单位或取值范围不一致，题面里两边同名的"房号""房型"含义相同，没有任何属性域冲突；B 错——两边名称都叫"客房"，不是命名问题；D 错——无此说法。
(2) 结构冲突必须**改变结构**才能消除：把两个分图对"客房"的描述统一成一个实体，属性集合取并集并核对含义。B 错——直接丢弃"可住人数"会丢掉预订部门需要的信息；C 错——同一对象建成两个实体会造成集成后语义重复；D 错——不做任何改动，属性不一致的问题原样保留，等于没集成。

**15. A。**
把 1:1 联系"管理"并入**部门**端后，部门关系模式要**加经理号作外键**，并且**联系的属性"任命日期"随联系一起并入这一端**；主键仍是原来的**部门号**。
B 错——漏掉经理号，部门表与经理表之间没有关联列，这个外键正是并入时最容易漏掉的一列；C 错——经理号是外键，把它一起写进主键会让主键包含可由部门号决定的属性，违反"主键不含多余属性"；D 错——联系并入哪一端，它的属性就跟到哪一端，把"任命日期"留在经理端等于把一条联系拆到两张表里。
说明：1:1 联系并入**任一端**都可以，本题并入部门端；若并入经理端，则写成 经理(**经理号**, 姓名, 部门号, 任命日期)，同样是加对方主键作外键、联系属性一并并入。两种写法都正确，考试写一种即可。

### 精华题答案

**1. 视图属于外模式；索引属于内模式**
视图是用户局部视图（外模式级，典型实现）；索引是物理存储组织（内模式级）。这题考"具体事物 → 归哪一层"：用户看到的逻辑 = 外模式，磁盘组织细节 = 内模式。

**2. 列数 = 3 + 2 − 1 = 4 列**（R 的 A、B、C 三列加 S 的 D 列，公共属性 B 只留一份）。
行数最多 = **2×3 = 6 行**（R 的每行 B 值恰好都能在 S 中配上时，最多达到笛卡尔积水平；若 B 值全对不上则 0 行）。

**3. R 最高属于 2NF**
候选键 = 仓库号（单属性）→ 无部分依赖 → 满足 2NF；仓库号→城市→地区编号是传递依赖 → 不到 3NF。
分解到 3NF：仓库(**仓库号**, 仓库面积, 城市) 和 城市(**城市**, 地区编号)。

**4. 候选键 = E**
右部出现过的属性：B、D、A、C；从未出现在右部的只有 **E**。试 E：E→A，A→B，B→C，C→D → 闭包 = ABCDE，全部推出 → **E 单属性即候选键**。（验证：E→A→B→C→D，链式全推。）

**易错点：答案不是 "AE"**。AE 也能推出全部属性（A→B→C→D，再加 E），但它**含冗余属性**——E 一个人就够了，A 是多余的。候选键的定义是**不含冗余属性的最小超键**，能少一个就少一个，多出来的那个只能叫超键。反向也要查一遍：A 行不行？A→B→C→D 只能推出 A、B、C、D，**推不出 E**，所以 A 不是候选键。本题**唯一候选键 = E**。

**5. 发生丢失修改时，A 的错误终值可能是 100 或 70；正确终值应为 120 或 140（取决于串行顺序）**
错误终值举例：T1 读 A=50 → T2 读 A=50 → T1 写回 70 → T2 写回 50×2=100，T1 的 +20 被覆盖丢失；另一交错 T2 先写 100、T1 再写 70，则 T2 的结果丢失。正确终值：先 T1 后 T2 串行 = (50+20)×2 = **140**；先 T2 后 T1 = 50×2+20 = **120**——两种都符合事务语义，但丢失修改哪种都得不到。此题演示"丢失修改 = 一个事务的写被另一个事务的写覆盖"。

**6. SQL 答案**：

```sql
-- (1) 嵌套查询
SELECT Sname FROM Student
WHERE Sno IN (SELECT Sno FROM SC WHERE Cno = 'C02');

-- (2) 选课超过 3 门
SELECT Sno FROM SC
GROUP BY Sno HAVING COUNT(Cno) > 3;

-- (3) 授权（可转授）
GRANT SELECT ON SC TO U1 WITH GRANT OPTION;
```
要点：(2) 聚合条件进 HAVING；(3) WITH GRANT OPTION 是"允许转授"的固定写法。

**7. 前者是不可重复读，后者是读脏数据**
"两次读结果不同"：两次读之间**别的已提交事务**改了数据；"读到未提交"：读到的事务随后可能回滚。判断窍门：看干扰事务**提交没有**——提交了 → 不可重复读；没提交（后回滚）→ 脏读。
