# 02.4 关系规范化 ★★★

### 为什么要规范化

一张大表什么都往里塞，会出现三种病：**数据冗余**（系主任跟着每个学生重复存）、**修改麻烦**（换主任要改几百行）、**插入/删除异常**（还没招生的系插不进来、最后一个学生毕业系主任信息也跟着没了）。规范化的目的就是**拆表**，把这些病一步步消掉。

### 函数依赖（判断范式的唯一工具）

先分清记号：假设有一张`选课(学号, 课程号, 姓名, 成绩)`表。**表**是“选课”，学号、课程号、姓名、成绩是表的**属性**（可理解为字段或列）。`X`、`Y` 不是表名，也不是某一行里的具体值，而是用来代指**属性或属性的组合**；例如 `X` 可以是“学号”，也可以是“(学号, 课程号)”，`Y` 可以是“姓名”。`K` 也代表属性组合，但特指这张表的一个**候选键**：凭它能唯一确定一行，且去掉其中任何一个属性就不行。若同一学生选同一课程只记一条记录，则本例的 `K = (学号, 课程号)`。

`X→Y` 读作“X 决定 Y”（Y 函数依赖于 X）：在这张表的业务规则下，**任意两行只要 X 相同，Y 就必须相同**。例如同一学号总对应同一姓名，所以 `学号→姓名`；只知道学号不能确定成绩，因为同一学生不同课程的成绩可以不同，而同时知道学号和课程号才能确定该次选课的成绩。这里比较的是列的取值规律，箭头两边写的是属性，不是“表决定表”，也不是某个具体值指向另一个值。

看下图中的三条记录。X、Y、K 是给**列或列的组合**起的代号；S01、C01、张三、86 才是各行里的**具体值**。

```text
                 选课表（每行是一条记录）
        X = 学号      课程号       Y = 姓名      成绩
第 1 行    S01          C01          张三          86
第 2 行    S01          C02          张三          92
第 3 行    S02          C01          李四          78

X → Y：第 1、2 行的学号同为 S01，姓名也同为张三。
X 不能决定成绩：第 1、2 行学号相同，成绩却不同。
K = (学号, 课程号)：两列合起来标识一条选课记录。
K → 成绩：同时给定学号和课程号，才能确定这次成绩。
```

图中的三行只是帮助看懂规则；判断函数依赖仍要依据业务约束，不能只因这几行恰好没有冲突，就认定某个箭头成立。

下面看三种关键形态（设 `K` 是候选键）：

- **完全依赖**：Y 依赖整个 K，去掉 K 中任何一个属性都不行。例：(学号, 课程号)→成绩。
- **部分依赖**：Y 依赖 K 的**一部分**就够了。例：(学号, 课程号)→姓名，其实学号→姓名——**部分依赖是病**。
- **传递依赖**：X→Y、Y→Z 且 Y 不决定 X，则 Z 传递依赖 X。例：学号→系名→系主任——**传递依赖是病**。

把同一个选课表的依赖画出来，更容易看清“整个键”和“键的一部分”的区别（箭头表示函数决定）：

```text
学号 ───────────────→ 姓名       只用学号就够：部分依赖
  │
  └─ 与课程号合在一起 ─→ 成绩     必须同时知道两者：完全依赖

学号 ─→ 系名 ─→ 系主任           经系名中转：传递依赖
```

这里的候选键是 `(学号, 课程号)`；“姓名”没有用到整个键，才是 2NF 要消除的问题。“系主任”的路径则说明 3NF 为什么还要检查传递依赖。

先把几个容易混的“键”分清。以学生表 `学生(学号, 身份证号, 姓名, 系名)` 为例：每个学生有唯一的学号和身份证号，知道其中任意一个，就能确定这一行的全部属性。

| 名称 | 怎么判断 | 本例中的结果 |
|---|---|---|
| **超键** | 能确定整行；允许含多余属性 | `学号`、`(学号, 姓名)` 都是 |
| **候选键** | 能确定整行，且删掉其中任何属性就不行 | `学号`、`身份证号` |
| **主键** | 从候选键中选一个作主要标识 | 假设选 `学号` |
| **主属性** | 出现在任一候选键中的**单个属性** | `学号`、`身份证号`；`姓名、系名` 是非主属性 |
| **全码** | 全部属性合在一起才是候选键 | 此学生表不是全码，见下例 |

再逐个检查几个属性组合。这里“能确定整行”只按上面声明的业务规则判断，不能只看当前表里是否碰巧没有重复值。

| 属性组合 | 能确定整行吗 | 有多余属性吗 | 属于什么 |
|---|---|---|---|
| `学号` | 能 | 没有 | 超键、候选键；本例选它作主键 |
| `身份证号` | 能 | 没有 | 超键、候选键；没有被选为主键 |
| `(学号, 姓名)` | 能 | 有，删掉姓名仍能确定整行 | 超键，但不是候选键 |
| `姓名` | 不能，同名学生可能有多位 | 不适用 | 不是键 |

所以**每个候选键都是超键，但超键不一定是候选键**；主键只是被选中的那个候选键。“主属性”说的是属性本身：身份证号即使没被选作主键，仍因出现在候选键中而是主属性。

**全码另看一个例子**：设 `选课记录(学号, 课程号, 学期)` 中，一名学生对同一门课在同一学期只记一条记录。学生可在不同学期重修同一课程，所以 `(学号, 课程号)` 不够；同一学期可选多门课，所以 `(学号, 学期)` 不够；同一课程同一学期可有多名学生，所以 `(课程号, 学期)` 也不够。若没有其他能决定属性的业务规则，必须三个属性一起才能确定一条记录，此时 `(学号, 课程号, 学期)` 是全码。学生表即使把四个属性全放在一起，也能确定整行，但学号一个就够了，所以它的全部属性只是超键，**不是全码**。

**反例演示（易错）**：若候选键有 `AB` 和 `AC`，主属性是 `A、B、C` 的并集，不是只看被选作主键的 `AB` 而把 C 误判为非主属性。范式判断看的是**所有候选键**，不是只看主键。

### 范式判定：一级一级"消病"

**先过 1NF 这一关。**

1NF（第一范式）要求每个字段的每一格只存一个可按当前业务使用的值，不能把一组同类值塞进一格。这里的“不可再分”是相对于业务而言：学号 `S01` 虽能拆成字符，但业务把它当一个编号，仍是原子值；`C01、C02` 若表示两门选修课，就不是一个课程号。

例如把课程号列表直接存进学生表：

| 学号 | 姓名 | 选修课程号 |
|---|---|---|
| S01 | 张三 | C01、C02 |

这一格里有两个课程号。若要查“谁选了 C02”或给 S01 再加一门课，都得拆读、改写整格；**这张表不满足 1NF**。把每门课单独记为一行：

| 学号 | 姓名 | 课程号 |
|---|---|---|
| S01 | 张三 | C01 |
| S01 | 张三 | C02 |

现在每格只有一个值，满足 **1NF**。但它还不是 2NF：假设每名学生可选多门课、每门课可被多名学生选，且同一学生选同一门课只记一条记录，那么候选键是 `(学号, 课程号)`；而 `学号→姓名`，姓名只依赖键的一部分。继续拆成 `学生(学号, 姓名)` 与 `选课(学号, 课程号)`，才能消除这个部分依赖。**1NF 只检查值是否原子，不保证已经消除重复或函数依赖问题。**

| 范式 | 要求 | 一句话判定 |
|---|---|---|
| 1NF | 每格是单个原子值 | 不把多个同类值塞在一格 |
| 2NF | 消除**部分依赖** | 每个非主属性都依赖**整个**候选键 |
| 3NF | 再消除**传递依赖** | 非主属性不间接依赖候选键 |
| BCNF | 每个非平凡依赖的决定因素都必须是超键 | 比 3NF 更严：主属性也不能有依赖毛病 |

**判定四步法（先确认满足 1NF，再按此流程检查更高范式）**：
1. 找候选键（见下）；
2. 列出所有"决定→被决定"；
3. 看有没有**非主属性只依赖候选键一部分** → 有则最高 1NF；
4. 再看有没有**非主属性靠别的非主属性中转** → 有则最高 2NF；都没有 → 3NF；若还有主属性被非主属性决定 → 不到 BCNF。

把判定压成一张“谁依赖谁”表：

| 观察到的依赖 | 造成什么问题 | 最高可能停在哪 |
|---|---|---|
| 非主属性依赖组合候选键的一部分 | 部分依赖 | 1NF |
| 非主属性经另一个非主属性间接依赖候选键 | 传递依赖 | 2NF |
| 决定因素不是超键，但右部是主属性 | 允许满足 3NF，不满足 BCNF | 3NF |
| 每个非平凡依赖的决定因素都是超键 | 无上述问题 | BCNF |

**快判 1**：候选键只有一个属性时，不可能存在“对候选键一部分”的依赖，因此只要满足 1NF 就自动满足 2NF。

**快判 2**：如果所有属性都是主属性，就没有“非主属性的部分依赖或传递依赖”，因此至少满足 3NF；但决定因素若不是超键，仍可能不到 BCNF。

例：R(A,B,C)，F={AB→C，C→B}。候选键有 `AB` 和 `AC`，所以 A、B、C 全是主属性，R 满足 3NF；但 `C→B` 的决定因素 C 不是超键，因此不满足 BCNF，最高为 **3NF**。

**主属性也会部分依赖，但不会把关系打回 1NF**：上例候选键 `AC` 中，主属性 B 由 C 单独决定，即 B 对候选键 AC 存在部分依赖。2NF 的检查对象是**非主属性**，所以该依赖不违反 2NF；它真正违反的是更严格的 BCNF 条件。不要见到“部分依赖”四个字就机械判 1NF，先看被决定者是不是非主属性。

**反例演示（易错）**：R(学号, 姓名, 系, 系主任)，学号→姓名、学号→系、系→系主任。候选键是学号（单属性），**不可能有部分依赖**（键只有一个属性，"一部分"还是它自己），所以它**直接就是 2NF**；但学号→系→系主任是传递依赖，所以**最高 2NF，不是 3NF**。最常见的错误就是把"有冗余"当成"不是 2NF"——单属性键的表不存在部分依赖，第一步就能跳过。

### 候选键怎么求（案例题必考）

候选键的严格工具是**属性闭包**。属性集 X 在函数依赖集 F 下能推出的全部属性，记作 `X⁺`。若 `X⁺` 等于关系的全部属性，则 X 是超键；再逐个删除 X 中属性，删谁都不能推全，X 才是候选键。

**先认清下面的记号**：X、Y、Z 都表示一组属性；`Y→Z` 表示已知 Y 就能确定 Z；`X⁺` 读作“X 的闭包”，计算时用它记录从 X 出发已经推出的属性。`⊆` 读作“包含于或等于”：`Y ⊆ X⁺` 表示 Y 中的每个属性都已经在 `X⁺` 里，例如 `{A1,A2} ⊆ {A1,A2,A3}`。满足这个条件，才能用 `Y→Z` 把 Z 收进闭包。

**闭包算法（通用形式）**：

1. 初始化 `X⁺ = X`；
2. 反复扫描每条函数依赖 `Y→Z`：若 `Y ⊆ X⁺`，就把 Z 加入 `X⁺`；
3. 一轮扫描后不再增加属性时停止；
4. 与属性全集比较，再做“逐个删除”最小性检查。

**手算口诀：先把自己圈进去；左边已齐，就收右边；一轮没新增，才算停。**

**Armstrong 三条公理**是闭包推导的依据：

- **自反律**：若 Y⊆X，则 X→Y；
- **增广律**：若 X→Y，则 XZ→YZ；
- **传递律**：若 X→Y 且 Y→Z，则 X→Z。

考试常直接使用三条派生规则：**分解**（X→YZ 可推出 X→Y、X→Z）、**合并**（X→Y 且 X→Z 可推出 X→YZ）、**伪传递**（X→Y 且 WY→Z，可推出 WX→Z）。

**完整演算**：R(A1,A2,A3,A4,A5,A6)，F={A1→A3，A1A2→A4，A5A6→A1，A3A5→A6，A2A5→A6}，求一个候选键。

1. 从未出现在任何依赖右部的属性是 `A2、A5`，它们无法由其他属性推出，必须进入每个候选键；
2. 初始化 `(A2A5)⁺={A2,A5}`；
3. 用 `A2A5→A6`，加入 A6；
4. 用 `A5A6→A1`，加入 A1；
5. 用 `A1→A3`，加入 A3；
6. 用 `A1A2→A4`，加入 A4；
7. 闭包已是 `{A1,A2,A3,A4,A5,A6}`，故 A2A5 是超键；去掉 A2 或 A5 都无法推全，因此 **A2A5 是候选键**。

把每次新收进来的属性排成一条推导链，可以看出闭包为何不能只扫一轮：

```text
起点 {A2,A5}
  │ A2A5→A6
  ▼
{A2,A5,A6}
  │ A5A6→A1
  ▼
{A1,A2,A5,A6}
  │ A1→A3，再由 A1A2→A4
  ▼
{A1,A2,A3,A4,A5,A6} = 全部属性
```

第二步得到 A1 后，原先不能使用的 `A1→A3` 和 `A1A2→A4` 才变得可用；每次有新增属性，都要继续扫描依赖。

反向验证：只用 A2 时没有任何依赖可启动；只用 A5 也无法启动，两个属性都不可删除，最小性成立。

**启发式口诀：从未在依赖右部出现的属性，必在每个候选键里**。但这只是起点，不是答案；必须继续算闭包并检查最小性。

例：R(A,B,C,D)，F = {A→B, B→C, D→B}。右部出现过的：B、C。从未出现在右部的：**A、D**。验证 AD：A→B，B→C，D→B → 可推出 A、B、C、D 全部 → **候选键 = AD**（ABD 虽也能决定全部，但含多余属性，是超键不是候选键）。

### 分解后怎么检查：无损连接与保持函数依赖

规范化不是“拆得越碎越好”。拆完必须过两道门：

1. **无损连接**：分表自然连接后能准确还原原关系，不丢行，也不产生原来不存在的假行；
2. **保持函数依赖**：原来的约束能在各分表内部检查，不必把表连接起来才能验证。

二元分解 `R→R1、R2` 的常用无损快判是：公共属性 `R1∩R2` 能否函数决定 R1 或 R2 的全部属性，即检查 `(R1∩R2)→R1` 或 `(R1∩R2)→R2` 是否成立。

例：R(A,B,C)，F={A→B}，分为 R1(A,B) 与 R2(A,C)。公共属性是 A，且 `A→AB` 成立，所以分解**无损**。

反例：仍是 R(A,B,C)，若分为 R1(A,B) 与 R2(B,C)，公共属性是 B，但由 F 只能知道 A→B，推不出 `B→AB` 或 `B→BC`，因此不能判为无损，实际可能连接出假行。

**保持依赖不等于无损**：两者是不同检查项。3NF 综合算法通常可以兼顾无损和保持依赖；BCNF 分解保证无损，但可能牺牲某些依赖保持。案例题若只问“能否还原原表”，答无损；若问“能否分别在单表内检查全部约束”，答保持函数依赖。

**应试动作**：背四步判定法 + "右部不出现的属性进候选键"；考"最高属于第几范式"时**从低往高验**，卡在哪级就答前一级。
