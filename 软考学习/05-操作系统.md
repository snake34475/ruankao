## 第一节 进程与线程 ★

### 为什么要有进程

程序是躺在我盘上的代码文件（静态），但系统里同时跑着浏览器、播放器、输入法——每个"正在执行的程序副本"就是一个**进程**（动态）。进程 = 程序的一次执行过程，由创建而产生、完成任务后撤销而消亡。**进程是系统进行资源分配和调度的独立单位**。

进程由三部分组成：**程序块 + 数据块 + 进程控制块 PCB**。

| 组成部分 | 作用 |
|---|---|
| 程序块 | 要执行的代码 |
| 数据块 | 处理的数据 |
| **PCB** | 进程的"身份证 + 档案袋"：进程标识符、状态、现场保护区、队列指针等 |

**PCB 是进程存在的唯一标志**——系统根本"看不见"程序，它只认 PCB。创建进程 = 建 PCB，撤销进程 = 撤 PCB。这是选择题直接考的一句话。

### 线程：进程内部的"分工"

进程是资源分配单位，但切换进程开销大，于是把"调度"下放到更小的单位——**线程**。线程是处理机调度的基本单位，同一进程内的多个线程共享进程的资源。

**共享 / 不共享（必背）**：

| 同一进程的线程**共享** | 线程**独有** |
|---|---|
| 进程的代码段、全局变量、堆、打开的文件、信号处理器 | **栈**（每个线程有自己的栈）、寄存器组、程序计数器 |

**反例演示（易错）**：题目爱问"以下叙述错误的是"——凡出现"线程间共享**栈 / 栈指针 / 寄存器**"必错；凡"共享代码段 / 全局变量 / 打开的文件"必对。记忆法：栈是各线程自己的"私人工作台"，代码和仓库（全局变量、文件）是整间办公室公用的。

**应试动作**：背两句话——"PCB 是进程存在的唯一标志"；"线程共享代码/全局数据/文件，独有栈和寄存器现场"。考场上认特征词：题干说"资源分配"→ 进程，说"调度/处理机"→ 线程。

## 第二节 进程状态转换 ★★★（几乎每年 1 题）

### 为什么要有状态

CPU 只有一个，进程几十个，必须给每个进程贴个状态标签，调度器才知道"谁在跑、谁能跑、谁在干等"。三态模型：

- **运行**：正在 CPU 上执行（单处理机上处于运行的进程**只有一个**）；
- **就绪**：万事俱备只欠 CPU——除 CPU 外什么资源都有了，排着队等调度；
- **阻塞（等待/睡眠）**：在等别的事件（如等 I/O 完成），**就算给它 CPU 也跑不了**。

### 三态转换图（必须能默写）

```
          调度（被选中）
  就绪 ────────────────→ 运行
   ↑  ←────────────────  │
   │      时间片到        │ 请求I/O等事件（主动等）
   │ 事件发生（I/O完成）   ↓
   └──────────────────  阻塞
```

| 转换 | 触发条件 | 可能吗 |
|---|---|---|
| 就绪 → 运行 | 被调度程序选中 | ✓ |
| 运行 → 就绪 | **时间片用完**（或被更高优先级抢占） | ✓ |
| 运行 → 阻塞 | 进程**主动**请求 I/O、等待某事件 | ✓ |
| 阻塞 → 就绪 | 等待的事件**发生**（如 I/O 完成） | ✓ |
| 运行 → 阻塞 与 阻塞 → 运行 之外的组合见下 | | |
| **就绪 → 阻塞** | —— | **✗ 不可能**（阻塞是"运行中主动去等"才会发生的，就绪的进程根本没在跑，没机会发起等待） |
| **阻塞 → 运行** | —— | **✗ 不可能**（事件发生后先进就绪队列排队，不能插队直接上 CPU） |

**公式三件套（判转换题的通用判据 + 算例 + 口诀）**：
- 判据：阻塞 → 运行必须经过**就绪**中转；就绪 → 阻塞不存在。
- 算例：进程 P 在运行中发出读盘请求 → 运行→阻塞；盘读完了 → 阻塞→就绪；轮到 P → 就绪→运行；P 时间片用完 → 运行→就绪。
- 口诀：**"运行一头两头堵"**——运行能去就绪（时间片到）也能去阻塞（等事件）；回来都得先到就绪，除了"事件发生"那条从阻塞回到就绪。

**五态模型（了解）**：三态基础上增加"挂起"——进程被换出到磁盘对换区（主存不足、故障调试时），活动就绪↔静止就绪、活动阻塞↔静止阻塞。记住：**三态中的每一种都可能被挂起**。

**应试动作**：背死两个"不可能"（就绪→阻塞、阻塞→运行）；场景题对号入座——"时间片到"→运行→就绪，"等 I/O"→运行→阻塞，"I/O 完成"→阻塞→就绪，"被调度选中"→就绪→运行。

## 第三节 进程调度与周转时间 ★★

### 为什么要算周转时间

用户交一个作业给系统，最关心的就是"多久能跑完"。周转时间衡量这个：从**到达**到**完成**的全部等待 + 运行时间。调度算法不同，周转时间不同——考题就是给几个作业的到达/运行时间，让你按某算法排顺序再求平均周转时间。

### 公式三件套

- **通用形式**：周转时间 = 完成时刻 − 到达时刻；平均周转时间 = 各作业周转时间之和 ÷ 作业数；带权周转时间 = 周转时间 ÷ 实际运行时间。
- **代入算例**：作业 J1 时刻 0 到达、需运行 4；J2 时刻 1 到达、需运行 3；J3 时刻 2 到达、需运行 1。按先来先服务（FCFS）单道顺序执行：J1 在 0–4 完成，周转 = 4−0 = 4；J2 在 4–7 完成，周转 = 7−1 = 6；J3 在 7–8 完成，周转 = 8−2 = 6。平均周转时间 = (4+6+6)/3 = 16/3 ≈ 5.33。
- **手算口诀**：先列表填"开始时刻、完成时刻"两列（完成 = 上一个完成时刻与本作业到达时刻中较大者 + 运行时间），再用"完成减到达"一列竖式扫下去。

### 常考调度算法

| 算法 | 规则 | 特征词 |
|---|---|---|
| FCFS 先来先服务 | 按到达顺序 | "先来先服务" |
| SJF 短作业优先（非抢占） | 可运行作业中挑**运行时间最短**的 | "短作业优先""平均周转时间最短" |

**反例演示（易错）**：SJF 非抢占时，**时刻 0 只能从已到达的作业里挑短的**，不是全场谁短谁先。上例改按 SJF：t=0 只有 J1 已到 → 仍先跑 J1（0–4）；t=4 时 J2(需 3)、J3(需 1) 都在等 → 挑短的 J3（4–5，周转 5−2 = 3）；再跑 J2（5–8，周转 8−1 = 7）。平均 = (4+3+7)/3 = 14/3 ≈ 4.67 < 5.33 ✓（SJF 平均周转更短，这正是它的卖点）。若错把 J3 提到最前面先跑，就掉进"未到达就运行"的陷阱。

**应试动作**：背公式"周转 = 完成 − 到达"；SJF 题每一步都先检查"该时刻这个作业到了没有"；选项给分数（16/3、14/3）时别慌，保留分数或算到两位小数即可。

## 第四节 进程同步与互斥：PV 操作 ★★★（必考）

### 为什么要互斥：临界资源

两个进程同时往同一台打印机上输出，纸上的内容就会交错成一团乱码。像打印机这种**同一时刻只允许一个进程使用的资源**叫**临界资源**，进程中访问临界资源的那段代码叫**临界区**。注意区分：临界资源必须互斥使用；普通共享资源（如可重入的代码）允许多进程同时用。

临界区管理的四条准则（选择题考过名称与含义）：**有空即进、无空则等、有限等待、让权等待**（进不了临界区就释放 CPU，避免"忙等"）。

### 信号量与 PV：一个会"记账"的变量

**信号量 S 是一个特殊变量**，本质是资源账本：S > 0 表示还剩 S 个资源可用；S = 0 表示资源刚好用光、无人排队；**S < 0 的绝对值 = 排队等资源的进程数**。

- **P(S)**（申请）：S 减 1；若 S < 0，本进程阻塞进等待队列。
- **V(S)**（释放）：S 加 1；若 S ≤ 0（说明有人在排队），唤醒一个等待进程。

初学者最容易问："不就是个加减法吗，为什么要绑定阻塞/唤醒？"——因为判断和等待必须**一步完成**：如果"先查 S 再决定等不等"分成两步，两个进程可能同时查到"还有 1 个"然后都进去，互斥就破了。PV 把"查账 + 排队/叫号"做成了不可拆的整体。

**初值怎么定（核心结论）**：

| 模型 | 信号量含义 | 初值 |
|---|---|---|
| **互斥**（多进程抢同一资源） | 资源数量 | = 资源数（1 台打印机 → 1；3 台同类打印机 → 3） |
| **同步**（前者做完了后者才能做） | "前者已完成"这个消息 | 一般为 **0** |
| **前趋图** | 每条有向弧一个信号量 | 全为 **0** |

**信号量取值范围题（公式三件套）**：
- 通用形式：n 个进程共享 k 个同类资源，S 初值 k，则 S 的最大值 = k，最小值 = k − n（负到"全部进程都在排队"为止）。
- 代入算例：10 个进程共享 3 台打印机：最大 3，最小 3 − 10 = −7，即 S ∈ [−7, 3]。
- 手算口诀：**"上界是初值，下界是初值减进程数"**。

### 前趋图配 PV：套路题（★★★）

前趋图刻画"哪些任务必须等哪些任务做完才能开始"（思想与数据结构的拓扑排序一致，见 [01-数据结构与算法.md](01-数据结构与算法.md) 第 3.5 节；与软件工程的关键路径网络图也同源）。

**规则（背死）**：
1. **图中有几条有向弧，就定义几个信号量**（每条弧一个，初值全为 0）；
2. 每条弧的**起点**（前趋任务）末尾做 **V**（"我做完了"），**终点**（后继任务）开头做 **P**（"等我的前置完成"）；
3. 一个任务有几条入弧，开头就要连续做几个 P；有几条出弧，末尾就连续做几个 V。

**代入算例**：弧为 A→B、A→C、B→D、C→D 共 4 条 → 信号量 S1~S4，初值均为 0：

```
A: 执行; V(S1); V(S2);
B: P(S1); 执行; V(S3);
C: P(S2); 执行; V(S4);
D: P(S3); P(S4); 执行;
```

**反例演示（易错）**：把 V 写在弧的终点、P 写在起点——顺序反了：变成"后继先 V 报信、前趋再 P 等待"，而信号量初值是 0，前趋 P 时会永远阻塞，整张图谁都跑不起来。记住口诀：**"V 在前驱末，P 在后继初"**。另一易错点：同步信号量与互斥信号量混用初值——同步（前趋图）初值 0，互斥初值 = 资源数，二者不能抄混。

**应试动作**：① 互斥 → 初值 = 资源数；同步/前趋 → 初值 0；② 取值范围 = [初值−进程数， 初值]；③ 前趋图按"弧数 = 信号量数、V 起点末、P 终点初"机械填写，填完逐弧检查一遍"每条弧恰好一个 V 和一个 P"。这种题若以小问嵌在案例大题里（历史上考过整道大题），按同一套路做。并发互斥的思想与数据库的锁机制同源，可对照 [02-数据库系统.md](02-数据库系统.md) 的并发控制一节。

## 第五节 死锁 ★★★

### 死锁是什么、为什么会发生

若干进程互相要对方手里的资源，谁都拿不齐、谁都不放手，全体卡死——这就是死锁。发生死锁必须**同时**满足四个必要条件（背名称+含义，选择题考配对）：

| 条件 | 含义 | 破坏它的预防策略 |
|---|---|---|
| **互斥** | 资源一次只能一个进程用 | 无法破坏（资源物理特性决定） |
| **请求和保持**（保持和等待） | 占着资源还去申请新的 | **一次性申请全部资源（静态分配）** |
| **不剥夺** | 别人不能抢走已分配的资源 | 允许强行剥夺 |
| **环路等待** | 形成"你等我、我等你"的环形链 | **资源有序分配法**（全系统资源统一编号、按序申请） |

处理策略四层次：**死锁预防**（破坏四条件之一）→ **死锁避免**（银行家算法，动态判断分配后是否安全）→ **死锁检测与解除**（资源图化简）。破坏"互斥"做不到，破坏其余三个都能预防。

### 死锁资源数公式（★★★ 必考计算）

- **通用形式**：m 个进程、每个进程最多需要 w 个同类资源、系统共有 n 个资源——
  - **不可能发生死锁的最小资源数**：n = **m×(w−1) + 1**（等价条件：n ≥ m(w−1)+1 时必不死锁）；
  - **可能发生死锁的最大资源数**：n = **m×(w−1)**（n ≤ m(w−1) 时**可能**死锁，不是必然）。
  - 推导思路：最坏情况是每个进程都拿到 w−1 个还差 1 个、把资源占光——此时共 m(w−1) 个资源全被占着，人人等资源，死锁；只要再多 1 个资源，就有人能凑齐跑完并释放，死锁解开。
- **代入算例**：3 个进程各需 4 个资源：不可能死锁的最小 n = 3×(4−1)+1 = 10；n = 9 时可能死锁（3 个进程各持 3 个，全占光）。
- **手算口诀**：**"每进程先扣 1，乘完再加 1"**。

反向题型（给 n 求 w）：3 个进程共享 10 个资源，每个进程最多申请 i 个，问"可能发生死锁的最小 i"——令 3×(i−1) ≥ 10，i−1 ≥ 3.34，i ≥ 4.34，取整数 **i = 5**。（i = 4 时 3×3 = 9 < 10，按鸽笼原理必有一个进程能拿到 4 个而完成，不死锁。）

### 进程资源图与"化简"（了解即可）

题目给出"进程—资源"请求分配图：**阻塞结点** = 当前申请无法满足的进程；**非阻塞结点** = 能满足、可执行完并释放资源的进程。判断法：反复找非阻塞结点、让它执行完并回收资源——**能全部化简 → 非死锁；无法化简 → 死锁**。目前软考的可化简图通常是非死锁的。

### 银行家算法（★★★）

**动机**：预防策略太死板（一次性分配浪费资源），银行家算法更聪明——每次分配前**先假装分出去，看看能不能找到一个让所有进程都跑完的顺序（安全序列）**：找得到就真分，找不到就不分。银行放贷同理：放钱前先算"这笔放出去后，是否还能让所有贷款人最终都还上钱"。

**判定步骤（五步模板，背下来直接套）**：

1. 算每个进程的**需求 Need = 最大需求 − 已分配**；
2. 算**剩余可用 Available** = 资源总量 − 各进程已分配之和；
3. 在未完成进程中找"Need ≤ Available"的进程，让它**执行完并归还全部已分配资源**（Available += 它的 Allocation），标记完成；
4. 重复第 3 步，直到所有进程完成（→ **安全**，执行顺序即安全序列）或找不到任何可满足的进程（→ **不安全**，拒绝本次分配）；
5. 若判断"某进程再申请 X 个能否满足"：先**试探性地**把 X 从 Available 划给它、Need 减 X，再走一遍第 2–4 步；不安全则**回滚并拒绝**。

**代入算例**：资源总量 10。P1 最大 5、已分 3（Need 2）；P2 最大 7、已分 2（Need 5）；P3 最大 6、已分 2（Need 4）。Available = 10 − (3+2+2) = 3。
- Need ≤ 3 的只有 P1（Need 2）→ P1 先跑，归还后 Available = 3+3 = 6；
- 此时 P2（Need 5 ≤ 6）、P3（Need 4 ≤ 6）都能跑 → 安全序列有 P1→P2→P3 和 P1→P3→P2 两条。

**反例演示（易错）**：① 只要**找到一条**安全序列就算安全，不要求唯一（但做题时若四个选项里三条都不通，剩下的那条就是答案）；② "不安全" ≠ "已死锁"，只是"可能死锁"，银行家算法宁可错杀不肯冒险；③ 算 Available 时忘了用"总量减已分配"，直接拿 Need 求和比较——必错。

**应试动作**：① 死锁资源数公式"每进程先扣 1 乘完再加 1"正反两个方向都要会算；② 四条件与破坏策略配对（一次性分配→破坏请求和保持；有序分配→破坏环路等待）；③ 银行家五步模板背熟，安全序列判定题在草稿上列表（Need / Available 两列）逐步推，每步检查"Need ≤ Available"。

## 第六节 存储管理：页式、段式、段页式 ★★★

### 为什么要"分页"

程序比内存大、或内存碎片零散装不下完整程序怎么办？**页式存储**把程序和内存都切成同样大小的块：程序的块叫**页**，内存的块叫**页帧（物理块）**，以页为单位离散装入内存——零散小空隙也能利用起来，利用率高、碎片小（缺点：查页表增加开销，页进出频繁时产生"抖动"）。

### 页式地址变换（★★★ 必考计算）

高级语言用的是**逻辑地址**，进内存要换成**物理地址**。逻辑地址结构 = **页号 + 页内地址**；物理地址 = **页帧号 + 页内地址**。

- **通用形式**：页大小 = 2^k，则逻辑地址的**低 k 位就是页内地址（变换前后不变）**；高位是页号 → 查页表得页帧号 → 物理地址 = 页帧号 × 页大小 + 页内地址。
- **代入算例**：页大小 4KB，页表"页 0→帧 5、页 1→帧 8、页 2→帧 3"。逻辑地址 1F48H：4KB = 2^12 = 1000H，低 3 位十六进制 F48H 是页内地址，高位 1H 是页号 → 查表页 1 → 帧 8 → 物理地址 = **8F48H**。验算（十进制走一遍）：0x1F48 = 8008，8008 = 1×4096 + 3912，页内偏移 3912；物理地址 = 8×4096 + 3912 = 36680 = 0x8F48 ✓。
- **手算口诀**：**"页内地址不动，页号查表换页帧"**。十六进制题先看页大小定拆分位数：4KB = 2^12 = 1000H → 低 3 位十六进制是页内地址；2KB = 2^11 → 十六进制不足 3 位对应，先转二进制拆低 11 位更稳；1KB = 2^10 → 低 10 位二进制是页内地址。

**反例演示（易错）**：① 忘了查页表，直接把逻辑地址当物理地址（1F48H → 1F48H 是错的）；② 把"页号 × 页大小"当成物理地址（只换了页号没加页内地址）；③ 页号页内地址拆分位 Number 弄错——**页大小决定页内地址位数**：4KB→12 位（低 3 位十六进制），1KB→10 位，2KB→11 位。

### 段式与段页式

| 方式 | 划分 | 地址结构 | 特点 |
|---|---|---|---|
| **页式** | 等大小分页（物理需要） | 页号+页内地址 | 利用率高、碎片小；无外部碎片，有页内零头 |
| **段式** | 按**自然段**分（逻辑需要），段长不等 | 段号+段内偏移 | 便于共享保护；碎片大、利用率低 |
| **段页式** | **先分段，段内再分页** | 段号+页号+页内地址 | 兼两者之长；开销最大、速度下降 |

**段式合法地址判定（公式三件套）**：
- 通用形式：逻辑地址 (段号 s, 段内偏移 d) 合法 ⇔ s 在段表内 **且 d < 段 s 的段长**；物理地址 = 该段基址 + d。
- 代入算例：段 0 段长 30K 基址 40K → (0, 25K) 合法（25K < 30K），物理地址 = 40K + 25K = 65K；(0, 35K) 非法（35K ≥ 30K，越界）。
- 口诀：**"偏移必须小于段长，物理地址 = 基址加偏移"**。

**应试动作**：① 页式计算背"页内地址不变，页号查表换页帧"，先把页大小化成 2 的幂定拆分位数；② 段式判断只看一条：偏移 < 段长？③ 三种方式按"等分/自然段/先段后页"配对，段页式缺点（开销大、速度降）考过。

## 第七节 页面置换：LRU / FIFO / OPT ★★

### 为什么需要置换

内存块比页数少，缺页时要把某页请出去腾位置——请谁走？置换算法决定。选错对象 → 刚换出的页马上又要用 → 缺页率飙升，极端情况 CPU 大部分时间忙着换页而不是干活，称**抖动（颠簸）**。

| 算法 | 淘汰谁 | 评价 |
|---|---|---|
| **FIFO**（先进先出） | 最先进入内存的页 | 实现简单；可能出现"刚换出又要用"（队列思想，见 [01-数据结构与算法.md](01-数据结构与算法.md) 第 1.3 节） |
| **LRU**（最近最久未使用） | **最近最长时间没被访问**的页 | 性能好；要记每页访问时间（历史用栈维护，见 01 课 1.2 节） |
| **OPT**（最佳置换） | **今后最长时间不再使用**的页 | 缺页率最低，但要预知未来，无法实现，只作评价基准 |

三种算法要靠**表格模拟**算缺页数——这是必考计算，模板如下。

**解题模板（三步）**：
1. 画表：列 = 引用串各位，行 = 3 个物理块；再记一行"是否缺页"；
2. 逐位走：内存中没有该页 → **缺页**，装入（满了按算法淘汰一页）；有 → 命中，**只更新"最近使用"信息，不淘汰**；
3. 数缺页次数 ÷ 引用串长度 = **缺页率**。

**代入算例**：3 个物理块，引用串 `1,2,1,3,4,1,2,3`（8 次）：

**FIFO**（记进入顺序，淘汰最老的）：
| 引用 | 1 | 2 | 1 | 3 | 4 | 1 | 2 | 3 |
|---|---|---|---|---|---|---|---|---|
| 块1 | 1 | 1 | 1 | 1 | 4 | 4 | 4 | 4 |
| 块2 | | 2 | 2 | 2 | 2 | 1 | 1 | 1 |
| 块3 | | | | 3 | 3 | 3 | 2 | 2 |
| 缺页 | ✓ | ✓ | 命中 | ✓ | ✓ | ✓ | ✓ | ✓ |

FIFO 缺页 7 次，缺页率 7/8 = 87.5%。

**LRU**（淘汰"最近最久未使用"的，比较每页**最后一次**被访问的时间）：

| 引用 | 1 | 2 | 1 | 3 | 4 | 1 | 2 | 3 |
|---|---|---|---|---|---|---|---|---|
| 块1 | 1 | 1 | 1 | 1 | 1 | 1 | 1 | 1 |
| 块2 | | 2 | 2 | 2 | 4 | 4 | 4 | 3 |
| 块3 | | | | 3 | 3 | 3 | 2 | 2 |
| 缺页 | ✓ | ✓ | 命中 | ✓ | ✓ | 命中 | ✓ | ✓ |

关键两步的淘汰依据：位5 引用 4 时内存 {1,2,3}，最后一次访问时间是 1@位3、3@位4、2@位2 → 最久未使用的是 **2**，淘汰 2；位7 引用 2 时内存 {1,4,3}，最后使用 1@位6、4@位5、3@位4 → 淘汰 **3**；位8 引用 3 时内存 {1,4,2}，最后使用 1@位6、2@位7、4@位5 → 淘汰 **4**。注意位5 时 2 和 3 都是"装入后没再访问"，比的是"刚进来"（位4）比"位2"更近，所以淘汰更久远的 2 而不是 3。

LRU 缺页 6 次，缺页率 6/8 = 75%。

**OPT**（淘汰"将来最久不用"的）：
- 位1 1 缺页；位2 2 缺页；位3 1 命中；位4 3 缺页 → [1,2,3]
- 位5 引用 4 缺页：往后看 位6=1、位7=2、位8=3——1 在位6 用、2 在位7 用、3 在位8 用 → 最晚再用的是 3 → 淘汰 3 → [1,2,4]
- 位6 1 命中；位7 2 命中
- 位8 引用 3 缺页（内存 {1,2,4} 都不再使用，任淘汰，缺页数不受影响）

OPT 缺页 = 位1、2、4、5、8 共 **5 次**，缺页率 5/8 = 62.5%。

**交叉验算（第二种方法）**：缺页数 = 串长 − 命中数。FIFO 命中仅位3 → 8−1 = 7 ✓；LRU 命中位3、位6 → 8−2 = 6 ✓；OPT 命中位3、位6、位7 → 8−3 = 5 ✓。三种算法缺页数 7 ≥ 6 ≥ 5，与"OPT 最优、LRU 次之、FIFO 最差"的理论一致 ✓。

**反例演示（易错）**：① 命中时**不淘汰、不装入**，只在心里更新"最近使用"——把命中当缺页是最常见失分点；② LRU 比的是"**最后一次被访问**距今多久"，不是"进入内存多久"（那是 FIFO）；③ OPT 往**后**看，LRU 往**前**看，别弄反方向。

**应试动作**：① 考场上直接画表逐位模拟，做完用"串长 − 命中数 = 缺页数"验算；② 背结论"缺页率 OPT < LRU < FIFO（一般情况）"；③ 认题特征词："最近最久未使用"→ LRU，"先进先出/最先进入"→ FIFO，"最长时间不被使用（未来）"→ OPT。

## 第八节 文件管理 ★★

### 索引文件计算（★★★）

**动机**：文件占很多离散的磁盘块，怎么记录"这个文件都放在哪些块"？——给文件建一张"块号清单"（索引表），清单本身也占块。索引表放不下怎么办？搞**多级索引**：一级索引块里存的不再是数据块号，而是"二级索引块的块号"，二级里才存数据块号。

- **通用形式**（UNIX 式索引节点）：设磁盘块大小 B、每个地址项占 A 字节，则一个索引块能存 **B/A** 个块号。若索引节点含 d 个**直接地址**（直接指向数据块）、1 个**一级间接**（指向的块里全是数据块号）、1 个**二级间接**（指向的块里全是"一级间接块"号），则文件最大长度 = (d + B/A + (B/A)²) × B。
- **代入算例**：块大小 1KB，地址项 4B，索引节点含 10 个直接、1 个一级间接、1 个二级间接：
  - 每个索引块存块号数 = 1KB ÷ 4B = 1024 ÷ 4 = 256 个；
  - 直接部分 10 × 1KB = 10KB；一级间接 256 × 1KB = 256KB；二级间接 256 × 256 = 65536 块 = 65536KB = 64MB；
  - 最大文件 = 10KB + 256KB + 65536KB = **65802KB ≈ 64.25MB**。
- **手算口诀**：**"直接乘，一级乘一次，二级平方乘"**——先算每块能装几个地址项（B/A），直接地址管 d 块，一级管 B/A 块，二级管 (B/A)² 块。

**反例演示（易错）**：二级间接的块数是 **(B/A)²** 不是 2×(B/A)——"二级"是嵌套两层，一层 256 个指向下一层，下一层每块再 256 个，256×256 = 65536，不是 512。

### 位示图计算（★★★）

**动机**：磁盘上哪些块空着、哪些被占？给全盘每个物理块安排 1 个比特：0 空闲、1 占用——这张比特表就是**位示图（bitmap）**。机器按"字"存取，一个字长 w 位能管 w 个块。

- **通用形式**：物理块号 b、字长 w、**均从 0 开始编号**：字号 = **⌊b / w⌋**，位号 = **b mod w**；位示图总字数 = ⌈总块数 / w⌉，其中总块数 = 磁盘容量 ÷ 物理块大小。
- **代入算例**：字长 32 位，块号 1000：1000 ÷ 32 = 31 余 8 → 字号 31、位号 8（即第 32 个字的第 9 位，若按从 1 计数）。验算：31×32 + 8 = 992 + 8 = 1000 ✓。
- **手算口诀**：**"除留字号，余做位号；容量除块得总块，总块除字长得字数"**。

容量型算例：磁盘 160GB、物理块 1MB、字长 32 位：总块数 = 160×1024 ÷ 1 = 163840 块；字数 = 163840 ÷ 32 = **5120 字**。验算：160GB = 163840MB，除以 1MB/块得 163840 块，除以 32 位/字得 5120 ✓。

**反例演示（易错）**：① 题干会说明块号、字号"从 0"还是"从 1"编号——从 0 换算成第几个时要 +1（从 1 计数时 1000 号块在第 32 个字）；② 忘了 GB→MB 的 1024 进制换算（160GB = 160×1024MB，不是 160×1000）。

### 目录与路径（★）

- 树形（多级）目录：**不同目录下允许同名文件**；一级目录不允许重名。
- **绝对路径**：从**根（盘符）**开始；**相对路径**：从**当前目录**开始。考法：给目录树和当前目录，写出某文件的两种路径，或问"从当前目录出发少走了哪一段"。

**应试动作**：① 索引文件公式背"每块地址数 = 块大小 ÷ 地址项大小"，二级平方；② 位示图两套小题（定位、容量）套口诀；③ 注意题目给的是 KB/MB/GB 混合单位，先统一成同一单位再除。

## 第九节 设备管理：磁盘调度与虚拟设备 ★★

### 磁盘的结构与存取时间

磁盘由多个盘面组成，每个盘面划分成一圈圈**磁道**（从外向里 0,1,2,…编号），每个磁道按角度分成**扇区**；多个盘面的同一号磁道构成**柱面**（所以磁道号也叫柱面号）。

**存取时间 = 寻道时间 + 旋转延迟（等待时间）+ 传输时间**：寻道 = 磁头移到目标磁道（**最耗时，有调度算法可优化**）；旋转延迟 = 等目标扇区转到磁头下（盘匀速转，无算法可言）；传输 = 读写数据。选择题直接考"三段构成"与"寻道时间最值得优化"。

### 磁盘调度算法（★★★ 计算）

磁头一次只在一个位置，多个磁道访问请求排队，按什么顺序服务？目标：**平均寻道距离最短**。

| 算法 | 规则 | 特征 |
|---|---|---|
| FCFS 先来先服务 | 按请求到达顺序 | 公平但寻道长；方向随时变 |
| **SSTF** 最短寻道时间优先 | 每次选**距当前磁头最近**的请求 | 贪心，效率高；可能让远处请求"饥饿"；方向随时变 |
| **SCAN** 扫描（电梯） | 沿一个方向扫，沿途服务，**到端头再折返**（题目会说明端头规则） | 不饥饿；方向固定到头才变 |
| C-SCAN 循环扫描 | 扫到端头后直接跳回另一端再同方向扫 | 各磁道等待更均匀 |

**解题模板**：① 列出请求磁道号和磁头起点；② 按算法规则排出服务顺序；③ 相邻两站求距离差绝对值；④ 全部加总 = 移动道数；除以请求数 = 平均寻道长度。

**代入算例**：磁头在 60 号磁道，请求队列：40、70、25、90、65、10。
- **SSTF**：60→65（5）→70（5）→90（20）→40（50）→25（15）→10（15），总移动 = 5+5+20+50+15+15 = **110 道**。验算两遍：① 逐站确认"最近"——60 处各请求距离 40:20、70:10、25:35、90:30、65:5、10:50，选 65 ✓；65 处 70:5 最近 ✓；70 处 90:20 < 40:30 ✓；90 处 40:50 最近（25:65、10:80）✓；② 路径逐段累加复核：5+5=10，+20=30，+50=80，+15=95，+15=110 ✓。
- **SCAN**（题干设定：磁头朝磁道号增大方向移动，移动到最外侧磁道 199 才折返）：60→65→70→90→199→40→25→10。总移动 = (199−60) + (199−10) = 139 + 189 = **328 道**。验算逐段：5+5+20+109+159+15+15 = 5+5=10，+20=30，+109=139，+159=298，+15=313，+15=328 ✓。

**反例演示（易错）**：① SCAN 是否"必须扫到磁盘端头再折返"，**不同题干设定不同**——有的按"到该方向最后一个请求即折返"处理。务必先读题干：本题明确说"到 199 号磁道才折返"，就必须走到 199，不能在 90 就回头（若在 90 折返则总移动 = (90−60)+(90−10) = 110）；② SSTF 每一步都要**重新**找最近，不是全局排序一次。

### Spooling 与虚拟设备

打印机是**独占设备**，一人占用整台机器别人只能干等。**Spooling（假脱机）技术**用磁盘当中转站：打印请求先排队写进磁盘上的输出井，打印进程慢慢取——用户感觉"随时都能提交打印"，仿佛打印机人人可共享。这种由独占设备改造出来的、逻辑上可共享的设备叫**虚拟设备**。特征词：**"独占设备改造成共享设备"→ Spooling → 虚拟设备**，三者一条链。

**应试动作**：① 存取时间三段构成背下来，"寻道可优化、旋转无算法"考过判断；② SSTF/SCAN 老老实实列表逐段相加，SCAN 先看题干折返规则；③ 认题：看到"假脱机/输入井输出井"选 Spooling，看到"虚拟设备"想"独占→共享"。

## 第十节 高频计算题型专攻（应试模板汇总）

本课所有计算题的考场流水线，考前把这张表过一遍：

| 题型 | 第一步 | 核心动作 | 验算方法 |
|---|---|---|---|
| **信号量取值范围** | 找资源数 k、进程数 n | 范围 [k−n, k] | 最小值含义 = 全部进程都在排队 |
| **前趋图 PV 填空** | 数弧 → 定信号量 | V 在弧**起点末尾**、P 在弧**终点开头** | 逐弧检查"一弧一 V 一 P" |
| **死锁资源数** | 认 m、w、n | n = m(w−1)+1 不死锁；n ≤ m(w−1) 可能死锁 | 反代：把答案代回公式看是否自洽 |
| **银行家安全序列** | 求 Need、Available | 反复找 Need ≤ Available 者执行并归还 | 找不到时验证"所有进程 Need > Available" |
| **页式地址变换** | 页大小化成 2^k | 低 k 位是页内地址（不变），高位查页表换帧号 | 十进制走一遍：物理 = 帧号×页大小+偏移 |
| **页面置换** | 画表逐位模拟 | 命中不淘汰；LRU 看过去、OPT 看未来 | 缺页数 = 串长 − 命中数 |
| **位示图** | 认清编号起点 | 字号 ⌊b/w⌋、位号 b mod w；字数 = 总块数/w | 乘回去：字号×w+位号 = 块号 |
| **索引文件最大长度** | 算每块地址项数 B/A | d + B/A + (B/A)² 块 × B | 分层逐项相加复核 |
| **磁盘调度** | 认起点、方向、折返规则 | 逐段绝对差相加 | 路径两头相减粗验（SCAN 到端头型：(端−起点)+(端−最远反端)） |
| **周转时间** | 列到达/运行时刻表 | 完成 = max(上一完成时刻， 到达) + 运行；周转 = 完成 − 到达 | 平均值介于最短/最长周转之间 |

**考场提示**：这类题是"送分题里最费草稿的"——一定画表，不心算；算完用表里最后一列的验算法快速复核，30 秒能拦住绝大多数失分。

## 答案与解析

### 课后考题答案（选择题）

**1. B**
PCB 记录进程的标识、状态、现场等全部管理信息，系统靠它感知进程的存在——"PCB 是进程存在的唯一标志"。程序和数据只是进程的组成部分，进程撤销后它们仍可能存在。

**2. C**
线程独有栈和寄存器现场，T3 的栈是 T3 的"私人工作台"，T1 不能直接访问（A、B、D 均为共享内容：代码段、打开的文件、全局变量）。这是"共享/独有"清单的直接考法。

**3. D**
就绪→阻塞不可能：阻塞源于"运行中的进程主动等待某事件"，就绪进程根本没在运行，无从发起等待。两个恒不可能的转换是"就绪→阻塞"与"阻塞→运行"，后者错在跳过了就绪排队。

**4. B**
时间片用完 = 被剥夺 CPU 但一切资源俱备 → 回就绪队列排队。若是进程主动请求 I/O 才转阻塞态（A 错）。

**5. A**
S 最大值 = 资源数 3（无人使用时）；最小值 = 初值 − 进程数 = 3 − 10 = −7（10 个进程全在排队）。C 项 [−3,10] 把上下界弄反了，B 项把进程数当成了下界来源且错用 10。

**6. C**
互斥信号量初值 = 资源数量，3 台打印机 → 3。若只有 1 台才是 1；0 是同步信号量的典型初值；−3 不是初值（初值非负）。

**7. C**
信号量个数 = 有向弧条数 = 6，前趋图（同步）信号量初值全为 0。5 是进程数不是弧数——这是最典型干扰项；初值 1 是互斥信号量的设定，与同步无关。

**8. D**
资源全系统统一编号、按序申请，使"环形等待链"无法闭合 → 破坏**环路等待**。一次性申请全部资源才破坏"请求和保持"（B）。

**9. C**
可能死锁 ⇔ n ≤ m(i−1)，即 10 ≤ 3(i−1) → i−1 ≥ 10/3 ≈ 3.34 → i ≥ 4.34 → 最小整数 i = 5。
验算 i = 4：每进程最多占 3 个，3 进程最多共占 9 个 < 10，必有资源空闲，持有 3 个的进程可补齐第 4 个而完成，不死锁 ✓；i = 5：3 个进程各持 3 个共 9 个，剩 1 个，任一进程拿走后仍差 1 个且无资源可补，人人等待 → 死锁可能 ✓。

**10. A**
页大小 4KB = 2^12 = 1000H → 低 3 位十六进制 D30H 是页内地址（不变），高位 2H 是页号 → 查表页 2 → 物理块 3 → 物理地址 = 3D30H。
十进制验算：0x2D30 = 11568，11568 = 2×4096 + 3376（偏移 3376 = 0xD30）；物理地址 = 3×4096 + 3376 = 12288 + 3376 = 15664 = 0x3D30 ✓。B 项是"没查页表"的直接照抄；C、D 是换了错误页帧号的结果。

**11. B**
FIFO 逐位模拟（3 块）：1缺[1]、2缺[1,2]、3缺[1,2,3]、4缺淘汰1[2,3,4]、1缺淘汰2[3,4,1]、2缺淘汰3[4,1,2]、5缺淘汰4[1,2,5]、1命中、2命中、3缺淘汰1[2,5,3]。缺页 8 次，缺页率 8/10 = 80%。
验算：命中仅第 8、9 两次，10 − 2 = 8 ✓。

**12. A**
合法条件：段号存在 且 偏移 < 段长。(0, 25K)：25K ≥ 段长 20K → 越界非法。B（20K < 25K）、C（10K < 15K）、D（24K < 25K）均合法。

**13. A**
字号 = ⌊5000 / 32⌋ = 156，位号 = 5000 mod 32 = 8。
验算：156×32 = 4992，4992 + 8 = 5000 ✓。B 项位号 9 是"按从 1 计数"误算；C 项把"除不尽向上"错用在定位题；D 项取整方向错（155×32 = 4960 ≠ 5000 起）。

**14. B**
SSTF：70→65（5）→82（17）→95（13）→110（15）→40（70），总移动 = 5+17+13+15+70 = 120 道。
逐位验算"最近"：70 处距 65 为 5 最近 ✓；65 处距 82 为 17（95 为 30、40 为 25）✓；82 处距 95 为 13（110 为 28、40 为 42）✓；95 处距 110 为 15 ✓；最后只剩 40，移动 70 ✓。

**15. B**
Spooling 用磁盘输入井/输出井做中转，把打印机这类独占设备改造成逻辑上可共享的**虚拟设备**。它不改变磁盘转速（C）、不优化寻道（D），A 把方向说反了。

**案例 2**

问题 1：
剩余可用 = 11 − (3+4+2) = **2**。
Need = 最大需求 − 已分配：P1 = 7−3 = **4**；P2 = 5−4 = **1**；P3 = 9−2 = **7**。

问题 2：**安全，且安全序列唯一，为 P2 → P1 → P3**。判定表：

| 步骤 | Available | 可满足者（Need ≤ Available） | 执行并归还后 Available |
|---|---|---|---|
| 1 | 2 | 只有 P2（1 ≤ 2；P1 需 4 > 2，P3 需 7 > 2） | 2 + 4 = 6 |
| 2 | 6 | 只有 P1（4 ≤ 6；P3 需 7 > 6） | 6 + 3 = 9 |
| 3 | 9 | P3（7 ≤ 9） | 9 + 2 = 11（全部完成） |

唯一性验证：Available = 2 时 P1、P3 都无法启动，第一步只能是 P2；P2 完成后 Available = 6，P3 需 7 > 6 仍无法启动，第二步只能是 P1——每一步都别无选择，故安全序列唯一 ✓。

问题 3：**不能满足**。试探性分配：Available = 2 − 2 = 0，P3 已分配 = 4、Need = 5。此时 P1 Need 4 > 0、P2 Need 1 > 0、P3 Need 5 > 0——没有任何进程的需求能被满足，找不到安全序列，该状态不安全（可能死锁），系统应**拒绝本次申请**、回滚试探分配。

### 精华题答案

**1.**
- **FIFO**（淘汰最先进内存的页）：1缺、3缺、1命中、2缺[1,3,2]、4缺淘汰1[3,2,4]、3命中、1缺淘汰3[2,4,1]、4命中 → 缺页 **5 次**，缺页率 5/8 = 62.5%。
- **LRU**（淘汰最近最久未使用）：1缺、3缺、1命中、2缺[1,3,2]、4缺（最后使用 1@位3、3@位2、2@位4 → 淘汰 3）[1,2,4]、3缺淘汰1[2,4,3]、1缺淘汰2[4,3,1]、4命中 → 缺页 **6 次**，缺页率 75%。
- **OPT**（淘汰将来最久不用）：1缺、3缺、1命中、2缺[1,3,2]、4缺（往后看 3@位6、1@位7、4@位8，2 不再用 → 淘汰 2）[1,3,4]、3命中、1命中、4命中 → 缺页 **4 次**，缺页率 50%。
- 验算（串长 − 命中数）：FIFO 命中位3、6、8 共 3 次 → 8−3 = 5 ✓；LRU 命中位3、8 共 2 次 → 8−2 = 6 ✓；OPT 命中位3、6、7、8 共 4 次 → 8−4 = 4 ✓。缺页数 OPT(4) < LRU(6) < FIFO(5)？注意本题 FIFO(5) < LRU(6)——FIFO 并不总比 LRU 差，具体取决于引用串，这也是考题爱设的"反直觉"点 ✓。

**2.**
① **SSTF**：100→90（10）→55（35）→30（25）→120（90）→140（20），总移动 = 10+35+25+90+20 = **180 道**。
逐位验算最近：100 处 90 最近（120 为 20、55 为 45）✓；90 处 55 最近（120 为 30、30 为 60）✓；55 处 30 最近（120 为 65）✓；30 处 120 最近（140 为 110）✓；最后 140 ✓。
② **SCAN**（到 0 号磁道才折返）：100→90→55→30→0→120→140。总移动 = (100−0) + (140−0) = **240 道**。
逐段验算：10+35+25+30+120+20 = 240 ✓。

**3.**
① n = m(w−1)+1 = 5×(3−1)+1 = **11**。最坏情形 5 个进程各持 2 个共 10 个仍各差 1 个，第 11 个资源让某进程凑齐跑完并释放 → 必不死锁。
② 可能发生：10 ≤ m(w−1) = 5×2 = 10 → 满足"可能死锁"的条件（如 5 个进程各持 2 个、资源分光，人人差 1 个 → 死锁）。

**4.**
① 总块数 = 512GB ÷ 4MB = 512×1024MB ÷ 4MB = 131072 块；字数 = 131072 ÷ 64 = **2048 个字**。验算：131072 = 2^17，64 = 2^6，2^17 ÷ 2^6 = 2^11 = 2048 ✓。
② 字号 = ⌊100000 / 64⌋ = 1562，位号 = 100000 mod 64 = 32。验算：1562×64 = 99968，99968 + 32 = 100000 ✓。即第 1563 个字（按从 1 计数）的第 33 位。

**5.**
页大小 2KB = 2048。页号 = 4500 ÷ 2048 = 2，页内偏移 = 4500 − 2×2048 = 404。查表页 2 → 物理块 7：物理地址 = 7×2048 + 404 = 14336 + 404 = **14740**。
验算（反向拆分）：14740 ÷ 2048 = 7 余 404（7×2048 = 14336，14740−14336 = 404）→ 块号 7、偏移 404，与正向一致 ✓。

**6.**
- **FCFS**：J1 0–5（周转 5−0 = 5）；J2 5–7（周转 7−2 = 5）；J3 7–8（周转 8−3 = 5）。平均 = (5+5+5)/3 = **5**。
- **SJF（非抢占）**：t=0 只有 J1 已到 → J1 0–5（周转 5）；t=5 时 J2（需 2）、J3（需 1）都已到达，挑短的 J3：5–6（周转 6−3 = 3）；再 J2：6–8（周转 8−2 = 6）。平均 = (5+3+6)/3 = 14/3 ≈ **4.67**。
验算：完成时刻 FCFS 为 5、7、8，SJF 为 5、6、8，均不早于各自到达时刻 ✓；SJF 平均更短，符合理论 ✓。

**7.**
每块可存地址项数 = 2KB ÷ 4B = 2048 ÷ 4 = 512 个。
- 直接：6 × 2KB = 12KB；
- 一级间接：512 × 2KB = 1024KB = 1MB；
- 二级间接：512 × 512 × 2KB = 262144 × 2KB = 524288KB = 512MB；
- 最大文件 = 12KB + 1MB + 512MB ≈ **513MB + 12KB**。
验算：512×512 = 262144 ✓；262144 块 × 2KB = 524288KB ÷ 1024 = 512MB ✓；三部分相加 524288 + 1024 + 12 = 525324KB ≈ 513.01MB ✓。
