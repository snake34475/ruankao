## 第一节 线性表、栈与队列

### 1.1 线性表：顺序存储 vs 链式存储

线性表就是"一排元素"。两种存法：

| 对比项 | 顺序存储（数组） | 链式存储（链表） |
|---|---|---|
| 内存 | 连续一片 | 每个节点散落 + 指针连接 |
| 按位置访问第 i 个 | **O(1)** 直接算地址 | **O(n)** 要从头数过去 |
| 插入/删除一个元素 | O(n)（后面全要挪） | **O(1)**（改指针即可，找到位置不算） |
| 空间 | 需预估容量，可能浪费 | 按需分配，但每个节点多一个指针开销 |

**★ 记忆口诀**：数组「查得快、插删慢」，链表「插删快、查得慢」。选择题几乎每年考这组对比。

链表变种（知道结构即可）：
- **单链表**：只有 next 指针，只能从头往后找。
- **循环链表**：尾节点 next 指回头节点，可"绕圈"遍历。
- **双向链表**：每个节点有 prior 和 next，可前后两个方向找。

### 1.2 栈：后进先出（LIFO）★

栈像一个只有一口的羽毛球筒：后放进去的先拿出来。

**必考应用**（三个都要会，表达式求值是重中之重）：

**① 表达式求值——中缀转后缀（逆波兰式）**

先弄清三个名词：
- **中缀**：我们平时写的式子，运算符夹在两个操作数中间，如 `a+b*c`。
- **后缀（逆波兰式）**：运算符写在两个操作数**后面**，如 `abc*+`。计算机按从左到右顺序扫一遍就能算，不需要括号。
- **前缀（波兰式）**：运算符写在前面，如 `+a*bc`，考试较少考。

**手算中缀→后缀的傻瓜法（不看代码版）**：按运算优先级给式子加满括号，再把每个运算符搬到**自己那对括号的右边**，最后去掉所有括号。

例 1：`a+b*c` → 加括号得 `a+(b*c)` → 运算符 `*` 搬到 `(bc)*`，`+` 搬到整对括号右 → `a(bc)*+` → 去括号得 **`abc*+`**。

**为什么要转后缀？运算符会"失去意义"吗？**

不会。你看到 `a+b*c` 觉得意义清楚，是因为脑中默认了两条**约定**：① 优先级（`*` 高于 `+`）② 运算符写在两个操作数**中间**。也就是说，中缀式的意义不在式子本身，而在读者脑子里的约定里。后缀式只是换了一套规则——**每个运算符"吃掉"它前面紧挨着的两个东西**——意义一点没少，只是把约定搬进了位置。

按这条规则读 `abc*+`：遇到 `*` 拿前面最近的 b、c 相乘，遇到 `+` 拿 a 和刚才的乘积相加——算出来恰好就是 `a+(b*c)`，一个字都没丢。对比着看：

| 中缀 | 后缀 | 运算符的作用对象 |
|---|---|---|
| `a+b` | `ab+` | 一样，都是 a 和 b |
| `a+(b*c)` | `abc*+` | `+` 作用于 a 和 b*c |
| `(a+b)*c` | `ab+c*` | `*` 作用于 a+b 和 c |

注意后两行：中缀里**必须靠括号**才能区分的两个式子，后缀 `abc*+` 和 `ab+c*` 天然不同——运算顺序被运算符的位置**唯一确定**，连括号都省了。

**计算机为什么偏爱后缀**：扫中缀式时遇到 `+` 不能马上算（右边可能藏着优先级更高的 `*`），得回头预判；而扫后缀式时，每个运算符出现时它的两个操作数**一定已经在栈里**，从左到右一遍扫完，不需要优先级表、不需要括号、不需要回溯。这就是编译器用逆波兰式做中间代码的原因，也是软考爱考它的原因。

例 2（带括号，考试更爱出）：`a*(b+c)-d` → 加括号 `((a*(b+c))-d)` → `b+c` 变 `bc+`；`a*(bc+)` 变 `abc+*`；整体减 d 变 `abc+*d-`。所以后缀是 **`abc+*d-`**。

**易错提醒**：搬运算符时，"前面紧挨着的两个东西"不是两个单字母，而是**已经成型的一整块**，且**左块在前、右块在后，内部顺序不动**。例 2 中 `a*(bc+)` 的 `*` 作用于左块 `a` 和右块 `bc+`，所以写成 `a(bc+)*` → `abc+*`（写成 `bc+a*` 就成了 (b+c)*a，操作数顺序反了，遇到减法除法必错）；减号的左操作数是整块 `abc+*`、右操作数是 `d`，所以 `-` 放在整个式子最末尾（写成 `abcd+*-` 读出来是 a-(b*(c+d))，错的）。

**后缀式怎么求值**：从左到右扫，**遇到操作数进栈，遇到运算符就弹出栈顶两个数计算（先弹出的是右操作数！），结果再进栈**。例：后缀 `ab+c*`，先 a、b 进栈，遇到 `+` 弹 b、a 得 a+b 进栈，遇到 `*` 与后面的 c 相乘。

**② 函数递归调用**：系统用栈保存每层调用的参数、局部变量和返回地址，函数返回时弹栈。所以「递归太深会栈溢出」；考题问"递归调用是利用什么实现的"→ 答**栈**。

**③ 括号匹配**：从左到右扫字符串，左括号进栈；遇到右括号就弹栈顶看是否配对（`{` 对 `}`），栈空或配不上就是错；扫完栈必须为空才合法。例：`{[()]}` 合法；`{[}]`——遇到 `}` 时栈顶是 `[`，配对失败。

**★ 卡特兰数：出栈序列有多少种**

问题：n 个元素按 1,2,…,n 顺序进栈（进栈和出栈可交替进行），最终出栈序列共有多少种？

答案 = **卡特兰数 Cₙ = C(2n, n)/(n+1) = (2n)! / ((n+1)!·n!)**。

- 会不会直接考公式计算？**会**。选择题常见考法两种：① 直接问"4 个元素依次进栈，出栈序列有几种"→ 套公式算 14；② 给一组序列问"哪个是不可能出现的出栈序列"（这种不套公式，靠模拟）。**考场只需背三样，30 秒内出答案**：① 数列前几项（n=0~5：**1, 2, 5, 14, 42, 132**），最常考的 n=3/4/5 直接对答案；② 通项公式 C(2n,n)/(n+1)，防它出稍大的 n 现算（如 n=6：C(12,6)/7 = 924/7 = 132）；③ 组合数手算口诀（见下方"公式怎么算"）。另外：同源问题（n 对括号合法匹配数、n 个节点能构成的二叉树棵数）用同一个公式，题干不会出现"卡特兰"三个字，看到这几类问法要能认出来；而"给具体序列问可不可能"的题不套公式，用栈模拟即可。

> **扩展（冷知识，了解即可）**：卡特兰数以比利时数学家卡特兰（Catalan，1838 年研究括号匹配）得名，但最早见于清代蒙古族数学家**明安图**1730 年代《割圜密率捷法》中的推导（比欧洲早约 20 年），欧拉 1751 年也独立发现过——属于"以研究者命名、但非最早发现者"的典型例子。

**公式怎么算（以 n=3 为例）**：C(6,3)/(3+1) = 20/4 = **5** 种。（这和通项式 (2n)!/((n+1)!·n!) 是一回事：C(6,3)/4 = 6!/(3!·3!)÷4 = 6!/(4!·3!)，因为 4! = 4×3!，只是 4 并进阶乘的写法不同。）其中 C(6,3) 是"从 6 个里选 3 个"的组合数，通用公式 **C(m,n) = m! / (n!·(m−n)!)**，手算口诀：分子从 m 往下连乘 n 个数，分母从 n 往下连乘 n 个数——因为分母里的 (m−n)! 恰好把分子 m! 末尾多余的因子约掉了。例：C(6,3) = (6×5×4)/(3×2×1) = 120/6 = 20。这 5 种用 A、B、C 演示如下（每一步要么"进栈"要么"出栈"）：

| 出栈序列 | 过程 |
|---|---|
| ABC | A进A出，B进B出，C进C出（进一个出一个） |
| ACB | A进A出，B进C进，C出B出 |
| BAC | A进B进，B出A出，C进C出 |
| BCA | A进B进，B出，C进，C出A出 |
| CBA | 三个全进栈，再依次弹出 |

注意 **CAB 不可能**：C 第一个出，说明 A、B 都还在栈里，且 B 压在 A 上面，只能先 B 后 A，不可能先 A。

**判断"某个出栈序列是否可能"的通用方法（必须练熟）**：按顺序模拟——元素 1,2,3,… 依次进栈，每进一个就检查：栈顶是不是目标序列当前要出的元素？是就弹出，重复检查；不是就继续进栈。若最后发现"要出的元素被压在栈底够不着"，该序列不可能。
例：判断 312（元素 1,2,3，出栈序 3,1,2）：要出 3 → 把 1、2、3 全进栈 → 弹 3 ✓；下一个要出 1，但栈顶是 2 → **不可能**。

卡特兰数还有一堆"同源问题"（答案同为卡特兰数，选择课示偶尔出现）：n 对括号的合法匹配数、n 个节点能构成的不同二叉树棵数、n+1 个数相乘的不同加括号方式。

### 1.3 队列：先进先出（FIFO）

队列像排队买票：先来的先走。应用：操作系统任务调度、打印队列、BFS（图的广度优先遍历）。

**★ 循环队列判满判空**（每年可能考一题）

题干会直接出现 front、rear、循环、取模、牺牲一个单元这些词。下面用容量 m=5 的队列把它们逐个画出来看懂。

**第 1 步：front 和 rear 各指哪一格？**

- **front（队头指针）**：指着**当前第一个元素**，出队时它往前走。
- **rear（队尾指针）**：指着**下一个能放新元素的空位**——它不指任何元素！这是最容易看错的地方。

空队列，两针重叠在下标 0；入队 a（a 放进 rear 指的 0 号格，rear 前移）；再入 b、c：

```
      0     1     2     3     4
   ┌─────┬─────┬─────┬─────┬─────┐
   │     │     │     │     │     │
   └─────┴─────┴─────┴─────┴─────┘
      ↑
  front=rear   ← 两针重叠 = 空
```

```
      0     1     2     3     4
   ┌─────┬─────┬─────┬─────┬─────┐
   │  a  │     │     │     │     │
   └─────┴─────┴─────┴─────┴─────┘
      ↑     ↑
    front  rear
```

```
      0     1     2     3     4
   ┌─────┬─────┬─────┬─────┬─────┐
   │  a  │  b  │  c  │     │     │
   └─────┴─────┴─────┴─────┴─────┘
      ↑                   ↑
    front               rear
```

口诀：**入队 = 先把元素放进 rear 指的格子，rear 再前移；出队 = 先取走 front 指的元素，front 再前移。**

**第 2 步：为什么需要"循环"？——因为"假溢出"**

接着出队 a、b（front 走到 2），再入队 d、e，rear 走到 4：

```
      0     1     2     3     4
   ┌─────┬─────┬─────┬─────┬─────┐
   │     │     │  c  │  d  │  e  │
   └─────┴─────┴─────┴─────┴─────┘
                  ↑           ↑
                front        rear
```

再想入队，rear 就要走到 5 号格——**可 5 号格不存在**！而 0、1 号格明明空着。这种"队头前面空着却报满"叫**假溢出**。

解决办法：**把数组首尾粘起来变成一个环**。rear 走过 4 号格，沿"回头路"绕回 0 号格继续放：

```
   0 ──► 1 ──► 2 ──► 3 ──► 4
   ▲                       │
   └───────────────────────┘
```

**第 3 步：取模 %m 就是"钟表绕圈"**

钟表 11 点再过 2 小时是 1 点——没有 13 点，因为 13−12=1。**取模 = 除以 m 取余数 = 超过 m−1 就绕回去**。m=5 时，0,1,2,3,4 就是一个只有 5 个刻度的钟面：

- rear=4 时再入队：`(4+1)%5 = 5%5 = 0`（5 除以 5 商 1 余 0），绕回 0 号格；
- 公式里 `% m` 的唯一作用就是**把绕过头的下标折回来**，没有其他含义。

**第 4 步：牺牲一个格子——为了分清"空"和"满"**

假如不牺牲：放满 m 个元素时，rear 绕一整圈又撞回 front，出现 `front == rear`；可空队列也是 `front == rear`。**空和满两个状态长得一模一样，程序无法区分**。

于是约定：rear 最多走到 front 的**下一格**就停，中间永远留一个空格当"隔离带"。接着上面继续入队 f（f 绕圈放进 0 号格，rear=1），再想入 g 时：

```
      0     1     2     3     4
   ┌─────┬─────┬─────┬─────┬─────┐
   │  f  │     │  c  │  d  │  e  │
   └─────┴─────┴─────┴─────┴─────┘
            ↑     ↑
          rear  front
```

判满：`(rear+1)%5 = (1+1)%5 = 2 == front` → 满！格 1 明明空着也不能放——它就是**牺牲的隔离带**。此后：

- **空** = 两针重叠 `front == rear`；
- **满** = rear 停在 front 的下一格 `(rear+1)%m == front`。

两个条件永远不撞脸。代价：容量 m 的循环队列**最多只能存 m−1 个元素**（选择题考过这个坑！）。

| 操作 | 公式 | 记忆 |
|---|---|---|
| 入队（rear 前进） | `rear = (rear+1) % m` | 先把新元素放进 rear，再后移 |
| 出队（front 前进） | `front = (front+1) % m` | 先取走 front 的元素，再后移 |
| **判空** | `front == rear` | 两个指针重叠 = 空 |
| **判满** | `(rear+1) % m == front` | rear 追到 front 的下一格 = 满 |
| **元素个数** | `(rear − front + m) % m` | 加 m 是防负数，再取模防越界 |

**元素个数公式的推导**：正常情况 rear 在 front 前面，个数 = rear − front；但绕圈后 rear 可能"反超"到 front 后面（下标反而小了），出现负数。`+m` 先把负数拉成正，`%m` 把绕圈的情况折算回来。用上面的满状态验算：`(1−2+5)%5 = 4` ✓（正好 4 = m−1 个）。

**例题完整走一遍**（m=5，牺牲一格法）：初始 front=rear=0（空）。

1. 入队 a、b、c：a→格 0、b→格 1、c→格 2，rear=3（见第 1 步第三张图）。个数 (3−0+5)%5=3 ✓。
2. 出队 2 次：取走 a（front→1）、取走 b（front→2）。front=2 指 c，格 0、1 空出。
3. 入队 d：d→格 3，rear=4。入队 e：e→格 4，rear=(4+1)%5=**0，绕圈**！个数 (0−2+5)%5=3 ✓：

```
      0     1     2     3     4
   ┌─────┬─────┬─────┬─────┬─────┐
   │     │     │  c  │  d  │  e  │
   └─────┴─────┴─────┴─────┴─────┘
      ↑               ↑
    rear            front
```

4. 入队 f：先判满 (0+1)%5=1 ≠ 2，不满 → f 绕圈放进 0 号格，rear=1。个数 (1−2+5)%5=4 ✓。
5. 再想入队 g：判满 (1+1)%5=2 == front(2) → **满**！格 1 空着也不能放——牺牲的隔离带（见第 4 步的图）。此时 c,d,e,f 共 4 = m−1 个，已是上限。

**补充：区分空满还有另外两种办法**（选择题考过"哪种方法可以/不需要牺牲空间"）：
1. **设标志位**：用一个变量记录上次是入队还是出队，front==rear 时看标志区分空满——不浪费空间，但多一个变量。
2. **记元素个数**：另设计数器 count，入队 +1、出队 −1，count==0 为空、count==m 为满——不牺牲空间，最直观。

## 第二节 树与二叉树 ★★★

### 2.1 基本性质（选择题最爱直接考结论）

二叉树：每个节点最多两个孩子，且分左右。

1. 二叉树第 i 层最多有 **2^(i-1)** 个节点（i 从 1 起）。
2. 深度为 k 的二叉树最多有 **2^k − 1** 个节点。
3. **叶子数 n0 = 度为 2 的节点数 n2 + 1**（即 n0 = n2 + 1）。这条考过无数次。
   - 推导思路：总节点 n = n0 + n1 + n2，边数 = n − 1 = n1 + 2n2，两式相减即得。
4. n 个节点的完全二叉树深度 = ⌈log₂(n+1)⌉。

**完全二叉树 vs 满二叉树**：满二叉树每层都满；完全二叉树只允许最后一层缺右边若干个节点。堆就是完全二叉树。

**★ 完全二叉树的顺序存储下标关系（选择题直接考）**：把完全二叉树按层序存进数组（下标从 1 开始），对下标为 i 的节点：
- 左孩子 = **2i**，右孩子 = **2i+1**，父节点 = **⌊i/2⌋**。
- i > ⌊n/2⌋ 的节点全是叶子。例：n=10 个节点，最后一个非叶节点是 5，建堆从它开始。
- 这也是堆排序"用数组存树"的原理（第五节建堆公式 ⌊n/2⌋ 就是从这来的）。

### 2.2 遍历 ★★★（必考，选择题 + 案例题都会出）

三种遍历的"序"说的是**根**被访问的时机：

| 遍历 | 顺序 | 记法 |
|---|---|---|
| 前序 | **根** → 左 → 右 | 根在前 |
| 中序 | 左 → **根** → 右 | 根在中 |
| 后序 | 左 → 右 → **根** | 根在后 |

**核心解题法（必须练熟）：**
- **前序第一个是根，后序最后一个是根，中序里根把树切成左右两半。**
- 已知「前序 + 中序」或「后序 + 中序」可唯一还原二叉树；**「前序 + 后序」不能唯一确定**（无法分左右），这是经典陷阱题。
- 还原步骤：从遍历序列中找根 → 中序里分左右子树 → 对左右子树递归重复。

例：前序 ABDEC，中序 DBEAC。根是 A，中序中 A 左边 DBE 是左子树、右边 C 是右子树；左子树前序 BDE，根是 B……依次还原。

**层序遍历**：从上到下从左到右逐层访问，用**队列**实现（注意：前中后序递归用**栈**）。

### 2.3 线索二叉树

利用二叉链表中的**空指针**（n 个节点有 n+1 个空指针，想想为什么：2n 个指针域、用了 n−1 条边）：

- **左孩子为空 → 左指针改为指向该节点在遍历序中的前驱**；
- **右孩子为空 → 右指针改为指向该节点在遍历序中的后继**；
- （按哪种遍历建立线索就叫"X 序线索树"，考试默认说清是哪种。）

**例子**：中序遍历 DBEAC 中，D 没有左孩子，它的左指针就指向前驱（若有）或为空；B 的左右孩子都在，不加线索；E 没有孩子，左指针指向其中序前驱 D、右指针指向后继 A。

- 目的：不借助栈/递归也能按遍历序找前驱后继。
- 考法：判断"某节点在 X 序线索树中的前驱/后继指向谁"——先写出该遍历序，再按定义套即可。
- 加线索后为区分"指针指向孩子还是线索"，节点需多存两个标志位 ltag/rtag。

### 2.4 哈夫曼树与哈夫曼编码 ★★★（几乎年年考）

- **概念**：带权路径长度（WPL）最小的二叉树。WPL = Σ(权值 × 该节点到根的路径长度)。
- **构造方法**：每次取**权值最小的两棵树合并**，新节点权值为两者之和，重复直到只剩一棵。
- **重要结论**：
  - n 个叶子的哈夫曼树**总节点数 = 2n − 1**，且**没有度为 1 的节点**。
  - 权值越大的叶子离根越近。
- **哈夫曼编码**：左分支记 0、右分支记 1（可互换），从根到叶子的路径就是该字符编码。它是**前缀码**（任何编码不是另一个的前缀），总长度最短。
  - **为什么必须是前缀码**：译码时从左往右扫，遇到一个编码就确定一个字符。若 a=0、b=01（b 包含了 a），收到 `01` 就分不清是"b"还是"a 开头后面还有"——歧义了。哈夫曼树中字符全在叶子上，从根到叶子的路径互不为前缀，所以天然无歧义。

例：权 {1, 2, 3, 4}，合并 1+2=3 → {3,3,4} → 合并 3+3=6 → {4,6} → 合并 4+6=10。WPL = 1×3+2×3+3×2+4×1 = 19。

### 2.5 平衡二叉树（AVL 树）

任意节点左右子树**高度差 ≤ 1** 的二叉排序树。插入后失衡时通过**旋转**恢复平衡。

**四种旋转怎么记**：LL、RR、LR、RL 的字母，第一个字母是**插入点相对失衡节点的位置**（L=左子树侧，R=右子树侧），第二个字母是再往里的方向。口诀：
- **LL 和 RR（同侧）**：做一次"反方向旋转"。LL（全在左边）→ 右旋；RR（全在右边）→ 左旋。想象三个节点排成一条直线，把中间那个提起来当根，树就转平了。
- **LR 和 RL（异侧）**：先对**中间两个节点**做一次旋转（变成 LL/RR），再按同侧规则转一次。口诀：**先局部再整体，转两次**。
- 考题常给一棵失衡树问"应采用哪种旋转"，先判断插入点位置即可作答。

**最少节点数**：高度为 h 的 AVL 树最少节点数 N(h) = N(h−1) + N(h−2) + 1（N(1)=1, N(2)=2）。
- **公式怎么来的**：要"节点最少"，根占 1 个；一棵子树塞满（高度 h−1），另一棵只求合法（高度只能是 h−2，差 1 是 AVL 的底线，再矮就失衡了）。所以 N(h) = 1 + N(h−1) + N(h−2)。
- **代入算例**：N(3)=N(2)+N(1)+1=2+1+1=4，N(4)=4+2+1=7，N(5)=7+4+1=12。考法："高度为 4 的 AVL 树最少有几个节点？" → 7。

### 2.6 B 树与 B+ 树（每年 0–1 题，记住对比即可）

| 对比 | B 树 | B+ 树 |
|---|---|---|
| 数据存放 | 所有节点都存关键字和记录 | **只有叶子节点存记录**，内部节点只存索引 |
| 叶子节点 | 不链接 | **串成链表**，便于范围查询 |
| 用途 | 文件系统 | **数据库索引**（MySQL） |

## 第三节 图 ★★★

### 3.1 存储结构

- **邻接矩阵**：n 个顶点用 n×n 矩阵，`A[i][j]=1` 表示有边。无向图矩阵对称。**空间 O(n²)**，适合稠密图；判断任意两点是否相邻 O(1)。
- **邻接表**：每个顶点挂一条链表存它的邻接点。空间 O(n+e)，适合**稀疏图**。

**★ 无向图边数 = 度数总和 ÷ 2**（每条边贡献 2 个度）。有向图：度 = 入度 + 出度，边数 = 入度总和 = 出度总和。

### 3.2 遍历

- **DFS（深度优先）**：一条路走到黑，走不动再回退。用**栈**（或递归）。类比走迷宫摸墙。
- **BFS（广度优先）**：一圈一圈向外扩。用**队列**。类比水波扩散。
- 复杂度：邻接矩阵 O(n²)，邻接表 O(n+e)。
- BFS 求出的单源路径是**边数最少**的路径。

### 3.3 最小生成树（MST）★

生成树：包含全部 n 个顶点、只有 n−1 条边、无回路的子图。带权图中权值和最小的生成树叫最小生成树。**同一张图的最小生成树可能不唯一，但权值和唯一。**

| 算法 | 思想 | 适用 |
|---|---|---|
| **Prim（普里姆）** | 从一个顶点出发，每次挑"树内到树外"最短的边，逐步长出树 | **稠密图**（边多） |
| **Kruskal（克鲁斯卡尔）** | 把所有边按权排序，从小到大选，不构成回路就要 | **稀疏图**（边少） |

**手算技巧**：Kruskal 就是"把边从短到长排队，依次画上去，画到会形成环的跳过"。

### 3.4 最短路径（Dijkstra）★

求一个源点到其他所有顶点的最短路径。思想：贪心，每轮把"当前距离最小的未确定顶点"确定为最终结果，再用它去松弛邻居。**不能处理负权边**（经典考点）。时间复杂度 O(n²)。

### 3.5 拓扑排序（AOV 网）

有向无环图（DAG）中把顶点排成序列，使每条边都从前面指向后面。方法：**每次取入度为 0 的顶点输出并删除其出边**。拓扑序列**不唯一**；图中有环则无法完成拓扑排序（工程上用于检测任务循环依赖）。

### 3.6 关键路径（AOE 网）★★★（计算题大户）

AOE 网：边表示活动（有权=工期），点表示事件（状态）。

- **关键路径 = 从源点到汇点的最长路径**，其长度 = 整个工程的最短工期。关键路径上的活动是**关键活动**，延误则整个工程延误。
- **四个量**（每个事件/顶点 v，每条活动/边 a）：
  1. 事件最早发生时间 ve(v)：从源点**顺推**取 max。
  2. 事件最迟发生时间 vl(v)：从汇点**逆推**取 min（vl(汇点)=ve(汇点)）。
  3. 活动最早开始时间 e(a) = 边起点的 ve。
  4. 活动最迟开始时间 l(a) = 边终点的 vl − 该活动工期。
- **时间余量 = l − e，等于 0 的活动就是关键活动。**
- 关键路径可以不止一条；**缩短工期必须压缩所有关键路径上的公共关键活动**。

手算例：某 AOE 网有活动 A→B(3)、A→C(2)、B→D(4)、C→D(5)、D→E(1)。从源点顺推：ve(B)=3，ve(C)=2，ve(D)=max(3+4, 2+5)=max(7,7)=7，ve(E)=7+1=8，**总工期 8**。可见两条路径长度同为 7，都是关键路径——这正解释了上面那条结论"缩短工期必须压缩所有关键路径的公共活动"：只压 B→D，A→C→D 这条关键路径不受影响，工期纹丝不动。做题时列表逐点算即可，务必动手练一遍真题。

## 第四节 查找 ★★

### 4.1 顺序查找与二分查找

- 顺序查找：O(n)，无序表也能查。
- **二分查找**：仅适用于**有序的顺序表**。O(log₂n)。
  - **★ 最多比较次数 = ⌈log₂(n+1)⌉**（即判定树深度）。n=15 时最多 4 次。
  - 判定树：中间元素做根，左右折半递归。**n 个元素二分查找的成功平均查找长度 ≈ log₂(n+1) − 1**。

### 4.2 散列表（Hash 表）★★（计算题大户）

把关键字通过哈希函数直接映射到存储位置，理想查找 O(1)。

- **冲突**：不同关键字映射到同一位置。**同义词**：哈希函数值相同的关键字。
- **冲突处理方法**：
  1. **开放定址法（线性探测）**：冲突就往后挪一格，直到有空位。缺点：会产生**堆积（聚集）**，非同义词也可能争抢同一批位置。
  2. **链地址法**：每个位置挂一条链表。优点：删除方便、无堆积。
  3. 再散列、公共溢出区（了解即可）。
- **装填因子 α = 表中元素数 / 表长**。α 越大越容易冲突，平均查找长度越大。
- **★ 平均查找长度（ASL）计算**：成功查找的 ASL = Σ(每个元素的比较次数)/元素个数。必须动手算一遍：例如线性探测下，某元素放的位置离它的哈希地址隔了 k 格，它查找成功就要比较 k+1 次。

## 第五节 排序 ★★★（每年稳定 1–2 题）

### 5.1 八大排序总表（背下来，直接得分）

| 算法 | 平均时间 | 最坏时间 | 空间 | 稳定性 | 备注 |
|---|---|---|---|---|---|
| 冒泡排序 | O(n²) | O(n²) | O(1) | **稳定** | 相邻比较交换 |
| 简单选择排序 | O(n²) | O(n²) | O(1) | 不稳定 | 每轮选最小放前头 |
| 直接插入排序 | O(n²) | O(n²) | O(1) | **稳定** | 序列**基本有序时效率最高** |
| 希尔排序 | O(n^1.3) 左右 | — | O(1) | 不稳定 | 分组插入 |
| 快速排序 | **O(nlog₂n)** | **O(n²)（本身有序时最坏）** | O(log₂n) 递归栈 | 不稳定 | 平均最快；每趟确定一个元素的最终位置 |
| 堆排序 | O(nlog₂n) | O(nlog₂n) | O(1) | 不稳定 | 建堆 O(n)，适合**只求前 k 大/小** |
| 归并排序 | O(nlog₂n) | O(nlog₂n) | **O(n)** | **稳定** | 两两合并；n 个元素归并趟数 = ⌈log₂n⌉ |
| 基数排序 | O(d(n+r)) | — | O(r) | **稳定** | 按位分配收集，不比较 |

**★ 稳定排序只有 4 个**：直接插入、冒泡、归并、基数。口诀：「**插冒归基**稳定，其余都不稳」。

**★ 稳定性含义**：相等元素排序后相对次序不变。考法："待排序列中相等元素排序前后顺序颠倒了，问可能是什么排序"——答不稳定的那个。

### 5.2 高频判别题：给中间过程猜算法

题目给出一趟或两趟排序后的序列，问是哪种排序。识别特征：
- **冒泡一趟**：从头两两比较，一趟结束后**最大（小）元素沉到末尾**。
- **选择一趟**：第一个位置换成全序列最小值，其余相对位置基本不动。
- **插入一趟**：前 i+1 个元素**局部有序**，后面原封不动。
- **快排一趟**：**某个元素到了最终位置**，它左边全比它小、右边全比它大。
- **堆排一趟**：最大元素到了末尾。

### 5.3 各排序补充要点

- **快排**：每趟以枢轴为界划分。**序列已有序（正序/逆序）时退化到 O(n²)**，这是最常考的"最坏情况"。
- **堆**：大顶堆（父 ≥ 子）用于升序排序。建堆从最后一个非叶节点 ⌊n/2⌋ 开始向前调整。
- **外部排序**：数据太大放外存时用**多路归并**，败者树/最佳归并树（哈夫曼思想）减少 I/O，选择题考过概念。

## 第六节 算法设计与分析基础

### 6.1 五大算法策略（选择题常考"这是哪种策略"）

| 策略 | 核心思想 | 典型例子 |
|---|---|---|
| **分治法** | 拆成独立子问题，分别解再合并 | 二分查找、归并排序、快排、大整数乘法 |
| **动态规划** | 子问题**重叠**，保存子问题解（自底向上），**最优子结构** | 矩阵连乘、最长公共子序列、0-1 背包、Fibonacci |
| **贪心法** | 每步取当前最优，**不回溯**，不保证全局最优 | Prim、Kruskal、Dijkstra、哈夫曼、部分背包 |
| **回溯法** | 深搜 + 试探 + **走不通退回来**（剪枝） | N 皇后、迷宫、子集和 |
| **分支限界** | 广搜式搜索，用界限剪枝 | 旅行商问题 |

**★ 动态规划 vs 分治**：分治的子问题互相独立；动态规划的子问题重叠，所以要用表保存结果避免重复计算。
**★ 贪心 vs 动态规划**：贪心只走一条路不回头，动态规划考察所有子问题。

### 6.2 时间复杂度（必考 1–2 题）

常见复杂度从小到大：**O(1) < O(log n) < O(n) < O(nlog n) < O(n²) < O(n³) < O(2ⁿ) < O(n!)**

- 二分查找、平衡树操作 → O(log n)
- 遍历链表/数组一遍 → O(n)
- 两层嵌套循环各 n → O(n²)
- 汉诺塔、暴力枚举子集 → O(2ⁿ)

**★ 渐近记号**：O 是上界、Ω 是下界、Θ 是精确界。选择题考"O(f(n)) 的含义：增长率不超过 f(n) 的量级"。

## 第七节 案例题专攻：算法填空解题套路（约 15 分）

案例第 4 题一般是「一段说明 + C 代码（或伪代码）+ 3~5 个空 + 1 小问」，常考：动态规划、贪心、回溯、字符串处理、链表/树操作。**套路如下：**

### 套路一：先读说明再读代码，说明就是答案说明书
题干「说明」部分会用文字描述算法步骤，例如"第 3 步：若 a[i] 大于当前最大值，则更新最大值"。**空基本就藏在文字步骤对应的代码行上，照着文字填代码。**

### 套路二：看空的位置判断要填什么
1. **空在初始化处**：常填 `0`、`1`、`-1`、`INT_MAX` 或数组首元素 `a[0]`。
2. **空在循环条件**：看循环变量和边界，`i < n`、`j > 0`，或动态规划的 `i <= n`。
3. **空在 if 内部更新处**：动态规划常填递推式 `dp[i] = dp[i-1] + xxx`；求最大值常填 `maxv = a[i]`。
4. **空在递归调用**：填递归式，参数看函数定义对应着填，注意返回值 `return f(...)`。
5. **空在 return**：动态规划常填 `dp[n]` 或 `dp[m][n]`。

### 套路三：代入一个具体例子验证
填完后，用一个 n=2 或 n=3 的小例子手动模拟整段代码，能跑通且结果符合说明，基本就对了。

### 常见考题模板速记
- **0-1 背包**：`dp[i][j] = max(dp[i-1][j], dp[i-1][j-w[i]] + v[i])`，j 从大到小滚动数组。
- **最长公共子序列**：字符相等 `dp[i][j]=dp[i-1][j-1]+1`，否则 `max(dp[i-1][j], dp[i][j-1])`。
- **Fibonacci / 爬楼梯**：`f[i] = f[i-1] + f[i-2]`。
- **链表插入**：`s->next = p->next; p->next = s;`（顺序不能反）。
- **链表删除**：`p->next = p->next->next;`。
- **二叉树递归遍历**：`visit(root); f(root->left); f(root->right);` 按序对应前中后序。

## 答案与解析

### 课后考题答案

**1. C**
n0 = n2 + 1 = 5 + 1 = 6。★ 必背结论。易错点：忘了 "+1"，或把度数为 1 的节点扯进来（不需要）。

**2. A（后序 DEBCA）**
前序第一个 A 是根；中序 DBE 在 A 左、C 在 A 右。左子树：前序 BDE + 中序 DBE → 根 B，中序中 D 在左 E 在右。后序 = 左(先D后E) → 右(C) → 根(A) = DEBCA。

**3. C**
循环队列用"牺牲一个单元法"时，front==rear 只表示**空**，满用 (rear+1)%m==front 判断。如果不牺牲单元，才需要额外标志位区分。C 的说法错在"既可以表示空也可以表示满"（在本题默认判满方式下）。

**4. B**
元素个数公式 (rear−front+m)%m，取模保证 front>rear（绕圈）时也算对。

**5. A**
合并：2+3=5 → {4,5,5} → 4+5=9 → {5,9} → 14。WPL = 2×3+3×3+4×2+5×1 = 6+9+8+5 = 28。
易错点：每次必须取**当前最小**的两个，合并后新权值要放回集合继续比。

**6. B**
哈夫曼树无度为 1 的节点，n0=n，n2=n0−1=n−1，总数 n+n−1=2n−1。

**7. B**
快排本身有序（正序或逆序）时枢轴划分极度不平衡，退化为 O(n²)。归并、堆排最坏仍 O(nlog₂n)。

**8. A**
一趟快排后，枢轴 49 必然到达**最终位置**：比 49 小的恰好有 3 个（38、13、27），所以 49 应落在第 4 位，且左边全是 <49、右边全是 >49。逐项检查：A ✓；B 中 76（>49）跑到 49 左边，✗；C 中 65（>49）在 49 左边，✗；D 中 49 还在第 2 位（未归位），✗。**判别要点：枢轴归位 + 两侧大小关系，不必精确模拟每步交换**（不同教材的一趟交换次序略有差异，但这条性质是唯一的）。

**9. B**
稳定的四个：直接插入、冒泡、归并、基数（口诀「插冒归基」）。

**10. A**
1000 顶点仅 10 条边 = 稀疏图，用邻接表省空间（O(n+e)）。三元组顺序表是**稀疏矩阵**的存储，不是图的。

**11. C**
Dijkstra 每轮取当前距离最小者确定下来，是贪心。易混：Floyd（多源）是动态规划。

**12. A**
拓扑排序标准做法：取入度 0 顶点输出并删其出边。B 说反了（那是逆拓扑的一种做法：取出度 0 并删入边，得到的序列是逆拓扑序，作为"得到拓扑序列"的表述在考题中通常判错）。D 深度优先遍历的逆序其实**可以**得到一种拓扑序——但本题 D 表述为"不可行"，错误，故选 A。★ 这题故意做成双干扰，记住核心方法即可。

**13. C**
最多比较 ⌈log₂(n+1)⌉ = ⌈log₂1001⌉ = 10 次。

**14. B**
⌈log₂65⌉ = 7。易错点：别用 log₂64=6 就填 6，公式里要 n+1。（部分教材按判定树深度的定义对 n=2^k−1 型给出 k 次，64 个元素判定树深度为 7。）

**15. C**
必须缩短**所有**关键路径共同经过的关键活动才能缩短工期；只压缩一条关键路径上的活动无效。A、B、D 均正确。

### 案例题答案

**问题 1：**
- (1) `dp[i] = 1`（每个元素自己构成长度为 1 的子序列，初始化）
- (2) `a[j] < a[i]`（a[j] 能接在 a[i] 前面成为递增序列的前驱）
- (3) `dp[i] = dp[j] + 1`（状态转移）

**问题 2：**
- 时间复杂度 O(n²)（两层循环）。
- 输入 {3, 1, 2, 4}：LIS 为 {1,2,4} 或 {3,4}，最长长度 **3**。

**填空套路复盘**：空 (1) 在初始化处填常数；空 (2) 在 if 条件处对应"递增"这一文字描述；空 (3) 在更新处填状态转移。与第七节套路一一对应。

### 精华题答案

**1. 前序 = ABCDEFGH，推导过程**：
后序最后一个是 A → 根 A；中序 BDCE | AFHG → 左子树 {BDCE}，右子树 {FHG}。
左子树后序 DECB → 根 B；中序 BDCE 中 B 居首 → B **无左孩子**，右子树 {DCE}；{D,C,E} 的后序（取原后序中对应段 D、E、C）→ 根 C；中序 D|C|E → D 是 C 的左孩子、E 是右孩子。
右子树后序 HGF → 根 F；中序 FHG 中 F 居首 → F 无左孩子，右子树 {HG}；后序 HG → 根 G，中序 H|G → H 是 G 的左孩子。
**前序：A B C D E F G H**（画出树形可验证：中序 B D C E A F H G ✓、后序 D E C B H G F A ✓）。

**2. WPL = 33，各字符编码长度：a(5)=2 位、b(2)=3 位、c(3)=2 位、d(1)=3 位、e(4)=2 位**
构造：1+2=3 → {3(新), 3(c), 4, 5} → 3+3=6 → {4, 5, 6} → 4+5=9 → {6, 9} → 15。
树形：15 根下左 6、右 9；6 的孩子是"节点(1+2)"和叶子 c(3)；9 的孩子是叶子 4 和 5；节点(1+2) 的孩子是 1 和 2。深度：a、c、e 在第 2 层，b、d 在第 3 层。
WPL = 5×2 + 2×3 + 3×2 + 1×3 + 4×2 = 10+6+6+3+8 = **33**。
验算（哈夫曼树性质）：WPL = 所有**非叶节点**权值之和 = 3+6+9+15 = 33 ✓。易错点：合并后要永远挑**当前最小**的两个；本题 {3,3,4,5} 里挑的是两个 3，不是 3 和 4。

**3. 插入过程**（H(key)=key%7，线性探测）：
- 15：15%7=1 → 放位置 1，比较 1 次
- 22：22%7=1 → 冲突，探到 2 → 位置 2，比较 2 次
- 8：8%7=1 → 冲突，2 冲突，探到 3 → 位置 3，比较 3 次
- 29：29%7=1 → 冲突 ×3，探到 4 → 位置 4，比较 4 次
- 36：36%7=1 → 冲突 ×4，探到 5 → 位置 5，比较 5 次
**ASL(成功) = (1+2+3+4+5)/5 = 3**。
这题展示的正是"同义词堆积"现象：全部 hash 到 1，线性探测让 ASL 恶化——考题常拿它对比链地址法。

**4. 总工期 8，关键路径两条：V1→V2→V4→V5 和 V1→V3→V4→V5**
- ve（顺推取 max）：V1=0，V2=3，V3=2，V4=max(3+4, 2+5)=**7**（两条路径长度恰好相等），V5=7+1=**8**。
- vl（逆推取 min）：V5=8，V4=8−1=7，V3=7−5=2，V2=7−4=3，V1=min(3−3, 2−2)=0。
- 活动（e=起点的 ve，l=终点的 vl − 工期）：a1: e=0, l=3−3=0 → 余量 0；a2: e=0, l=2−2=0 → 余量 0；a3: e=3, l=7−4=3 → 余量 0；a4: e=2, l=7−5=2 → 余量 0；a5: e=7, l=8−1=7 → 余量 0。
- 本例**所有活动都是关键活动**——因为两条路径长度同为 7，全都是关键路径，每个活动都在某条关键路径上。它演示了"缩短工期必须压缩**所有**关键路径的公共活动"：两条路径的公共活动只有 a5，只压 a1 或 a2 工期纹丝不动。
- **做题教训**：算 ve 时对每个入点都要取 max（这里 max(7,7) 很容易漏算成单边），每步动手验算。

**5. 快速排序**
第一趟后 25 在位置 4（最终位置），左侧 {20,15,21} 全 <25，右侧全 >25，且 84 也恰在末尾（本轮的边界比较把它交换到最右），符合快排一趟特征。

**6. O(n log n)**
外层 i*=2 执行 log₂n 次，内层 n 次，相乘得 O(nlog₂n)。易错点：外层不是 +1 而是 ×2，别答 O(n²)。

**7. 共 2 种：ABCDE 和 ACBDE**
分析约束：A 是唯一入度为 0 的顶点 → 必须最先；E 入度来自 D → 必须最后；B→D 和 C→D 都指向 D → D 必须排在 B、C **两者**之后，而 B、C 之间无约束、可互换。于是 D 只能落在第 3 位（A 之后、B/C 之后），序列只有 A、{B,C 两种顺序}、D、E 一种骨架 → **2 种**。若答 4 种，是漏了 C→D 这条边对 D 的约束（只看到 B→D 就以为 D 可紧跟 B）。
