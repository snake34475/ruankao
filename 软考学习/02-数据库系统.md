## 第一节 三级模式与两级映像 ★

### 为什么需要"三级模式"

数据库是被很多应用程序**共享**的：财务程序、人事程序、报表工具都要读同一批数据，但它们各只关心自己那一块，而且谁都不希望"存储结构一改、我的程序就得重写"。为此数据库把数据组织分成三个视角、配上两层"翻译层"，把**变化隔离**在各自层内——这就是考"独立性"的全部动机。

| 层次 | 别名 | 看到什么 | 例子 |
|---|---|---|---|
| 外模式 | 用户模式/子模式 | 某类用户看到的部分数据 | 一个视图、一张报表用的字段 |
| 概念模式 | 模式/逻辑模式 | 全体数据的逻辑结构 | 一张张表的定义 |
| 内模式 | 存储模式 | 数据在磁盘上怎么存 | 索引、压缩、存储顺序 |

**两级映像**（考试考"哪个映像对应哪种独立性"，必背）：

| 映像 | 连接的两层 | 保证的独立性 | 白话 |
|---|---|---|---|
| **外模式/模式映像** | 外模式 ↔ 模式 | **逻辑独立性** | 表的逻辑结构变了（加字段），应用程序不用改 |
| **模式/内模式映像** | 模式 ↔ 内模式 | **物理独立性** | 换了存储方式（加了索引、换了磁盘），应用程序和表定义都不用改 |

**反例演示（易错）**：题目说"数据存储结构改变，模式不变"——变化发生在内模式层，靠**模式/内模式映像**挡住 → **物理独立性**；说"表新增了字段，应用程序不变"——变化发生在模式层，靠**外模式/模式映像**挡住 → **逻辑独立性**。判断口诀：**变化发生在哪一层，挡住它的映像就连着哪一层；看应用程序"感知不到什么"来选词**。别把"逻辑独立性 = 跟逻辑有关所以是内模式"想反了——逻辑独立性恰恰是指**逻辑结构变化也影响不到应用**。

**应试动作**：背"外模式/模式映像 ↔ 逻辑独立性，模式/内模式映像 ↔ 物理独立性"这一组对应，考试只考配对，认出题干描述的变化发生在哪层即可。

## 第二节 E-R 模型 ★★★（案例题必考）

### 实体、属性、联系

- **实体**：客观存在可区分的事物（一个学生、一门课），矩形框。
- **属性**：实体或联系的性质（学号、姓名），椭圆；能唯一标识实体的属性叫**码**。
- **联系**：实体之间的关系，菱形（如学生"选修"课程）。

### 联系类型：1:1、1:n、m:n（必须会判）

拿具体业务判断"一个 A 对应几个 B"：

- **1:1**：一个部门只有一个经理，一个经理只管一个部门。
- **1:n**：一个部门有多个员工，一个员工只属于一个部门 → 部门:员工 = 1:n。
- **m:n**：一个学生选多门课，一门课被多个学生选 → 学生:课程 = m:n。

**判断反例（易错）**：别看到"多个"就判 m:n——**只有两边都能是"多个"才是 m:n**。"一个班有多名学生"但"一名学生只属一个班"是 1:n，不是 m:n。

### E-R 图转关系模式（案例题必考步骤）

| 联系类型 | 转换规则 |
|---|---|
| 1:1 | 联系并入任一端实体（加对方的主键作外键） |
| 1:n | 联系并入 **n 端**实体（加 1 端的主键作外键） |
| **m:n** | **联系必须单独建一张关系模式**，主键 = 两端主键的组合 |

**反例演示（易错）**：学生-课程是 m:n，若把"选课"并入学生表（学生表加课程号、成绩列），一个学生选多门课就要占多行，学号、姓名重复存储，而且学号不再能作主键——错。**口诀：多对多，单独坐一桌**。

### E-R 集成时的三类冲突（选择题考过）

多个分 E-R 图合并时会撞车：**属性冲突**（同一属性类型/单位不一致）、**命名冲突**（同名异义、异名同义）、**结构冲突**（同一对象在此图是实体、在彼图是属性）。**没有"实体冲突"这种说法**——选项里出现即排除。

## 第三节 关系代数 ★★

关系代数就是"对表做运算"。考三种：

### 选择 σ：挑行

σ<sub>系别='计算机'</sub>(学生) = 从学生表里**抽出满足条件的行**（水平方向切）。条件写在 σ 的下标位置；手写时把条件写在 σ 右下方即可。

### 投影 π：挑列

π(姓名,系别)(学生) = 只保留指定**列**（垂直方向切）。**注意：投影会自动去掉重复行**（只剩两列后原本不同的行可能变得相同）。

### 连接 ⋈：两张表拼起来

- **θ 连接**：从笛卡尔积中保留满足一般比较条件（`=、>、<、≥、≤、≠`）的组合。
- **等值连接**：θ 连接的条件只使用 `=`，但参与比较的两列仍都保留。
- **自然连接**：按**所有同名属性**相等来拼接，并把同名列**只保留一份**。因此自然连接是特殊的等值连接。

**公式三件套（考数字计算）**：
- 笛卡尔积 R×S：若 R 有 r 行 s 列、S 有 t 行 u 列，结果 **r×t 行、s+u 列**。
- 自然连接结果的**列数 = s + u − 公共属性个数**（重复列只留一份）。
- 例：R(A,B,C) 有 3 行，S(C,D,E) 有 4 行，公共列 1 个（C）→ 自然连接列数 = 3+3−1 = **5**。

自然连接的**行数不能只看两表各有几行**，要看公共属性的值能配成多少对。通用计数式为：

> 连接行数 = 对每个公共属性值 v，分别计算 `R 中 v 的行数 × S 中 v 的行数`，再把各项相加。

例如：

| R(A,B) | | S(B,C) | |
|---|---|---|---|
| r1 | x | x | s1 |
| r2 | x | x | s2 |
| r3 | y | z | s3 |

公共值 `x` 在 R 中有 2 行、在 S 中有 2 行，贡献 `2×2=4` 行；`y` 和 `z` 对不上，贡献 0 行，所以自然连接共 **4 行**。反向核对：实际组合正是 `(r1,x,s1)`、`(r1,x,s2)`、`(r2,x,s1)`、`(r2,x,s2)` 四行。

**边界检查**：若完全配不上，行数可为 0；若两表每行的公共属性值都相同，最多可达 `r×t` 行。故只给出两表行数而不给数据值时，只能回答“行数不确定，范围为 0～r×t”。

**反例演示（易错）**：自然连接 ≠ 笛卡尔积再挑同名相等的行之后还保留两份 C 列——重复列必须**去掉一份**；选项里列数算成 s+u 的是陷阱。另外投影和选择的别记反：**选择管行（横向内容）、投影管列（纵向结构）**，σ 的 σ 像"筛子"筛行，π 的两条竖线像切列的刀。

**应试动作**：背"σ 行、π 列、⋈ 拼表去重列"；行数列数计算用上面公式代数字。

## 第四节 关系规范化 ★★★（选择题 + 案例题双考）

### 为什么要规范化

一张大表什么都往里塞，会出现三种病：**数据冗余**（系主任跟着每个学生重复存）、**修改麻烦**（换主任要改几百行）、**插入/删除异常**（还没招生的系插不进来、最后一个学生毕业系主任信息也跟着没了）。规范化的目的就是**拆表**，把这些病一步步消掉。

### 函数依赖（判断范式的唯一工具）

X→Y 读作"X 决定 Y"：知道 X 就能唯一确定 Y。三种关键形态（设 K 是候选键）：

- **完全依赖**：Y 依赖整个 K，去掉 K 中任何一个属性都不行。例：(学号, 课程号)→成绩。
- **部分依赖**：Y 依赖 K 的**一部分**就够了。例：(学号, 课程号)→姓名，其实学号→姓名——**部分依赖是病**。
- **传递依赖**：X→Y、Y→Z 且 Y 不决定 X，则 Z 传递依赖 X。例：学号→系名→系主任——**传递依赖是病**。

先把几个容易混的“键”分清：

- **超键**：能决定全部属性的属性集，可以含多余属性；
- **候选键**：不含多余属性的最小超键，可能不止一个；
- **主键**：人为从候选键中选一个作为主要标识；
- **主属性**：出现在**任一候选键**中的属性；其余是非主属性；
- **全码**：整个关系模式的全部属性合在一起才构成候选键，即所有属性都是主属性且缺一不可。

**反例演示（易错）**：若候选键有 `AB` 和 `AC`，主属性是 `A、B、C` 的并集，不是只看被选作主键的 `AB` 而把 C 误判为非主属性。范式判断看的是**所有候选键**，不是只看主键。

### 范式判定：一级一级"消病"

| 范式 | 要求 | 一句话判定 |
|---|---|---|
| 1NF | 属性不可再分（数据库默认满足） | 所有属性都是原子值 |
| 2NF | 消除**部分依赖** | 每个非主属性都依赖**整个**候选键 |
| 3NF | 再消除**传递依赖** | 非主属性不间接依赖候选键 |
| BCNF | 每个决定因素都必须是候选键 | 比 3NF 更严：主属性也不能有依赖毛病 |

**判定四步法（背流程，别背定义）**：
1. 找候选键（见下）；
2. 列出所有"决定→被决定"；
3. 看有没有**非主属性只依赖候选键一部分** → 有则最高 1NF；
4. 再看有没有**非主属性靠别的非主属性中转** → 有则最高 2NF；都没有 → 3NF；若还有主属性被非主属性决定 → 不到 BCNF。

把判定压成一张“谁依赖谁”表：

| 观察到的依赖 | 造成什么问题 | 最高可能停在哪 |
|---|---|---|
| 非主属性依赖组合候选键的一部分 | 部分依赖 | 1NF |
| 非主属性经另一个非主属性间接依赖候选键 | 传递依赖 | 2NF |
| 决定因素不是超键，但右部是主属性 | 允许满足 3NF，不满足 BCNF | 3NF |
| 每个非平凡依赖的决定因素都是超键 | 无上述问题 | BCNF |

**快判 1**：候选键只有一个属性时，不可能存在“对候选键一部分”的依赖，因此只要满足 1NF 就自动满足 2NF。

**快判 2**：如果所有属性都是主属性，就没有“非主属性的部分依赖或传递依赖”，因此至少满足 3NF；但决定因素若不是超键，仍可能不到 BCNF。

例：R(A,B,C)，F={AB→C，C→B}。候选键有 `AB` 和 `AC`，所以 A、B、C 全是主属性，R 满足 3NF；但 `C→B` 的决定因素 C 不是超键，因此不满足 BCNF，最高为 **3NF**。

**主属性也会部分依赖，但不会把关系打回 1NF**：上例候选键 `AC` 中，主属性 B 由 C 单独决定，即 B 对候选键 AC 存在部分依赖。2NF 的检查对象是**非主属性**，所以该依赖不违反 2NF；它真正违反的是更严格的 BCNF 条件。不要见到“部分依赖”四个字就机械判 1NF，先看被决定者是不是非主属性。

**反例演示（易错）**：R(学号, 姓名, 系, 系主任)，学号→姓名、学号→系、系→系主任。候选键是学号（单属性），**不可能有部分依赖**（键只有一个属性，"一部分"还是它自己），所以它**直接就是 2NF**；但学号→系→系主任是传递依赖，所以**最高 2NF，不是 3NF**。最常见的错误就是把"有冗余"当成"不是 2NF"——单属性键的表不存在部分依赖，第一步就能跳过。

### 候选键怎么求（案例题必考）

候选键的严格工具是**属性闭包**。属性集 X 在函数依赖集 F 下能推出的全部属性，记作 `X⁺`。若 `X⁺` 等于关系的全部属性，则 X 是超键；再逐个删除 X 中属性，删谁都不能推全，X 才是候选键。

**闭包算法（通用形式）**：

1. 初始化 `X⁺ = X`；
2. 反复扫描每条函数依赖 `Y→Z`：若 `Y ⊆ X⁺`，就把 Z 加入 `X⁺`；
3. 一轮扫描后不再增加属性时停止；
4. 与属性全集比较，再做“逐个删除”最小性检查。

**手算口诀：先把自己圈进去；左边已齐，就收右边；一轮没新增，才算停。**

**Armstrong 三条公理**是闭包推导的依据：

- **自反律**：若 Y⊆X，则 X→Y；
- **增广律**：若 X→Y，则 XZ→YZ；
- **传递律**：若 X→Y 且 Y→Z，则 X→Z。

考试常直接使用三条派生规则：**分解**（X→YZ 可推出 X→Y、X→Z）、**合并**（X→Y 且 X→Z 可推出 X→YZ）、**伪传递**（X→Y 且 WY→Z，可推出 WX→Z）。

**完整演算**：R(A1,A2,A3,A4,A5,A6)，F={A1→A3，A1A2→A4，A5A6→A1，A3A5→A6，A2A5→A6}，求一个候选键。

1. 从未出现在任何依赖右部的属性是 `A2、A5`，它们无法由其他属性推出，必须进入每个候选键；
2. 初始化 `(A2A5)⁺={A2,A5}`；
3. 用 `A2A5→A6`，加入 A6；
4. 用 `A5A6→A1`，加入 A1；
5. 用 `A1→A3`，加入 A3；
6. 用 `A1A2→A4`，加入 A4；
7. 闭包已是 `{A1,A2,A3,A4,A5,A6}`，故 A2A5 是超键；去掉 A2 或 A5 都无法推全，因此 **A2A5 是候选键**。

反向验证：只用 A2 时没有任何依赖可启动；只用 A5 也无法启动，两个属性都不可删除，最小性成立。

**启发式口诀：从未在依赖右部出现的属性，必在每个候选键里。**但这只是起点，不是答案；必须继续算闭包并检查最小性。

例：R(A,B,C,D)，F = {A→B, B→C, D→B}。右部出现过的：B、C。从未出现在右部的：**A、D**。验证 AD：A→B，B→C，D→B → 可推出 A、B、C、D 全部 → **候选键 = AD**（ABD 虽也能决定全部，但含多余属性，是超键不是候选键）。

### 分解后怎么检查：无损连接与保持函数依赖

规范化不是“拆得越碎越好”。拆完必须过两道门：

1. **无损连接**：分表自然连接后能准确还原原关系，不丢行，也不产生原来不存在的假行；
2. **保持函数依赖**：原来的约束能在各分表内部检查，不必把表连接起来才能验证。

二元分解 `R→R1、R2` 的常用无损快判是：公共属性 `R1∩R2` 能否函数决定 R1 或 R2 的全部属性，即检查 `(R1∩R2)→R1` 或 `(R1∩R2)→R2` 是否成立。

例：R(A,B,C)，F={A→B}，分为 R1(A,B) 与 R2(A,C)。公共属性是 A，且 `A→AB` 成立，所以分解**无损**。

反例：仍是 R(A,B,C)，若分为 R1(A,B) 与 R2(B,C)，公共属性是 B，但由 F 只能知道 A→B，推不出 `B→AB` 或 `B→BC`，因此不能判为无损，实际可能连接出假行。

**保持依赖不等于无损**：两者是不同检查项。3NF 综合算法通常可以兼顾无损和保持依赖；BCNF 分解保证无损，但可能牺牲某些依赖保持。案例题若只问“能否还原原表”，答无损；若问“能否分别在单表内检查全部约束”，答保持函数依赖。

**应试动作**：背四步判定法 + "右部不出现的属性进候选键"；考"最高属于第几范式"时**从低往高验**，卡在哪级就答前一级。

## 第五节 SQL ★★★（案例题必考）

SQL 分四类语句，案例题主要考前两类：

| 类别 | 关键词 | 用途 |
|---|---|---|
| DDL 数据定义 | CREATE / ALTER / DROP | 建表、建视图、改结构 |
| DML 数据操纵 | SELECT / INSERT / UPDATE / DELETE | 查和改数据 |
| DCL 数据控制 | GRANT / REVOKE | 授权、收权（选择题常考） |
| TCL 事务控制 | COMMIT / ROLLBACK | 提交事务、回滚事务 |

### SELECT 完整骨架（背顺序）

```sql
SELECT   列名或函数            -- ⑤ 挑列
FROM     表                    -- ① 数据从哪来（可 JOIN ... ON）
WHERE    行条件                -- ② 先筛行
GROUP BY 分组列                -- ③ 按列分组
HAVING   组条件                -- ④ 筛组（条件里通常带聚合函数）
ORDER BY 排序列 [ASC|DESC];    -- ⑥ 最后排序
```

**为什么 HAVING 和 WHERE 要分家**：WHERE 在分组**前**筛原始行，此时还没有算出平均分这类聚合值；HAVING 在分组**后**筛"每组"。所以"查询平均分大于 80 的课程"必须写 `HAVING AVG(成绩)>80`，写进 WHERE 直接报错——这是最常见的案例扣分点。

### 建表与完整性（案例题第 1 小问模板）

```sql
CREATE TABLE SC (
    Sno   CHAR(8),
    Cno   CHAR(6),
    Grade SMALLINT,
    PRIMARY KEY (Sno, Cno),                -- 实体完整性：主键
    FOREIGN KEY (Sno) REFERENCES Student(Sno),  -- 参照完整性：外键
    FOREIGN KEY (Cno) REFERENCES Course(Cno),
    CHECK (Grade BETWEEN 0 AND 100)        -- 用户定义完整性
);
```

三种完整性对应关系：主键 → 实体完整性；外键 → 参照完整性；CHECK/取值范围 → 用户定义完整性。**选择题爱考对应关系，案例题爱考写外键子句**。

### 数据增、删、改与修改表结构

只会 `SELECT` 不够，题目若出现“新增一条记录、批量涨价、删除不及格记录、给旧表加列”，分别认下面四个模板：

```sql
-- INSERT：列名和值按位置一一对应
INSERT INTO Student(Sno, Sname, Dept)
VALUES ('20260001', '李明', '计算机');

-- UPDATE：一定先写 WHERE，防止误改整表
UPDATE SC
SET Grade = Grade + 5
WHERE Cno = 'C02' AND Grade < 60;

-- DELETE：删除满足条件的行，不删除表结构
DELETE FROM SC
WHERE Grade IS NULL;

-- ALTER：修改表结构，这里是给 Student 加一列
ALTER TABLE Student
ADD Email VARCHAR(50);
```

**反例演示（易错）**：`DELETE SC WHERE ...` 少了 `FROM`；`UPDATE SC SET Grade=0` 若忘写 WHERE，会把整张表全部改成 0；`DROP TABLE SC` 则连表结构和数据一起删除，绝不是“删除几行”。

**应试动作**：看到“记录/元组”想到 `INSERT、UPDATE、DELETE`；看到“列/表结构”想到 `ALTER`；看到“整个对象”才考虑 `DROP`。

### 视图与授权

```sql
CREATE VIEW 计算机系学生 AS
    SELECT Sno, Sname FROM Student WHERE Dept = '计算机';

GRANT SELECT, INSERT ON SC TO 用户1 WITH GRANT OPTION;  -- 授权（可转授）
REVOKE SELECT ON SC FROM 用户1;                          -- 收回权限
```

**视图的动机**：视图是一张**虚表**（只存定义不存数据），作用有二——① 简化常用查询；② **提供逻辑独立性/安全隔离**（用户只见视图字段，表结构改了只需改视图定义）。考题问"视图的作用/提高了什么独立性"→ 答**逻辑独立性**（视图是外模式级的东西，正好呼应第一节）。

### 嵌套查询（选择题常考）

```sql
SELECT Sname FROM Student
WHERE Sno IN (SELECT Sno FROM SC WHERE Cno = 'C02');
```

IN 后面跟子查询结果集合；EXISTS 写法是"存在即保留"，选择题考"IN 与 EXISTS 等价改写"。

把同一查询改写为 `EXISTS`：

```sql
SELECT S.Sname
FROM Student AS S
WHERE EXISTS (
    SELECT 1
    FROM SC
    WHERE SC.Sno = S.Sno
      AND SC.Cno = 'C02'
);
```

读法是：对外层每个学生 S，去 SC 表中寻找一行，使“学号等于当前学生学号且课程号为 C02”；只要找到一行，`EXISTS` 就为真，保留该学生。`SELECT 1` 中的 1 没有特殊数据含义，`EXISTS` 只关心“有没有行”，不关心子查询选出什么列。

**反例演示（易错）**：若漏掉关联条件 `SC.Sno = S.Sno`，只要全校有任何人选了 C02，子查询对每个学生都为真，最终会错误地返回全校学生。

**应试动作**：SELECT 骨架六个子句的**执行顺序**（FROM→WHERE→GROUP→HAVING→SELECT→ORDER）必须背熟，它是所有 SQL 题的做题导航。

## 第六节 事务、并发控制与故障恢复 ★★

### 事务与 ACID

事务是"要么全做、要么全不做"的一组操作。经典例子：转账 = A 扣 100 + B 加 100，两个 UPDATE 必须同生共死。

| 性质 | 含义 | 靠什么保证 |
|---|---|---|
| 原子性 Atomicity | 全做或全不做 | 故障恢复（UNDO） |
| 一致性 Consistency | 事务前后数据都处于正确状态 | 原子性 + 隔离性共同效果 |
| 隔离性 Isolation | 并发事务互不干扰 | 并发控制（锁） |
| 持久性 Durability | 提交后永久生效 | 故障恢复（REDO/日志） |

考法："转账中途断电，钱不能凭空消失"体现**原子性**；"提交后断电重启数据仍在"体现**持久性**。

### 并发带来的四类错误（反例各背一个）

两个事务 T1、T2 同时操作 A=100：

1. **丢失修改**：T1 和 T2 都读 A=100，T1 加 10 写回 110，T2 减 5 写回 95——T1 的修改被**覆盖丢了**（应是 105）。
2. **不可重复读**：T1 读 A=100，T2 把 A 改成 200 并提交，T1 再读 A 变 200——**同一事务内两次读结果不同**。
3. **读脏数据**：T1 把 A 改成 200（还没提交），T2 读到 200；T1 随后**回滚**，A 恢复 100——T2 读到的 200 是"脏"的，根本没生效过。
4. **幻读**：T1 第一次查询“成绩≥90 的学生”得到 3 行；T2 插入一名 95 分学生并提交；T1 用同一条件再查得到 4 行——像凭空多出一行“幻影”。

不可重复读与幻读都表现为“两次查询不同”，区别在对象：前者是**已有同一行的字段值变了**，后者是**满足条件的行数增减了**。口诀：**丢改是写被盖，脏读是读未交，不可重复是同一行变，幻读是结果集增减行。**

### 封锁与两段锁协议

- **S 锁（共享锁/读锁）**：持锁事务可以读，其他事务还可加 S 锁一起读，但不能加 X 锁写。
- **X 锁（排他锁/写锁）**：持锁事务可以读写，其他事务不能再加 S 或 X 锁。

相容矩阵必须会看：行表示“已有锁”，列表示“新申请锁”。

| 已有锁 \ 新申请 | S 锁 | X 锁 |
|---|---:|---:|
| S 锁 | 相容 | 不相容 |
| X 锁 | 不相容 | 不相容 |

- **两段锁协议**：事务分两阶段——先**扩展阶段**（只加锁不放锁），后**收缩阶段**（只放锁不加锁）。一旦释放了第一把锁，就不能再申请新锁。
- 遵守两段锁协议 → 调度**可串行化**，即并发结果等价于某一种串行顺序执行；但它**不能避免死锁**。

反例：T1 先锁 A 再等 B，T2 先锁 B 再等 A，两者都处于扩展阶段、都可能符合两段锁，却形成循环等待。因此固定结论是：**两段锁保证可串行化，不保证不死锁。**

选择题若给出调度并问是否可串行化，简化做法是尝试把所有冲突操作的先后关系画成“事务箭头”：若 T1 必须在 T2 前，同时又推出 T2 必须在 T1 前，形成环，就不能等价为串行调度；无环则可按拓扑顺序串行化。

### 故障恢复：先分故障，再定 REDO/UNDO

| 故障类型 | 题干识别词 | 影响范围 | 主要恢复手段 |
|---|---|---|---|
| 事务故障 | 单个事务越界、死锁被撤销、逻辑错误 | 某个事务 | 利用日志 UNDO 该事务 |
| 系统故障 | 断电、操作系统崩溃、数据库进程崩溃 | 内存内容丢失，磁盘通常未坏 | 从检查点和日志执行 REDO/UNDO |
| 介质故障 | 磁盘损坏、盘块不可读、数据库文件毁坏 | 持久化数据受损 | 装入备份，再用归档日志 REDO |

**反例演示（易错）**：断电通常属于系统故障，不等于磁盘介质已经损坏；“磁盘磁头损坏导致数据文件不可读”才是介质故障。系统故障靠日志即可恢复，介质故障必须先有备份作底。

依靠**日志**（先写日志、后写数据库）+ **检查点**。系统重启后扫描日志：

- 事务**已提交**（BEGIN 后有 COMMIT）→ **REDO 重做**（结果应该生效，重放保证落盘）；
- 事务**未提交**（只有 BEGIN 没有 COMMIT）→ **UNDO 撤销**（做了一半的必须抹掉）。

口诀：**提交了就重做（REDO），没提交就撤销（UNDO）**。检查点的作用是记录当时的恢复起点和活跃事务，使恢复时不必从日志开头全量扫描；不能机械理解为“检查点之前的一切都不用管”，跨越检查点但尚未结束的事务仍要结合日志处理。

日志片段若显示 T1 有 `COMMIT`、T2 只有 `BEGIN` 和若干写操作，那么恢复动作就是 **REDO T1、UNDO T2**。反向核对语义：提交的结果必须保持，未提交的半成品必须消失。

### 分布式数据库：四特性与四种透明性

先分清两类问题：“系统本身有什么特点”问**特性**；“用户不必知道什么细节”问**透明性**。

| 特性 | 白话含义 | 题干识别词 |
|---|---|---|
| 共享性 | 各站点的数据能被全局用户共享 | 跨节点共同访问数据 |
| 自治性 | 每个站点能独立管理本地数据库 | 本地独立控制、独立运行 |
| 可用性 | 某站点故障时可使用其他站点或副本继续服务 | 单点故障后系统仍可用 |
| 分布性 | 数据物理存放在网络中的多个场地 | 多节点、不同地域存储 |

四种透明性则按“用户被屏蔽的细节”识别：

| 透明性 | 用户不必知道 | 关键词 |
|---|---|---|
| 分片透明（最高层） | 一张全局表如何横向或纵向分块 | 分片、分块规则 |
| 复制透明 | 同一数据复制了几份、更新哪些副本 | 副本、复制份数 |
| 位置透明 | 数据或副本位于哪个站点 | 地址、节点、场地位置 |
| 局部映像透明/逻辑透明（最低层） | 局部 DBMS 的数据模型和操作语言 | 异构数据库、模型转换 |

**易错对比**：“表被怎样切成几块”是分片透明；“某一块放在哪座机房”是位置透明；“同一块存了三份”是复制透明。不要把“分片”误当成物理位置。

**应试动作**：ACID 四个词背全称；四类并发错误能看描述对号入座；S/X 锁只记住“S-S 唯一相容”；“两段锁 → 可串行化但可能死锁”背成一句；故障题先分事务/系统/介质，再套 REDO/UNDO；分布式题先判断问的是“特性”还是“透明性”。

## 第七节 案例题专攻：数据库设计大题（约 15 分）

案例第 2 题一般是"业务说明 + 不完整 E-R 图 + 关系模式 + SQL 填空"，三小问固定套路：

### 套路一：E-R 图补全——读句子找联系

题干每个动词都暗示一条联系："学生**选修**课程""教师**讲授**课程""部门**聘用**员工"。补空时：
1. 先数图中已有几实几联系，句子里的名词 = 实体、动词 = 联系；
2. 联系类型用业务常识判："一个 X 对应几个 Y"，两边都可多个才是 m:n；
3. m:n 联系上若有自己的属性（如"成绩"属于选课联系而非学生或课程），标在菱形上。

### 套路二：关系模式填空——主键外键往哪放

1. 每个实体一张表，主键 = 实体的码；
2. 1:n 联系：把 1 端主键放进 **n 端表**作外键；
3. m:n 联系：单独建表，主键 = **两端主键组合**，联系的属性（成绩）也放这张表；
4. 小问问"XX 表的主键是什么"：先想清它是实体表还是联系表，联系表的主键几乎总是组合键。

### 套路三：SQL 填空——按 SELECT 骨架对号入座

1. 空 FROM：看 SELECT 和 WHERE 里用了哪些列，缺哪张表补哪张，多表加 `JOIN ... ON 连接条件`；
2. 空 WHERE：对应题干"查询**满足某条件**的行"，日期/字符串加引号；
3. 空在聚合旁："每门课/每个部门的平均/最高/数量"→ `GROUP BY` 分组列，条件带 AVG/MAX/COUNT 写 `HAVING`；
4. 空在 CREATE TABLE：主键 `PRIMARY KEY(...)`、外键 `FOREIGN KEY(...) REFERENCES 表(列)`；
5. 填完代入一条具体数据心里跑一遍（同第一课算法填空的自检法）。

### 套路四：题目要求“增加实体”时怎么改

这类小问不是只在图上多画一个矩形，而是要完成“业务句子 → E-R 图 → 关系模式”整条链。

例：在运动会业务中新增规则：“记录教练，教练属性包括教练编号、姓名；每名运动员恰由一名教练指导，一名教练可指导多名运动员。”

1. 名词“教练”有独立编号和属性 → 新增实体 **教练**；
2. 动词“指导”连接教练与运动员；
3. 一名教练对多名运动员、每名运动员只对一名教练 → 教练:运动员 = **1:n**；
4. 转关系模式：新增 `教练(教练编号, 姓名)`；把 1 端的教练编号放到 n 端，因此运动员表改为 `运动员(运动员编号, 姓名, 团编号, 教练编号)`，教练编号是外键。

**反例演示（易错）**：把“指导”单独建成 `指导(教练编号, 运动员编号)` 并非一定语法错误，但对没有自身属性的 1:n 联系属于多余拆表；标准答法是把 1 端主键并入 n 端。若题干改成“运动员可由多名教练共同指导”，两边都可多，才应单独建立联系表。

范式小问的答题模板：**“候选键为……；非主属性对候选键存在/不存在部分依赖，所以满足/不满足 2NF；存在/不存在传递依赖……，所以最高为……；建议分解为……，公共属性……能决定其中一表，故无损。”** 按这条链写，结论和理由都有分。

## 精华题（历年必考风格，考前必刷）

## 答案与解析

### 课后考题答案

**1. B**
外模式就是某类用户看到的局部数据逻辑（典型实现即视图）。概念模式是全体逻辑，内模式/存储模式是物理层。★ 对应关系直接背。

**2. B**
存储结构变化发生在内模式，靠模式/内模式映像屏蔽 → 物理独立性。易错点：把"逻辑独立性"跟"存储"联想到一起——恰好相反，逻辑独立性屏蔽的是**逻辑结构（表定义）**的变化。

**3. B**
一门课只属一个教师、一个教师可授多门课 → 教师:课程 = 1:n。易错点：见到"多门"就选 m:n——必须**两边都可多**才是 m:n，这里课程一侧只能一个教师。

**4. C**
m:n 联系必须单独建关系模式，主键 = 学生主键 + 课程主键组合，联系自身的属性（成绩）也放这里。并入任一端都会造成学号重复存储、学号失去主键资格。

**5. D**
行数：自然连接行数取决于同名属性上相等的元组如何配对，**不能确定**（最少可能 0 行）；列数 = 4+6−1 = **9**。所以选"行数不确定、9 列"。易错点：列数算成 10（忘了去掉一份重复列）或行数答 15（那是笛卡尔积的行数）。

**6. B**
选择 σ 挑行，投影 π 挑列。口诀：σ 像筛子筛行，π 两条竖线切列。

**7. A**
能唯一标识元组且**无多余属性**正是候选键的定义。超键只要求"能唯一标识"（可含多余属性）；主属性是包含在任一候选键中的属性，不是属性集；外键是引用他表主键的属性。

**8. A**
右部出现过的属性：B（A→B）、C（B→C）、B（D→B）——即 B、C。从未出现在右部的：**A、D** → 先试 AD：A→B，B→C，D→B，闭包 = A、B、C、D 全部 → 候选键 = AD。再看其余三个为何只是超键：ABD 闭包虽也是 ABCD，但 B 可由 A 推出（A→B），去掉 B 剩 AD 仍能推全 → B 是多余属性；ACD 同理，C 可由 A→B→C 推出，去掉 C 剩 AD 仍推全 → C 多余；ABCD 显然更冗余。**候选键 = 无多余属性的"最小"超键，四个选项里只有 AD 满足**。

**9. B**
候选键 = 学号（单属性）→ 不存在部分依赖，直接满足 2NF；但学号→系→系主任是传递依赖 → 达不到 3NF。**最高 2NF**。易错点：因"有冗余"误判 1NF——单属性键的表第一步就不可能有部分依赖。

**10. D**
范式是逐级加严的包含链：1NF ⊃ 2NF ⊃ 3NF ⊃ BCNF。BCNF ⇒ 3NF 成立（C 对），反过来 3NF 不一定到 BCNF（D 错，反例：存在主属性被非主属性决定的情况）。A、B 是标准定义。

**11. B**
聚合条件只能写 HAVING：`GROUP BY 课程号 HAVING AVG(成绩)>=80`。WHERE 在分组前执行，彼时 AVG 还没算出来，A 语法错误。D 把成绩当分组列，会把每个分数各成一组，不符合"按课程"。

**12. B**
GRANT 授予、REVOKE 收回。DROP 是删除对象（DDL），DENY 不是软考教材标准关键词。

**13. C**
读到"未提交、随后被回滚"的数据 = 脏数据（读脏数据）。区分：不可重复读是"本事务两次读之间被**别人提交**的修改弄得不一致"；丢失修改是两个都提交导致一个写被覆盖。

**14. B**
两段锁协议：先统一加锁、后统一放锁 → 保证可串行化；但两个事务可能互相持有对方要的锁（T1 锁 A 等 B，T2 锁 B 等 A）→ **不能避免死锁**。A、C、D 均为典型错误表述。

**15. B**
故障恢复口诀：**已提交 REDO（重做），未提交 UNDO（撤销）**。未完成的事务做了一半，必须撤销抹掉。ROLLBACK 是事务运行期间的主动回滚操作，不是恢复策略本身。

### 案例题答案

**问题 1（E-R 图描述）**：
实体三个：代表团、运动员、比赛项目。
- 代表团—运动员：**1:n** 的"组成"联系；
- 运动员—比赛项目：**m:n** 的"参赛"联系，联系属性：成绩。
（画图时：三个矩形 + 两个菱形；"参赛"菱形上挂"成绩"椭圆。）

**问题 2（关系模式）**：
- 代表团(**团编号**, 团名, 团所在地)
- 运动员(**运动员编号**, 姓名, **团编号**) ← 1:n 联系，把 1 端主键"团编号"并入 n 端作外键
- 比赛项目(**项目编号**, 项目名称)
- 参赛(**运动员编号, 项目编号**, 成绩) ← m:n 联系单独建表

**"参赛"表的主键 =（运动员编号，项目编号）组合键**——单靠任何一端都无法唯一标识一行（同一运动员参加多个项目、同一项目多名运动员）。

**问题 3（SQL）**：

```sql
-- (1) 建参赛表
CREATE TABLE 参赛 (
    运动员编号  CHAR(8),
    项目编号    CHAR(6),
    成绩        SMALLINT,
    PRIMARY KEY (运动员编号, 项目编号),
    FOREIGN KEY (运动员编号) REFERENCES 运动员(运动员编号),
    FOREIGN KEY (项目编号)   REFERENCES 比赛项目(项目编号)
);
```

```sql
-- (2) 各代表团总分，保留 300 分以上
SELECT 代表团.团编号, 代表团.团名, SUM(参赛.成绩) AS 总分
FROM 代表团
JOIN 运动员 ON 代表团.团编号 = 运动员.团编号
JOIN 参赛   ON 运动员.运动员编号 = 参赛.运动员编号
GROUP BY 代表团.团编号, 代表团.团名
HAVING SUM(参赛.成绩) >= 300;
```
（要点：三表连接取全路径代表团→运动员→参赛；GROUP BY 带上团编号防止两个代表团重名被并成一组；聚合条件进 HAVING。）

```sql
-- (3) 建视图
CREATE VIEW vHighScore AS
SELECT 运动员.运动员编号, 运动员.姓名, 比赛项目.项目名称
FROM 运动员
JOIN 参赛 ON 运动员.运动员编号 = 参赛.运动员编号
JOIN 比赛项目 ON 参赛.项目编号 = 比赛项目.项目编号
WHERE 参赛.成绩 >= 95;
```

### 补充题答案

**1. A⁺={A,B,C,D,E}，A 是候选键；C⁺={C}，C 不是候选键。**

演算 A⁺：初始 `{A}`；A→BC，加入 B、C；B→D，加入 D；已有 C、D，可用 CD→E，加入 E；闭包达到全集。A 是单属性，无法再删，故为候选键。反向验证 C⁺：只有 C 时，CD→E 缺 D，其余依赖左部也不满足，没有新属性可加入，故停在 `{C}`。

**2. 候选键为 AB、AC；主属性为 A、B、C；最高为 3NF。**

`(AB)⁺=ABC`，且 A⁺、B⁺都推不全，所以 AB 是候选键。`(AC)⁺` 中由 C→B 得到 B，故为 ABC；A⁺、C⁺都推不全，所以 AC 也是候选键。全部属性都出现在某个候选键中，都是主属性，因此至少满足 3NF；但依赖 C→B 中，C 不是超键，违反 BCNF，故最高 **3NF**。这也反向验证了“全属性皆主属性不代表一定是 BCNF”。

**3. A。**

分解 A 的公共属性是 A，且 A→AB，所以公共属性能决定 R1，分解无损。分解 B 的公共属性是 B，而由 F={A→B} 推不出 B→AB 或 B→BC，不能用该条件判为无损。

**4. 4 行、3 列。**

公共值 x 在 R 中出现 2 行，在 S 中出现 2 行，产生 `2×2=4` 个组合；y、z 互相配不上。列数为 `2+2−1=3`，属性是 A、B、C。用实际枚举四个组合可反向核对行数。

**5. SQL 如下：**

```sql
SELECT S.Sname
FROM Student AS S
WHERE EXISTS (
    SELECT 1
    FROM SC
    WHERE SC.Sno = S.Sno
      AND SC.Cno = 'C02'
);
```

`SC.Sno = S.Sno` 把内层记录与“当前外层学生”绑定。若省略，只要全校任意一人选了 C02，子查询对每个学生都为真，会错误返回全校学生。

**6. A。**

S 与 S 相容，所以 T2 可再申请 S 锁；S 与 X 不相容，X 锁必须等待。矩阵中唯一的“相容”格就是 S-S。

**7. D。**

同一范围查询的结果集新增了满足条件的行，属于幻读。不可重复读通常指已存在的同一行字段值改变；脏读必须涉及未提交数据。

**8. 系统故障；REDO T1、UNDO T2。**

断电但磁盘未损坏属于系统故障。T1 已提交，其结果必须保留，故 REDO；T2 未提交，半成品必须消失，故 UNDO。反向检查：恢复后数据库只应体现已提交事务。

**9. 分片透明；可用性。**

“怎样水平切块”描述分片规则，属于分片透明；站点失效后仍能借助其他副本服务，描述系统抗单点故障，体现可用性。后者问的是特性，不是复制透明。

### 精华题答案

**1. 视图属于外模式；索引属于内模式**
视图是用户局部视图（外模式级，典型实现）；索引是物理存储组织（内模式级）。这题考"具体事物 → 归哪一层"：用户看到的逻辑 = 外模式，磁盘组织细节 = 内模式。

**2. 列数 = 3 + 2 − 1 = 4 列**（R 的 A、B、C 三列加 S 的 D 列，公共属性 B 只留一份）。
行数最多 = **2×3 = 6 行**（R 的每行 B 值恰好都能在 S 中配上时，最多达到笛卡尔积水平；若 B 值全对不上则 0 行）。

**3. R 最高属于 2NF**
候选键 = 仓库号（单属性）→ 无部分依赖 → 满足 2NF；仓库号→城市→地区编号是传递依赖 → 不到 3NF。
分解到 3NF：仓库(**仓库号**, 仓库面积, 城市) 和 城市(**城市**, 地区编号)。

**4. 候选键 = E**
右部出现过的属性：B、D、A、C；从未出现在右部的只有 **E**。试 E：E→A，A→B，B→C，C→D → 闭包 = ABCDE，全部推出 → **E 单属性即候选键**。（验证：E→A→B→C→D，链式全推。）

**易错点：答案不是 "AE"**。AE 也能推出全部属性（A→B→C→D，再加 E），但它**含冗余属性**——E 一个人就够了，A 是多余的。候选键的定义是**不含冗余属性的最小超键**，能少一个就少一个，多出来的那个只能叫超键。反向也要查一遍：A 行不行？A→B→C→D 只能推出 A、B、C、D，**推不出 E**，所以 A 不是候选键。本题**唯一候选键 = E**。

**5. 发生丢失修改时，A 的错误终值可能是 100 或 70；正确终值应为 120 或 140（取决于串行顺序）**
错误终值举例：T1 读 A=50 → T2 读 A=50 → T1 写回 70 → T2 写回 50×2=100，T1 的 +20 被覆盖丢失；另一交错 T2 先写 100、T1 再写 70，则 T2 的结果丢失。正确终值：先 T1 后 T2 串行 = (50+20)×2 = **140**；先 T2 后 T1 = 50×2+20 = **120**——两种都符合事务语义，但丢失修改哪种都得不到。此题演示"丢失修改 = 一个事务的写被另一个事务的写覆盖"。

**6. SQL 答案**：

```sql
-- (1) 嵌套查询
SELECT Sname FROM Student
WHERE Sno IN (SELECT Sno FROM SC WHERE Cno = 'C02');

-- (2) 选课超过 3 门
SELECT Sno FROM SC
GROUP BY Sno HAVING COUNT(Cno) > 3;

-- (3) 授权（可转授）
GRANT SELECT ON SC TO U1 WITH GRANT OPTION;
```
要点：(2) 聚合条件进 HAVING；(3) WITH GRANT OPTION 是"允许转授"的固定写法。

**7. 前者是不可重复读，后者是读脏数据**
"两次读结果不同"：两次读之间**别的已提交事务**改了数据；"读到未提交"：读到的事务随后可能回滚。判断窍门：看干扰事务**提交没有**——提交了 → 不可重复读；没提交（后回滚）→ 脏读。
