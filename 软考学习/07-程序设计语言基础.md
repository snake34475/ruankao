## 第一节 语言处理程序：编译与解释 ★★★

**动机**：计算机 CPU 只认识机器码（0/1 指令），而我们写的是高级语言（C、Java、Python…）。中间必须有一个"翻译程序"把高级语言翻译成机器能执行的东西。按翻译方式不同，分两大流派：

| 对比项 | 编译方式 | 解释方式 |
|---|---|---|
| 代表语言 | C、C++、Pascal、Fortran | Python、PHP、JavaScript、Ruby |
| 翻译过程 | **整本翻译**：源程序一次性翻译成目标程序（机器码） | **逐句翻译**：边解释边执行，翻译一句执行一句 |
| 是否生成目标程序 | **生成** | **不生成** |
| 执行效率 | 高（运行时不再翻译） | 低（运行时还要翻译） |
| 灵活性/可移植性 | 差（目标程序绑定具体机器） | 好（源程序拿到哪都能跑） |
| 翻译程序是否参与执行 | 编译器**不参与**执行 | 解释器**参与**执行 |

共同点：两种方式**都**要做词法分析、语法分析、语义分析——别以为解释器就"不分析"，它只是不生成目标程序。

**记忆口诀**：编译"先翻完再念"，解释"边念边翻"——像拿到一本外文书：编译是请人整本翻译好再读，解释是请个翻译坐在旁边念一句你听一句。

**Java / C# 是特殊流派（选择题爱考）**：它们**先编译成中间代码**（Java 字节码 / .NET 中间语言），**再由虚拟机（JVM / CLR）解释或即时编译执行**——"先编译后解释"。正因为中间代码与平台无关、各平台各有虚拟机，Java 才能"一次编写，到处运行"。

**反例演示**：判断题「解释方式也会生成与源程序等价的目标程序」——**错**。这是本考点最常见的陷阱选项；解释器从头到尾不产出可独立执行的目标程序。反向陷阱「编译方式执行效率比解释方式低」——错，编译是"先翻完再念"，运行时零翻译开销，效率更高。

**应试动作**：背对比表的三行——①是否生成目标程序（编译生成、解释不生成）②执行效率（编译高）③可移植性（解释好）。考场上题干不会出现"流派"这种词，直接给"某语言程序需先翻译成目标程序后执行""逐句翻译执行"等描述让你归类。

## 第二节 编译的六个阶段 ★★★

**动机**：为什么翻译不一步到位，要分六个阶段？因为"读懂一段话"本身就是分层的：先认字（词法），再看句子通不通（语法），再理解意思对不对（语义），最后才落笔翻译（中间代码→优化→目标代码）。分层后每个阶段只管一件事，出错也好定位——你在第 2 阶段就发现"句子结构不对"，不必等到最后生成机器码才发现。

| 阶段 | 输入 → 输出 | 干什么 | 依据/工具 | 理论考点 |
|---|---|---|---|---|
| ① **词法分析** | 源程序字符流 → **记号流**（单词符号序列） | 从左到右逐个扫描字符，识别出关键字、标识符、常数、运算符、分隔符 | 正规式、**有限自动机** | 词法错误 |
| ② **语法分析** | 记号流 → **语法树** | 按语法规则把单词组成语法单位，检查结构合法性（如 if…end if 配对、括号匹配） | **自顶向下**：递归下降、预测分析；**自底向上**：移进-归约 | 语法错误 |
| ③ **语义分析** | 语法树 | 类型检查等**静态语义**检查（如对浮点数做取余、运算对象类型不合法） | **符号表**辅助 | 静态语义错误 |
| ④ **中间代码生成** | 语义分析结果 → 中间代码 | 生成与**具体机器无关**的中间形式 | 常用形式：**后缀式、语法树、三地址码、四元式** | 四元式 (运算符， 对象1， 对象2， 结果) |
| ⑤ **代码优化** | 中间代码 → 更优的中间代码 | 提高效率（删冗余、提公共子表达式等） | — | — |
| ⑥ **目标代码生成** | 中间代码 → **目标程序** | 转成低级语言代码，**与硬件系统结构密切相关**（寄存器分配等） | — | — |

**顺序口诀**：**词法 → 语法 → 语义 → 中间 → 优化 → 目标**（"认字 → 组句 → 懂意 → 打草稿 → 改稿 → 定稿"）。另外**符号表**贯穿编译全程，记录各符号（变量、函数）的信息，辅助语义检查和代码生成。

**中间代码举例**（四元式）：对 `x := y + z * 60`：

```
(*, z, 60, t1)   ← 先算乘法，结果放临时变量 t1
(+, y, t1, t2)   ← 再算加法
(:=, t2,  , x)   ← 赋值
```

中间代码"中间"的意义：它站在高级语言和机器语言之间，**与机器无关**——前端（词法/语法/语义）只管"读懂"，产出到中间代码为止；后端（优化/目标代码）才管"搬到具体机器上"。换一种 CPU，前端原封不动，只改后端。

**错误分类（必考表格，背熟）**：

| 类别 | 发现时机 | 例子 |
|---|---|---|
| **词法错误** | 编译时（词法分析阶段） | 使用了语言字符集以外的非法字符、单词拼写错误、标点符号错误（如误用中文标点） |
| **语法错误** | 编译时（语法分析阶段） | 括号不匹配、缺少分号、if…end if 不配对、**表达式中缺少操作数** |
| **静态语义错误** | 编译时（语义分析阶段） | 运算符与运算对象**类型不合法**（如对浮点数做取余、整型与字符串相加） |
| **动态语义错误** | **运行时** | 除数为零、数组下标越界、陷入死循环、无效指针引用 |

**反例演示（最易混的两组）**：①「拼写错误 vs 缺分号」——单词拼错、用了中文标点属于**词法**错误；缺分号、缺括号、缺操作数属于**语法**错误（涉及语言结构）。②「编译时 vs 运行时」——除零、下标越界编译器查不出来（它不知道运行时下标是多少），所以叫**动态**错误；死循环也是运行时才暴露。

**应试动作**：① 背死六阶段顺序和三个"输入→输出"（字符流→记号流→语法树→中间代码→目标程序）；② 错误四分类给例子能归类——判断窍门先问"编译时能发现吗"，再按词法（字符级）/语法（结构级）/静态语义（类型级）定位；③ 记住自顶向下=递归下降/预测分析，自底向上=移进-归约。

## 第三节 表达式：前缀、中缀、后缀 ★★（与第 1 课联动）

这一节第 1 课（[01-数据结构与算法.md](01-数据结构与算法.md) 第一节 1.2）已详细讲过中缀转后缀的"傻瓜法"（按优先级加满括号，运算符搬到自己那对括号的右边）。这里给速查表和**前缀**补全：

| 表达式 | 运算符位置 | 例子（(a+b)*c−d） | 特点 |
|---|---|---|---|
| 中缀 | 两操作数**中间** | `(a+b)*c−d` | 人习惯，需括号和优先级 |
| **后缀（逆波兰式）** | 两操作数**后面** | `ab+c*d−` | 计算机求值最方便，无括号 |
| **前缀（波兰式）** | 两操作数**前面** | `−*+abcd` | 无括号，考试较少考 |

**转前缀的傻瓜法**：同样先加满括号，把运算符搬到自己那对括号的**左边**。例：`(a+b)*c−d` → `(((a+b)*c)−d)` → `+ab` 变 `+ab`，`(+ab)c` 变 `*+abc`，整体减 d → `−*+abcd`。

**后缀求值（必考，完整步骤）**：从左到右扫，**操作数进栈；遇运算符弹出栈顶两个数计算——先弹出的是右操作数——结果再进栈**。例：后缀 `8 2 3 * − 4 +`：

| 读到 | 动作 | 栈 |
|---|---|---|
| 8, 2, 3 | 依次进栈 | 8, 2, 3 |
| `*` | 弹 3、弹 2，算 2×3=6，进栈 | 8, 6 |
| `−` | 弹 6、弹 8，算 **8−6**=2，进栈 | 2 |
| 4 | 进栈 | 2, 4 |
| `+` | 弹 4、弹 2，算 2+4=6 | 6 |

结果 6。**反向验证**：该后缀对应中缀 `8−2*3+4` = 8−6+4 = **6** ✓。

**为什么编译器爱用后缀做中间代码**：第二节说过中间代码常用形式里就有"后缀式"——扫后缀式时每个运算符出现时它的操作数一定已在栈里，一遍扫完，不需要优先级表和括号。

**反例演示**：后缀求值时**先弹的是右操作数**，减法除法顺序不能反。`8 6 −` 是 8−6=2；若先弹的当左操作数就算成 6−8=−2，错。

**应试动作**：① 中缀转后缀用"加满括号搬右边"，转前缀"搬左边"；② 求值时先弹的当**右**操作数；③ 考题给后缀式求值，用栈表逐步算，算完还原成中缀验一遍。

## 第四节 文法与语法树 ★

**动机**：语法分析"按语法规则组句"，这条规则的形式化描述就是**文法**。

一个形式文法是四元组 **G = (V, T, S, P)**：

| 成分 | 名称 | 含义 |
|---|---|---|
| V | **非终结符** | 不是语言的最终组成部分，是"占位符"（如 `<句子>`、S、A） |
| T | **终结符** | 语言的最终组成部分（如 a、b、关键字） |
| S | **起始符** | 推导从它开始（S ∈ V） |
| P | **产生式** | 替换规则，形如 A → α（用右部替换左部） |

例：文法 S → aSb | ε。从 S 出发反复推导：S → aSb → aaSbb → … → aⁿbⁿ。它描述的语言是 {aⁿbⁿ | n≥0}——非终结符 S 像"待填的坑"，终结符 a、b 才是最终结果。

**闭包与正则闭包（公式三件套）**：

- **通用形式**：正则闭包 A⁺ = A¹ ∪ A² ∪ …（**1 个或多个** A 连接）；闭包 A* = A⁰ ∪ A⁺（在正则闭包基础上**加上 A⁰ = {ε}**，ε 是空串）。
- **代入算例**：A = {ab} 时，A⁺ = {ab, abab, ababab, …}；A* = {ε, ab, abab, …}——只多一个空串 ε。
- **手算口诀**：**"加 1 乘 0"**——`+` 表示 1~n 个（不含空串），`*` 表示 0~n 个（含空串）。

**语法推导树**：从起始符 S 出发按产生式展开画出的树——根是 S，内部节点是非终结符，叶子从左到右拼起来就是推导出的句子。语法分析阶段输出"语法树"用的就是它。

**重要结论**：常见的程序设计语言（C、Java 等）的语法规则通常是**上下文无关文法**——选择题直接考这个结论。

**应试动作**：① 四元组各成分一句话定义；② 背"加 1 乘 0"；③ 背"程序语言通常用上下文无关文法"这一句。

## 第五节 正规式与正规集 ★★★

**动机**：词法分析阶段要识别"什么样的字符串算一个标识符、什么样的算一个整数"——这种**单词的模式**就用正规式（正则表达式）描述。它是描述字符串集合的最简工具。

### 5.1 三种运算与优先级

正规式只有三种基本运算（按优先级从高到低）：

| 运算 | 符号 | 含义 | 例 |
|---|---|---|---|
| **闭包** | `*` | 重复 0 次或多次（优先级**最高**） | `a*` = {ε, a, aa, aaa, …} |
| **连接** | `·`（常省略） | 依次拼接（次高） | `ab` = {ab} |
| **或** | `|` | 二选一（**最低**） | `a|b` = {a, b} |

**公式三件套（以 `(a|b)*` 为例）**：① 通用形式——闭包作用于括起来的整体，表示括号内串的任意次拼接；② 代入算例——`(a|b)*` = {ε, a, b, ab, ba, aab, abb, …}，即**所有由 a、b 组成的串（含空串）**；③ 手算口诀——先算 `*`（闭包），再算连接，最后算 `|`；想改变顺序就加括号。

**常用正规式速查表（背熟，考题基本不出这张表）**：

| 正规式 | 表示的正规集 |
|---|---|
| `ab` | 仅 {ab} |
| `a|b` | {a, b} |
| `a*` | {ε, a, aa, aaa, …}（任意多个 a，含空串） |
| `(a|b)*` | 所有由 a、b 组成的串（含空串） |
| `a(a|b)*` | **以 a 开头**的 a、b 串 |
| `(a|b)*abb` | **以 abb 结尾**的 a、b 串 |
| `(a|b)*aa(a|b)*` | **含有连续 aa** 的 a、b 串 |

**反例演示（三组经典混淆，逐组看会错在哪）**：

1. `ab*` ≠ `(ab)*`。`ab*` 中 `*` 只作用于 b（闭包优先级最高）：{a, ab, abb, abbb, …}——**一个 a 后跟任意多个 b**；`(ab)*` 是 {ε, ab, abab, …}。若把 `ab*` 误当成 `(ab)*`，就会得出"`abb` 属于 `(ab)*`"的错误结论——按 `(ab)*` 逐块切分 `abb`：第一块 ab，剩下 `b` 不够一块，切不动 → 不属于。
2. `a|b*` ≠ `(a|b)*`。`a|b*` = {a} ∪ {ε, b, bb, …}——**单个 a，或若干个 b**；绝没有 ab、ba 这种混合串。
3. 「以 abb 结尾」≠「含有 abb」。`(a|b)*abb` 要求串**最后三个字符**恰好是 abb；若多写一段成 `(a|b)*abb(a|b)*`，就放宽成"中间只要出现过 abb"——此时 `abba`（以 a 结尾）也会被匹配。边界条件差一段闭包，集合就完全不同。

### 5.2 专题：给正规式判串（完整判定步骤）

**考场四步法**：

1. **翻译**：把正规式翻译成大白话——"以什么开头 / 以什么结尾 / 中间任意 / 至少含什么"。
2. **首尾筛查**：先用开头、结尾条件快速淘汰选项（最快）。
3. **分块回代**：对存活选项，把串按正规式结构**切分**——闭包部分逐字符核对是否都在字母表内，`|` 部分逐位二选一。
4. **反向验证**：把选中的串按"开头块 + 闭包块 + 结尾块"重新拆一遍，确认每块都能对上号，且没有剩余字符没归属。

**例（完整演算）**：正规式 `r = (a|b)*aa(a|b)*`，判断哪个串属于 L(r)。

1. 翻译：所有**含有连续两个 a（子串 aa）** 的 a、b 串。
2. 首尾筛查：首尾无限制（两端都是 `(a|b)*`），此步淘汰不了，直接进第 3 步。
3. 分块回代：
   - `ababa`：逐字符找 aa——a、ab、aba…均无相邻两个 a → 不属于 ✗
   - `baab`：中间 b**aa**b，含 aa → 候选 ✓
   - `abab`：无 aa ✗
   - `abba`：无 aa ✗
4. 反向验证：`baab` = `(a|b)*` 取 b ＋ `aa` ＋ `(a|b)*` 取 b，三块拼回恰好是 baab，无剩余字符 ✓。

**结论：只有 baab 属于 L(r)**。注意第 3 步找"连续 aa"是看**相邻**两个字符，别隔位看。

**给串选正规式**（反过来问）同样用四步法：先看待匹配串的结构特征（开头/结尾/含什么），再逐个选项检查——特别警惕"形似但范围不同"的选项，用上面第 5.1 节的反例 1、2 的切分法排除。

**应试动作**：背熟速查表 + 三组反例。考场上题干给一个正规式四个串，30 秒流程：翻译成大白话 → 首尾筛 → 存活者分块回代 → 反向拼回验证。哪些考法套这套流程：给正规式选串、给串选正规式都是；"给状态图写正规式"用第六节的方法。

## 第六节 有限自动机：DFA 与 NFA ★★★

**动机**：正规式描述了单词的"模式"，但程序怎么**执行**这个模式？有限自动机（FA）就是正规式的"可执行版本"——词法分析器内部就是一台有限自动机在逐字符扫描。正规式和自动机**描述能力等价**，可互相转换。

### 6.1 定义与五元组

自动机 M = (S, Σ, δ, s₀, Z)：

| 成分 | 含义 |
|---|---|
| S | 有限**状态集** |
| Σ | 有穷**输入字母表**（每个元素一个输入字符） |
| δ | **转换函数**：当前状态 + 输入字符 → 下一状态 |
| s₀ | 唯一**初态**（s₀ ∈ S） |
| Z | **终态集**（可空） |

状态转换图：圆圈是状态，箭头标输入字符表示转移，双圈（或打星）是终态。

**识别规则**：从初态出发，逐个读入字符串的字符沿箭头走；**读完整个串恰好停在终态**，则该串被自动机接受（识别）；中途走不动或读完不在终态，则不接受。

**DFA vs NFA（必考区别）**：

| | 确定有限自动机 DFA | 不确定有限自动机 NFA |
|---|---|---|
| 转移函数 | **单值对照**：一个状态面对一个输入符号，转移到的状态**唯一确定** | 面对同一输入符号可转移到**多个**状态（一个集合），可有 ε 转移（不读字符就跳） |
| 识别能力 | 与 NFA **等价** | 与 DFA 等价（NFA 可用**子集法**确定化成 DFA） |

注：DFA 是 NFA 的特例；两者识别的语言类相同（都恰好是正规式能描述的语言）。这与第 1 课（[01-数据结构与算法.md](01-数据结构与算法.md)）里算法的"确定性"是同一种思想——DFA 每一步走向唯一，模拟它就是照表走。

### 6.2 专题：判定自动机接受哪些串（完整步骤）

**考场三步法**：

1. **列转移表**：把每个状态对每个输入字符的走向列成表（题干给状态图就照图抄表）。
2. **逐步走串**：从初态开始，对候选串**逐字符查表**，每步写出当前状态；中途出现"该状态对该字符无转移"则立即拒绝。
3. **终态核对 + 反向验证**：读完整个串看是否停在终态；再用该自动机对应的**语言特征**（先根据几条路径归纳出"以××开头/结尾"等规律）反向检查一遍，两条路结论一致才落笔。

**例（完整演算）**：DFA 状态转移表如下（q₀ 为初态，q₂ 为唯一终态）：

| 状态 | 输入 0 | 输入 1 |
|---|---|---|
| →q₀ | q₀ | q₁ |
| q₁ | q₀ | q₂ |
| *q₂ | q₀ | q₂ |

**先归纳语言**：观察——只有"连续读入两个 1"才能从 q₀ 经 q₁ 到达 q₂；到了 q₂ 之后读 1 停在 q₂、读 0 回 q₀。所以接受的是**以 11 结尾**的 0、1 串（等价正规式 `(0|1)*11`）。

**逐步走串**（判 `1011`）：q₀ --1--> q₁ --0--> q₀ --1--> q₁ --1--> q₂。读完停在终态 q₂ → **接受** ✓。

**反向验证**：`1011` 以 "11" 结尾，与归纳的语言特征一致 ✓。再判 `1101`：q₀ --1--> q₁ --1--> q₂ --0--> q₀ --1--> q₁，读完停在 q₁ 非终态 → 拒绝；反向看 `1101` 以 "01" 结尾，不一致才对（它确实不以 11 结尾）✓。两条路结论吻合。

**给状态图写正规式**：先**归纳语言**（看什么路径能从初态走到终态、走终态前必须经过什么），再用速查表（第五节）把特征写成正规式——以"以 11 结尾"为例：前面任意 `(0|1)*` ＋ 结尾固定 `11`，得 `(0|1)*11`。写完拿一个被接受的串和一个被拒绝的串各回代验一次。

**应试动作**：① 背 DFA/NFA 区别一句话——"DFA 单值、NFA 多值（可含 ε），能力等价"；② 判串题老老实实逐字符查表走，别心算跳步；③ 归纳语言看"到达终态前最后一段路径"的形状。给图写正规式、给串判接受，都靠"逐字符走 + 归纳语言"两把刀。

## 第七节 函数调用：传值 vs 传址（引用）★★★

**动机**：函数想用主调方的数据，有两条路——把**值复印一份**带过去（传值），或把**地址/引用**（钥匙）递过去直接操作原件（传址/引用）。复印本改坏了不影响原件；钥匙能真改房子。

| 对比项 | 传值调用 | 传址/引用调用 |
|---|---|---|
| 形参拿到什么 | 实参的**值**（副本） | 实参的**地址**（原件本身） |
| 形参改变影响实参吗 | **不影响**（单向传递） | **影响**（双向传递） |
| 实参可以是 | 变量、**常量、表达式**均可 | 只能是**变量**（必须是地址；常量和表达式没有地址可取） |

**记忆口诀**：**传值复印本，改了不还乡；传址寄钥匙，改屋真变样**。另一条判断规则：传值的实参随意（常量、表达式都行），传址的实参必须是变量。

**反例演示**：① 传值调用下 `f(a)` 里把形参改成 100，函数返回后 a 纹丝不动——想通过参数"带出"结果却用了传值，是初学者最常见 bug；② 引用调用写 `f(a+1, b)` 直接编译报错/无意义——`a+1` 是表达式，没有地址可传。

**关于作用域与闭包（大纲提及，考得浅，知道概念即可）**：**作用域**决定一个名字在程序哪些位置可见。多数语言（C、Java）采用**静态作用域**（词法作用域）——名字属于哪一层，看程序文本的嵌套结构，**编译时**就能确定；动态作用域则按**运行时的调用链**确定（少数早期语言）。**闭包**指函数与其所引用的外部变量捆绑在一起（如 Python/JS 的嵌套函数把外层变量"记住了"），选择题了解词义即可。

### 7.1 专题：传值/传址追踪（完整步骤）

**考场四步法**：

1. **标记身份**：传值参数在旁边标"副本"，传址参数直接标"= 实参"（形实一体）。
2. **逐句执行**：按语句顺序更新形参；每次用到传址参数，**写的就是实参的新值**（前一句可能刚改过它）。
3. **同步回写**：传址参数每变一次，立即同步到对应实参，防止最后漏记。
4. **双法验证**：先按逐步追踪得出一套结果，再**反向验证**——传址调用整体等价于"把函数体里的形参名全部替换成实参名后在主调方原地执行一遍"，按这个视角重算一次，两法结果一致才定稿。

**例 1（基础对比）**：`procedure f(x, y) { x = x + 2; y = x + y; }`，调用 `f(a, b)`，初始 a=1, b=3。

| | 传值调用 | 传址调用 |
|---|---|---|
| 执行 x = x+2 | x 副本：1→3 | a = 1+2 = **3** |
| 执行 y = x+y | y 副本：3+(3)=6 | b = 3+3 = **6**（x 此刻已是 3） |
| 函数返回后 | a=**1**, b=**3**（原件没动） | a=**3**, b=**6** |

反向验证（传址版）：形参换名后函数体即 `a = a+2; b = a+b`，原地执行 a=3、b=3+3=6 ✓ 与追踪一致。

**例 2（顺序陷阱）**：`procedure g(x, y) { x = x + y; y = x + y; }`，调用 `g(a, b)`，初始 a=2, b=5。

- 传值：副本 x=2, y=5 → x=7，y=7+5=12；返回后 **a=2, b=5**（不变）。
- 传址：a = 2+5 = **7**；接着 y = x+y 用的是**新 x**：b = 7+5 = **12**。

反向验证（传址版）：换名后即 `a = a+b; b = a+b` → a=7, b=7+5=12 ✓。**易错点**：第二句若拿旧值算成 b=2+5=7 就错了——传址下第一句已经把 a 改成 7，后续语句必须用新值。

**应试动作**：① 背两条性质——传值单向、实参可任意；传址双向、实参必须变量；② 追踪题按四步法列表逐句算，传址参数"每句用新值、同步回写实参"；③ 用"换名原地执行"反向验证。这是纯送分题，唯一失分方式就是跳步。

## 第八节 各语言特点与分类 ★

**动机**：选择题常给一个应用场景（"人工智能符号处理""科学计算"）问选什么语言，或给一个语言问它的分类。这纯是背诵题，一张表解决。

**按翻译方式分类**：

| 类别 | 语言 |
|---|---|
| 编译型 | C、C++、Pascal、Fortran |
| 解释型（脚本语言多属此类） | Python、PHP、JavaScript、Ruby |
| 先编译为中间代码、再由虚拟机执行 | **Java**（字节码 + JVM）、**C#**（中间语言 + .NET） |

**静态类型 vs 动态类型**：静态类型语言（C、C++、Java）在**编译期**检查类型；动态类型语言（Python、JavaScript）变量类型在**运行期**才确定、随赋值变化。

**各语言特点表（背"语言 → 一句话"）**：

| 语言 | 一句话特点 |
|---|---|
| Fortran | 科学计算，执行效率高 |
| Pascal | 为教学而开发，表达能力强 |
| C | 指针操作能力强、高效，常用于操作系统开发 |
| **Lisp** | **函数式**语言，符号处理，**人工智能** |
| **Prolog** | **逻辑推理**，用于数据库和专家系统 |
| C++ | 面向对象且高效 |
| Java | 面向对象，编译为中间代码（字节码），跨平台 |
| C# | 面向对象，中间代码，.NET 平台 |
| Python | 解释型、面向对象、通用脚本语言 |
| PHP | 服务器端脚本语言，嵌入 HTML 的动态网页 |

**应试动作**：重点背两个"最容易和别的搞混"的——**Lisp=函数式/AI**、**Prolog=逻辑推理/专家系统**（两者都沾 AI，别互换）；再背 Java 跨平台靠"字节码 + JVM"这条机制描述。其余扫一眼有印象即可。

## 答案与解析

### 课后考题答案

**1. C**
编译是"先整本翻译成目标程序，再直接运行目标程序"，执行时编译器不参与，效率高（A 反了）；解释器逐句翻译执行、**不生成**目标程序（B 反了）；两种方式都要做词法、语法、语义分析（D 反了）。易错点：B 是最常见陷阱——"解释也要分析，但不产出目标程序"。

**2. B**
词法分析：字符流 → **记号流**；语法分析的输出才是语法树（C）；目标代码是最后阶段产物（D）。记忆链：字符流→记号流→语法树→中间代码→目标程序。

**3. A**
固定顺序：词法④ → 语法② → 语义⑤ → 中间代码① → 优化⑥ → 目标代码③。B 把优化提到中间代码之前（没有中间代码，优化什么？）；C 词法语法颠倒（先认字才能组句）；D 语义跑到语法前面（不懂结构怎么查语义）。口诀：词法语法语义，中间优化目标。

**4. D**
下标越界要等**运行时**才知道实际下标是多少，编译器无法发现——动态语义错误。同类的还有除数为零、死循环。凡是"运行时才暴露"的都选动态语义错误。

**5. C**
静态语义错误 = **类型类**错误且编译时能查：对浮点数做取余是运算对象类型不合法。A、B 是语法错误（结构问题）；D 是动态语义错误（运行时）。判断窍门：编译时+类型有关 → 静态语义；编译时+结构有关 → 语法；运行时 → 动态语义。

**6. D**
常用中间代码四种：后缀式、语法树、三地址码、四元式——它们都与具体机器无关。汇编指令代码是**目标代码级**的东西，不是中间代码。

**7. A**
逐步演算（傻瓜法：加满括号，运算符搬到自己那对括号右边）：
`(a+b)*c-(d-e)` → `(((a+b)*c)-(d-e))`；`a+b` → `ab+`；`(ab+)*c` → `ab+c*`；`d-e` → `de-`；最后整体减法：`ab+c*` ＋ `de-` ＋ `-` → **`ab+c*de--`**。
反向验证：按"每个运算符吃掉前面紧挨的两块"读 `ab+c*de--`——`+` 吃 a、b 得 a+b；`*` 吃 (a+b)、c；`-` 吃 d、e 得 d−e；最后一个 `-` 吃 (a+b)*c 与 (d−e)——恰为原式 ✓。
B 读出来是 a+b*c−(d−e)（`*` 抢先作用于 b、c）；C 读出来是 (a+b)*c−d*e；D 读出来是 (a+b)−(c−d)*e，均与原式不符。

**8. B**
翻译：`(a|b)*aa(a|b)*` = 两端任意、**中间含连续 aa** 的 a、b 串（速查表第 7 行）。A、C 错在把"含 aa"窄化成"开头/结尾是 aa"——`baab` 含 aa 但既不以 aa 开头也不以 aa 结尾，却在集合中；D 更是无关。反向验证：`baab` = b＋aa＋b，三块拼回无剩余 ✓。

**9. A**
`abab` = (ab)(ab)，是 `ab` 重复两次 → A ✓。反向验证其余选项：B `a(ab)*` 生成的串长度为 1+2k（1、3、5…），长度 4 的 `abab` 不可能；C `a*b*` 是"若干 a 后跟若干 b"，`abab` 交替出现不满足；D `b*a*` 是"若干 b 后跟若干 a"，`abab` 开头是 a、中间又有 b，不满足。四个选项恰好只有一个能匹配。

**10. B**
口诀"加 1 乘 0"：`+`（正则闭包）表示 1 到 n 个 a 连接——{a, aa, aaa, …}，**不含空串**；含空串 ε 的是 `a*`（A 是 `a*` 的集合）。C、D 显然不对。

**11. B**
NFA 的定义特征：一个状态面对同一输入符号可转移到**多个**状态（还允许 ε 转移）；DFA 则是单值对照。A 无根据（DFA 与 NFA 状态数没有必然大小关系）；C 错——NFA 与 DFA 识别能力等价，都能识别正规语言；D 错——没有终态的自动机什么都接受不了（终态集可空，但那样它不接受任何串，不可能"识别所有串"）。

**12. C**
逐字符查表走串：
- A `1101`：q₀ --1--> q₁ --1--> q₂ --0--> q₀ --1--> q₁，停在 q₁ 非终态 ✗
- B `0110`：q₀ --0--> q₀ --1--> q₁ --1--> q₂ --0--> q₀，停在 q₀ ✗
- C `1011`：q₀ --1--> q₁ --0--> q₀ --1--> q₁ --1--> q₂，**停在终态 q₂ ✓**
- D `1110`：q₀ --1--> q₁ --1--> q₂ --1--> q₂ --0--> q₀，停在 q₀ ✗
反向验证：该 DFA 的语言是"以 11 结尾的 0、1 串"（见第六节例题）；C `1011` 以 11 结尾 ✓，A 以 01 结尾、B 以 10 结尾、D 以 10 结尾，均不符。两条路结论一致。

**13. B**
②④正确：传值传的是副本，实参给常量表达式都行，但形参改动**不会**影响实参（①错，单向）；引用调用双向传递（④对），但实参必须是**变量**——常量和表达式没有地址可传（③错）。记忆口诀：传值复印本（单向、实参随意），传址寄钥匙（双向、实参须变量）。

**14. B**
逐句追踪（引用调用：x 即 a，y 即 b）：
- 初始 a=6, b=2
- `x = 2*x` → a = 2×6 = **12**
- `y = x - y` → b = 12 − 2 = **10**（x 必须用**新值** 12）
反向验证：换名后函数体即 `a = 2*a; b = a - b`，原地执行 a=12、b=12−2=10 ✓。
A 是传值调用的结果（原件不动）；C 错在第二句没用新 x；D 错在第一句没执行。易错点：传址追踪每句都用**当前最新值**。

**15. A**
Prolog 是**逻辑推理型**语言（用于专家系统、数据库），不是面向对象语言——A 的对应关系错误，选它。B、C、D 均为正确对应。易错点：Lisp（函数式/AI）与 Prolog（逻辑推理）都沾"人工智能"，但"函数式"标签专属 Lisp，"逻辑推理"标签专属 Prolog，别互换。

### 案例题答案

**案例 1**

**问题 1**（p 传值 = 副本；q 引用 = y 本身）：

| 语句 | p（副本） | q（=y） | x | y | r |
|---|---|---|---|---|---|
| 初始 | 5 | 3 | 5 | 3 | — |
| `q = q - p` | 5 | 3−5=−2 | 5 | **−2** | — |
| `p = p - q` | 5−(−2)=**7** | −2 | 5 | −2 | — |
| `return p` | — | — | 5 | −2 | **7** |

结果：**r=7，x=5，y=−2**。
反向验证：q 引用即"函数体中 q 全部换成 y"：`y = y−x` → y=−2；`p` 是副本不受影响，p=5−(−2)=7，返回 7；x 从未被引用绑定，保持 5 ✓。

**问题 2**（都传值，p、q 均为副本）：

| 语句 | p | q | x | y | r |
|---|---|---|---|---|---|
| 初始 | 5 | 3 | 5 | 3 | — |
| `q = q - p` | 5 | −2 | 5 | 3 | — |
| `p = p - q` | 7 | −2 | 5 | 3 | — |
| `return p` | — | — | 5 | 3 | **7** |

结果：**r=7，x=5，y=3**。反向验证：全是副本，主调方 x、y 纹丝不动 ✓。

**问题 3**：两次返回值恰好相同（返回值只依赖形参自身的算术，与传递方式无关），但**引用调用把对形参的修改带回了实参（y 由 3 变 −2），传值调用完全不影响实参**——本质区别：传的是"复印本"还是"原件本身（地址）"，即数据能否双向流动。

**案例 2**

**问题 1**：观察转移表：从 q₀ 想到达终态 q₂，唯一入口是 q₁ --b--> q₂；而到 q₁ 只能靠读 a（q₀ --a--> q₁ 或 q₁ --a--> q₁）；q₂ 读 a 回 q₁、读 b 回 q₀（一旦读 b 彻底清零，必须重新积累）。所以接受的是**所有以 ab 结尾**的 a、b 串。
等价正规式：**(a|b)*ab**。
反向验证：拿 `aab`（∈L）回代正规式——(a|b)* 取 a、结尾 ab，拼回 aab ✓；拿 `abb`（∉L）检验——它以 bb 结尾，不满足"以 ab 结尾" ✓。

**问题 2**（逐字符列轨迹）：

| 串 | 轨迹 | 结论 |
|---|---|---|
| `aab` | q₀ --a--> q₁ --a--> q₁ --b--> q₂ | 停在终态，**接受** ✓ |
| `abb` | q₀ --a--> q₁ --b--> q₂ --b--> q₀ | 停在 q₀，拒绝 ✗ |
| `abab` | q₀ --a--> q₁ --b--> q₂ --a--> q₁ --b--> q₂ | 停在终态，**接受** ✓ |
| `baab` | q₀ --b--> q₀ --a--> q₁ --a--> q₁ --b--> q₂ | 停在终态，**接受** ✓ |

反向验证：aab、abab、baab 都以 ab 结尾，abb 以 bb 结尾——与"以 ab 结尾"的语言特征一致 ✓。

**问题 3**：变成了 **NFA（不确定有限自动机）**。依据：DFA 要求转移函数是**单值对照**——一个状态面对一个输入符号只有唯一后继；改成"q₁ 或 q₂ 均可"后，同一状态同一输入对应一个**状态集合**，这正是 NFA 的定义特征。（NFA 与 DFA 识别能力等价，可用子集法把这台 NFA 确定化。）

### 精华题答案

**1. B**
中间代码的定义特征就是**与具体机器无关**（后缀式、三地址码、四元式都不绑定硬件）✓。A 反了——语义分析的输入是语法树，输出记号流的是词法分析；C 反了——目标代码生成恰恰要考虑硬件系统结构（寄存器分配等）；D 说的是语法分析的任务，词法分析是逐字符识别单词（依据正规式/有限自动机）。

**2. A**
先归纳语言：p₂（终态）只接受"刚连续读了两个 a"（p₀ --a--> p₁ --a--> p₂）；在 p₂ 再读 a 停在 p₂、读 b 回 p₀ 清零重来。所以语言 = **以 aa 结尾**的 a、b 串 → `(a|b)*aa`。
反向验证各选项：B `a(a|b)*a` 只要求首尾是 a——串 `aba` 满足 B 但不被自动机接受（p₀a→p₁b→p₀a→p₁ 非终态），B 范围偏大；C `(a|b)*a` 只要结尾是 a——`ba` 满足 C 但自动机不接受（p₀b→p₀a→p₁）；D `aa(a|b)*` 只要开头 aa——`aab` 满足 D 但自动机不接受（p₀a→p₁a→p₂b→p₀）。只有 A 与自动机语言完全重合。
（注意本题机器与案例 2 的机器形状相同、语言不同——案例 2 的"入口"是读 b，本题"入口"是读 a，归纳时看清到达终态的最后一步用什么字符。）

**3. A**
翻译：`1(0|1)*0` = 以 1 开头、中间任意 0/1、以 0 结尾的串。逐项排除：B 开头结尾反了；C"含 10"太宽——`0101` 含 10 但以 0 开头 1 结尾，不属于 `1(0|1)*0`；D 无关。反向验证：`1010` = 1＋(01)＋0，三块拼回 ✓ 且首字符 1、末字符 0 ✓。

**4. A**
**引用调用**（p≡x，q≡y）逐句追踪：
- 初始 x=4, y=1
- `p = p + q` → x = 4+1 = **5**
- `q = p - q` → y = 5−1 = **4**（p 用新值 5）
- 返回 p × q = **20**。结果 x=5、y=4。
**传值调用**：p=4、q=1 均为副本 → p=5，q=5−1=4，返回 5×4=**20**；x=4、y=1 不动。
两次返回值相同（返回值只依赖形参自身的算术，与传递方式无关），实参只有引用方式被改动。反向验证：引用调用等价于"形参换名原地执行"：`x=x+y; y=x−y` → x=5、y=5−1=4 ✓。B"返回值不同"无根据；C 错在引用调用下 y 已改为 4 仍写 1；D 错在第一句 p=p+q 已把 x 改为 5 仍写 4。

**5. B**
栈逐步演算（先弹出的当**右**操作数）：

| 读到 | 动作 | 栈 |
|---|---|---|
| 8, 2, 3 | 进栈 | 8, 2, 3 |
| `*` | 2×3=6 进栈 | 8, 6 |
| `-` | **8−6**=2 进栈 | 2 |
| 4 | 进栈 | 2, 4 |
| `+` | 2+4=6 | 6 |

值 = **6**。反向验证：该后缀对应中缀 `8−2*3+4` = 8−6+4 = 6 ✓（C 的 14 是误算成 8+2×3；D 的 26 是误算成 (8−2)*3+4×2 之类的乱序；A 的 2 是漏加 4）。

**6. D**
下标越界要等**运行时**才知道实际下标，编译阶段无法发现——动态语义错误。A 是语法错误、B 是静态语义错误、C 是词法错误，三者都在编译时被发现。判断口诀：编译时查"字（词法）、形（语法）、型（静态语义）"；运行时才见"值"（除零、越界、死循环）。

**7. C**
Java 源程序先由编译器生成**平台无关的字节码（中间代码）**，再由各平台各自的 JVM 解释/JIT 执行——"先编译后解释"，这是跨平台的机制基础。A"直接生成各平台机器码"就没有跨平台意义了；B 错，Java 要先编译成字节码，并非纯解释；D 错，任何高级语言程序都无法不经翻译直接被 CPU 执行。
