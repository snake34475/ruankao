# 01.2 树与二叉树 ★★★

### 2.1 基本性质（选择题最爱直接考结论）

二叉树：每个节点最多两个孩子，且分左右。先在一棵具体的树上把术语认全（这棵树后面反复用）：

```
            A          ← 根节点（没有父节点）
           / \
          B   C       ← A 的左孩子、右孩子
         / \  \
        D   E  F      ← D、E、F 都没有孩子，是叶子
```

- **根**：最顶上的 A；**叶（叶子节点）**：没有孩子的 D、E、F。
- **度**：一个节点的孩子个数。A、B 的度为 2，C 的度为 1，叶子度为 0。
- **层**：根是第 1 层，往下逐层 +1（A 第 1 层，B/C 第 2 层，D/E/F 第 3 层）。
- **深度 / 高度**：默认按"经过的**边**数"算——D 的深度 = A 走到 D 经 2 条边；树的高度 = 根到最深叶子的边数（上图 = 2）。个别教材按"节点数"算（结果差 1），题干会说明，看清即可。

**性质的"为什么"（理解了才不用死背）：**

1. **第 i 层最多 2^(i-1) 个节点**：每往下走一层，每个节点最多分裂成 2 个，所以每层最多是上一层的 2 倍——1、2、4、8……第 i 层即 2^(i-1)。
2. **深度 k 最多 2^k − 1 个节点**：把每层拉满求和 1+2+4+…+2^(k−1)。这个和有个特点：再加一项 2^k 就整体翻倍，所以和 = 2^k − 1（如 1+2+4=7=8−1）。
3. **叶子数 n0 = 度为 2 的节点数 n2 + 1**（考过无数次，完整推导一遍）：

   **先认识符号**：n0、n1、n2 是把树上所有节点**按"孩子个数"分类**后，每一类的**实际个数**（不是最大值）——
   - **n0** = 度为 0 的节点个数 = **叶子数**（没有孩子）；
   - **n1** = 度为 1 的节点个数（只有一个孩子）；
   - **n2** = 度为 2 的节点个数（两个孩子都齐）。
   
   例如 7 个节点的满二叉树：n0=4、n1=0、n2=3。

   **先破一个典型误解："n2 个节点每人生 2 个孩子，叶子不该是 n2×2 吗？"——不对，孩子 ≠ 叶子。** n2×2 算出的是"孩子总数"，但孩子自己一旦又生了孩子，就从叶子变成了内部节点。看反例：

   ```
             A            ← 度 2（分叉①）
            / \
           B   C          ← B 度 2（分叉②）；C 没孩子 → 叶子
          / \
         D   E            ← D、E 没孩子 → 叶子
   ```

   - A、B 度为 2 → n2=2；C、D、E 是叶子 → n0=3。检验：3 = 2+1 ✓，而 n2×2=4 ✗。
   - n2×2=4 数的是**孩子总数**（B、C、D、E 共 4 个），其中 B 自己当了爸爸、不是叶子——"出生人数" ≠ "绝后人数"。

   **直觉推导（记住这个就不用背）**：从根出发若人人只生一个孩子（整条 n1 链），走到底只有 **1 个叶子**（此时 n2=0，n0=1，公式成立）。每出现一个度为 2 的节点，就是把链上某个节点**分岔成两支**：一个潜在叶子变成两个，叶子**净多 1 个**。分叉 n2 次 → 叶子 = 1 + n2。口诀：**分叉一次，叶子多一**。n1 完全不参与——度为 1 的节点只把链拉长，叶子不多不少。

   **代数推导（掰"边"）**：
   - 从"人数"数：n = n0 + n1 + n2（三类节点各数一遍）；
   - 从"边"数：每个节点头顶恰好一条边（根除外），所以边数 = n − 1；每条边都从父亲长出来，度为 1 的节点长 1 条、度为 2 的长 2 条，所以边数 = n1 + 2·n2；
   - 两式相等：n0 + n1 + n2 − 1 = n1 + 2·n2，两边消掉 n1 → **n0 = n2 + 1**（和 n1 无关）。
   - 用上面反例树验证：n=5，人数式 5 = 3+0+2 ✓；边数式 5−1 = 0+2×2 = 4 ✓。
   
   **应试动作**：背结论 `n0 = n2 + 1`；题干给"5 个度为 2 的节点"问叶子数，直接 5+1=6——不需要知道 n1 和总节点数。
4. n 个节点的**完全**二叉树深度 = ⌈log₂(n+1)⌉。

**满二叉树 vs 完全二叉树**（选择题爱考"给一棵树判断是不是完全二叉树"）：

**满二叉树 = 每一层都塞满**。每层节点数 1、2、4、8……，深度 k 的满二叉树**恰好** 2^k − 1 个节点，一层不多不少：

```
深度 3 的满二叉树（7 个节点）
            A
          /   \
         B     C        ← 第 2 层：2 个，满
        / \   / \
       D   E F   G      ← 第 3 层：4 个，满
```

**完全二叉树 = 只有最后一层可以缺，且只能缺最右边**。从上到下、从左到右数，节点必须连续不跳号；缺可以，但缺的只能是"最右边几个"，**左边不能空**：

```
完全二叉树 ✓                      不是完全二叉树 ✗
        A（满）                        A（满）
      /   \                          /   \
     B     C（满）                  B     C（满）
    / \   /                        / \     \
   D   E F     ← 只缺右边 G、H    E   F     G   ← B 的左孩子 D 缺了，
                                                  左边空、右边在 → 断档
```

判断口诀：**从左往右数，只能右边缺席，左边不许空**。

**为什么要有"完全二叉树"这个概念**：它是长得最"紧凑"的形状——按层序编号塞进数组**不留空洞**，这正是堆能用数组存的原因：

```
完全二叉树：  数组 [A][B][C][D][E][F]   ← 编号 1~6 连续，无浪费
非完全二叉树：数组 [A][B][C][?][F][G]   ← 位置 4（D）空洞，浪费
```

| | 满二叉树 | 完全二叉树 |
|---|---|---|
| 定义 | 每层都满 | 仅最后一层可缺**最右边**若干 |
| 节点数 | 恰好 2^k − 1 | 1 ～ 2^k − 1 之间任意值 |
| 关系 | 满是完全的**特例**（取到最大值） | 完全不一定满 |

**易错点**：中文教材的"满二叉树"（每层全满）对应英文 **Perfect** Binary Tree；英文 **Full** Binary Tree 指"每个节点有 0 或 2 个孩子"，和中文"满"不是一回事——软考按中文教材口径考。另注意题干描述"叶子只出现在最下两层""最后一层从左到右连续"都是在暗示完全二叉树。

**★ 完全二叉树的顺序存储下标关系（选择题直接考）**：把完全二叉树按层序（从上到下、从左到右）编号存进数组，**下标从 1 开始**：

```
树：        A(1)
           /   \
          B(2)  C(3)
         /  \  /
        D(4) E(5)F(6)
```

- **公式里的 i 是什么**：i 指「当前节点在数组里的编号」，也就是它按层序排到了第几号（编号从 1 开始，根 A = 1）。**算谁的孩子，就把谁的编号代入 i**。比如算 B 的孩子们时，令 i = 2（B 是 2 号），于是左孩子 = 2×2 = 4（D）、右孩子 = 2×2+1 = 5（E）；算 C 时令 i = 3，左孩子 F = 2×3 = 6。
- **通用公式**：左孩子 = **2i**，右孩子 = **2i+1**，父节点 = **⌊i/2⌋**。用上面的例子验证：B 是 2 号，左孩子 D 恰是 2×2=4 号、右孩子 E 是 5 号；C 是 3 号，左孩子 F 是 6 号。
- 为什么恰好是倍数：按层序编号，每层排满时总数是 2^层 − 1，下一层从头接着编——父与长子之间正好隔开"一整层的名额"，编号差了一倍，所以左孩子 = 2i。
- i > ⌊n/2⌋ 的节点全是叶子。例：n=10 个节点，最后一个非叶节点是 5，建堆从它开始。
- 这也是堆排序"用数组存树"的原理（第五节建堆公式 ⌊n/2⌋ 就是从这来的）。

**延伸阅读**：术语与结构的更多配图见 [hello-algo · 二叉树](https://www.hello-algo.com/chapter_tree/binary_tree/)（在线打开可看插图；离线阅读时忽略本行即可，不影响本讲义自足）。

### 2.2 遍历 ★★★（必考，选择题 + 案例题都会出）

三种遍历的"序"说的是**根**被访问的时机：

| 遍历 | 顺序 | 记法 |
|---|---|---|
| 前序 | **根** → 左 → 右 | 根在前 |
| 中序 | 左 → **根** → 右 | 根在中 |
| 后序 | 左 → 右 → **根** | 根在后 |

**别死背三种"序"，想象"绕树走一圈"就全通了。**

从根出发，贴着树的左侧走，把整棵树的外围**绕一圈**回到根。你会发现每个节点都被路过**三次**：第一次是从上面来（经过它的上方）、第二次是走完它左边绕回来（经过它的下方）、第三次是走完它右边绕回来（经过它的上方）。约定在不同次路过时记下节点，就得到三种遍历：

- **第 1 次路过时记** → **前序**
- **第 2 次（下方）路过时记** → **中序**
- **第 3 次（离开）路过时记** → **后序**

用 2.1 的那棵树实际走一圈（每步都记录，三个"记录本"分别得到三种序）：

三本记录：**前序 ABDEC**、**中序 DBEAC**、**后序 DEBFCA**。同一个"绕圈"动作，只因记录时机不同，就得到三种序——这就是三个定义的全部秘密。

**为什么"下方"那一次恰好是中序**：中序 = 左 → 根 → 右。走完左子树绕回节点，正是"左"结束的时刻，此刻记它，结果自然是"左在前、根居中"。前序（一到达就记，根跑在左右前面）、后序（离开才记，根落在最后）同理。

用递归的话说也相通：第 1 次到达 = **递**进去，第 3 次离开 = **归**出来；"递"时记是前序、"归"时记是后序、递归完左边回头时记是中序。

**核心解题法（必须练熟）：**
- **前序第一个是根，后序最后一个是根，中序里根把树切成左右两半。**
- 已知「前序 + 中序」或「后序 + 中序」可唯一还原二叉树；**「前序 + 后序」不能唯一确定**（无法分左右），这是经典陷阱题。
- 还原步骤：从遍历序列中找根 → 中序里分左右子树 → 对左右子树递归重复。

**还原例题一步步看**：前序 ABDEC，中序 DBEAC。

```
第 1 步：前序第一个 A 是根；中序里 A 把序列切成 DBE | A | C
        A
       / \
      ？   ？      ← 左子树 {D,B,E}，右子树 {C}

第 2 步：左子树 3 个节点，它的前序是 BDE → 第一个 B 是它的根；
        中序 DBE 里 B 的左边 D、右边 E，即 D、E 是 B 的孩子

第 3 步：右子树只剩 C，直接挂上。还原完成：
        A
       / \
      B   C
     / \
    D   E
```

检验：对还原出的树走一圈——前序 A B D E C ✓，中序 D B E A C ✓，与题目一致。

**层序遍历**：从上到下从左到右逐层访问，用**队列**实现（注意：前中后序递归用**栈**）。可以想成"水波扩散"：根先入队，处理 A 时把 B、C 排进队，处理 B 时把 D、E 排进队……队列的"先进先出"恰好保证了同一层先访问完才轮到下一层。

**延伸阅读**：遍历的动态过程配图见 [hello-algo · 二叉树遍历](https://www.hello-algo.com/chapter_tree/binary_tree_traversal/)（在线打开可看；离线不影响本讲义自足）。

### 2.3 线索二叉树

利用二叉链表中的**空指针**（n 个节点有 n+1 个空指针，想想为什么：2n 个指针域、用了 n−1 条边）：

- **左孩子为空 → 左指针改为指向该节点在遍历序中的前驱**；
- **右孩子为空 → 右指针改为指向该节点在遍历序中的后继**；
- （按哪种遍历建立线索就叫"X 序线索树"，考试默认说清是哪种。）

**例子**（中序线索树）：

```
          A
         / \
        B   C
       / \
      D   E
中序序位：D(1) → B(2) → E(3) → A(4) → C(5)
```

- **E**（叶子，两个指针原本都空着）：左指针改为指向**前驱 B**，右指针改为指向**后继 A**。
- **D**（叶子，且是中序第 1 个）：没有前驱可指，左指针保持空；右指针指向后继 B。
- **C**（叶子，且是中序最后一个）：没有后继可指，右指针保持空；左指针指向前驱 A。
- **B** 的两个孩子都在（左 D 右 E）：不加线索。
- （按哪种遍历建立线索就叫"X 序线索树"，考试默认说清是哪种。）

- 目的：不借助栈/递归也能按遍历序找前驱后继。
- 考法：判断"某节点在 X 序线索树中的前驱/后继指向谁"——先写出该遍历序，再按定义套即可。
- 加线索后为区分"指针指向孩子还是线索"，节点需多存两个标志位 ltag/rtag。

### 2.4 哈夫曼树与哈夫曼编码 ★★★（几乎年年考）

**它解决什么问题**：压缩。给文件里的字符分配二进制编码时，字符出现频率天差地别——`a` 可能出现 5000 次，`z` 只出现 3 次。如果每个字符都固定占 8 位，等于让"天天用的 a"和"几乎不用的 z"付一样的房租。**朴素想法**很自然：常用的给短码、少用的给长码，总位数就降下来了。但马上冒出新麻烦：码长不一，读的时候会切错位置。哈夫曼树就是那个"既让常用字拿到短码、又保证读起来不歧义"的标准答案。

#### 先认五个关键词（丢分多半丢在这几个名词上）

**① 路径长度**：从一个节点往下走到另一个节点，**经过的边数**（走一条边算 1）。根走到根，路径长度是 0。

**② 权（weight）**：贴在节点上的一个数字，表示它的"分量"。在哈夫曼编码里，权就是**该字符出现的次数（频率）**。

**③ 带权路径长度 WPL**：Σ（每个叶子的权 × 该叶子到根的路径长度）。两个限定必须记牢：**只算叶子**，**乘的是边数不是层次号**。

```
                        *            ← 根（内部节点，权 = 8 + 7 = 15）
                      /   \
                     (8)  *      ← 内部节点，权 = 5 + 2 = 7
                        /   \
                       (5) (2)

  三个叶子：(8) 路径长 1    (5) 路径长 2    (2) 路径长 2
  WPL = 8×1 + 5×2 + 2×2 = 8 + 10 + 4 = 22
```

图中带括号的 **(8)、(5)、(2) 是带权的叶子**，星号节点是合并出来的**内部节点**（它的权值等于两个孩子之和，只是算 WPL 时用不上）。最高频的失分点就在这儿：WPL 求和时**只挑叶子**，那些 7、15 写在那儿也不许乘路径长——用非叶节点求和是另一套算法（见后面结论 4），两套不能混着用。

**④ 哈夫曼树**：在所有"叶子权值恰好是给定这组数"的二叉树里，**WPL 最小的那一棵**（因此也叫最优二叉树）。

**⑤ 前缀码**：任何一个字符的编码，都不是另一个字符编码的**开头**。所有的二进制编码只要满足这条，就能从左往右一路读下去、不会切错。（为什么必须满足，后面有反例。）

#### 构造过程：拿权 {1, 2, 3, 4} 走一遍

规则一句话：**每轮从森林里挑权值最小的两棵树，合并成一棵新树（新根权值 = 两者之和），再放回森林。重复到只剩一棵。**

下面三张图里，**( ) 带括号的是原始叶子，裸写的数字是合并出来的内部节点**——权值撞车时（下面就会出现两个 3）靠这个区分。

```
时刻 0   森林 = { (1)  (2)  (3)  (4) }       ← 四棵单节点树，全是叶子

时刻 1   挑最小的两个（1 和 2）→ 合并，新根权 = 1 + 2 = 3

              3
             / \
           (1) (2)                          森林 = { 3, (3), (4) }

时刻 2   现在的数是 3、3、4 —— 最小的两个是"两个 3"（新 3 与原 3）

                6
              /   \
             3    (3)
            / \
          (1) (2)                           森林 = { 6, (4) }

时刻 3   只剩 4 和 6 → 合并，新根权 = 10，森林只剩一棵，结束

                  10
                /    \
               6     (4)
              / \
             3  (3)
            / \
          (1) (2)
```

**别踩这个坑**：时刻 2 森林里是 {3（刚合并的）, 3（原来的）, 4}，"最小的两个"是 **3 和 3**，不是 3 和 4。假如挑了 3 和 4，会合并出 7，森林变成 {3, 7}，时刻 3 再算 3 + 7 —— **结果还是 10，看起来"没差"**。但把它当哈夫曼树来算 WPL 就露馅了：

```
                    10
                 /      \
               (3)       7          ← 权 4 到了第 2 层，权 3 却还在第 1 层
                        /   \       ← （违反"权大离根近"，一眼就该起疑）
                      (4)   3
                           / \
                         (1) (2)

WPL = 3×1 + 4×2 + 1×3 + 2×3 = 3 + 8 + 3 + 6 = 20   （非叶节点和 = 3+7+10 = 20 ✓ 自洽）
```
**教训**：别拿"最后总数一不一样"当判据，**WPL 才是唯一判据**；用结论 4 自查一遍立刻就能发现。

#### 从树到编码：左 0 右 1

约定**左分支记 0、右分支记 1**（左右互换也合法，编码变了但码长不变）。从根出发，把走过的分支依次写下来，就是这个叶子的编码：

```
                  10            ← 根
                /    \
               6     (4)        ← (4) 在根的右边
              / \
             3  (3)             ← (3) 在 6 的右边：先左后右
            / \
          (1) (2)              ← 1、2 在"左、左"之后分道
```

| 叶子（权） | 从根走的路径 | 编码 | 码长 | 贡献位数 |
|---|---|---|---|---|
| 4 | 右 | `1` | 1 | 4×1 = 4 |
| 3 | 左 → 右 | `01` | 2 | 3×2 = 6 |
| 1 | 左 → 左 → 左 | `000` | 3 | 1×3 = 3 |
| 2 | 左 → 左 → 右 | `001` | 3 | 2×3 = 6 |

**WPL = 4×1 + 3×2 + 1×3 + 2×3 = 19**。
**第二种方法验算**：WPL = 所有**非叶节点**权值之和 = 3 + 6 + 10 = **19** ✓
**它的含义**：这 4 个字符一共出现 10 次（1+2+3+4），用这套编码只需要 19 位；定长编码 4 个字符要 2 位，同样 10 次要 20 位。只省 1 位——因为 {1,2,3,4} 这组权太均匀了，**权值越悬殊，哈夫曼的收益越大**。下一个例子正好演示这一点。

#### 再看一个"像真题"的例子：权 {5, 9, 12, 13, 16, 45}

6 个字符、频率悬殊，这是考题的典型长相。照规则走：

```
  5 + 9   = 14   →  森林 {12, 13, 14, 16, 45}
 12 + 13  = 25   →  森林 {14, 16, 25, 45}
 14 + 16  = 30   →  森林 {25, 30, 45}
 25 + 30  = 55   →  森林 {45, 55}
 45 + 55  = 100  →  只剩一棵，结束
```

最终树形（裸写数字＝节点权值，内部节点的值恒等于两个孩子之和）：

```
                    100
                 /       \
                45      55
                     /      \
                    25      30
                   /  \    /  \
                  12 13   14 16
                         /  \
                         5  9
```

按"左 0 右 1"读根到每个叶子的路径，得到编码表：

| 权（字符频率） | 编码 | 码长 | 贡献位数 |
|---|---|---|---|
| 45 | `0` | 1 | 45 |
| 12 | `100` | 3 | 36 |
| 13 | `101` | 3 | 39 |
| 16 | `111` | 3 | 48 |
| 5 | `1100` | 4 | 20 |
| 9 | `1101` | 4 | 36 |

**WPL = 45×1 + 12×3 + 13×3 + 16×3 + 5×4 + 9×4 = 45 + 36 + 39 + 48 + 20 + 36 = 224**
**验算**：非叶节点权值之和 = 14 + 25 + 30 + 55 + 100 = **224** ✓

两个值得记住的观察：
- **频率越大码越短**：45 只占 1 位，5 和 9 要 4 位。这就是"常用字付低房租"。
- **收益来自不均衡**：6 个字符定长要 3 位，100 次共 300 位；哈夫曼只用 224 位，省掉 25%。

#### 前缀码为什么必须满足，哈夫曼为什么天然满足

译码的方式是**从左往右一位一位读**，读到凑够某个字符的完整编码，就切一刀、认一个字。

**反例**：假设编码表是 `e=0、a=1、b=01、d=00`（随手定的、没有树在背后撑腰），收到一串 `0100`：
- 按 `e`(0) 切：剩下 `100` → 没有任何字符的编码是 `100`，**卡住译不下去**；
- 换个切法：`01`(b) + `00`(d) → 读出 `bd`。

同一串二进制读出两种结果，这就是**非前缀码**的歧义（`b=01` 以 `e=0` 开头，读的时候分不清 0 后面还有没有内容）。

哈夫曼树不会出这种事，因为**所有字符都挂在叶子上**，而"叶子"的定义就是**没有孩子、路到此为止**：

> **叶子 = 编码终点；中间节点不是字符，只是岔路口。**

从根走到一个叶子的路径，绝不可能恰好是通往另一个叶子的路径的开头——只要在中间某点就"认出字"了，那个点下面就不会再有路，它也就不是中间节点了。所以这一条反过来说明：**字符必须放在叶子上，不能放在中间节点**。

#### 四条必背结论（选择题原话考）

1. **n 个叶子的哈夫曼树，节点总数 = 2n − 1，且没有度为 1 的节点。**
   为什么：每轮合并都是"两棵并成一棵"，新造出来的节点必然有两个孩子 → 所有非叶节点的度都是 2，**不存在度为 1 的节点**。n 棵单节点树要合并 n−1 次，所以非叶节点共 n−1 个，总数 n + (n−1) = 2n−1。
2. **权越大的叶子离根越近**（路径长度越小）——这是每轮挑最小合并的顺序决定的。
3. **哈夫曼树不唯一，但 WPL 唯一。** 权值相同的叶子可以左右互换、并列最小的几组可以调换合并次序，长出来的形状可能不同，但最小总长是定死的。同理：**编码不唯一，但码长分布唯一**。考题问"编码是否唯一"答**不唯一**，问"WPL / 最短码长"答**唯一**，两者别混。
4. **WPL = 所有非叶节点权值之和**（自检神器：用叶子算一遍，再用非叶节点算一遍，两个数必须相等；不等就是合并过程挑错了数）。

#### 应试动作（手算四步，30 秒内）

1. **把权值抄成升序列表**——避免"最小两个"漏挑。
2. **合并 → 划掉两个 → 写下和 → 把和插回有序列表**，逐轮写清楚（草稿纸上一行一轮，别跳步）。
3. **树从最后一次合并往回拆着画**，不要一开始就凭空画树。
4. **求 WPL 用两种方法互验**：叶子求和法 ↔ 非叶节点求和法；两者不等就回第 2 步重查。

**补充一句读法**：有些教材把"第几层"和"路径长度"混着说——层次从 1 起算时，**路径长度 = 层次 − 1**。本讲义一律用"路径长度 = 边数"，根为 0。

### 2.5 平衡二叉树（AVL 树）★（低频，选择题偶尔 1 题）

**先把考频说清**：这一节不是重点。按考频编排的考前资料里，AVL 只剩**一句话定义**（"任一结点的左右子树高度之差不超过 1"），真题精选题库里也几乎不单独出它的题。所以别背过程，做到三件事就够：**认得出**一棵树是不是 AVL、**判得出**插入点该用哪种旋转、**记得住**最少节点数公式。真正要花时间的是 2.2 遍历和 2.4 哈夫曼。

**它解决什么问题**：二叉排序树的效率完全取决于树的形状——按 1、2、3、4、5 的顺序插入，树会退化成一条斜链，查找从 O(log₂n) 掉回 O(n)。AVL 的解法是给树加一条硬规矩：**任何节点左右子树的高度差不许超过 1**，插完发现违规就**旋转**修正，把最坏情况重新压回 O(log₂n)。（BST 本身的定义、插入删除、退化过程在第四节 4.4，那里讲得更细。）

**两个词必须先认识**：

- **AVL 树**：任意节点左右子树**高度差 ≤ 1** 的**二叉排序树**。两个条件都要满足——先得是 BST，再谈平衡。
- **平衡因子（BF）**：`BF = 左子树高度 − 右子树高度`，合法取值只有 **−1、0、+1** 三个。某个节点的 BF 一旦变成 ±2，这棵树就失衡了。（高度按**层数**算：只有一个节点的子树高 1，空子树高 0——这是教材算 BF 的通用口径。）

```
【是 AVL】每个节点的 BF 都落在 −1 ~ +1 内

        5
       / \
      3   8
     /   / \
    1   7   9

  BF(5) = 左高 2 − 右高 2 = 0        BF(3) = 1 − 0 = +1        BF(8) = 1 − 1 = 0
  1、7、9 是叶子（左右都空，0 − 0 = 0），BF 也都是 0    → 全部合法 ✓

【不是 AVL】节点 8 失衡

        8
       / \
      6   25
     / \
    4   7
   /
  2

  BF(8) = 左子树(6→4→2)高 3 − 右子树(25)高 1 = +2  → 越界 ✗
  （BF(6) = 2 − 1 = +1、BF(4) = 1 − 0 = +1 都合法；整棵树只要有一个节点越界，就不是 AVL）
```

**四种旋转怎么记**：LL、RR、LR、RL 的字母，第一个字母是**插入点相对失衡节点的位置**（L=左子树侧，R=右子树侧），第二个字母是再往里的方向。口诀：

- **LL 和 RR（同侧）**：做一次"反方向旋转"。LL（全在左边）→ **右旋**；RR（全在右边）→ **左旋**。想象三个节点排成一条直线，把中间那个提起来当根，树就转平了。
- **LR 和 RL（异侧）**：先对**中间两个节点**做一次旋转（变成 LL/RR），再按同侧规则转一次。口诀：**先局部再整体，转两次**。

```
【LL 型】插入点落在"左子树的左边" → 对失衡节点做一次右旋

变换前（插入 0 之后，节点 5 失衡）：

        5
       / \
      3   8
     /
    1
   /
  0

变换后（3 提上来当根，5 降为它的右孩子）：

        3
       / \
      1   5
     /     \
    0       8
```

```
【LR 型】插入点落在"左子树的右边" → 先左旋、再右旋（转两次）

变换前（插入 8 之后，节点 10 失衡）：

        10
       /  \
      5    15
     / \
    3   7
         \
          8

第一步：对 5 做左旋（7 提上来，5 降为它的左孩子）：

        10
       /  \
      7    15
     / \
    5   8
   /
  3

第二步：再对 10 做右旋（7 提上来当根，10 降为它的右孩子）：

        7
       / \
      5   10
     /   /  \
    3   8    15
```

**最少节点数**：高度为 h 的 AVL 树最少节点数 N(h) = N(h−1) + N(h−2) + 1（N(1)=1, N(2)=2）。

- **公式怎么来的**：要"节点最少"，根占 1 个；一棵子树塞满（高度 h−1），另一棵只求合法（高度只能是 h−2，差 1 是 AVL 的底线，再矮就失衡了）。所以 N(h) = 1 + N(h−1) + N(h−2)。
- **代入算例**：N(3)=N(2)+N(1)+1=2+1+1=4，N(4)=4+2+1=7，N(5)=7+4+1=12。考法："高度为 4 的 AVL 树最少有几个节点？" → 7。

**考试怎么问**：① 给几棵树问"哪个是 AVL"——数每个节点的 BF，越界的排除；② 给一棵插入后的失衡图问"应采用哪种旋转"——先找**离插入点最近的失衡节点**，再看插入点落在它的左子树侧还是右子树侧。旋转后的树形很少要求现场画，记住"谁当新根、哪棵子树改挂"就够了。

### 2.6 B 树与 B+ 树（每年 0–1 题，记住对比即可）

**考频先说清**：真题目库里几乎没有 B 树的独立题，按考频精炼的考前资料里干脆不提它。所以只做三件事：**知道它为什么存在**、**认得出两张结构图的区别**、**背下那张对比表**。阶数公式、插入分裂过程都不必背。

**它解决什么问题**：磁盘 I/O。二叉树查找要一层层往下走，**每下一层就是一次磁盘访问**——100 万条记录，二叉树高度约 20，最坏情况要读 20 次盘。把树"变胖"就解决了：一个节点塞几百个关键字、带几百个孩子，树高压到 3～4 层，磁盘只需读三四次。**B 树是被磁盘逼出来的结构，不是为内存设计的。**

**定义（m 阶 B 树）**："阶"就是一个节点**最多能有多少个孩子**。

- 每个节点最多 m 个孩子、m−1 个关键字；
- 除根外每个节点至少有 ⌈m/2⌉ 个孩子（根至少 2 个）；
- **所有叶子节点都在同一层**——这一条让它天然平衡，不需要旋转。

**结构图**：下面是 3 阶（每个节点最多 3 个孩子、2 个关键字）的两种树。两者的拓扑长得几乎一样，差别只在**数据放在哪、叶子连不连**：

```
【B 树】关键字和数据存在每一个节点里，查到哪一层就在哪一层返回

                  [ 8 |17 ]
              /       |       \
      [ 3 | 5 ]   [ 11|13 ]   [ 20|25 ]
```

```
【B+ 树】上层只做"路标"，数据全压在最后一层，且横向串成链表
（示意图，只强调"数据放在哪、叶子连不连"两点；节点的关键字个数与子树的严格对应关系软考不考）

                  [ 8 |17 ]                 ← 内部节点：只有索引，没有数据
              /       |       \
      [ 3 | 5 ]   [ 11|13 ]   [ 20|25 ]     ← 叶子节点：数据都在这儿
      +-----------+-----------+             ← 叶子串成链表，范围查询顺着扫
```

| 对比 | B 树 | B+ 树 |
|---|---|---|
| 数据存放 | 所有节点都存关键字和记录 | **只有叶子节点存记录**，内部节点只存索引 |
| 叶子节点 | 不链接 | **串成链表**，便于范围查询 |
| 查找路径 | 可能在半路就命中，长度不定 | **一定要走到叶子**，每次查找路径长度相同 |
| 用途 | 文件系统 | **数据库索引**（MySQL） |

**为什么数据库索引用 B+ 树不用 B 树**（两句就够）：

1. 内部节点不存数据 → 同样一个磁盘块能装下更多关键字 → 树更矮 → 磁盘访问次数更少；
2. 叶子串成链表 → "查 10 到 500 之间的记录"顺着链表扫一段就行，B 树得反复回到上层重新往下走。

**考试怎么问**：给两张图问"哪棵是 B+ 树"（看数据是不是全在最底层、叶子有没有连线）；问"B+ 树叶子节点的作用"（存全部数据 + 串成链表支持范围查询）；问"数据库为什么用 B+ 树"（上面那两句）。都不涉及算法，背表即可。
