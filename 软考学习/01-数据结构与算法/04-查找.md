# 01.4 查找 ★★

### 4.1 五种查找的定位（先看清各自的"前提条件"）

查找这件事的难点不在算法本身，而在**前提条件**：你手上是一张无序表还是有序表？是顺序存储还是链式存储？数据是静态的还是要频繁插入删除？条件不同，可选的算法完全不同，**软考最爱考的就是"哪个方法在这个条件下不能用"**。

| 查找方法 | 前提条件 | 平均时间 | 一句话 |
|---|---|---|---|
| **顺序查找** | 无要求（顺序/链式、有序/无序都行） | O(n) | 一个个比过去，最笨但最万能 |
| **二分查找** | **有序 + 顺序存储（数组）** | O(log₂n) | 每次砍一半 |
| **分块查找** | 块间有序、块内无序 | O(√n) 量级 | 先查索引再查块，二分与顺序的折中 |
| **二叉排序树** | 树是 BST | 平均 O(log₂n)，最坏 O(n) | 动态查找：插入删除都方便 |
| **散列表（Hash）** | 有哈希函数 | **O(1)**（理想） | 直接算出地址，不比较 |

**易错点（第一条就是送分题级别的）**：**链表不能做二分查找**。二分要靠下标跳到"中间元素"，而链表找中间元素只能从头走，砍一半的便宜立刻没了。所以"有序链表用二分查找做 O(log n) 查询"是错的。

### 4.2 顺序查找与二分查找

- **顺序查找**：从头到尾逐个比。无序表也能用（这是它唯一的优势）。等概率下查找成功的平均查找长度 **ASL = (n+1)/2**。
  - **公式推导**：如果目标在第 1、2、3、……、n 个位置，分别需要比较 1、2、3、……、n 次。这里的 `1、2、3、……、n` 是**等差数列**，因为相邻两项的差都为 1。等差数列前 n 项的和 =（首项 + 末项）× 项数 ÷ 2，所以比较次数总和为 `(1+n)×n÷2`。再除以 n 个等可能的位置：`ASL = [n(n+1)/2]÷n = (n+1)/2`。
  - **小例子**：n=5 时，5 个位置需要比较 `1、2、3、4、5` 次，平均为 `(1+2+3+4+5)÷5 = 15÷5 = 3` 次。注意，这个公式的前提是**查找成功，且每个元素被查到的概率相同**。
- **二分查找（折半查找）**：每次取中间元素比较，小就往左半区、大就往右半区，比较一次砍掉一半。**O(log₂n)**。
  - **★ 最多比较次数 = ⌈log₂(n+1)⌉**（等于判定树的深度）。n=15 → ⌈log₂16⌉ = **4 次**；n=1000 → ⌈log₂1001⌉ = **10 次**。
  - **判定树**：把"每次取中间元素"的过程画成树——第一层的中间元素做根，左右两半各自递归。**树有几层，最多就比较几次**。
  - **ASL（成功，等概率）≈ log₂(n+1) − 1**。
  - 二分查找的"找不到"也不难判：最后区间为空就是失败；"插入位置"就是最后落幕的那个下标（案例题的二分插入代码常挖这个空）。

**判定树长什么样（n=11 的例子）**：中间元素是第 6 个，它做根；左边 1～5、右边 7～11 各自再取中间，得到深度 4 的树，⌈log₂12⌉ = 4 ✓

```
            6
         /     \
        3        9
       / \      / \
      1   5    7   11
       \  /     \  /
        2 4     8 10
```

**应试动作**：看到"有序 + 顺序存储 + 求最多比较次数"，直接套 ⌈log₂(n+1)⌉；n 给 2^k−1（如 15、31、63）时答案就是 k，别自己算错。

### 4.3 分块查找（索引顺序查找）

**动机**：顺序查找太慢、二分查找又要求全体有序（维护成本高）。折中方案：把表分成若干块，**块间有序、块内无序**。

- 分块规则：第一块里所有元素都小于第二块里所有元素，第二块全小于第三块……**块内不要求有序**。
- 查找分两步：① 先在**索引表**（每个块的最大值和块起始位置，是有序的）里确定目标在哪块；② 再在**该块内顺序查找**。

结合上图记住三点：

- **索引表记两样：每块的「最大值」和「起始位置」**。最大值用来"决定去哪块"——从第一块最大值的随即往后比，一旦某块最大值 ≥ 目标，就进该块；小于则整块跳过，所以**不需要记最小值**（起点已由第一块兜住）。起始位置用来"真正定位"——确定目标块后靠它跳到块头再顺序走，二者缺一不可。
- **块间有序是前提，不是碰巧**：构造时每个元素已按值域归入该在的块（比 60 大的必进最大值 100 那块，绝不会躺进最大 60 的块2）。若真出现一个 96 混进块2，这套结构就已退化成无序表，不再适用分块查找，ASL 也退回 (n+1)/2 而非 √n+1。考题里凡叫"分块查找"的，前提必然成立，直接套公式。

- **总 ASL = 索引查找的 ASL + 块内查找的 ASL**。n 个元素分成 b 块、每块 s 个（b·s = n），两边都用顺序查找时：
  `ASL = (b+1)/2 + (s+1)/2 = (b+s+2)/2`
- **★ 最优块长 s = √n**（这样 b = s = √n 时 b+s 最小），此时 **ASL ≈ √n + 1**。
  - 代入算例：n=100 → 取 s=10、b=10 → ASL = (10+10+2)/2 = **11 = √100 + 1** ✓
  - n=100 若用顺序查找，ASL = (100+1)/2 = 50.5 → 分块把它降到 11，这就是分块的价值。

**应试动作**：认题特征——题干出现"索引表/块/分块"，或给一张"块内无序、块间有序"的表问平均查找长度。记两条：**总 ASL = 两步 ASL 相加**、**s=√n 时最优、ASL≈√n+1**。

### 4.4 二叉排序树（BST）★★——动态查找的答案

**要解决的问题**：顺序表插入删除要搬家（O(n)），链表查找要走路（O(n)）。有没有一种结构，**查找像二分那样快，插入删除又像链表那样便宜**？答案就是二叉排序树。

**定义（也叫二叉搜索树/BST）**：一棵二叉树，满足"**左子树上所有节点的值 < 根 < 右子树上所有节点的值**"，且左右子树各自也是二叉排序树。

**★ 最重要的一条性质**：**对二叉排序树做中序遍历，得到的序列是递增有序的**（因为它就是"左 < 根 < 右"）。考法：给一棵树问"中序序列是什么"（直接考），或"这棵树是不是 BST"（中序递增就是）。

**查找**：从根开始，目标比当前节点小就往左走、大就往右走——**一次比较砍掉一整棵子树**，同二分一个道理。

**插入**：按查找的路线一路走到 NULL，把新节点挂在那个空位置上（所以**新插入的节点一定是叶子**）。

**删除（三种情况，按树的形状分）**，设要删的节点为 p：
1. **p 是叶子**：直接摘掉。
2. **p 只有一个孩子**：让这个孩子直接顶替 p 的位置（整棵子树搬上去）。
3. **p 有两个孩子**：不能简单顶替（两个都得管）。做法是找一个"替身"来占 p 的位置——**中序前驱**（左子树里最大的那个，即左子树一路往右走到底）或**中序后继**（右子树里最小的那个），把它的值写到 p 上，然后**递归地去删除那个替身节点**（替身至多只有一个孩子，于是退回情况 1 或 2，好删）。

**完整演算一遍**（本例树后续还用来算 ASL）：

```
            45                    ← 根
          /    \
        24      53
       /  \        \
     12    37       93
```

- **删 12**（叶子）：直接摘掉，树变成 45 下左子树只剩 37 ✓
- **删 53**（只有一个孩子 93）：让 93 顶替 53，成为 45 的右孩子 ✓
- **删 24**（有两个孩子 12、37）：取**中序前驱**（左子树里最大）= **37**，把 37 写到 24 的位置，再去删原来的 37（它是叶子）。结果：
  ```
            45
          /    \
        37      53
       /           \
     12             93
  （若改用"中序后继"= 右子树最小，本例右子树只有 37 自己，结果相同；两者都对。）
  ```

**查找效率：完全取决于树的形状**（这是本节最常考的判断）：
- **最好的形状是平衡**（左右差不多高）→ 高度约 log₂n → 查找 O(log₂n)，和二分一样快。
- **最坏的形状是一条斜链**（每个节点只有一个孩子）→ 高度 n → 查找 O(n)，退化成一个链表。
- **什么时候会退化**：**按有序顺序依次插入**。例：依次插入 1、2、3、4、5，1 是根、2 挂右、3 再挂右……形成一条向右下斜的链，**找 5 要比较 5 次**。反例记住这一句话就够："**BST 最坏时可退化成单支树，查找退化为 O(n)**。"
- **ASL 算例**（用上面那棵 6 个节点的原始树，等概率）：各节点的比较次数 = 它所在的层数：
  45 第 1 层（1 次）、24 和 53 第 2 层（各 2 次）、12、37、93 第 3 层（各 3 次）
  → **ASL(成功) = (1 + 2 + 2 + 3 + 3 + 3) / 6 = 14/6 ≈ 2.33**
  **应试公式**：`ASL(成功) = 所有节点所在层数之和 / 节点总数`。本题就是 `(1 + 2 + 2 + 3 + 3 + 3) / 6`。层数从根开始按第 1 层计，**节点所在层数 = 查找该节点所需的比较次数**；因此做题时只要逐个数层数、求和、除以节点数即可。

**和平衡二叉树的关系**（联动第二节 2.5 平衡二叉树）：既然形状决定效率，那就**强制它平衡**——这就是 **AVL 树**（任意节点左右子树高度差 ≤ 1），插入失衡就旋转修正，把最坏情况从 O(n) 拉回 O(log₂n)。

**应试动作**：
- 认题特征："左小右大""中序递增""无序插入后建树"→ 立刻画树，千万别只在脑子里想。
- 必背三条：**中序递增**；**插入的节点必是叶子**；**删除有两个孩子的节点要用中序前驱/后继顶替**。
- 算 ASL：**数层数**求平均；问最好/最坏情况就答"平衡时 log₂n / 退化成单支时 n"。

**延伸阅读**：BST 的查找/插入/删除过程与配图见 [hello-algo · 二叉搜索树](https://www.hello-algo.com/chapter_tree/binary_search_tree/)（在线可看；离线不影响自足）。

### 4.5 散列表（Hash 表）★★（计算题大户）

**要解决的问题**：前面几种方法最快也要 O(log₂n)，因为它们都在"比较"。**能不能不比较？** 能——用哈希函数 `H(key)` 直接**算出**关键字该放的位置，一次到位，理想情况查找 O(1)。

**哈希函数怎么定**：最常用**除留余数法** `H(key) = key mod p`，其中 **p 通常取"不大于表长的最大素数"**（取素数能让余数分布更均匀）。例：表长 13 → p = 13；表长 12 → p = 11。

**冲突与同义词**：
- **冲突**：两个不同的关键字算出了同一个地址。
- **同义词**：`H(key)` 值相同的那些关键字（比如 9 和 17 在 `H=k mod 8` 下都是 1，它们就是同义词）。

**冲突处理方法**：

| 方法 | 做法 | 优缺点 |
|---|---|---|
| **线性探测**（开放定址） | 该位置被占了就往后挪一格、再挪一格……直到有空位 | 实现简单；**会产生"堆积（聚集）"**：连续被占的区间越来越长，**非同义词也被牵连**（见下面算例） |
| **平方探测**（开放定址） | 依次试 +1²、−1²、+2²、−2²…… | 缓解堆积，但可能漏掉空位 |
| **再散列（双散列）** | 冲突时换第二个哈希函数算新地址 | 分布更好，实现稍麻烦 |
| **链地址法** | 每个位置挂一条链表，冲突的节点都挂在同一链上 | **无堆积**（不同地址互不干扰）、**删除方便**；链表变长时可改成树 |
| 公共溢出区 | 冲突的一律丢进另一张表 | 了解即可 |

**★ 装填因子** `α = 表中元素个数 / 表长`。**α 越大冲突越多、ASL 越大**——散列表的查找效率取决于 **α**，而**不是表的绝对长度**（这句是原话考点：把表长从 100 改成 1000、元素数同比例变化时 ASL 基本不变）。

**★ ASL 一定要动手算**：`ASL(成功) = Σ(每个元素的比较次数) / 元素个数`。每个元素的比较次数 = **从它的哈希地址走到它的实际位置，一路上看了几个格子**。

**算例（同时演示"堆积怎么牵连别人"）**：表长 8，`H(key) = key mod 8`，依次插入 **9、17、25、3**。

| 关键字 | H(key) | 线性探测后的位置 | 比较次数 | 说明 |
|---|---|---|---|---|
| 9 | 1 | 1 | 1 | 一次命中 |
| 17 | 1 | 2 | 2 | 位置 1 被占，往后挪 |
| 25 | 1 | 3 | 3 | 位置 1、2 都被占 |
| **3** | **3** | **4** | **2** | **注意：3 本来该待在自己家 3 号位，但 25 占了它 → 被牵连到 4 号位** |

- 线性探测：**ASL(成功) = (1+2+3+2)/4 = 2**。
- 换**链地址法**：位置 1 挂链 `9→17→25`，位置 3 挂链 `3` → 各自的比较次数 1、2、3、**1** → **ASL = (1+2+3+1)/4 = 1.75**。
- **对比出的结论**：25 只是一次普通冲突，却把毫不相干的 3 号位置"占"了，害得 3 多比一次——**这就是堆积，链地址法没有这个问题**，因为每个地址各自成链、互不干扰。

**易错点**：
- 算 ASL 时**别把"哈希地址"当"存储位置"**，实际存放位置要按探测规则一步步推。
- 线性探测下"某元素查找成功需要比较 k+1 次"里的 k 是**它离自己哈希地址的格数**（隔 0 格就是 1 次）。
- 散列表的删除**不能直接抹掉**（线性探测下会截断别人的探测链），要用"墓碑标记"；链地址法没有这个烦恼——这也是"链地址法删除方便"的由来。

**延伸阅读**：四种冲突处理方式的实现与对比见 [hello-algo · 哈希冲突](https://www.hello-algo.com/chapter_hashing/hash_collision/)（在线可看；离线不影响自足）。

### 4.6 第四节小结与应试清单

| 考点 | 一句话抓手 |
|---|---|
| 顺序查找 | 万能但慢：ASL=(n+1)/2 |
| 二分查找 | **有序 + 顺序存储**；最多比较 ⌈log₂(n+1)⌉；**链表不能用** |
| 分块查找 | 两步 ASL 相加；s=√n 最优，ASL≈√n+1 |
| 二叉排序树 | 中序递增；插入必在叶子；删双孩子用中序前驱/后继顶替；ASL 数层数；最坏退化 O(n) |
| 散列表 | 除留余数法（p 取≤表长的最大素数）；线性探测有堆积、链地址无堆积；ASL 手算；效率看 α |

**跨课联动**：B 树/B+ 树（第二节 2.6 B 树与 B+ 树）是"磁盘上的多路平衡查找树"，数据库索引用它正是因为外存查找一次 I/O 代价高、要让树尽量矮——把本节"平衡 → O(log n)"的直觉套到磁盘上，这个考点就通了。
