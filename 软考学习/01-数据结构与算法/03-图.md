# 01.3 图 ★★★

### 3.0 先认图：从"一对一"到"多对多"

线性表是**一对一**（排队，前一个后一个），树是**一对多**（族谱，一个爸爸几个孩子），图是**多对多**——朋友圈里互相是好友、地铁站互相能到达、任务之间互相有依赖，都是"谁都可能认识谁"的关系。

图为什么值得单开一节：树里的"父子"关系规定了层级，所以只有前中后序那么几种走法；图里没有层级，任意两点都可能相连，于是"怎么存、怎么走、怎么找最优解"各自都变成了一类固定题型，也就是软考固定考的六块：**存储、遍历、最小生成树、最短路径、拓扑排序、关键路径**。

**一张图 = 一堆点 + 一堆线**，记作 `G = (V, E)`：V 是顶点（vertex）集合，E 是边（edge）集合。本课反复用下面这张图（叫它 **G1**，无向、无权、连通、带一个回路）：

```
        A ─── B
        │     │
        C ─── D ─── E

顶点 V = { A, B, C, D, E }              （5 个顶点）
边   E = { A-B, A-C, B-D, C-D, D-E }    （5 条边，无向边不写箭头）
```

肉眼验一下：A-B-D-C-A 这一圈首尾相接 → 图里有**回路**（这正是图与树的区别，树不允许有回路）。

**术语一次认全**（选择题直接考定义，下面这张表要能默写）：

| 术语 | 含义 | 用 G1 对照 |
|---|---|---|
| 无向图 / 有向图 | 边有没有方向。有向边写 A→B，A 是起点、B 是终点 | G1 是无向图 |
| 邻接 | 两点之间直接有边相连 | A 与 B 邻接；A 与 E 不邻接 |
| 度 | 一个顶点连着的边数 | D 的度 = 3（B-D、C-D、D-E） |
| 入度 / 出度 | 有向图专用：多少条边指向它 / 由它指出 | 无向图不分入度出度 |
| 路径 | 从一点走到另一点经过的边序列 | A-D-E 是 A 到 E 的一条路径 |
| 路径长度 | 无权图 = 路径上的**边数**；带权图 = 各边**权值之和** | A-D-E 长度为 2 |
| 回路（环） | 起点与终点相同的路径 | A-B-D-C-A 是 G1 的回路 |
| 连通图 | 图中**任意两点**之间都有路径 | G1 连通 |
| 连通分量 | 非连通图里"各自连成一片"的极大子图 | 见下面例子 |
| 完全图 | **任意两点之间都有边** | n 个顶点的无向完全图有 n(n−1)/2 条边 |
| 子图 | 从原图里挑一部分顶点和一部分边 | `A─B` + `D─E` 是 G1 的子图 |
| 生成树 | 含**全部 n 个顶点**、恰好 **n−1 条边**、无回路的子图 | 3.3 节详讲 |
| 网 | 每条边带权值的图（带权图），权可以是距离/费用/工期 | 3.3 节开始使用 |

**连通分量长什么样**——把「连通图」和「不连通图」并排看最清楚：

```
   连通图 G1（占满全图，只有 1 个分量）         不连通图（脱成 2 片）

        A ─── B                                    A ─── B        C ← 孤立点
        │     │                                    │     │
        C ─── D ─── E                              └──── D

   A、B、C、D、E 全部互相可达，          A、B、D 三点互相可达 → 连成一片，算 1 个分量
   连成一片，就是 1 个连通分量          C 谁也不连 → 它自己也算 1 个分量
   ⇒ 连通图 = 1 个连通分量            ⇒ 这张图共有 2 个分量，所以它「不是」连通图
```

**判别口诀**：**连通分量 = 数一数图被"断"成了几片**（孤立的一个点也算一片）。遍历时对每个未访问顶点各起一次遍历，起了几次就有几个连通分量（3.2 节会用到）。

**完全图长什么样**——完全图 = **任意两点之间都有直接连边**，不许"隔着别人绕路"。从 3 个点一路看到 5 个点：

```
   无向 K3：3 个点两两直接连 → C(3,2) = 3 条边
        A                       三条边 = AB、AC、BC
       / \                      每对点都有直连 ✓
      /   \
     B ─── C

   无向 K4：4 个点 → 四边形再加两条对角线 = 6 条边
        A ──── B
        │ \   / │      六条边 =
        │  \ /  │      四边形 AB、BC、CD、DA
        │   X   │      再补对角线 AC、BD
        │  / \  │      （图中 \ 与 / 交叉处 = 两对角线相交）
        │ /   \ │
        D ──── C

   无向 K5：5 个点两两全连，数一遍正好 10 条（= C(5,2)）
       A─B  A─C  A─D  A─E      每一行 = 一个点连到"它后面的所有点"
       B─C  B─D  B─E           相加 5+4+3+2+1 = 10
       C─D  C─E                一个点对都不漏，才是完全图 ✓
       D─E
```

**有向完全图** = 把上面每条无向边**拆成方向相反的两条**：A→B 与 B→A 是两条不同的边，所以数量正好翻倍——K3=6、K4=12、K5=20，一般地 `n(n−1)` 条。

**★ 边数公式（必背两条 + 一条反推）**：
1. **无向完全图**：`n(n−1)/2` 条边。n=5 → 5×4/2 = 10 条。
2. **有向完全图**：`n(n−1)` 条边（每对顶点两个方向的边都要有）。n=5 → 20 条。
3. 反推：无向图边数**最多** `n(n−1)/2`。边数接近这个上限 = **稠密图**；远小于上限 = **稀疏图**。这个判别直接决定 3.1 节用哪种存储（稠密用矩阵、稀疏用邻接表）。

**边数公式背后的原理：为什么无向要 ÷2？（组合 vs 排列）**——`n(n−1)/2` 和 `n(n−1)` 只差那个「÷2」，两者本质是同一个计数问题的两种数法：从 n 个点里选 2 个，**要不要分先后**。

先看通用公式（k 个一组）：

- **组合 C(n,k)**（从 n 个里「不分先后」选 k 个）：
  `C(n,k) = n! / (k!·(n−k)!)`
- **排列 P(n,k)**（从 n 个里「分先后」选 k 个）：
  `P(n,k) = n! / (n−k)!`
- 两者的桥：`P(n,k) = C(n,k) × k!`，也就是 `C(n,k) = P(n,k) / k!`。

代入 k = 2：

- **C(n,2) = n! / (2!·(n−2)!) = n(n−1) / 2**　→　n=5：5!/(2·3!) = 120/12 = 10 ✓
- **P(n,2) = n! / (n−2)! = n(n−1)**　→　n=5：5!/3! = 120/6 = 20 ✓

对回完全图：

| | 含义 | 该用哪个 | 边数 |
|---|---|---|---|
| 无向完全图 | 两点之间**只有 1 条边**，"来去"算同一条 | 组合 **C(n,2)**（不分先后） | `n(n−1)/2` |
| 有向完全图 | A→B 与 B→A 是**两条不同的边**，"选谁当起点"也算区别 | 排列 **P(n,2)**（分先后） | `n(n−1)` |

关键的一步：`P(n,2) = C(n,2) × 2!`，乘这个 `2! = 2`，正是无向公式里那个「÷2」的来历——无向把来、回两条折叠成一条，所以要除以 2。**口诀：无向 ÷2（不分来去）、有向不 ÷2（来去两条）**。

> 顺手钉死一个易混点：**C(n, n−1) 不等于 n(n−1)**。`C(n, n−1) = C(n, 1) = n`（"选 n−1 个"等价于"挑 1 个不要"，就 n 种）。完全图公式用的是 C(n,2)，不是 C(n, n−1)。

</details>

**★ 度数定理（每年都有它的题）**：无向图中**所有顶点的度数之和 = 2e**（e 是边数）。理由很朴素：一条边有两个端点，它给两头的度数各加 1。

- 用 G1 验算：度数 2+2+2+3+1 = **10**（A2、B2、C2、D3、E1），边数 5 → 10 = 2×5 ✓
- 反向用（这是常见考法）："某无向图有 10 个顶点、每个顶点的度都是 4，问边数" → 度数和 = 40 = 2e → **e = 20**。
- 推论（握手定理）：**度数为奇数的顶点个数必为偶数**。所以"给一组度数问能不能画出图"的题，第一步就数奇数度的点有几个——奇数个就直接不存在。
- 有向图版本：**入度总和 = 出度总和 = 边数**（每条边恰好贡献一个入度和一个出度）。

**易错点**：**连通 ≠ 完全**。连通要求"能走到"，完全要求"直接有边"。完全图一定是连通图；连通图不必是完全图（G1 连通，但 A 和 E 之间没有直连边，所以不是完全图）。题目常把这两句换着说法让你判对错。

### 3.1 存储结构：邻接矩阵 vs 邻接表

**要解决的问题**：图（点和线）怎么放进内存？两条路——**把所有"谁和谁相邻"记成一张表格（矩阵）**，或者**给每个顶点各挂一张"我的邻居"清单（链表）**。

#### 邻接矩阵：一张 n×n 的表

n 个顶点就开 n×n 的二维数组，`A[i][j] = 1` 表示顶点 i 到顶点 j 有边，`0` 表示无边。**G1 的邻接矩阵**（顶点顺序按 A、B、C、D、E）：

```
        A  B  C  D  E
   A [  0  1  1  0  0 ]     ← A 与 B、C 相邻
   B [  1  0  0  1  0 ]     ← B 与 A、D 相邻
   C [  1  0  0  1  0 ]     ← C 与 A、D 相邻
   D [  0  1  1  0  1 ]     ← D 与 B、C、E 相邻
   E [  0  0  0  1  0 ]     ← E 只与 D 相邻
```

读法：**第 i 行第 j 列为 1 ⇒ 顶点 i 与顶点 j 之间有边**。行号列号的对应关系靠"顶点顺序表"记着（这里第 1～5 行分别是 A～E）。

三个可以直接考的结论：
1. **无向图的矩阵一定对称**（A 与 B 有边 ⇔ B 与 A 有边），主对角线全是 0（自己跟自己不算相邻）。
2. **某一行上 1 的个数 = 该顶点的度**。D 那行有 3 个 1 → D 的度是 3 ✓ 这也是"数度"最快的算法。
3. 若把 1 换成边的权值 → 就是**带权图**的邻接矩阵（无边处记 ∞ 或 0，看题目约定）。

**有向图不对称，反例先说清**：若边是有向的，比如 A→B 存在、B→A 不存在，那么第 A 行 B 列为 1、第 B 行 A 列为 0 → 矩阵**不对称**。于是有这条判别：**矩阵不对称 ⇒ 一定是有向图；矩阵对称 ⇒ 可能是无向图，也可能是"有向图但两个方向恰好都有边"**（参考资料里的原话："不对称的矩阵一定是有向图，对称的矩阵可能是有向图"）。

**代价**：空间 O(n²)。G1 只有 5 条边却开了 25 格，浪费；顶点多时（如 1000 个顶点、10 条边）几乎全是 0，浪费更严重。优点是**查"两点是否相邻"是 O(1)**（直接看格子的值），以空间换时间。

#### 邻接表：每个顶点一条"邻居清单"

开一个一维数组存 n 个顶点，每个顶点后面挂一条链表，链表里存它的所有邻接顶点。**G1 的邻接表**：

```
   [0] A → B → C ∧
   [1] B → A → D ∧
   [2] C → A → D ∧
   [3] D → B → C → E ∧
   [4] E → D ∧
```

- 空间 **O(n+e)**：n 个顶点各一个表头 + 每条边在两头的链表中各出现一次（无向图），所以"边节点"总数 = 2e。G1：5 个表头 + 10 个边节点 = 15 个节点。
- **★ 固定考点（参考资料原话）**："有向图的邻接表有 **n+e** 个点，无向图的邻接表有 **n+2e** 个点。"有向图每条边只在一个链表里出现一次，所以是 n+e。**这个 n+e / n+2e 是选择题的固定考法。**
- 缺点是**判断两点是否相邻要从头扫链表**（O(度) 而不是 O(1)）。

#### 两种存储的正面对比（背下来）

| 对比项 | 邻接矩阵 | 邻接表 |
|---|---|---|
| 空间 | O(n²) | **O(n+e)** |
| 判断两点是否相邻 | **O(1)** | O(n)（要扫链表） |
| 适合的图 | **稠密图**（边接近 n(n−1)/2） | **稀疏图**（边很少） |
| 无向图存法 | 对称矩阵，存一份或两倍 | 每条边在两个链表各出现一次（2e） |
| 数的度数 | 扫一行 O(n) | 扫自己的链表 O(度) |
| 存带权图 | 矩阵元素直接放权值 | 链表节点多带一个权值字段 |

**手算口诀**：**稠密用矩阵、稀疏用邻接表；矩阵好查（O(1)）费空间，邻接表省空间查得慢。**

**还有两个"见过就行"的存储**（软考偶尔在选项里出现，知道名字和用途即可）：
- **十字链表**：有向图的邻接表改良版，一条边只存一次又能同时顺着"出边"和"入边"找，专门服务有向图求入度/出度。
- **邻接多重表**：无向图的邻接表改良版，同样让每条边只存一份（邻接表里无向边要存两次），便于**删除边**。

**应试动作**：
- 认题特征：题目给一个矩阵问"这是哪种存储/某顶点的度是多少/图是否连通"，就看**行内 1 的个数（度）**、**是否对称（无向）**。
- 背什么：`O(n²)` vs `O(n+e)`、`n+e` vs `n+2e`、无向完全图边数 `n(n−1)/2`、度数和 `= 2e`。
- 哪些靠算：给邻接表算某点的度、给矩阵算边数——都是"数 1"的活，别慌，慢慢数。

**延伸阅读**：矩阵/邻接表的增删边与顶点、效率对比表见 [hello-algo · 图的基础操作](https://www.hello-algo.com/chapter_graph/graph_operations/)（在线可看；离线不影响自足）。

### 3.2 遍历：DFS 与 BFS（选择题必有，案例题也用）

**要解决的问题**：从某个顶点出发，怎样把整张图**每个点恰好走一遍**？

树为什么不用操心这个？因为树没有回路，顺着走就能不重不漏。**图里有回路**（G1 里 A-B-D-C-A 就是一圈），走法不当就会原地转圈。所以图遍历比树遍历多了一个必需装备：**visited 标记数组**，走过的点打标记，遇到打过标记的点就跳过。**忘掉 visited 是本节最容易犯的错**（也是判断题里最爱设计的陷阱）。

两种走法，区别只在"优先照顾哪个方向的邻居"：

#### DFS（深度优先遍历，Depth-First Search）：一条路走到黑

策略：访问当前顶点 → 挑一个**还没访问过的邻居**钻进去 → 继续往下钻 → 直到某个顶点周围全是"已访问"，**回退**到上一个还有未访问邻居的顶点，继续钻。实现靠**栈**（递归写法用的就是系统栈）。

用 G1 从 A 出发（邻居按邻接表顺序取，字母小的先取）：

```
   G1 邻接表：  A→B→C   B→A→D   C→A→D   D→B→C→E   E→D
```

| 步 | 动作 | 栈（顶在右） | 已访问（输出序） |
|---|---|---|---|
| 1 | A 无路可退，先访问 A、压栈 | `A` | A |
| 2 | A 的第一个未访问邻居 B → 访问 B、压栈 | `A B` | A B |
| 3 | B 的第一个未访问邻居 D → 访问 D、压栈 | `A B D` | A B D |
| 4 | D 的第一个未访问邻居 C → 访问 C、压栈 | `A B D C` | A B D C |
| 5 | C 的邻居 A、D **都访问过了** → 无路可走，弹栈回退到 D | `A B D` | A B D C |
| 6 | 回到 D，找它下一个未访问邻居 E → 访问 E、压栈 | `A B D E` | A B D C **E** |
| 7 | E 的邻居 D 已访问 → 无路可走，连续弹栈回退到 A，栈空，结束 | （空） | A B D C E |

**DFS 序列：A B D C E**

两个必须看懂的细节：
- **第 5 步弹栈时 C 不再输出**。弹栈只是"退回去找别的路"，不是"重新访问"。C 只在第 4 步被输出一次。
- **回退的粒度是"顶点"不是"边"**：C 走不通，一次退到最近的一个"还有未访问邻居"的顶点（这里是 D），不是退一步就停。

#### BFS（广度优先遍历，Breadth-First Search）：一圈一圈往外扩

策略：先把起点的**所有邻居**访问完，再访问邻居的邻居……实现靠**队列**（先进先出，保证同层先来先服务）。

同样从 A 出发：

| 步 | 动作 | 队列（头在左） | 已访问（输出序） |
|---|---|---|---|
| 1 | A 入队 | `[A]` | |
| 2 | 出队并访问 A，把 A 的未访问邻居 B、C **入队** | `[B, C]` | A |
| 3 | 出队并访问 B，把 B 的未访问邻居 D 入队 | `[C, D]` | A B |
| 4 | 出队并访问 C，C 的邻居 A、D **都已访问/已在队** → 不入队 | `[D]` | A B C |
| 5 | 出队并访问 D，把 D 的未访问邻居 E 入队 | `[E]` | A B C D |
| 6 | 出队并访问 E，邻居 D 已访问 → 队空，结束 | `[]` | A B C D E |

**BFS 序列：A B C D E**

**★ BFS 的关键实现细节**：标记 visited 要在**入队的那一刻**就打，不能等出队。否则第 3 步 D 入队后，第 4 步处理 C 时看到 D 还没"被访问"（只是排队），会把 D **重复入队**。判断题常拿这里做考点。

为什么 D 会被重复入队？因为"等出队才打标"留出了**空窗期**：D 入队时没打标记，它还挂在队列里排队。等到出队 C、C 检查邻居 D 时，标记数组里查不到 D，就误以为 D 没见过，把第二个 D 塞了进去——队列从 `[C, D]` 变成 `[D, D]`，D 就被访问了两遍。一句话记死：**重复份数 = 出队前先被它邻居处理的次数；入队即打标，就是把重复份数固定成 1。**

#### 两者对比（这张表要能默写）

| | DFS 深度优先 | BFS 广度优先 |
|---|---|---|
| 走法 | 一条路走到黑，走不动才回退 | 一圈一圈向外扩 |
| 辅助结构 | **栈**（或递归） | **队列** |
| 树的对应 | 相当于树的**先根**（前序）遍历 | 相当于树的**层序**遍历 |
| 生活类比 | 走迷宫贴着墙一直走到底 | 水波从落水点向外扩散 |
| 遍历序列 | **不唯一**（邻居次序不同结果不同） | **不唯一** |
| 求**无权图**单源最短路径 | 不行 | **可以**：BFS 第一次到达某点时的层数就是最少边数 |
| 时间复杂度 | 邻接矩阵 O(n²)、邻接表 **O(n+e)** | 同左 |

**两个可以直接考的结论**：
1. **遍历序列不唯一**，因为"先钻哪个邻居"没有硬性规定。所以题目若给出**邻接表 + 起点 + 邻居顺序**，序列才是唯一的——题干一般都会强调"按邻接表顺序访问"。反过来，"下面哪个序列**不可能**是某个图的 DFS/BFS 序列"这类题，要靠"同层内任意、跨层有约束"去筛。
2. **复杂度只和存储结构有关，与 DFS/BFS 无关**：矩阵 O(n²)、邻接表 O(n+e)。记住这句原话，选择题很喜欢用它做选项。
3. **非连通图**一次遍历只能走完一个连通分量；要访问全部顶点，就得对每个未访问顶点各起一次遍历 → **调用遍历的次数 = 连通分量个数**。

**应试动作**：
- 认题特征：给一个图/邻接表问"从 V1 出发的 DFS 序列"，或给序列问"是否是 DFS 序列"。看到"深度/一条路走到黑"选 DFS（栈），看到"逐层/由近及远"选 BFS（队列）。
- 手算技巧：DFS 在草稿上**画出递归的走向箭头**（进去 →、回退 ←），比盯代码快；BFS 就老老实实画队列的进出。
- 背什么：栈 ↔ DFS、队列 ↔ BFS；无权图最短路径只能靠 BFS。

**延伸阅读**：BFS/DFS 的逐帧动画与实现代码见 [hello-algo · 图的遍历](https://www.hello-algo.com/chapter_graph/graph_traversal/)（在线可看；离线不影响自足）。

### 3.3 最小生成树：Prim 与 Kruskal

**要解决的问题**：n 座城市要铺通信线路，任意两城能互通即可（不要求直连），怎么铺**总造价最低**？

这个问题有两个隐含要求，正是"生成树"的定义：**要连通**（否则有的城市联系不上）、**要最省**（能连通 n 个点最少只要 n−1 条边，多铺一条都是浪费）——再不允许有回路（有回路就说明多铺了一条线）。

**生成树的四个特征**（说三个就能推出第四个）：含**全部 n 个顶点**、恰好 **n−1 条边**、**连通**、**无回路**。

**最小生成树（MST）**：带权图中"边权之和最小"的那棵生成树。
- **★ 权值和唯一，但树本身可能不唯一**：当图里有**权值相同的边**时，可选的方案不止一种，但最小权值和是唯一的。这句话选择题直接考。
- **找法思路**：不管哪种算法，都是**贪心**——每一步都挑当前最小的边，区别只在"从哪里开始挑"。

#### 先用一张图把两个算法都跑一遍（G2）

```
        A ──4── B
        │ ╲     │
        5   2   1
        │     ╲ │
        D ──3── C
        │
        4
        │
        E

   G2 的边（无向）：A-B 4、A-C 2、A-D 5、B-C 1、C-D 3、D-E 4        共 6 条边、5 个顶点
```

#### Kruskal（克鲁斯卡尔）：加边法——"把边按长短排队，短的先上，成环就跳过"

一步都不用画树，纯排序 + 查环：

| 步 | 候选边（从小到大） | 权 | 判断 | 是否选中 | 已选中的边 |
|---|---|---|---|---|---|
| 1 | B-C | 1 | 两端不连通 | ✔ | BC |
| 2 | A-C | 2 | 不连通（A 还是孤点） | ✔ | BC、AC |
| 3 | C-D | 3 | 不连通（D 还是孤点） | ✔ | BC、AC、CD |
| 4 | **A-B** | 4 | A、B **已经连通**（A-C-B）→ 选了会成环 | ✘ 跳过 | — |
| 5 | D-E | 4 | 不连通（E 还是孤点） | ✔ | BC、AC、CD、DE |
| — | A-D 5 | 5 | 已连满 4 条边（n−1=4），结束 | — | — |

**结果**：MST = {BC 1, AC 2, CD 3, DE 4}，**权值和 = 1+2+3+4 = 10**，4 条边 = n−1 ✓，无回路 ✓，覆盖 A～E ✓

**反例前置（最容易错的一步）**：第 4 步 A-B 权 4 比 D-E 的 4 一样小，看着都该选——但 A 和 B 此时已经通过 A-C-B 连通了，加上 A-B 就形成回路 A-B-C-A，而生成树**不许有回路**，所以必须**跳过**。很多同学"见小的就选"，就错在这一步。Kruskal 唯一要动脑的地方就是**查环**：只要一条边的两个端点已经连通，就跳过。

#### Prim（普里姆）：加点法——"从一棵树苗开始，每次接一个最近的顶点进来"

Prim 不排序边，而是维护一个"已经长成的树"的顶点集合 S：

| 步 | 已选顶点集合 S | 从 S 连到**集合外**的所有边 | 最短的 | 接进来的点 |
|---|---|---|---|---|
| 起始 | {A} | A-B 4、A-C 2、A-D 5 | A-C 2 | C |
| 2 | {A, C} | A-B 4、A-D 5、C-B 1、C-D 3 | C-B 1 | B |
| 3 | {A, C, B} | A-D 5、C-D 3 | C-D 3 | D |
| 4 | {A, C, B, D} | D-E 4 | D-E 4 | E（点全到齐，结束） |

**结果**：选中的边 = {AC 2, CB 1, CD 3, DE 4}，**权值和 = 10** —— 与 Kruskal 完全一致 ✓

> **这正是一次"用第二种方法反向验证"**：两个算法的思路差得远（一个加边一个加点），却给出同一个权值和 10，说明算对了。考场上若时间允许，用另一个算法复核，比反复验算同一条路更可靠。

**易错点**：Prim 第 2 步"从 S 连到集合外的边"要**包括 S 里所有点**发出的边（A-B 4 和 C-B 1 都要列出来），只盯新接进来的 C 会漏掉 A-B，可能选错。**Prim 是"整个集合对外的最短边"，不是"新点的最短边"**。

#### 两个算法的分工（常考"选哪个算法"）

| | Prim（普里姆） | Kruskal（克鲁斯卡尔） |
|---|---|---|
| 思路 | **加点**：每次把离树最近的**顶点**接进来 | **加边**：每次取全图最短的**边**，成环则跳过 |
| 复杂度关键 | 与**顶点数** n 有关（传统实现 O(n²)） | 与**边数** e 有关（排序 O(e·log e)） |
| 更适合 | **稠密图**（边多，n 小） | **稀疏图**（边少） |
| 手算感觉 | 围着"已选集合"一圈一圈找最近的点 | 把边排成一队，从上往下捡 |

**手算口诀**：**Prim 加点（对外找最短）、Kruskal 加边（排队捡短的、成环丢掉）；稠密 Prim、稀疏 Kruskal。**

**应试动作**：
- 认题特征："求最小生成树/最省造价线路" → 立即边列表排序（Kruskal）或标出已选集合（Prim）。
- 必查三件事：**边的条数 = n−1**、**无回路**、**覆盖所有顶点**。三件都过才算做完（这也是自检口径）。
- 背什么：MST 权值和唯一、树可能不唯一；Prim 稠密、Kruskal 稀疏。
- 哪些靠算：给图算 MST 权值和——必须动手画一遍，光看不能得出答案。

**延伸阅读**：也有用"优先队列"实现 Prim/Kruskal 的写法，若想看代码可查 [hello-algo · 图的基础操作](https://www.hello-algo.com/chapter_graph/graph_operations/)（软考只考手算，不考代码）。

### 3.4 最短路径：BFS（无权）与 Dijkstra（带权）

**要解决的问题**：从一点到另一点怎么走最近？注意分两种"近"：
- **无权图**：边没有权值，"近"= **经过的边数最少** → 用 **BFS**（3.2 已述：BFS 第一次到达某点时的层数就是最少边数）。
- **带权图（网）**：边上带距离/花费/时间，"近"= **权值之和最小** → 用 **Dijkstra（迪杰斯特拉）**。

#### Dijkstra 的思路：贪心，每轮"认定"一个点

一句话：**每轮从"还没确定的点"里挑出当前距离最小的那个，宣布它的最短距离已定，然后用它去更新（松弛）所有邻居的距离。**

- "松弛"（relax）= 试着用新确定的点做中转：`若 起点的距离 + 这条边的权 < 邻居原来的距离，就改小它`。**"松弛"这个词会出现在题干里，要知道它就是"试一试能不能更短"**。
- 直觉：既然所有边权都是正的，那么**当前离起点最近的那个点**，不可能再有别的更短路线绕到它（绕路只会花更多）——所以可以放心"认定"。这就是贪心法的立足点。

#### 完整演算一遍（G3，有向网，源点 V1）

```
   顶点从左到右排：V1  V2  V3  V4  V5       所有箭头一律只能「从左指向右」（无环）

   V1 ══4══▶ V2 ══1══▶ V3 ══5══▶ V4 ══2══▶ V5      ← 主干链
   V1 ══6══▶ V3                                     ← 跨一格
   V2 ══7══▶ V4                                     ← 跨一格
   V3 ══9══▶ V5                                     ← 跨一格
```

初始化：`d(V1)=0`（起点到自己），有直接边的先写上权值，其余记 ∞。
即 **d(V2)=4、d(V3)=6、d(V4)=∞、d(V5)=∞**。已确定的集合 S = {V1}。

| 轮 | 未确定的点及其当前距离 | 本轮认定（距离最小者） | 松弛动作 | 松弛后的距离 |
|---|---|---|---|---|
| 1 | V2=4、V3=6、V4=∞、V5=∞ | **V2（4）** | V2→V3：4+1=5 < 6 → 改小；V2→V4：4+7=11 < ∞ → 写上 | d(V3)=**5**、d(V4)=**11** |
| 2 | V3=5、V4=11、V5=∞ | **V3（5）** | V3→V4：5+5=10 < 11 → 改小；V3→V5：5+9=14 < ∞ → 写上 | d(V4)=**10**、d(V5)=**14** |
| 3 | V4=10、V5=14 | **V4（10）** | V4→V5：10+2=12 < 14 → 改小 | d(V5)=**12** |
| 4 | V5=12 | **V5（12）** | 没有出边，结束 | — |

**最终结果：d(V1)=0、d(V2)=4、d(V3)=5、d(V4)=10、d(V5)=12。**
V1 到 V5 的最短路径 = **V1→V2→V3→V4→V5**，长度 **4+1+5+2 = 12**。

**反向验算**（必须做）：V1 到 V5 的其他可能路线：
- V1→V2→V4→V5 = 4+7+2 = 13 > 12 ✗
- V1→V3→V4→V5 = 6+5+2 = 13 > 12 ✗
- V1→V3→V5 = 6+9 = 15 ✗
所以 12 确实是最小的 ✓

**这一轮最值得看的是 V3**：V1 到 V3 明明有直达边权 6，但第 1 轮经 V2 中转只需 4+1 = 5，于是 d(V3) 从 6 被改小成 5。**这就是"松弛"的价值，也说明了为什么每轮都要重新挑最小**——不能一开始就把"直达边的权值"当成最终答案。

#### 两个固定考点

1. **Dijkstra 不能处理负权边**（选择题几乎年年出）。
   反例（就三个点，一眼看懂）：
   ```
   V1 ══1══▶ V2        V1 ══2══▶ V3        V3 ══(−2)══▶ V2
   ```
   真实最短路径：V1→V3→V2 = 2 + (−2) = **0**。
   但 Dijkstra 第 1 轮会挑中 V2（d=1）并**宣布它已确定**；第 2 轮才处理 V3，发现 V1→V3→V2 只要 0，比已宣布的 1 更小——算法却不会再回头改。**负权边破坏了"当前最近的点不可能被绕路超越"这个贪心前提**，所以 Dijkstra 失效。
2. **Floyd（弗洛伊德）求"多源"最短路径**：一次算出**任意两点之间**的最短路径（Dijkstra 是单源：只算一个源点到其他所有点）。Floyd 是**动态规划**思想，三重循环实现；它可以处理负权边，但同样不能处理**负权回路**。
   **记法**：**单源 Dijkstra（贪心）、多源 Floyd（动态规划）**。这句对照几乎每年以选项形式出现。

**应试动作**：
- 认题特征：给带权有向/无向图问"源点到各点的最短距离""哪条是最短路径" → Dijkstra 表格法（画一列表格逐轮填）。
- 手算纪律：**每轮必须重新扫描所有未确定的点选最小**，别凭直觉跳步；每轮松弛完把距离写清楚，便于回查。
- 背什么：Dijkstra 是贪心、不能负权；Floyd 是多源、可负权不能负环；无权图最短路用 BFS。
- 哪些靠算：具体的最短距离与路径必须自己算一遍（本例 12），光看答案记不住。

### 3.5 拓扑排序（AOV 网）

**要解决的问题**：做事情有先后依赖——"先打地基才能砌墙""先修课程 A 才能修课程 B"。怎么把一堆有依赖关系的活动排成一个合法的执行顺序？

**AOV 网**：**顶点表示活动，有向边表示活动之间的先后约束**（A→B 表示 A 必须排在 B 前面）。要求这张有向图**没有回路**（有回路意味着"A 要在 B 前、B 又要 A 在 A 前"，矛盾）——没有回路的有向图叫 **DAG（有向无环图）**。

**拓扑排序**：把 AOV 网的所有顶点排成一个线性序列，使得**每条边都从序列的前面指向后面**（若图中有 Vi→Vj 的路径，序列里 Vi 必须排在 Vj 之前）。

#### 做法：反复挑"入度为 0"的点

**入度为 0 = 没有任何前置活动**——这种活现在就能干。步骤：

1. 找一个入度为 0 的顶点，输出它；
2. **删除**它的所有出边（相当于"这件活干完了，它解锁了后面的活"）；
3. 重复 1～2，直到所有顶点都输出（或发现没有入度为 0 的点 → 说明有环，排序失败）。

演算一遍（AOV：A→B、A→C、B→D、C→D、D→E）：

```
   A ──→ B ──┐
   │         ↓
   └──→ C ──→ D ──→ E

   各点入度：A 0、B 1、C 1、D 2、E 1
```

| 步 | 当前所有入度为 0 的点 | 本轮输出（任选一个） | 删除它的出边后，入度变化 |
|---|---|---|---|
| 1 | A | **A** | 删 A→B、A→C → B 变 0、C 变 0 |
| 2 | B、C | **B**（也可先输出 C） | 删 B→D → D 从 2 变 1 |
| 3 | C | **C** | 删 C→D → D 从 1 变 0 |
| 4 | D | **D** | 删 D→E → E 从 1 变 0 |
| 5 | E | **E** | 无出边，结束 |

得到一个合法拓扑序列：**A B C D E**（另一个是 A C B D E，**只有这两种**：A 必须第一、E 必须最后、B 与 C 之间无约束可互换、D 必须夹在 B、C 之后和 E 之前）。

#### 三条结论（选择题原话考）

1. **拓扑序列不唯一**：没有先后约束的点之间可以任意换位置。
2. **图中有环 → 拓扑排序做不下去**（会出现"所有剩下的点入度都 ≥ 1"的死局）。工程上正用它来**检测循环依赖**（比如 Makefile/编译系统报"circular dependency"）。
3. **深度优先遍历的逆序也是一种合法的拓扑序列**。道理：DFS 退出的时刻，某个点后面能到达的点都已经先退出了，所以把"退出顺序"倒过来看，就是"被依赖的排后面"→ 正好满足拓扑序。（顺带记住另一条：**逆拓扑排序**是每次取出度为 0 的点输出并删除其所有入边。）

**易错点**：
- 拓扑排序只关心**入度**（谁没有被依赖），别看去度去。判"是否能完成拓扑排序"用入度法最稳。
- 拓扑排序**不是**排序算法（不比较大小），它只解决"先后约束"，和第五节那些排序是两码事。
- 题干给的"先后关系"要转成边的方向：**"A 必须在 B 之前完成" ⇒ 边 A→B**（从"前"指向"后"），画反了整题就反了。

**应试动作**：
- 认题特征：题目出现"先后顺序/前置任务/课程安排/能否完成"，或直接问"下列哪个是合法拓扑序列"。
- 判别"某个序列是否合法"的最快方法：**对着题图的每条边检查一次**"起点是否排在终点前面"，有一条不满足就非法。（一句话口诀："图中 A→B，序列中 A 在 B 前面；A 和 B 没有关系，序列中 A 可前可后。"）
- 背什么：入度法三步；有环则无拓扑序；DFS 逆序可行。

### 3.6 关键路径（AOE 网）★★★（计算题大户）

**要解决的问题**：整个工程**最快多久能完工**？哪些活动**一天都不能拖**（拖了就拖累整体工期）、哪些活动**可以摸鱼**（拖几天不影响总工期）？

**AOE 网**：**边表示活动**（边权 = 活动工期），**顶点表示事件**（事件的"发生"= 它所有前置活动都已完成的状态）。
- **源点**：入度为 0 的顶点，代表工程开始；**汇点**：出度为 0 的顶点，代表工程结束。
- 与 AOV 网的区别一句话：**AOV 边只表示先后（顶点是活动），AOE 边既表示先后又带工期（边是活动）**。AOV 用来排顺序，AOE 用来算工期。

**★ 关键路径 = 从源点到汇点的最长路径**，它的长度 = **整个工程的最短工期**。

**"最长"为什么反而是"最短工期"**（这是本节的"动机"，理解了才不别扭）：汇点要"发生"，它前面所有的活动都得干完；而最长的那条链上一个活动都省不掉，工期**不可能**比它短。同时，按这条最长链去安排进度，其余活动都能塞进这个时间窗内完成，所以这个时间**刚好够**。上下夹住，于是最长路径长度 = 最短完工时间。

**四个量、两趟推**（每个事件一个 ve/vl，每个活动一个 e/l）：

| 量 | 含义 | 怎么算 |
|---|---|---|
| **ve(v)** 事件最早发生时间 | 这个事件最早什么时候能发生 | 源点 ve(源)=0；**顺推取 max**：ve(v) = max 所有入边 { ve(前驱) + 该活动工期 } |
| **vl(v)** 事件最迟发生时间 | 这个事件最晚什么时候发生还不拖累工期 | 汇点 vl(汇)=ve(汇)；**逆推取 min**：vl(v) = min 所有出边 { vl(后继) − 该活动工期 } |
| **e(a)** 活动最早开始时间 | 起点事件一发生它就能开工 | e(a) = **起点**的 ve |
| **l(a)** 活动最迟开始时间 | 再晚开工就拖累工期 | l(a) = **终点**的 vl − 该活动工期 |

**★ 时间余量（松弛时间）= l(a) − e(a)**，**余量为 0 的活动就是关键活动**，把它们连起来就是关键路径。

#### 完整算一遍（G4，6 个事件、7 个活动）

```
       a1=3                 a3=2
  V1 ────────▶ V2 ───────────────▶ V4 ─────a6=2────▶ V6
   │                                ▲                 ▲
   │ a2=2                           │ a4=4            │
   └─────────▶ V3 ──────────────────┘                 │
               │                                      │
               │ a5=3                                 │
               └─────────▶ V5 ───────a7=1─────────────┘

  事件（顶点）：V1 源点、V6 汇点
  活动（边）：a1 V1→V2 =3   a2 V1→V3 =2   a3 V2→V4 =2   a4 V3→V4 =4
              a5 V3→V5 =3   a6 V4→V6 =2   a7 V5→V6 =1
```

**第一趟：顺推求 ve（取 max）**

| 事件 | 谁指向它 | 计算 | ve |
|---|---|---|---|
| V1（源点） | — | 规定为 0 | **0** |
| V2 | V1(a1=3) | 0+3 | **3** |
| V3 | V1(a2=2) | 0+2 | **2** |
| V4 | V2(a3=2)、V3(a4=4) | max(3+2=5, 2+4=6) | **6** |
| V5 | V3(a5=3) | 2+3 | **5** |
| V6（汇点） | V4(a6=2)、V5(a7=1) | max(6+2=**8**, 5+1=6) | **8** |

→ **总工期 = ve(V6) = 8**。注意 V4 那步必须把所有入边都算上取最大（只用一条会算成 5，这是最常见的错）。

**第二趟：逆推求 vl（取 min）**

| 事件 | 它指向谁 | 计算 | vl |
|---|---|---|---|
| V6（汇点） | — | 与 ve 相同 = 8 | **8** |
| V5 | V6(a7=1) | 8−1 | **7** |
| V4 | V6(a6=2) | 8−2 | **6** |
| V3 | V4(a4=4)、V5(a5=3) | min(6−4=2, 7−3=4) | **2** |
| V2 | V4(a3=2) | 6−2 | **4** |
| V1（源点） | V2(a1=3)、V3(a2=2) | min(4−3=1, 2−2=**0**) | **0** |

（自检：源点逆推出来必须是 0，不是 0 说明前面算错了。）

**第三趟：算每个活动的 e、l、余量**

| 活动 | 起点 ve（=e） | 终点 vl − 工期（=l） | 余量 l−e | 是否关键 |
|---|---|---|---|---|
| a1 V1→V2 =3 | 0 | 4−3 = 1 | **1** | 否 |
| a2 V1→V3 =2 | 0 | 2−2 = 0 | **0** | **★ 是** |
| a3 V2→V4 =2 | 3 | 6−2 = 4 | **1** | 否 |
| a4 V3→V4 =4 | 2 | 6−4 = 2 | **0** | **★ 是** |
| a5 V3→V5 =3 | 2 | 7−3 = 4 | **2** | 否 |
| a6 V4→V6 =2 | 6 | 8−2 = 6 | **0** | **★ 是** |
| a7 V5→V6 =1 | 5 | 8−1 = 7 | **2** | 否 |

**关键路径：V1 → V3 → V4 → V6，长度 = 2+4+2 = 8**，与 ve(V6) 一致 ✓

**反向验算（必做）**：从源点到汇点的其他所有路线都不许超过 8——
- V1→V2→V4→V6 = 3+2+2 = **7** < 8 ✓
- V1→V3→V5→V6 = 2+3+1 = **6** < 8 ✓
只有 V1→V3→V4→V6 达到 8，所以关键路径唯一 ✓（关键活动 a2、a4、a6 首尾相接，恰好构成一条从源点到汇点的完整通路，这也是自检口径。）

#### 三条必考结论

1. **关键路径可能不止一条**。多条关键路径时，**所有关键活动都长在关键路径上，但某条关键路径上的活动未必在另一条上**，于是有了结论 2。
2. **缩短工期必须压缩"所有关键路径的公共关键活动"**。只压缩某一条关键路径上的活动，另一条关键路径长度不变，总工期纹丝不动。
   - 用本例看：a1 有余量 1，压缩它（哪怕压到 0）工期仍是 8；压 a6 才有用。
3. **关键路径可能因"压过头"而转移**：把某条关键路径压到比另一条短，最长路径就换人了，工期不再继续缩短——所以"压关键活动一定能缩短工期"这句话只在"压公共活动且没压过头"的前提下成立。选择题里"缩短任一关键活动都能缩短工期"是**错的**（见课后题 15）。

**易错点清单**：
- 顺推**取 max**、逆推**取 min**，别记反（顺推是"要等所有前置做完才能开始"，所以取最大；逆推是"必须给所有后续留够时间"，所以取最小）。
- l(a) = **终点**的 vl **减**工期。写成"起点的 vl"或"加工期"都错。
- ve 和 vl 是**事件**（顶点）的量，e 和 l 是**活动**（边）的量，两张表别混。
- 时间余量为 0 **才**是关键活动（余量不为 0 的活动还有缓冲）。

**应试动作**：
- 认题特征：题干出现"AOE 网/工期/最早发生/最迟开始/时间余量" → 立刻画两张表（ve 表、vl 表），再列活动表算 e、l、余量。
- 手算纪律：每张表算完做一次自检——**ve(源)=0、vl(源)=0、vl(汇)=ve(汇)、关键活动首尾相接构成一条源→汇通路**，四条全过基本就没算错。
- 背什么：四个量的定义与"顺 max 逆 min"、余量 0 即关键、"压缩要压公共关键活动"。
- 哪些靠算：任何一道关键路径题都必须动手列表，凭直觉猜最长路径在 4 个以上的活动时几乎必错。

**跨课联动**：软件工程部分（[03-软件工程基础.md](03-软件工程基础.md)）里的甘特图、项目工期、总时差（松弛时间）与本节是同一套东西，只是那边用 ES/EF/LS/LF 的记号表示，本质完全一致——**在这里算熟，那边直接得分**。

### 3.7 第三节小结：六块内容的"一句话抓手"

| 内容 | 一句话抓手 | 最常考的判别点 |
|---|---|---|
| 图的术语与边数 | 无向完全图 n(n−1)/2 条边；度数和 = 2e | 连通 vs 完全；度数和必为偶数 |
| 存储 | 稠密用矩阵 O(n²)、稀疏用邻接表 O(n+e) | 有向 n+e 个点、无向 n+2e 个点；无向矩阵对称 |
| 遍历 | DFS 用栈一条路走到黑；BFS 用队列一圈圈扩 | 序列不唯一；复杂度只看存储；无权最短路只能用 BFS |
| 最小生成树 | Prim 加点（对外找最短）、Kruskal 加边（排队捡短的、成环丢掉） | 边数 n−1；权值和唯一、树可能不唯一；Prim 稠密 / Kruskal 稀疏 |
| 最短路径 | 单源 Dijkstra（贪心、不能负权）；多源 Floyd（动态规划） | 松弛要重挑最小；负权失效的三个点反例 |
| 拓扑排序 | 反复取入度 0 的点，删它的出边 | 序列不唯一；有环则失败（用来查循环依赖）；DFS 逆序也合法 |
| 关键路径 | 最长路径 = 最短工期；余量 0 即关键 | 顺 max 逆 min；压缩要压公共关键活动 |

**案例题里图怎么考**（与第七节「案例题专攻」联动）：算法填空题常给**邻接矩阵的遍历**（两层 for 扫矩阵）或**BFS 队列式最短路**（入队/出队 + 距离数组）的代码挖空。填这类空的抓手就是本节的三句话：**"矩阵是两层循环扫 n×n""BFS 用队列、入队时标记 visited""Dijkstra 每轮找当前最小并松弛邻居"**。
