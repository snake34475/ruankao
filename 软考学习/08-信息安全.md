# 08 信息安全

> **分值地位**：选择题约 3–4 题（第二梯队稳定得分点）。本课不对应独立案例大题，但「数字签名流程（谁用谁的私钥/公钥）」是**永恒考点**，几乎隔年必考一题；对称与非对称加密的区分、主动/被动攻击分类、防火墙功能边界也是反复出现的旧题翻新，套路极固定，练熟就是纯送分。
>
> **学习目标**：读完讲义后，你能——① 一眼把 DES/AES/RSA 归进对称/非对称阵营；② 分清「公钥加密（保密）」与「私钥签名（认证）」两个方向，独立写出"既要保密又要签名"的完整通信流程；③ 说清数字证书是干什么的、验证证书用谁的公钥；④ 给攻击场景归类（重放/SQL 注入/DDoS/钓鱼…）并背下防火墙"能管什么、管不了什么"。

## 第一节 安全的目标与攻击分类 ★★

**动机**：先想清楚"安全"到底要保住什么，后面每个技术（加密、签名、防火墙）才能对号入座——**每个安全技术都是为了守住某一条安全属性而生的**。

### 1.1 五大安全属性

| 属性 | 含义 | 一句话理解 | 被谁破坏 |
|---|---|---|---|
| **机密性** | 信息不泄露给未授权者 | 偷看不得 | 截获/窃听 |
| **完整性** | 信息不被未授权篡改 | 改动不得 | 篡改 |
| **可用性** | 授权用户要用时能用 | 想用就能用 | 中断（如 DoS） |
| **不可否认性** | 发过的话不能赖账 | 赖账不得 | 伪造/抵赖 |
| **可控性** | 对信息传播与内容具有控制能力 | 流传范围可控 | 越权传播 |

选择题最爱的配对：**截获→机密性；篡改→完整性；中断→可用性；伪造→真实性/不可否认性**。记法："看（截获）改（篡改）断（中断）造（伪造）"对"密完可用真"。

### 1.2 主动攻击 vs 被动攻击 ★★★

这是历年真题反复考的二分类，判别标准只有一条：**是否修改/破坏了系统中的数据和资源**。

| 类别 | 特征 | 包含的攻击 |
|---|---|---|
| **被动攻击** | 只**偷看**，不改数据，难察觉 | **窃听**（网络监听、搭线）、**流量分析**（不看内容只分析通信的模式、频率、流向） |
| **主动攻击** | **动手改**数据或破坏系统 | **篡改**、**伪造**、**伪装**（冒充他人）、**重放**、**拒绝服务 DoS / 分布式拒绝服务 DDoS** |

**反例演示**（最容易错的一道）：「流量分析」听起来很"主动"（在主动分析嘛），但它**只观察通信模式、不修改任何数据**，属于**被动攻击**。真题就爱把它混进"主动攻击"选项里。反向陷阱：「拒绝服务」听起来只是"让服务慢一点"，但它**主动发起请求洪流破坏可用性**，属于主动攻击。

**应试动作**：背判断句"**只看不改是被动（窃听、流量分析），又改又砸是主动（篡改、伪造、伪装、重放、DoS/DDoS）**"。考场上题干给攻击名让你分类，或给"以下不属于主动攻击的是"——找"窃听/流量分析"。

### 1.3 贯穿总表：「属性 → 用什么技术 → 被什么攻击」（学完全课回来自检）

把本课所有技术按"它到底守住哪个属性"串成一张表，做题时对号入座：

| 安全属性 | 用哪种技术守住 | 被哪种攻击破坏 |
|---|---|---|
| **机密性** | 加密（对称/非对称）、数字信封 | 窃听、流量分析（被动） |
| **完整性** | 信息摘要（Hash）比对、数字签名 | 篡改 |
| **可用性** | 冗余、限流、CDN、防火墙 | DoS/DDoS、资源耗尽攻击（海量请求蹭连接） |
| **不可否认性 / 真实性** | 数字签名、数字证书（CA 认证身份） | 伪造、伪装、抵赖 |
| **可控性** | 访问控制、操作审计 | 越权传播 |

一句话穿起来：**"加密管机密、摘要管完整、签名管真实不赖账、防火墙/限流管可用、访问控制管可控"**——几乎每一章都是一个技术守一个属性、防一类攻击。考试时先问"这题在考哪个属性"，再反推用哪个技术/是哪类攻击。

## 第二节 对称加密与非对称加密 ★★★

**动机**：想把一段话保密，最直观的办法是"加密"——用一把钥匙把明文搅成乱码，收到的人用钥匙再搅回来。那钥匙怎么设计？历史上只有"同一把钥匙加又解"，直到 1976 年才有人发明"加解各用一把、成对出现"的方案。这两条技术路线就是本节主角。

### 2.1 对比表（选择题直接查这张表作答）

| 对比项 | 对称加密（私钥加密/共享密钥加密） | 非对称加密（公钥加密/公开密钥加密） |
|---|---|---|
| 密钥结构 | 加密、解密用**同一把**密钥 | **成对**出现：公钥 + 私钥 |
| 密钥分发 | 难：必须先走秘密信道把钥匙送到对方手里 | 易：公钥可公开随便发，私钥自己藏着 |
| n 人需要密钥数 | **n(n−1)/2** 个（每两人共用一把） | **2n** 个（每人一对） |
| 速度 | **快**（约快 1~2 个数量级） | **慢** |
| 加密数据量 | 适合**大量数据** | 适合**少量数据**（密钥、摘要） |
| 代表算法 | **DES**（分组 64 位，有效密钥 56 位）、3DES、**AES**（分组 128 位，密钥 128/192/256 位）、IDEA、RC-5 | **RSA**（基于大整数分解难题）、ECC（椭圆曲线）、ElGamal |
| 能否数字签名／提供不可否认性 | **原则上不能**：加解密用同一把钥匙，发送方、接收方**双方都有**，"签"得出来却举证不了是谁签的 | **能**：**私钥唯一**，只有本人能签 → 提供不可否认性 |

**记忆口诀**：对称"一把钥匙开一把锁，双方同款"；非对称"公锁私钥一对凑，公钥上锁私钥开"。算法名归类口诀：**"DES、AES 是兄弟（对称），RSA 单干是公私（非对称）"**——考场上认名字：带 DES/AES/IDEA 的选对称，带 RSA/ECC/DSA 的选非对称。

**密钥数公式的来历**（防遗忘就地展开）：n 个人两两通信都要保密，任何两人的密钥都不能与第三者相同，所以是"从 n 人里取 2 人配一把"= C(n,2) = n(n−1)/2。例如 n=10：C(10,2) = (10×9)/(2×1) = **45** 把。非对称则每人只需自己的一对：n=10 → 10 对共 20 把。这个对比正说明了非对称在密钥管理上的优势。

### 2.2 两个方向，别拧反了（本课第一易错点）

非对称加密的两把钥匙有**两种用法**，方向必须刻进脑子：

| 用法 | 加密用谁 | 解密用谁 | 达到什么目的 |
|---|---|---|---|
| **加密（保密）** | **接收者的公钥** | **接收者的私钥** | 只有收方能看 → 机密性 |
| **签名（认证）** | **发送者的私钥** | **发送者的公钥** | 只有本人能签 → 身份真实 + 不可否认 |

**反例演示**：「甲用乙的公钥加密后发给乙」✓ 保密方向；若写成「甲用自己的公钥加密后发给乙」就错了——公钥人人都有，别人也能解开，毫无保密性。「甲用乙的私钥签名」更是无中生有——乙的私钥只有乙自己有，甲根本拿不到；签名必须用自己的私钥。

一句话锁死：**"想让对方独看，用对方公钥锁；想证明是自己，用自己私钥签"**。

**为什么对称加密做不了数字签名（本节关键一问）**：签名要提供"不可否认性"——证明"这件事只有你能做、别人替不了"。对称加密里加密和解密是**同一把钥匙**，收发双方都握着它，那么甲乙两人谁都能用这把钥匙做出"签名效果"，事后谁也说不清到底是甲还是乙签的——**举证不了、无法定责**，相当于"章谁都能盖"。数字签名必须依赖**私钥唯一**的非对称体系：全天下只有甲持有甲的私钥，甲签出来的东西别人仿造不出，才"赖不掉"。理解这一句，就等于掌握了"数字签名为什么注定走非对称"的根本原因——考题若问"为什么对称加密不能提供不可否认性"，答**密钥双方共有、无法归因到唯一签名者**。

### 2.3 数字信封（混合加密）★★★

**动机**：实战里"鱼与熊掌要兼得"——对称快但钥匙难送，非对称好送但慢。办法：**用对称加密保护大数据，用对方的公钥只加密那把对称密钥**。这个"套了一层非对称外皮的对称密钥"就叫**数字信封**。

流程（以 A 发给 B）：

1. A 生成一把**一次性对称密钥** K，用 K 加密正文（快，管大数据）；
2. A 用 **B 的公钥**加密 K（只加密一小段，慢也无所谓）——这就是"信封"；
3. 把密文 + 加了密的 K 一起发给 B；
4. B 用**自己的私钥**解出 K，再用 K 解开正文。

**应试动作**：背"**对称保正文，公钥保钥匙；封谁用谁公钥，拆封谁用谁私钥**"。选择题给出流程步骤让你填"用谁的什么钥"，按这句作答。DES/AES/RSA 名字归类题则直接查 2.1 对比表。

## 第三节 信息摘要（Hash 函数）★★★

**动机**：验证一份大文件"有没有被改过一个字节"，把整个文件倒来倒去比对太笨。办法：用 Hash 函数给文件算出一个短短的"指纹"——**信息摘要**。指纹变了哪怕一点点，文件必然动过。

### 3.1 Hash 函数的四大特性

1. **定长输出**：无论输入多长（1 字节还是 1GB），输出固定长度；
2. **单向性**：从摘要反推出原文，计算上不可行——所以也叫**单向散列函数**；
3. **抗碰撞性**：找两个不同输入对应同一摘要，计算上不可行；
4. **雪崩效应**：原文改动 1 个比特，摘要面目全非。

**代表算法**：**MD5**（摘要 **128** 位）、**SHA-1**（摘要 **160** 位）、SHA-256、国密 SM3。

### 3.2 摘要 ≠ 加密（第二易错点）

**反例演示**：选项「MD5 是一种加密算法」——**错**。摘要有两个"非加密"特征：① **无密钥**（任何人算同一个文件得到的摘要都一样）；② **不可逆**（加密要求能解密还原，摘要不能）。摘要的用途是**完整性验证**，不是保密。

**应试动作**：背"MD5-128、SHA-1-160"两个数字 + 一句"Hash 无密钥、不可逆、管完整性"。考场上问"属于信息摘要算法特性的是"，挑"定长输出/单向/抗碰撞"；问"MD5 摘要长度"，答 128 位。

## 第四节 数字签名 ★★★（永恒考点，必须能默写流程）

**动机**：公钥体系解决了保密，但有个新漏洞——乙收到"甲"发来的消息，怎么确认真是甲发的、而不是别人冒名的？而且甲事后赖账说"我没发过"怎么办？答案：让甲用**只有自己才有的私钥**处理一段消息。全世界只有甲能这么干，这就是**数字签名**——它一举解决**真实性**（确是甲发）和**不可否认性**（甲不能赖账），顺带用摘要比对保证**完整性**。

### 4.1 标准签名与验证流程（四步，背到能默写）

以甲发消息给乙为例：

1. **生成摘要**：甲用**单向 Hash 函数**对正文算出信息摘要；
2. **签名**：甲用**自己的私钥**对摘要加密——这一步就是"签名"；
3. **发送**：甲把**正文 + 已签名的摘要**一起发给乙；
4. **验证**：乙用**同一个 Hash 函数**对收到的正文重新算出新摘要；再用**甲的公钥**解开签名得到原摘要；两者一致 → 消息确实出自甲、且中途未被改。

**为什么只签"摘要"、不签"全文"？**两个原因，背下来回答"为什么不能对全文签名"的题：① **慢**——签名用的是非对称（公钥）运算，天生慢，大文件全文签一遍开销巨大；② **摘要短、够等价**——Hash 摘要定长（如 128 位）且有雪崩效应，正文动一个字节摘要就面目全非，比对这个短摘要**完全等价于**比对整篇全文。所以标准做法永远是"**先算摘要、再签摘要**"——这正是 Hash 在数字签名里不可替代的位置。

### 4.2 方向速查表（考场填空就查这张）

| 动作 | 谁的什么钥 | 为什么 |
|---|---|---|
| 甲**签名** | **甲的私钥** | 私钥唯一，签了就赖不掉 |
| 乙**验证签名** | **甲的公钥** | 公钥配对私钥，能解开才证明是甲签的 |
| 乙**验证数字证书** | **CA 的公钥** | 证书是 CA 签的名（见第五节） |
| 发密文给对方 | **对方的公钥** | 保密方向 |

**反例演示**：真题选项里的三大错误方向——「乙用**乙的公钥**验证」（错，验证必须用**发方**甲的公钥，乙自己的钥匙对是拆"发给乙的密文"用的）；「甲用**甲的公钥**签名」（错，公钥人人有，谁都能"签"，就证明不了身份）；「甲用**乙的私钥**签名」（错，乙的私钥甲根本拿不到）。

### 4.3 签名 + 保密，一步不乱（真题最爱组合）

**动机**：签名流程里"正文 + 签名摘要"是**明文**发的——只解决了身份和完整性，**没解决机密性**。若既要保密又要签名，就在第 3 步外面再套一层数字信封（2.3 节）。完整流程（背诵模板）：

> 甲：Hash 求摘要 → **甲私钥**签名摘要 → （正文+签名）用 **乙公钥** 加密发出
> 乙：**乙私钥**解密 → **甲公钥**验签名 → 同一 Hash 重算摘要比对

记忆口诀："**先签后封，私签公验；封用收方公，拆用收方私**"。

**应试动作**：这是本课最高频考法。把 4.2 的速查表背熟，无论题干怎么换人名（甲乙/AB/发送接收方），第一步先问自己"这个动作是**保密**还是**认证**"——保密走对方公钥，认证走自己私钥。案例题风格题见本课末尾第 16 题。

## 第五节 数字证书与 CA ★★

**动机**：非对称体系还剩最后一个窟窿——**公钥怎么证明是本人的**？乙手里那把"甲的公钥"，万一是攻击者伪造的（攻击者把自己的公钥冒充成甲的发给你），后面整个签名验证都白搭。**数字证书**就是给公钥办的"身份证"：由一个大家信任的权威机构 **CA（证书授权中心）**，把"用户身份 + 用户公钥"捆在一起并盖章。

### 5.1 证书里有什么、怎么验证

- **证书内容**：用户身份信息、**用户的公钥**、证书有效期、序列号，以及最关键的——**CA 用自己的私钥对证书摘要做的数字签名**。
- **验证证书（三步，别只停在"验签名"）**：拿到一张证书，除了用 **CA 的公钥**验 CA 的签名，还要再查两件事才算有效：
  1. **验签名**：用 **CA 的公钥**解开证书上的 CA 签名，比对摘要 → 确认这张证书确实是 CA 签发的、不是伪造的；
  2. **查有效期**：确认证书**当前在有效期内**（未过期、也未被提前撤销）；
  3. **查吊销**：到 CA 或证书库查这张证书**是否已被列入吊销列表（CRL）**——私钥泄露、用户离职都可能让 CA 提前作废证书，正文却仍"未过期"。
  
  三步全过，才证明"**这把公钥确实属于这个人、且当前有效**"。

- **信任链与根证书**：未必每个 CA 都天生被信任。现实里是一串"**信任链**"——顶层有一个大家都信任的**根证书**（内置在操作系统/浏览器里），它给下层 CA 签发证书，下层 CA 再给普通用户签发；验证时逐级向上，直到找到一个你本来就信任的根证书为止。选择题若问"浏览器为什么凭内置根证书就能信某个 CA 签的证书"，本质就是靠这条自下而上的信任链。
- CA 的职责：证书的签发、更新、**撤销（吊销列表 CRL）**、管理。

### 5.2 与第 6 课联动

浏览器地址栏的 **HTTPS**（端口 443，见 [06-计算机网络.md](06-计算机网络.md)）握手时就用到这一套：服务器出示**数字证书**，浏览器用 **CA 的公钥**验证书，确认服务器身份后再协商对称会话密钥加密通信——"证书验身份 + 对称管数据"的组合再现。

**反例演示**：选项「验证数字证书要用证书持有者的公钥」——**错**。证书上的签名是 **CA** 签的，所以要用 **CA 的公钥**验。持有者的公钥是证书**里装的东西**，不是验证工具。

**应试动作**：背两句——"证书 = 身份 + 公钥 + CA 签名"；"验证书用 CA 的公钥，验证普通签名用发送者的公钥"。考场给场景问"浏览器如何确认某网站公钥的真实性"，答"用 CA 公钥验证网站的数字证书"。

## 第六节 防火墙与入侵检测 ★★

**动机**：加密和签名保的是"数据本身"，而防火墙保的是"网络边界"——像小区门禁，控制什么人能进、什么包能过。

### 6.1 防火墙是什么

位于**内部网络与外部网络（Internet）之间**的屏障，按规则**控制进出网络的数据包与流向**，是内外网之间信息流的唯一通道。

### 6.2 两种常考类型

| 对比项 | 包过滤防火墙 | 应用代理防火墙（应用网关） |
|---|---|---|
| 工作层次 | **网络层**（有的含传输层） | **应用层** |
| 检查内容 | 数据包的**源/目的 IP、端口**等头部信息 | **具体应用协议的内容**（如 URL、命令） |
| 是否转发原始包 | 直接放行/丢弃，内外**直通** | 内外**不直通**，代理替两头转接 |
| 优点 | 快、开销小、透明 | 安全控制粒度细、能审计内容 |
| 缺点 | 看不懂应用内容，挡不住应用层攻击 | 速度慢、每种协议要单独代理 |

（另有"状态检测"防火墙，跟踪连接状态，介于两者之间，选择题见过即可。）

### 6.3 三种经典部署体系结构（补充，属认知拓宽，非真题高频）

| 体系结构 | 特征 | 一句话理解 |
|---|---|---|
| **双宿主主机（Dual-Homed Host）** | 一台主机装**两块网卡**，分别接内网、外网，主机上**关闭 IP 路由转发**，成为内外网之间的唯一"闸门" | 一台"两头堵"的机器，掐断内外直连、全要靠它转 |
| **屏蔽主机（Screened Host）** | 一台**屏蔽路由器**（包过滤）在外层先筛普通流量，另配一台**堡垒主机**负责接待必须进入内部的关键服务 | "路由在前粗筛 + 主机在后守关键服务" |
| **屏蔽子网（Screened Subnet / DMZ 非军事区）** | 内外网之间再用一道路由器**隔出一段子网**，把对外服务（Web、Mail）放在这中间缓冲带 | "两层路由夹一段缓冲子网，公网服务放中间的格子里" |

直觉：这套体系是按"边界防御的层次"从单薄到周密排列的——一台机器当闸门（双宿主）→ 一层路由加一台主机（屏蔽主机）→ 两层路由夹一段缓冲子网（屏蔽子网/DMZ）。选择题若问"把对外服务器放在内外网之间的隔离缓冲区"指哪个，答**屏蔽子网（DMZ）**。

### 6.4 防火墙的"能与不能"（送分判断题）

**能**：控制进出数据包与流向；提供流量日志与审计；隐藏内部 IP 与网络结构细节（NAT）。

**不能**（真题三连）：
- 不能防范**内部**人员的攻击（它在边界上，管不着墙内）；
- 不能防范**不经过它的**连接（如内部拨号直连外网）；
- **不能防病毒**——它按 IP/端口/规则过滤，不做代码级查毒；"漏洞扫描"也不是它的功能。

### 6.5 入侵检测系统（IDS）

**动机**：防火墙是"门禁"，但进了门或绕过门的人干坏事谁盯着？**入侵检测系统 IDS** 监视网络/系统，发现可疑行为**报警**。

- 定位：**监测 + 告警**，是防火墙之后的第二道防线；**本身不负责拦截阻断**（能主动阻断的是 IPS，入侵防御系统）。
- 采集方式：从网络抓包分析（基于网络）或读主机审计日志（基于主机）。

**应试动作**：背"包过滤=网络层看头，应用代理=应用层看内容；防火墙不防内部、不防病毒、不管绕道的；IDS 只报警不拦截"。这三句覆盖本节所有真题考法。

## 第七节 常见攻击与恶意代码 ★★

**动机**：前面学的都是"防御方"，本节换到"进攻方"视角——考场上给一段场景描述，让你指出"这是什么攻击"，认得出才能答对。

### 7.1 攻击类型认领表

| 攻击 | 场景特征（题干关键词） | 防御 |
|---|---|---|
| **重放攻击** | 截获合法报文，**事后原样重发**骗系统（主战场是身份认证） | **时间戳**、**一次性口令/一次性令牌**、挑战-应答、序列号 |
| **DoS/DDoS** | 海量请求**淹没**服务器，耗尽带宽/连接资源，**合法用户进不来**（破坏可用性）；DDoS = 僵尸网络里成千上万台"肉鸡"同时发起 | 流量清洗、限流、CDN 分散 |
| **SQL 注入** | 在**输入框/URL 参数**里夹带 SQL 片段，骗数据库执行（如 `' or '1'='1` 绕过登录） | **参数化查询（预编译语句）**、过滤特殊字符、最小权限（联动 [02-数据库系统.md](02-数据库系统.md)） |
| **钓鱼攻击** | 仿冒官网/邮件诱骗用户主动**交出**账号密码 | 核对域名、不点陌生链接 |
| **窃听/流量分析** | 只监听不修改（被动攻击，见第一节） | 加密 |
| **伪装/假冒** | 冒充合法用户或主机 | 身份认证、数字签名 |
| **IP 欺骗** | 伪造数据包的**源 IP 地址**，冒充可信主机（如内网地址）骗取对方信任 | 认证、过滤可信源地址、加密 |
| **会话劫持** | 中途**插入/接管**已建立的合法会话，冒充其中一方继续通信（常配合嗅探拿到会话标识） | 会话加密、会话标识随机化、超时注销 |
| **资源使用攻击（资源耗尽）** | 占用服务器**资源**（连接数、内存、CPU）让合法请求没资源可用；DDoS 是其大规模化形态 | 限流、连接数上限、负载均衡 |
| **后门 / 特洛伊陷阱** | 攻击者事先在系统里**留下隐蔽入口**，随时绕过正常认证进入 | 全面补丁、基线核查、最小权限、网络隔离 |

**重放 vs DDoS 一句话分清**：重放是"把**旧的**合法报文再发一遍"骗认证；DDoS 是"发**海量的**垃圾报文"拖垮服务。

### 7.2 恶意代码四兄弟（背区别）

| 名称 | 定义要点 | 区别关键 |
|---|---|---|
| **计算机病毒** | 依附于**宿主程序**、能自我复制、破坏功能或数据的代码 | **必须有宿主**，靠寄生的程序/文件传播 |
| **蠕虫** | **独立程序**，利用系统漏洞**自我复制**、主动在网络传播 | **不需要宿主、不需要人操作**，自己爬 |
| **木马** | 伪装成正常软件，隐藏在受害机器里开"后门"，供攻击者**远程控制** | 靠"伪装+远程控制"获利，**不自我复制** |
| **逻辑炸弹** | 平时潜伏，**满足特定条件**（日期、事件）时爆发破坏 | **条件触发** |

**记忆口诀**："病毒寄生、蠕虫自爬、木马开门、炸弹看日子"。四者共同点：都是恶意代码；考场上抓题干关键词——"寄生在正常程序中"选病毒，"利用漏洞自主传播"选蠕虫，"远程控制/后门"选木马，"某日触发"选逻辑炸弹。

**补充一个相关概念（DDoS 的"作案工具"）——僵尸网络**：攻击者先用木马/蠕虫等手段**批量感染**大量主机，这些被控主机被称为"**僵尸机/肉鸡**"，它们组成的受控集群就叫**僵尸网络（Botnet）**。发起 DDoS 攻击时，攻击者只是向网络里的肉鸡群下达"同时向目标狂发请求"的命令——所以 DDoS 的流量面广、难以追溯到真凶。识别特征：题干说"攻击者控制了大量被入侵的计算机同时发起攻击"→ 僵尸网络。

**防毒常识**（顺带背）：不打开来历不明附件、及时打补丁、升级杀毒软件**特征库**、重要数据备份。

## 答案与解析

### 课后考题答案

**1. B**
"篡改首页内容"改动了数据，破坏**完整性**。A 机密性对应"偷看/泄露"；C 可用性对应"服务瘫痪、用不了"；D 不可否认性对应"发过却抵赖"。配对口诀"看改断造对密完用真"，见第一节 1.1 表。

**2. A**
被动攻击 = 只看不改。流量分析只观察通信模式与流向，不改任何数据，属被动攻击。B 重放"重发了旧报文"、C 拒绝服务"发洪流砸服务"、D 篡改"改了数据"，都动了手，全是主动攻击。这是真题原考点：把"流量分析"塞进主动攻击选项里设坑。

**3. B**
DES 是**对称（共享密钥）加密**算法：分组 64 位、有效密钥 56 位，加解密同一把钥匙。A 非对称代表是 RSA/ECC；C 摘要代表是 MD5/SHA；D 数字签名不是算法类别而是一种技术应用。归类口诀：DES/AES/IDEA → 对称；RSA/ECC → 非对称。

**4. C**
公钥可以随便给、私钥自己藏——这正是非对称体制解决密钥分发问题的核心。A 反了，对称快、非对称慢（差 1~2 个数量级）；B 反了，对称加密加解密用**同一把**；D 反了，RSA 慢，只适合加密少量数据（如密钥、摘要），大文件交给对称算法。

**5. C**
对称体制下每两人共用一把密钥：C(10,2) = (10×9)/(2×1) = **45**。交叉验证：第 1 人要与其余 9 人各一把共 9 把，第 2 人再与新对象配 8 把……9+8+…+1 = 9×10/2 = 45 ✓。B（20）是误用非对称算法 2n=20；D（90）是误算 n(n−1)=90，忘了除以 2（同一把钥匙被两人共用，不能算两次）。

**6. B**
数字信封标准流程：**对称密钥管大数据（快），对方公钥只管那一小段对称密钥（好分发）**。A 反了——用公钥加密全部大数据太慢，对称密钥也没必要"加密乙的私钥"；C、D 都出现了"加密私钥"这种无意义操作，且用乙的私钥加密甲根本做不到（乙的私钥只有乙有）。

**7. C**
Hash 函数**无密钥**：任何人算同一文件的摘要结果都一样，这正是它可用于第三方完整性验证的原因。A、B、D 都是摘要的正当特性（定长输出、单向性、雪崩效应）。本题逆向选"不具备的"，审题别顺拐。

**8. B**
MD5 摘要 **128 位**；C（160 位）是 SHA-1 的摘要长度——这两个数字是历年选择题挖坑对挖的经典搭档，一起背。

**9. A**
签名是甲用**甲的私钥**做的，验证必须用配对的**甲的公钥**（验签 = 用发方公钥解签名、比对摘要）。C/D 是乙自己的钥匙对，用于"发给乙的密文"的加解密，与验签名无关。速查表见第四节 4.2。

**10. D**
签名管"真、赖不掉、没被改"（A 真实性、B 不可否认性、C 完整性），但签名后的"正文+签名摘要"是**明文**发送的，第三方照样能看——机密性要靠再用对方公钥加密（第四节 4.3）。

**11. B**
完整流程：甲用**甲私钥**签摘要（证明是甲），再用**乙公钥**加密整包（只有乙能拆）。A 方向错乱："公钥签名"不能证明身份（公钥人人有），"私钥加密消息"乙没有甲的私钥解不开；C 用对方公钥签名、用自己公钥加密，两处都错；D 用乙的私钥——甲根本拿不到乙的私钥。口诀"先签后封，私签公验；封用收方公"。

**12. A**
证书里装的就是**持有者的身份 + 持有者的公钥**。B 错——证书上的签名是 CA 做的，验证要用 **CA 的公钥**；C 错——证书由权威机构 CA 签发，不是持有者自制（自制就无公信力可言）；D 错——**任何人的私钥都不进证书**，私钥永远自己保管。

**13. C**
包过滤防火墙在**网络层**按 IP、端口等头部字段过滤。A 应用层是应用代理防火墙的地盘；会话层、物理层不承担包过滤功能。配套记忆：包过滤"网络层看头"，应用代理"应用层看内容"。

**14. C**
防火墙守在**内外网边界**，对内部人员之间的攻击无能为力——"不防内部"是它最经典的局限性，考"不正确的是"就选它。A、B、D 都是防火墙的正当功能（控制包流向、日志审计、隐藏内部结构）。

**15. A**
题干关键词"**截获合法报文 + 原样重发**"正是重放攻击的定义，主战场是身份认证。B SQL 注入是在输入里夹带 SQL 片段；C DDoS 是海量请求拖垮服务；D 钓鱼是仿冒诱骗用户主动交出凭证。防重放靠时间戳/一次性口令（见精华题 4）。

**16. 案例题答案**

（1）**单向 Hash 函数**（信息摘要函数）。要求"未被篡改"，靠摘要比对实现；只有乙能读取靠加密实现，两者分工明确。

（2）**甲的私钥**。签名永远用发送方自己的私钥——私钥唯一，签了才赖不掉，满足要求②的"确实由甲发出"。

（3）**乙的公钥**。要求①"只有乙能读取"是保密方向，用接收方乙的公钥加密，全世界只有持有对应私钥的乙能解开。

（4）乙先用**自己的私钥**解密，得到"指令+签名"；再用**甲的公钥**验证签名，并用**同一个 Hash 函数**重算指令摘要、与解出的摘要比对，一致则确认出自甲且未被篡改。

（5）这种攻击叫**重放攻击**。防御：在认证报文中引入**时间戳**（过期作废）或**一次性口令/挑战-应答**（每次认证用一次性凭据），让"旧报文"重发时失效。

### 精华题答案

**1. A**
两步定式："私签公封"——甲私钥签名（认证自己），乙公钥加密（保密给乙）。B 用甲的公钥"签名"（谁都能做，无效）+ 用乙的私钥加密（甲拿不到乙的私钥）；C、D 签名与加密双双方向错乱。凡此类题，先问"这一步要保密还是认证"，再套 4.2 速查表。

**2. B**
证书上的签名是 **CA 用自己的私钥**盖的章，验证自然用 **CA 的公钥**。A 的网站公钥是证书里**被证明的对象**，不是验证工具；C 用户自己的公钥与本证书无关；D 私钥永远不外露，也不用于验证。

**3. D**
防火墙管外不管内，"不防内部攻击"是正确描述。A、B 两个工作层次正好说反：**包过滤=网络层看头部，应用代理=应用层看内容**；C 错——不经过防火墙的连接（如内部私拉拨号）它无法防范，这正是局限性之一。

**4. A**
重放攻击的命门是"旧报文依然有效"，所以给凭据**加时效（时间戳）或改成一次性（一次性口令）**即可防住。B 是保密与身份手段，管不住"报文本身合法但是旧的"；C 是防火墙手段；D 增加密钥长度对抗的是破解，与报文新旧无关。

**5. B**
题干三个关键词"**不寄生（无宿主）+ 漏洞自我复制 + 网络主动传播**"是蠕虫的画像。A 病毒必须依附宿主程序；C 木马靠伪装驻留做远程控制、不自我复制；D 逻辑炸弹靠条件触发。口诀"病毒寄生、蠕虫自爬、木马开门、炸弹看日子"。

**6. C**
海量请求把服务器"砸瘫"，合法用户要用时用不了——破坏**可用性**（对应安全攻击里的"中断"）。A 窃听破坏机密性；B 篡改破坏完整性；D 伪造破坏真实性/不可否认性。四类攻击"截获—篡改—中断—伪造"与属性的配对要形成条件反射。
