# 04.8 案例题专攻：程序设计题

下午卷第 5 题有两个分支：**Java/C++ 设计模式代码填空**（近年主流）与**纯 C 程序理解填空**（指针、数组、递归）。形态固定为「说明 + 挖空代码 + 2～3 个小问」，约 15 分。上一节（04.7 套路四）处理的是这一类题的"问模式名"小问，本节处理另一半——**把代码填对**。填空要用的角色名，来自 04.6 第 4.4 节的中英默写表，两道一起过。

## 套路一：Java/C++ 模式填空（四步法）

**第 1 步：读说明定模式。** 说明几乎都会先给场景关键词，用 04.7 的"题干—模式"对照表 5 秒定位："状态改变通知各方"选观察者；"可切换/可扩充的算法或方式"选策略；"全局唯一"选单例；"接口不兼容的旧系统"选适配器。

**第 2 步：把代码对到角色。** 类与接口就是模式的角色，先逐条在代码旁标注角色（按 04.6 第 4.4 节的命名习惯）：

- `interface Xxx` 或 `abstract class Xxx` —— 抽象角色（`Observer`、`Strategy`、`Component` 一类）；
- **持有抽象角色引用**的类（有字段、有 setter 的那个）—— `Subject` / `Context` / `Decorator`；
- `class Yyy implements Xxx` 或 `extends Xxx` —— 具体角色（`ConcreteObserver`、`ConcreteStrategy` 等）。

**第 3 步：按四种高频空型对号入座。** 五个空中通常有三个以上落在这四类里：

| 空型 | 固定写法 | 例 |
|---|---|---|
| ① 继承声明空（跟在类名后） | Java 接口写 `implements 接口名`；抽象类写 `extends 类名` | `class EmailAlert implements StockObserver` |
| ② 字段与注入空 | 字段声明 `抽象角色 变量名;`；赋值 `变量 = 参数;` | `strategy = s;` |
| ③ 通知／委托调用空 | 循环体或方法体内调**抽象角色**声明的那个接口方法 | `observer.update(stock);`、`strategy.pay(amount);` |
| ④ 注册空（往集合里登记） | 观察者登记 `observers.add(o);`，注销 `observers.remove(o);` | 第 2 步里 Subject 持有的那个列表 |

**第 4 步：小例子走一遍再交卷。** 填完把"设置一次、通知一次"的调用链在草稿上代入 2～3 个元素追踪；C++ 分支额外检查三件事：接口用 `virtual ... = 0` 表达、继承写 `class X : public Y`、需要运行时绑定的方法不能少 `virtual`。

**反例前置（最常见的三种丢分写法）：**

1. **先通知、后赋值**：setter 挖空常连挖两空，顺序写反时观察者收到的是**旧值**。正确顺序永远是"赋值，再通知"。
2. **`implements` 与 `extends` 混用**：Java 里接口只能用 `implements`，类与抽象类才用 `extends`；C++ 没有 `implements`，一律 `class X : public 基类名`，照搬 Java 写法直接错。
3. **凭空发明方法名**：空③必须调用**接口/抽象类里已声明**的方法名（如 `update`、`pay`），写自己编的名字不得分——判卷按代码上下文对答案。

### 微例（策略模式，逐空演示）

【说明】自动售票机支持刷卡、扫码等多种付费方式，可随配置切换；售票机自身不做计费，只记住当前付费方式，计费委托给它。

```java
interface PayStrategy {
    double pay(double amount);
}

class TicketMachine {
    private PayStrategy strategy;          // 上下文持有抽象策略

    public void setPayStrategy(PayStrategy s) {
        /* (1) */
    }

    public double charge(double amount) {
        return /* (2) */;
    }
}

class CardPay /* (3) */ {
    public double pay(double amount) {
        return amount * 0.8;
    }
}
```

| 空 | 怎么想 | 答案 |
|---|---|---|
| (1) | `setPayStrategy` 收到参数 `s`，上下文要靠字段记住它 | `strategy = s` |
| (2) | `charge` 要把计费委托给当前策略，方法名只能取接口声明的 `pay` | `strategy.pay(amount)` |
| (3) | CardPay 是一种具体付费方式，必须继承抽象角色；`PayStrategy` 是接口 | `implements PayStrategy` |

配套小问模板（认模式／角色／优点）：**策略（Strategy）模式**；TicketMachine 是 Context（上下文），PayStrategy 是 Abstract Strategy（抽象策略），CardPay 是 Concrete Strategy（具体策略）。新增一种付费方式只需增加一个具体策略类，**不必修改 TicketMachine 与已有策略的代码**，符合开放-封闭原则。

## 套路二：纯 C 程序理解填空（指针／数组／递归）

填空空位就藏在"值怎么流动"里，动手前先立三条规矩：

1. **写出函数契约**：在草稿上写"这个函数拿什么、回什么"——如 `length(head)` 返回链表结点数。契约对了，空自然知道该喂什么。
2. **对空问三句**：它是**终止条件**吗？是**递推／遍历推进**吗？还是**返回值的组合**？三种身份各有固定写法。
3. **代入 2～3 个元素的小例子追踪**：逐行写出每一步的状态（指针停在哪、变量当前值），与契约一致才算填对；只"看着顺眼"不代入，是本题最大的失分来源。

**递归题固定构件**：终止段 `if (head == NULL) return 基值;`；推进段 `f(head->next)`；组合段 `return f(head->next) 与 head->data 的合并式`。**链表遍历固定搭配**：`p = p->next`（推进）与 `p->data`（取值）；`p` 是指针时取成员只能写 `p->data`，不能写 `p.data`。

**反例（空基值写成 0）**：求链表数据的最大值时，若把空结表的返回基值填 0，全负的链表会被 0 压住、返回错误的最大值。基值必须取"不参与胜负的值"（如 `limits.h` 里的 `INT_MIN`）。这正是 C 分支"代码改错"小问的标准考点。

## 应试动作

- 小问问模式：先写模式名，再写角色对照（上下文／抽象角色／具体角色，英文名照 04.6 第 4.4 节默写），最后收在"只增新类、不改旧码 + 开放-封闭原则"上；
- 只考填码：填完必走一遍小例子，优先复查"先赋值后通知"、方法名是否取自接口、递归基值是否无害；
- 练习位置：本课 90 文件案例题第四道（策略模式 Java 填空 + C 递归链表各一道）；模拟卷案例五（观察者 Java 填空）已走过完整流程，两者对照着做。
