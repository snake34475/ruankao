# 04.1 面向对象基本概念 ★

### 1.1 四大基石与"为什么"

- **封装**：把数据和对数据的操作捆在一起（类），对外只暴露接口、隐藏实现细节。**动机**：使用者不必知道内部怎么实现，内部改动不波及外部——和数据库三级模式的"隔离变化"是同一个思想。
- **继承**：子类自动拥有父类的属性和方法，并可扩展。**动机**：共同点写一遍（放父类），差异点写在子类——消除重复。
- **多态**：同一消息发给不同对象，各自做出不同响应。**动机**：调用方写一段代码（面向父类/接口），加新子类时调用方**一行都不用改**——否则就得写满 `if 类型==... else if ...`，每加一种类型都要回头改调用方。
- **消息**：对象之间通过发送消息（调用操作）通信。

**类的正式定义**（选择题原话出处）：类是对象的**模板**，描述一类对象共有的特征（属性）和行为（方法）；对象是类的**实例**。一个对象 = **属性（数据）+ 方法（操作）+ 对象标识（ID）**——三样都要有，缺 ID 就不是对象。对象占用内存空间，类不占（类是描述，不是数据本身）。

**应试动作**：认"三件套"——问"对象由什么组成"答「属性 + 方法 + 对象 ID」。

### 1.2 类的三种类型（识别题高频）★

建模时会画一堆类，出题人爱问"某某类属于哪一类"。三类各有**外形特征**，抓住"属性多还是方法多、管不管流程"就能秒判：

| 类型 | 别名 | 干什么 | 外形特征 | 例子 |
|---|---|---|---|---|
| **实体类** | 数据类 | 表示现实世界真实存在的实体 | **属性多、方法少** | 读者、图书、借阅记录、订单 |
| **边界类** | 接口类 | 为用户提供与系统交互的方式（窗口、接口、外部系统接口） | **方法多、属性少**；常带 interface、UI、Adapter | 借书窗口、登录界面、支付接口 |
| **控制类** | 控制/协调类 | 描述业务逻辑、控制活动流，协调实体类与边界类 | 名字常带 **Controller、Manager、Session** | 借书控制器、订单处理器 |

**反例演示（易错）**："图书"和"图书管理界面"都是名词，但一个是**实体类**（有书名/作者/定价等一堆属性），一个是**边界类**（它自己不存数据，只提供"输入书号""显示结果"这些操作）。做题时别只看名字像不像名词，要看**它是"存数据的"还是"干活的/给人用的"**。

**应试动作**：背一句口诀「**实体存数据、边界接用户、控制管流程**」；看到 Controller / Manager / Session / Handler 结尾的名字，优先判控制类。

### 1.3 重载 vs 重写（必考对比）

| | 重载 overload | 重写 override |
|---|---|---|
| 位置 | **同一个类**里 | **子类**覆盖父类方法 |
| 签名 | 方法名相同，**参数列表必须不同** | 方法名、参数列表**完全相同** |
| 绑定时机 | **编译期**根据参数选方法 | **运行期**根据实际对象类型（多态的基础） |
| 关系 | 体现同一个类中的不同表现 | 体现父类与子类的不同表现 |

**反例演示（易错）**：只改返回值类型、参数完全相同——既不是重载也不是重写，是编译错误（重载要求参数不同）；子类方法参数列表与父类不同，那就成了重载（新方法），**父类版本没有被覆盖**，用父类引用调用时执行的还是父类版本——这是"以为重写了、其实重载了"的经典陷阱。

**应试动作**：抓两个判别词——"同类不同参 = 重载；子类同签名 = 重写"。考题常给一段代码问"输出什么"：父类引用指向子类对象，调用被重写的方法 → 执行**子类**版本。

### 1.4 多态的四种形态（选择题送分点）★

"多态"不是只有一种，按**形成机制**分四类。考题常问"哪种多态应用最广泛/最纯"或"下面的例子属于哪种多态"：

| 形态 | 机制 | 一句话认法 | 例子 |
|---|---|---|---|
| **过载多态**（ad hoc） | 同一个名字在不同上下文中含义不同 | **就是重载** | `add(int,int)` 与 `add(String,String)` |
| **参数多态** | 类型作为参数，一套代码适配多种类型 | **泛型**（"最纯、应用最广泛"） | `List<T>`、`swap<T>(a,b)` |
| **包含多态** | 同样操作可用于一个类型**及其子类型** | **子类替换父类**，需运行期类型检查 | 父类引用调子类重写的方法 |
| **强制多态** | 编译程序通过语义操作把类型**强行变换** | **隐式类型转换** | `int` 参与浮点运算时自动转 `double` |

**记忆抓手**：**过载**名字一样、**参数**类型当参、**包含**子类包进来、**强制**编译器硬转。

**反例演示（易错）**：别把"参数多态"和"包含多态"混了 —— 判断标准是**靠类型参数化还是靠继承层次**。`List<int>` 和 `List<String>` 用同一个 `List` 是**参数多态**（没有继承关系）；父类引用指向子类对象是**包含多态**（有继承关系）。

### 1.5 动态绑定：多态落地要同时满足三个条件 ★

讲义前面说"父类引用指向子类对象、调用被重写的方法就执行子类版本"——这不是无条件成立的，**三个条件缺一不可**：

1. 要有**继承关系**（子类继承父类）；
2. 要发生了**重写**（子类覆盖了父类的方法）；
3. 要有**父类引用指向子类对象**（`父类类型 变量 = new 子类类型();`）。

**绑定时机对照**：**静态绑定**发生在**编译时**（如重载按参数类型选定方法）；**动态绑定**发生在**运行时**（按对象的实际类型选定方法）。

**反例演示（易错）**：三个条件少一个，多态就不发生 —— 若父类方法**没被子类重写**，父类引用调它就是父类版本；若用**子类引用**调，即使重写了也谈不上"多态"（本来就是子类对象，直接调即可）；若方法被声明为不可覆盖（Java 的 `static`、`final`、`private` 方法），走的就是静态绑定。

**应试动作**：看到代码题里出现 `父类 p = new 子类();`，先在心里核对这三条，再判定"调的是哪个版本"；问"为什么输出父类版本"时，答案往往就是**该方法没有被重写**，或**它不是通过父类引用调用的**。
