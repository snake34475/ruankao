# 11.9 答案与解析

### Passage 1 答案与解析

**1. A — testable（可测试的）**

句子结构是 `clear, consistent, and ___`，空格与两个形容词并列，也应填形容词。后面的 `so that testers can determine whether...` 直接解释：需求要能让测试人员判断是否满足，所以是 testable。B invisible（不可见的）、C temporary（临时的）、D accidental（偶然的）都与高质量需求相反或无关。

**2. B — identify（识别、确定）**

`to + 动词原形`，四项词性都可，需看专业含义。需求获取时，分析人员与利益相关者沟通，是为了确定真实需求，故 `identify their real needs`。delete（删除）、encrypt（加密）、compile（编译）均不符合需求获取任务。

**3. A — management（管理）**

固定专业搭配是 `configuration management`（配置管理），用于版本和变更控制。其余三项无法与 configuration 组成此处所需概念。

**4. B — assess（评估）**

追踪矩阵把需求连接到设计和测试，因此能更容易评估一次变更会影响哪些内容，即 `assess the impact`。postpone 是推迟，hide 是隐藏，randomize 是随机化。

**5. B — feedback（反馈）**

原型的常见目的，是尽早让用户看到并反馈，从而降低需求不确定性。`obtain feedback from users` 是固定而自然的搭配。bandwidth、ciphertext、deadlock 分属网络、安全和操作系统语境。

全文意译：需求工程负责发现、记录和维护系统应做什么。好需求应清晰、一致且可测试。分析人员通过沟通识别真实需求；已批准需求纳入配置管理。可追踪矩阵帮助评估变更影响，原型帮助尽早获得用户反馈。

### Passage 2 答案与解析

**6. A — do**

`either all operations take effect or none do` 中，do 代替前面重复的 `take effect`。若写 `none are/have/make`，句子缺少合适的补足成分或搭配不成立。专业含义是原子性“要么全做，要么全不做”。

**7. A — intermediate（中间的）**

并发事务不应看到另一个事务尚未完成时的不恰当中间状态。`intermediate states` 与 isolation 的定义完全对应。permanent（永久的）、public（公开的）、graphical（图形的）都不是隔离性要避免的核心问题。

**8. A — failures（故障）**

持久性意味着事务一旦提交，即使系统发生故障，结果也能保留，固定表达是 `survive system failures/crashes`。query、index、schema 本身不是持久性定义中的灾害事件。

**9. B — ciphertext（密文）**

加密用密钥把 plaintext（明文）变成 ciphertext（密文）。metadata 是元数据，bandwidth 是带宽，source code 是源代码。

**10. C — modification（修改、篡改）**

Hash 摘要用于检测数据是否被修改，对应完整性；后一句又明确说它本身不能保密。compression、allocation、scheduling 分别是压缩、分配、调度。

全文意译：事务把多个操作组合成一个逻辑工作单元。原子性保证全做或全不做；隔离性避免事务看到不合适的中间状态；持久性保证提交结果能经受系统故障。加密把明文变密文以保密，Hash 摘要用来检测篡改，两者目的不同。

### Passage 3 答案与解析

**11. A — changes（变化）**

弹性是随工作负载变化而扩缩容量，`as the workload changes` 语法、语义都成立。其余选项虽是 IT 动词，但 workload 不会“解密、继承或提交”。这是典型的“专业词看似都认识，主谓搭配决定答案”。

**12. B — Internet**

SaaS 应用通过互联网交付给用户。compiler、register、semaphore 分别属于编译、CPU/程序设计和操作系统领域，无法作为应用交付网络。

**13. A — programmed（编程规定）**

机器学习的经典表述是：从样例中学习，而不是为每种情况显式编程，即 `explicitly programmed`。`instead of` 已给出对照逻辑。

**14. C — sets（集合）**

固定术语是 `training set` 和 `test set`。这里前面同时修饰 training and test，故用复数 sets。locks、keys、frames 分别属于并发控制、安全和网络。

**15. B — overfitted（过拟合的）**

题干定义“记住训练数据噪声，但在新数据上表现差”，正是 overfitting。portable 是可移植，atomic 是原子的，serialized 是串行化的。

全文意译：云计算按需提供共享资源，弹性允许容量随负载变化。IaaS 中客户管理操作系统和应用，SaaS 中提供商管理大部分技术栈。机器学习从样例中学习；训练集用于学习，测试集用于评估未知数据表现。记住噪声而无法泛化就是过拟合。

### 综合阅读题答案

**16.** `deployed` 在这里是“**部署、上线**”，即把新版本放到实际运行环境中，不是普通的“展开”。

**17.** 证据是 `CPU utilization remained moderate`，即 CPU 利用率仍处于中等水平，没有接近饱和。

**18.** 一个高频查询因为迁移时删除了有用索引，只能**全表扫描 Orders 表**；请求增多时数据库时延随之上升。

**19.** 把该查询加入回归测试套件，是为了在以后修改后重新检查这个已修复场景，防止同类性能退化再次出现。Regression testing 的核心是确认变更没有破坏已有正确功能或重新引入旧缺陷。

**20.** 还包含预防未来问题。文本依据是团队更新部署检查清单，要求 `future schema changes would be reviewed before release`，即今后的数据库模式变更要在发布前审查。这不是只恢复当前索引，而是建立预防措施。

### 精华题答案与解析

**1. B — frequently**

持续集成要求开发者**频繁**把小改动合入共享仓库。rarely 与 continuous 的思想相反；secretly、accidentally 不符合工程实践。

**2. A — feedback**

测试失败后团队立即收到反馈，固定搭配 `receive rapid feedback`。后文 `can correct the problem while the change is still small` 说明快速反馈的价值。

**3. A — detect**

结构是 `make problems easier to + 动词原形`。CI 让集成问题更易被发现和定位，`detect and locate` 语义并列。manufacture（制造）、postpone（推迟）、authorize（授权）均不合逻辑。

**4. B — automatically**

后面 `without requiring manual steps` 是直接同义提示：不需要人工步骤，就是自动运行。A manually 与后文矛盾；visually、separately 无此照应。

**5. A — expensive**

缺陷拖到后期通常修复成本更高。`more + adjective + to fix` 需要形容词，四项词性都可以，但只有 expensive 与“早发现降低风险”的因果关系一致。

精华短文意译：持续集成要求频繁合并代码，每次变更触发自动构建和测试。快速反馈让团队趁改动还小时修复问题。CI 不保证零缺陷，但能让集成问题更易发现和定位。可重复的构建、自动测试和尽早发现缺陷能降低后期修复成本。

**6. B**

Authentication 是“确认你是谁”，authorization 是“确认你被允许做什么”。其他三项分别属于压缩、调度、路由，不是权限控制。

**7. A**

高内聚、低耦合是良好模块化设计的核心目标：模块内部职责紧密，模块之间依赖尽量少。B、C、D 均不以 cohesion/coupling 描述。

### 补充题答案

**B1. A — protection（保护）**

`little ____ against media failure`＝"形容词 + 名词"，空里需名词；`against` 引出要防备的对象，固定搭配是 `provide protection against`（针对……提供保护）。machine、compiler、format 都无法与 against media failure 构成"防备介质故障"的语义。

**B2. A — since（自从）**

增量备份只保存"自上次备份以来发生变化的那些数据"，`the data that has changed since the previous backup`。逻辑是时间起点：`since`（自从）引出变化的起点；unless（除非）、before、into 均无法表达"从上次备份之后"的起点。

**B3. B — automatically（自动地）**

`must run ____ on a schedule`＝"情态动词 + 动词原形 + 空"，动词后有宾语潜位，此处是副词修饰动词语气；后文 `on a schedule`（按计划）暗示不是人手操作，而是**自动**运行。manually 与"按计划自动"相反；secretly、rarely 无此语境。

**B4. B — tested（被测试、被校验）**

`must be periodically ____ to confirm it can actually be used`：`be + 过去分词`被动结构，且 to confirm（确认可用）提示是"验证、测试恢复出来的数据"，故 `tested`。deleted（删除）语义相反，encrypted（加密）、inherited（继承）均与"确认可用"无关。

**B5. C — disaster（灾难）**

`survive a fire or other ____`＝"介词 + 名词"，备灾语境里"火灾或其他**灾难**"，固定表达 `other disaster`。milestone（里程碑）、register（寄存器/注册）、argument（实参/论点）均不是"消防与离线副本要防的灾害"。

**C1. B — server**

`The process sends the request to the server, and it responds with a cached copy.` 后半句主语 `it` 与 `responds`（回应）匹配——发出回应的是 server（服务器），不是 process。找指代：向前找到最近、单复数一致的能"respond"的名词→server。

**C2. A — retrieved（被取回）**

主语 `The data` 是动作承受者（数据是被取回的），且空格后有介词短语 `from the file server`，二者之间应是被动分词短语：`The data retrieved from the file server`。`retrieving`（主动）错——数据不会主动去取东西；`to retrieve`、`retrieves` 使句子缺谓语、真正谓语应靠在句中判断。此空考"分词后置定语/被动"这一最小语法卡。
