# 11 专业英语

> **分值地位**：基础知识第 71–75 题通常固定为一篇 IT 主题英文短文、5 个完形填空，共 **5 分（约占上午卷 6.67%）**。它不单独对应下午案例大题，但题号固定、选项明确，是很值得争取的稳定分。
>
> **学习目标**：学完本课后，你能——① 不逐字翻译也能快速判断短文主题；② 用“词性—搭配—逻辑—专业知识”四层筛选选项；③ 掌握软件工程、数据库、网络安全、云计算和 AI 的高频词；④ 避开 `actual`、`execute`、`library`、`argument` 等“看着眼熟却容易译错”的词；⑤ 在 5–7 分钟内完成一组 5 空专业英语题，并说出每个答案的文本依据。

## 第一部分 本课导航

### 1. 本章究竟考什么

专业英语不是单独考语法，也不是要求翻译整篇文章。它把三种能力揉在一起：

1. **专业知识**：知道 requirement、transaction、encryption、scalability 等概念；
2. **英文搭配**：知道 `comply with`、`be responsible for`、`rather than` 怎样搭配；
3. **上下文推理**：能根据因果、转折、同义复现判断空格含义。

常见主题包括：软件工程与测试、面向对象与设计模式、数据结构与数据库、操作系统与网络、信息安全，以及 cloud、AI、machine learning 等新技术。

### 2. 本章与已有课程的联动

英文题常常只是把你学过的中文结论换一种语言表达。例如：

- `high cohesion and low coupling` = 高内聚、低耦合；
- `a transaction is atomic` = 事务具有原子性；
- `only Load/Store instructions access memory` = 只有 Load/Store 指令访存；
- `a digital signature provides authentication and non-repudiation` = 数字签名提供身份认证和不可否认性。

所以专业英语的本质是：**用英文识别熟悉的计算机知识**，不需要把自己训练成文学翻译。

### 3. 建议得分目标与时间

| 当前基础 | 第一目标 | 做题时间 |
|---|---:|---:|
| 英语较弱 | 先保 3/5 | 7 分钟内 |
| 一般 | 稳定 4/5 | 5–6 分钟 |
| 较好 | 冲 5/5 | 4–5 分钟 |

做题顺序：先读本章解题法和词汇表，再做 3 篇课后完形，最后限时做精华题。

## 第二部分 讲义（通俗讲解）

## 第一节 五步解题法：不要从第一个空开始硬翻 ★★★

### 1.1 第一步：扫读主题

先用 20–30 秒读首句、末句和重复出现的名词，回答：“这段在讲什么？”

例如反复出现 `requirements, stakeholders, traceability, test cases`，主题大概率是**需求工程**；反复出现 `model, training data, prediction, overfitting`，主题就是**机器学习**。

知道主题后，大脑会自动缩小词义范围。`model` 在 AI 文章中通常是“模型”，在软件工程中也可能是“开发模型”，不能一看到就只译成“模特”。

### 1.2 第二步：先判词性，再看词义

空格前后的结构会直接淘汰一半选项：

| 线索 | 空格常需什么 | 例子 |
|---|---|---|
| `a/an/the + ___` | 名词，或形容词+名词 | an **interface** |
| `be + ___` | 形容词、过去分词或现在分词 | is **reliable** |
| `to + ___` | 动词原形 | to **reduce** cost |
| `can/must/should + ___` | 动词原形 | can **detect** errors |
| `___ + noun` | 形容词或名词作定语 | **secure** channel |
| `verb + ___` | 名词/代词作宾语，或副词修饰动词 | improve **quality** |
| `one of the + ___` | 复数名词/最高级+复数名词 | one of the **methods** |

**反例前置**：句子 `The system can ___ failures.` 中，若选项有 `detection`（名词）和 `detect`（动词），即使两个都认识，也只能选 `detect`。情态动词 `can` 后必须接动词原形。

### 1.3 第三步：检查固定搭配

专业英语里很多答案不是“意思勉强通顺”就行，而是搭配固定：

| 搭配 | 含义 |
|---|---|
| be responsible **for** | 对……负责 |
| depend/rely **on** | 依赖 |
| comply **with** | 遵守、符合 |
| consist **of** | 由……组成 |
| prevent A **from** doing B | 防止 A 做 B |
| protect A **from/against** B | 保护 A 免受 B |
| be divided **into** | 被分成 |
| contribute **to** | 有助于、导致 |
| result **in** | 导致某结果 |
| result **from** | 由某原因引起 |
| be compatible **with** | 与……兼容 |
| have access **to** | 有权/能够访问 |
| in terms **of** | 在……方面 |
| rather **than** | 而不是 |

**反例**：`The failure results ___ data loss.` 应填 `in`，因为后面是结果；`Data loss results ___ the failure.` 才填 `from`，因为后面是原因。口诀：**result in 去结果，result from 找来源**。

### 1.4 第四步：寻找逻辑信号

| 关系 | 常见信号词 | 做题动作 |
|---|---|---|
| 转折 | but, however, although, while, whereas | 前后意思通常相反或对比 |
| 因果 | because, since, therefore, thus, so, as a result | 找原因与结果 |
| 递进 | moreover, furthermore, in addition | 后句延续同方向 |
| 举例 | for example, such as, including | 后面解释前面的类别 |
| 换言 | in other words, that is | 前后近义解释 |
| 条件 | if, unless, provided that | 判断条件成立与否 |
| 对照 | rather than, instead of, on the other hand | 排除相反项 |

例：`The algorithm is accurate; however, it is computationally ___.` `however` 表示转折，前面夸“准确”，后面通常指出缺点，故应考虑 `expensive`（计算开销大），而不是 `efficient`。

### 1.5 第五步：代回全文，做三项检查

每空选完后，不要立刻交卷。把答案代回去检查：

1. 语法是否完整；
2. 专业结论是否正确；
3. 全段逻辑是否自洽。

如果两个词都通顺，优先选能与上下文形成**复现或照应**的词。例如前文说 `users report problems quickly`，后文出现 `shortens the feedback ___`，通常选 `cycle`，因为快速报告问题会缩短反馈周期。

### 1.6 完整演示：把五步走完一整篇 5 空题

> 练习全篇：先自己试做下面这篇（不列选项先想一遍词性与意思），再对照"思考痕迹"。这篇同时也作为本课"真题标杆"短文的范本。

**短文（主题：软件测试）**：
> Software testing is the process of finding defects before software is delivered to users. A well-designed test case consists of input values, the environment in which they run, and the expected **(1)**, so that an actual result can be compared with it. Good test suites cover normal inputs as well as **(2)** cases, such as boundary values and invalid data. Because a defect discovered late is far more **(3)** to fix, testing is carried out throughout the life cycle instead of only at the end. Automated tests can be executed repeatedly at low cost, which is why teams keep a **(4)** test suite to ensure that recent changes do not **(5)** already-working behavior.

**逐空思考痕迹（每一次动手前先背口诀：扫主题—判词性—看搭配—找逻辑—代回读）**：

- **(1) A. output　B. quickly　C. implemented　D. removable**
  先判词性：`the expected ____`＝"定冠词 + 形容词 + 空"，所以空里应填**名词**。四个选项只有 `output`（输出结果）是名词；`quickly` 是副词、`implemented`/`removable` 都是分词/形容词。→ 选 **A**。
- **(3) A. expensive　B. portable　C. automatic　D. shared**
  找逻辑：句首 `Because` 是因果信号，"后期才发现的缺陷"通常是**修复成本更高**，所以选 `expensive`（昂贵的）。它是形容词，也满足 `far more + 形容词 + to fix` 的结构。→ 选 **A**。
- **(5) A. break　B. encrypt　C. compile　D. measure**
  判词性：`do not ____ already-working behavior`，情态/助动词 `do` 后应接**动词原形**；四个都能作动词原形，再看语义——"确保最近改动不**破坏**已正常工作"，`break`（破坏）最贴。→ 选 **A**。
- **(2) A. unusual　B. encrypted　C. affordable　D. broken**
  先判词性：`____ cases` 是"形容词 + 名词"的结构，四个都能当形容词。这时**不要硬猜词义，用逻辑与共现**：`normal inputs as well as ____ cases, such as boundary values and invalid data`——`as well as` 表示加一种**有别于正常**的情况，后面举例"边界值、非法数据"，所以选 `unusual`（不寻常的）。`encrypted`（加密的）与测试用例边界无关，`affordable`/`broken` 均无该语境。→ 选 **A**。
- **(4) A. regression　B. routing　C. symmetric　D. remote**
  **这一步示范"先跳过空"**：如果刚看完前几句一时判断不了，不要耗时间，先标号跳过，做完后面再回来。最后一句 `ensure that recent changes do not break already-working behavior`（确保近期改动不破坏已工作的行为），正是**回归测试**要防的事，固定术语是 `regression test suite`（回归测试套件）。其余 `routing`（路由）、`symmetric`（对称的）、`remote`（远程的）都无法与 test suite 组成此专业搭配。→ 回到 **(4)** 选 **A**。

**代回检查**：把 A、A、A、A、A 逐个代回读一遍——每空语法完整、专业结论正确、段落逻辑自洽（先讲测试目的→测试用例构成→覆盖正常与非常规→因因果强调尽早测试→自动化与回归）。五步收工。

**应试动作**：(1)(2)(3) 靠**判词性 + 找逻辑**，(4) 靠**搭配 + 先跳过 + 代回读**，(5) 靠**判词性**。把它们分别标到这类题上，就能在两分钟内做完一组 5 空。

## 第二节 软件工程高频词 ★★★

### 2.1 开发过程与需求

| English | 中文 | 常见搭配/辨析 |
|---|---|---|
| requirement | 需求 | functional/non-functional requirement |
| requirements elicitation | 需求获取 | elicit requirements from stakeholders |
| stakeholder | 利益相关者 | 用户、客户、管理者等 |
| specification | 规格说明 | requirements specification |
| feasible / feasibility | 可行的 / 可行性 | feasibility study |
| lifecycle | 生命周期 | software development lifecycle, SDLC |
| iteration / increment | 迭代 / 增量 | iterative and incremental development |
| prototype | 原型 | clarify unclear requirements |
| deliverable | 可交付成果 | each phase produces deliverables |
| traceability | 可追踪性 | trace requirements to test cases |
| baseline | 基线 | approved baseline |
| configuration management | 配置管理 | control versions and changes |

必背句：

- A prototype helps users **clarify requirements**. 原型帮助用户明确需求。
- Traceability links requirements **to** design elements and test cases. 可追踪性把需求与设计、测试用例关联起来。
- The spiral model emphasizes **risk analysis**. 螺旋模型强调风险分析。
- Agile development welcomes changing requirements and delivers software in short **iterations**. 敏捷开发接纳需求变化，以短迭代交付。

### 2.2 设计与质量

| English | 中文 | 一眼识别 |
|---|---|---|
| cohesion | 内聚 | within a module |
| coupling | 耦合 | between modules |
| maintainability | 可维护性 | easy to analyze/change/test |
| reliability | 可靠性 | failure-free operation |
| availability | 可用性 | ready for use when needed |
| usability | 易用性 | easy to learn and operate |
| portability | 可移植性 | move across environments |
| scalability | 可伸缩性 | handle growing workload |
| reusability | 可复用性 | reuse components |
| modularity | 模块化 | divide into manageable modules |

高频结论：Good design aims for **high cohesion and low coupling**（高内聚、低耦合）。

**易错反例**：`availability` 在系统质量中不是普通的“有没有货”，而是“系统需要时可用的概率/能力”；`reliability` 强调一段时间内无故障运行。系统可能很可靠但修复极慢，长期可用性仍受影响。

### 2.3 测试与维护

| English | 中文 |
|---|---|
| verification | 验证：产品是否按规格正确构建（Are we building the product right?） |
| validation | 确认：产品是否满足用户真正需要（Are we building the right product?） |
| unit testing | 单元测试 |
| integration testing | 集成测试 |
| system testing | 系统测试 |
| acceptance testing | 验收测试 |
| regression testing | 回归测试 |
| test case / test suite | 测试用例 / 测试套件 |
| defect / fault / bug | 缺陷、故障、错误 |
| debugging | 调试、定位并修复缺陷 |
| corrective maintenance | 改正性维护 |
| adaptive maintenance | 适应性维护 |
| perfective maintenance | 完善性维护 |
| preventive maintenance | 预防性维护 |

**反例**：testing 和 debugging 不是同义词。Testing 的目标是**发现缺陷**，debugging 的目标是**定位原因并修复缺陷**。

**应试动作**：软件工程词先背三组：`requirement–stakeholder–traceability`；`cohesion–coupling–maintainability`；`verification–validation–regression testing`。看到英文定义时先回忆对应中文考点，再选词。

## 第四节 数据库、操作系统与网络词汇 ★★★

### 4.1 数据库

| English | 中文 | 典型表达 |
|---|---|---|
| relation / tuple / attribute | 关系 / 元组 / 属性 | table / row / column |
| primary key / foreign key | 主键 / 外键 | uniquely identify / reference another table |
| constraint | 约束 | integrity constraint |
| normalization | 规范化 | reduce redundancy |
| redundancy | 冗余 | duplicated data |
| transaction | 事务 | a logical unit of work |
| atomicity | 原子性 | all or nothing |
| consistency | 一致性 | valid state to valid state |
| isolation | 隔离性 | concurrent transactions appear independent |
| durability | 持久性 | committed changes survive failures |
| concurrency control | 并发控制 | locks, serializability |
| commit / rollback | 提交 / 回滚 | make permanent / undo |
| query / retrieve | 查询 / 检索 | retrieve rows from a table |

ACID 识别句：

- `either all operations occur or none do` → atomicity；
- `concurrent transactions do not interfere improperly` → isolation；
- `committed data survives a crash` → durability；
- `constraints remain satisfied` → consistency。

### 4.2 操作系统

| English | 中文 |
|---|---|
| process / thread | 进程 / 线程 |
| scheduling | 调度 |
| mutual exclusion | 互斥 |
| synchronization | 同步 |
| semaphore | 信号量 |
| deadlock / starvation | 死锁 / 饥饿 |
| virtual memory | 虚拟存储 |
| page fault | 缺页 |
| page replacement | 页面置换 |
| file system | 文件系统 |
| device driver | 设备驱动程序 |
| interrupt | 中断 |

`process` 在操作系统中是“进程”，但作普通动词是“处理”。要用句子位置判断：`a running process` 是名词；`the server processes requests` 是动词。

### 4.3 网络

| English | 中文 | 典型词组 |
|---|---|---|
| packet / frame / segment | 分组 / 帧 / 报文段 | network/data-link/transport layer |
| routing | 路由选择 | select a path |
| forwarding | 转发 | send to next hop |
| bandwidth | 带宽 | capacity per unit time |
| latency | 时延 | time taken to travel/respond |
| throughput | 吞吐率 | actual delivered rate |
| congestion | 拥塞 | too much traffic |
| reliable delivery | 可靠交付 | acknowledgment and retransmission |
| connection-oriented | 面向连接 | TCP |
| connectionless | 无连接 | UDP/IP |

**易错反例**：bandwidth 和 throughput 不等价。Bandwidth 像公路理论车道容量，throughput 是实际每秒通过多少车；latency 是一辆车从起点到终点花多久。

**应试动作**：数据库重点背 ACID 的英文定义；操作系统重点背 process/thread、deadlock、page fault；网络重点背 bandwidth/throughput/latency 三分法。

## 第五节 信息安全、云计算与 AI 词汇 ★★★

### 5.1 信息安全

| English | 中文 | 识别句 |
|---|---|---|
| confidentiality | 机密性 | prevent unauthorized disclosure |
| integrity | 完整性 | prevent/detect unauthorized modification |
| availability | 可用性 | accessible when needed |
| authentication | 身份认证 | verify identity |
| authorization | 授权 | determine permitted actions |
| non-repudiation | 不可否认性 | prevent denial of an action |
| encryption / decryption | 加密 / 解密 | plaintext ↔ ciphertext |
| symmetric / asymmetric | 对称 / 非对称 | shared key / public-private key pair |
| hash / digest | 哈希 / 摘要 | fixed-length, one-way |
| digital signature | 数字签名 | private key signs, public key verifies |

**反例**：authentication 回答“你是谁”，authorization 回答“你能做什么”。已经登录成功只说明通过认证，不代表有权访问所有资源。

### 5.2 云计算

| English | 中文 |
|---|---|
| on demand | 按需 |
| resource pooling | 资源池化 |
| elasticity | 弹性伸缩，随负载快速增减资源 |
| scalability | 可伸缩性，处理增长负载的能力 |
| virtualization | 虚拟化 |
| virtual machine / container | 虚拟机 / 容器 |
| infrastructure/platform/software as a service | IaaS / PaaS / SaaS |

| fault tolerance | 容错 |

三种服务模型用“谁管理得更多”来记：

- IaaS：提供基础设施，用户还要管操作系统和应用；
- PaaS：提供运行平台，用户重点管应用和数据；
- SaaS：直接使用应用，提供商管理最多。

### 5.3 AI 与机器学习

| training / inference | 训练 / 推理 | learn parameters / make predictions |
| training set / validation set / test set | 训练集 / 验证集 / 测试集 | 学习 / 调参 / 最终评估 |
| feature / label | 特征 / 标签 | input property / target |
| supervised learning | 监督学习 | labeled data |
| unsupervised learning | 无监督学习 | discover structure without labels |
| classification / regression | 分类 / 回归 | 离散类别 / 连续数值 |
| overfitting / underfitting | 过拟合 / 欠拟合 | 记住噪声 / 模型过于简单 |
| generalization | 泛化 | 对未见数据的表现 |
| accuracy / precision / recall | 准确率 / 精确率 / 召回率 | 三个指标不可混用 |

必背句：A model that performs well on training data but poorly on unseen data is **overfitting**（训练集好、陌生数据差，就是过拟合）。

**应试动作**：安全题先分“身份 authentication / 权限 authorization / 保密 confidentiality / 防篡改 integrity”；云题抓 `on-demand, elasticity, service`；AI 题抓 `training, prediction, unseen data, overfitting`。

## 第八节 长句拆解：只抓主干，不被修饰成分拖走 ★★

专业短文常把条件、定语从句塞进一句话里。拆句只做三件事：找主语 S、谓语 V、宾语/表语 O/C。

例句：

> A cache, which stores recently accessed data, reduces the time that the processor spends waiting for main memory.

先去掉两个修饰成分：

- `which stores recently accessed data` 修饰 cache；
- `that the processor spends waiting for main memory` 修饰 time。

主干只剩：`A cache reduces the time.`（Cache 减少时间。）

再把修饰补回：Cache 保存最近访问的数据，从而减少处理器等待主存的时间。

拆句的难点来自三类结构，下面把"最小语法"补一张四卡 + 三个示范，让你不必死记专业语法书。

### 8.1 四张最小语法卡

**卡①　五大基本句型**：任何句子必有主语 S + 谓语 V，它是哪种句型看谓语后面还跟什么：

| 句型 | 结构 | 示例（先看 V 后有什么） |
|---|---|---|
| S+V | 主+谓 | The process runs. 进程运行。 |
| S+V+O | 主+谓+宾 | The server sends a packet. 服务器发送分组。 |
| S+V+C | 主+谓+表语 | The system is reliable. 系统是可靠的。 |
| S+V+O+O | 主+谓+双宾语 | The cache gives the CPU data. 缓存把数据给 CPU。 |
| S+V+O+C | 主+谓+宾+宾补 | We call this object an instance. 我们把这个对象称为实例。 |

判别口诀：**"先找 V（谓语），它后面有没有宾语 O，宾语后面是否还跟一个词/句说明 O（宾补 C）"**。真题里出现频率最高的是 S+V+O 与 S+V+C（系动词 be 后接表语）。

**卡②　被动语态 = be + 过去分词**：主语是动作的**承受者**。抓法：`is/are/was/were/has been/be + 过去分词（-ed 或不规则）`。例：`Data is transferred over the network.`（数据被通过网络传输）。
反例：`The file is downloading`（下载中，现在进行，-ing）≠ `The file is downloaded`（已被下载，被动）。看到 `be + ___` 的空格，选项里 `-ed` 与 `-ing` 二选一时，若主语承受动作就选 `-ed`。

**卡③　分词作后置定语**：名词后面直接跟短语修饰它，分词两兄弟分工明确：
- 现在分词 `-ing`：表**主动、正在进行**（相当于 something that does…）→ `the process running in background`（正在后台运行的那个进程）；
- 过去分词 `-ed`：表**被动、已完成**（相当于 something that is done）→ `the data sent`（被发送的那些数据）。

判别：看名词与动作的关系——名词主动去做用 `-ing`，名词被动承受用 `-ed`。反例：`the data sending`（数据在"主动发送别人"）是病句，数据是被发送的，应写 `the data sent`。

**卡④　代词指代**：`it / they / which / that` 往前找一个名词作指代对象。找法：**向前找到最近的、单复数与代词一致的那个名词**。
例：`The client sends the request to the server, and it processes it.` 两个 `it` 指不同对象——前一个 `it` 指 server（它处理请求），后一个 `it` 指 request。反例：硬把 `it` 指回句首 `client`，会误读成"客户端处理它自己发出的请求"。

### 8.2 三个难句拆解示范

**示范 1　被动句**：`The bandwidth of a link is shared by all active users.`
拆：先找 `be + 过去分词` = `is shared`，所以是被动句；主语是 `The bandwidth`，`by` 引出动作执行者 `all active users`。主干"带宽被所有活跃用户共享"，翻译别写成"带宽共享所有用户"。**被动句的关键是分清承受者（主语）与执行者（by 后面的名词）**。

**示范 2　插入语（逗号夹层）**：`The server, after receiving the request, replies with the stored data.`
拆：划掉逗号之间的插入 `after receiving the request`，主干 `The server replies with the stored data.`（服务器用存储的数据回复）；再把插入补回：服务器在收到请求之后回复。**插入语不一定是定语，也可能是时间/伴随状语，先划掉再读主干最稳**。

**示范 3　代词指代（含对比）**：`Each thread shares the process's memory, whereas different processes do not; instead each process has its own address space.`
拆：`whereas` 表对比，前半句主干 `Each thread shares the memory`（每个线程共享进程的内存），后半句 `each process has its own address space`（每个进程有它自己的地址空间）。`its` 指 `each process`，不要指回 `thread`。**对比结构里，`its/they` 常指对比另一侧的名词，回看单复数与就近名词**。

常见从句信号：

- `which/that/who`：通常引出修饰前面名词的定语从句；
- `when/if/unless`：条件或时间；
- `because/since`：原因；
- `so that/in order to`：目的；
- `while/whereas`：对比。

**反例**：不要遇到 `that` 就翻成“那个”。在 `the data that the client sends` 中，that 只连接定语从句，整体是“客户端发送的数据”。

**应试动作**：长句先圈谓语动词，再找谁做这个动作。括号、逗号之间的插入说明可以暂时划掉，先读主干，再逐层加回。

## 第五部分 答案与解析

### Passage 1 答案与解析

**1. A — testable（可测试的）**

句子结构是 `clear, consistent, and ___`，空格与两个形容词并列，也应填形容词。后面的 `so that testers can determine whether...` 直接解释：需求要能让测试人员判断是否满足，所以是 testable。B invisible（不可见的）、C temporary（临时的）、D accidental（偶然的）都与高质量需求相反或无关。

**2. B — identify（识别、确定）**

`to + 动词原形`，四项词性都可，需看专业含义。需求获取时，分析人员与利益相关者沟通，是为了确定真实需求，故 `identify their real needs`。delete（删除）、encrypt（加密）、compile（编译）均不符合需求获取任务。

**3. A — management（管理）**

固定专业搭配是 `configuration management`（配置管理），用于版本和变更控制。其余三项无法与 configuration 组成此处所需概念。

**4. B — assess（评估）**

追踪矩阵把需求连接到设计和测试，因此能更容易评估一次变更会影响哪些内容，即 `assess the impact`。postpone 是推迟，hide 是隐藏，randomize 是随机化。

**5. B — feedback（反馈）**

原型的常见目的，是尽早让用户看到并反馈，从而降低需求不确定性。`obtain feedback from users` 是固定而自然的搭配。bandwidth、ciphertext、deadlock 分属网络、安全和操作系统语境。

全文意译：需求工程负责发现、记录和维护系统应做什么。好需求应清晰、一致且可测试。分析人员通过沟通识别真实需求；已批准需求纳入配置管理。可追踪矩阵帮助评估变更影响，原型帮助尽早获得用户反馈。

### Passage 2 答案与解析

**6. A — do**

`either all operations take effect or none do` 中，do 代替前面重复的 `take effect`。若写 `none are/have/make`，句子缺少合适的补足成分或搭配不成立。专业含义是原子性“要么全做，要么全不做”。

**7. A — intermediate（中间的）**

并发事务不应看到另一个事务尚未完成时的不恰当中间状态。`intermediate states` 与 isolation 的定义完全对应。permanent（永久的）、public（公开的）、graphical（图形的）都不是隔离性要避免的核心问题。

**8. A — failures（故障）**

持久性意味着事务一旦提交，即使系统发生故障，结果也能保留，固定表达是 `survive system failures/crashes`。query、index、schema 本身不是持久性定义中的灾害事件。

**9. B — ciphertext（密文）**

加密用密钥把 plaintext（明文）变成 ciphertext（密文）。metadata 是元数据，bandwidth 是带宽，source code 是源代码。

**10. C — modification（修改、篡改）**

Hash 摘要用于检测数据是否被修改，对应完整性；后一句又明确说它本身不能保密。compression、allocation、scheduling 分别是压缩、分配、调度。

全文意译：事务把多个操作组合成一个逻辑工作单元。原子性保证全做或全不做；隔离性避免事务看到不合适的中间状态；持久性保证提交结果能经受系统故障。加密把明文变密文以保密，Hash 摘要用来检测篡改，两者目的不同。

### Passage 3 答案与解析

**11. A — changes（变化）**

弹性是随工作负载变化而扩缩容量，`as the workload changes` 语法、语义都成立。其余选项虽是 IT 动词，但 workload 不会“解密、继承或提交”。这是典型的“专业词看似都认识，主谓搭配决定答案”。

**12. B — Internet**

SaaS 应用通过互联网交付给用户。compiler、register、semaphore 分别属于编译、CPU/程序设计和操作系统领域，无法作为应用交付网络。

**13. A — programmed（编程规定）**

机器学习的经典表述是：从样例中学习，而不是为每种情况显式编程，即 `explicitly programmed`。`instead of` 已给出对照逻辑。

**14. C — sets（集合）**

固定术语是 `training set` 和 `test set`。这里前面同时修饰 training and test，故用复数 sets。locks、keys、frames 分别属于并发控制、安全和网络。

**15. B — overfitted（过拟合的）**

题干定义“记住训练数据噪声，但在新数据上表现差”，正是 overfitting。portable 是可移植，atomic 是原子的，serialized 是串行化的。

全文意译：云计算按需提供共享资源，弹性允许容量随负载变化。IaaS 中客户管理操作系统和应用，SaaS 中提供商管理大部分技术栈。机器学习从样例中学习；训练集用于学习，测试集用于评估未知数据表现。记住噪声而无法泛化就是过拟合。

### 综合阅读题答案

**16.** `deployed` 在这里是“**部署、上线**”，即把新版本放到实际运行环境中，不是普通的“展开”。

**17.** 证据是 `CPU utilization remained moderate`，即 CPU 利用率仍处于中等水平，没有接近饱和。

**18.** 一个高频查询因为迁移时删除了有用索引，只能**全表扫描 Orders 表**；请求增多时数据库时延随之上升。

**19.** 把该查询加入回归测试套件，是为了在以后修改后重新检查这个已修复场景，防止同类性能退化再次出现。Regression testing 的核心是确认变更没有破坏已有正确功能或重新引入旧缺陷。

**20.** 还包含预防未来问题。文本依据是团队更新部署检查清单，要求 `future schema changes would be reviewed before release`，即今后的数据库模式变更要在发布前审查。这不是只恢复当前索引，而是建立预防措施。

### 精华题答案与解析

**1. B — frequently**

持续集成要求开发者**频繁**把小改动合入共享仓库。rarely 与 continuous 的思想相反；secretly、accidentally 不符合工程实践。

**2. A — feedback**

测试失败后团队立即收到反馈，固定搭配 `receive rapid feedback`。后文 `can correct the problem while the change is still small` 说明快速反馈的价值。

**3. A — detect**

结构是 `make problems easier to + 动词原形`。CI 让集成问题更易被发现和定位，`detect and locate` 语义并列。manufacture（制造）、postpone（推迟）、authorize（授权）均不合逻辑。

**4. B — automatically**

后面 `without requiring manual steps` 是直接同义提示：不需要人工步骤，就是自动运行。A manually 与后文矛盾；visually、separately 无此照应。

**5. A — expensive**

缺陷拖到后期通常修复成本更高。`more + adjective + to fix` 需要形容词，四项词性都可以，但只有 expensive 与“早发现降低风险”的因果关系一致。

精华短文意译：持续集成要求频繁合并代码，每次变更触发自动构建和测试。快速反馈让团队趁改动还小时修复问题。CI 不保证零缺陷，但能让集成问题更易发现和定位。可重复的构建、自动测试和尽早发现缺陷能降低后期修复成本。

**6. B**

Authentication 是“确认你是谁”，authorization 是“确认你被允许做什么”。其他三项分别属于压缩、调度、路由，不是权限控制。

**7. A**

高内聚、低耦合是良好模块化设计的核心目标：模块内部职责紧密，模块之间依赖尽量少。B、C、D 均不以 cohesion/coupling 描述。

### 补充题答案

**B1. A — protection（保护）**

`little ____ against media failure`＝"形容词 + 名词"，空里需名词；`against` 引出要防备的对象，固定搭配是 `provide protection against`（针对……提供保护）。machine、compiler、format 都无法与 against media failure 构成"防备介质故障"的语义。

**B2. A — since（自从）**

增量备份只保存"自上次备份以来发生变化的那些数据"，`the data that has changed since the previous backup`。逻辑是时间起点：`since`（自从）引出变化的起点；unless（除非）、before、into 均无法表达"从上次备份之后"的起点。

**B3. B — automatically（自动地）**

`must run ____ on a schedule`＝"情态动词 + 动词原形 + 空"，动词后有宾语潜位，此处是副词修饰动词语气；后文 `on a schedule`（按计划）暗示不是人手操作，而是**自动**运行。manually 与"按计划自动"相反；secretly、rarely 无此语境。

**B4. B — tested（被测试、被校验）**

`must be periodically ____ to confirm it can actually be used`：`be + 过去分词`被动结构，且 to confirm（确认可用）提示是"验证、测试恢复出来的数据"，故 `tested`。deleted（删除）语义相反，encrypted（加密）、inherited（继承）均与"确认可用"无关。

**B5. C — disaster（灾难）**

`survive a fire or other ____`＝"介词 + 名词"，备灾语境里"火灾或其他**灾难**"，固定表达 `other disaster`。milestone（里程碑）、register（寄存器/注册）、argument（实参/论点）均不是"消防与离线副本要防的灾害"。

**C1. B — server**

`The process sends the request to the server, and it responds with a cached copy.` 后半句主语 `it` 与 `responds`（回应）匹配——发出回应的是 server（服务器），不是 process。找指代：向前找到最近、单复数一致的能"respond"的名词→server。

**C2. A — retrieved（被取回）**

主语 `The data` 是动作承受者（数据是被取回的），且空格后有介词短语 `from the file server`，二者之间应是被动分词短语：`The data retrieved from the file server`。`retrieving`（主动）错——数据不会主动去取东西；`to retrieve`、`retrieves` 使句子缺谓语、真正谓语应靠在句中判断。此空考"分词后置定语/被动"这一最小语法卡。
