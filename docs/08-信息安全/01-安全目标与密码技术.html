08.1 安全目标与密码技术 ★★★

动机：先想清楚"安全"到底要保住什么，后面每个技术（加密、签名、防火墙）才能对号入座——每个安全技术都是为了守住某一条安全属性而生的。

1.1 五大安全属性

属性 含义 一句话理解 被谁破坏
机密性 信息不泄露给未授权者 偷看不得 截获/窃听
完整性 信息不被未授权篡改 改动不得 篡改
可用性 授权用户要用时能用 想用就能用 中断（如 DoS）
不可否认性 发过的话不能赖账 赖账不得 伪造/抵赖
可控性 对信息传播与内容具有控制能力 流传范围可控 越权传播

选择题最爱的配对：截获→机密性；篡改→完整性；中断→可用性；伪造→真实性/不可否认性。记法："看（截获）改（篡改）断（中断）造（伪造）"对"密完可用真"。

1.2 主动攻击 vs 被动攻击 ★★★

这是历年真题反复考的二分类，判别标准只有一条：是否修改/破坏了系统中的数据和资源。

类别 特征 包含的攻击
被动攻击 只偷看，不改数据，难察觉 窃听（网络监听、搭线）、流量分析（不看内容只分析通信的模式、频率、流向）
主动攻击 动手改数据或破坏系统 篡改、伪造、伪装（冒充他人）、重放、拒绝服务 DoS / 分布式拒绝服务 DDoS

反例演示（最容易错的一道）：「流量分析」听起来很"主动"（在主动分析嘛），但它只观察通信模式、不修改任何数据，属于被动攻击。真题就爱把它混进"主动攻击"选项里。反向陷阱：「拒绝服务」听起来只是"让服务慢一点"，但它主动发起请求洪流破坏可用性，属于主动攻击。

应试动作：背判断句"只看不改是被动（窃听、流量分析），又改又砸是主动（篡改、伪造、伪装、重放、DoS/DDoS）"。考场上题干给攻击名让你分类，或给"以下不属于主动攻击的是"——找"窃听/流量分析"。

1.3 贯穿总表：「属性 → 用什么技术 → 被什么攻击」（学完全课回来自检）

把本课所有技术按"它到底守住哪个属性"串成一张表，做题时对号入座：

安全属性 用哪种技术守住 被哪种攻击破坏
机密性 加密（对称/非对称）、数字信封 窃听、流量分析（被动）
完整性 信息摘要（Hash）比对、数字签名 篡改
可用性 冗余、限流、CDN、防火墙 DoS/DDoS、资源耗尽攻击（海量请求蹭连接）
不可否认性 / 真实性 数字签名、数字证书（CA 认证身份） 伪造、伪装、抵赖
可控性 访问控制、操作审计 越权传播

一句话穿起来："加密管机密、摘要管完整、签名管真实不赖账、防火墙/限流管可用、访问控制管可控"——几乎每一章都是一个技术守一个属性、防一类攻击。考试时先问"这题在考哪个属性"，再反推用哪个技术/是哪类攻击。

第二节 对称加密与非对称加密 ★★★

动机：想把一段话保密，最直观的办法是"加密"——用一把钥匙把明文搅成乱码，收到的人用钥匙再搅回来。那钥匙怎么设计？历史上只有"同一把钥匙加又解"，直到 1976 年才有人发明"加解各用一把、成对出现"的方案。这两条技术路线就是本节主角。

2.1 对比表（选择题直接查这张表作答）

对比项 对称加密（私钥加密/共享密钥加密） 非对称加密（公钥加密/公开密钥加密）
密钥结构 加密、解密用同一把密钥 成对出现：公钥 + 私钥
密钥分发 难：必须先走秘密信道把钥匙送到对方手里 易：公钥可公开随便发，私钥自己藏着
n 人需要密钥数 n(n−1)/2 个（每两人共用一把） 2n 个（每人一对）
速度 快（约快 1～2 个数量级） 慢
加密数据量 适合大量数据 适合少量数据（密钥、摘要）
代表算法 DES（分组 64 位，有效密钥 56 位）、3DES、AES（分组 128 位，密钥 128/192/256 位）、IDEA、RC-5 RSA（基于大整数分解难题）、ECC（椭圆曲线）、ElGamal
能否数字签名／提供不可否认性 原则上不能：加解密用同一把钥匙，发送方、接收方双方都有，"签"得出来却举证不了是谁签的 能：私钥唯一，只有本人能签 → 提供不可否认性

记忆口诀：对称"一把钥匙开一把锁，双方同款"；非对称"公锁私钥一对凑，公钥上锁私钥开"。算法名归类口诀："DES、AES 是兄弟（对称），RSA 单干是公私（非对称）"——考场上认名字：带 DES/AES/IDEA 的选对称，带 RSA/ECC/DSA 的选非对称。

密钥数公式的来历（防遗忘就地展开）：n 个人两两通信都要保密，任何两人的密钥都不能与第三者相同，所以是"从 n 人里取 2 人配一把"= C(n,2) = n(n−1)/2。例如 n=10：C(10,2) = (10×9)/(2×1) = 45 把。非对称则每人只需自己的一对：n=10 → 10 对共 20 把。这个对比正说明了非对称在密钥管理上的优势。

2.2 两个方向，别拧反了（本课第一易错点）

非对称加密的两把钥匙有两种用法，方向必须刻进脑子：

用法 加密用谁 解密用谁 达到什么目的
加密（保密） 接收者的公钥 接收者的私钥 只有收方能看 → 机密性
签名（认证） 发送者的私钥 发送者的公钥 只有本人能签 → 身份真实 + 不可否认

反例演示：「甲用乙的公钥加密后发给乙」✓ 保密方向；若写成「甲用自己的公钥加密后发给乙」就错了——公钥人人都有，别人也能解开，毫无保密性。「甲用乙的私钥签名」更是无中生有——乙的私钥只有乙自己有，甲根本拿不到；签名必须用自己的私钥。

一句话锁死："想让对方独看，用对方公钥锁；想证明是自己，用自己私钥签"。

为什么对称加密做不了数字签名（本节关键一问）：签名要提供"不可否认性"——证明"这件事只有你能做、别人替不了"。对称加密里加密和解密是同一把钥匙，收发双方都握着它，那么甲乙两人谁都能用这把钥匙做出"签名效果"，事后谁也说不清到底是甲还是乙签的——举证不了、无法定责，相当于"章谁都能盖"。数字签名必须依赖私钥唯一的非对称体系：全天下只有甲持有甲的私钥，甲签出来的东西别人仿造不出，才"赖不掉"。理解这一句，就等于掌握了"数字签名为什么注定走非对称"的根本原因——考题若问"为什么对称加密不能提供不可否认性"，答密钥双方共有、无法归因到唯一签名者。

2.3 数字信封（混合加密）★★★

动机：实战里"鱼与熊掌要兼得"——对称快但钥匙难送，非对称好送但慢。办法：用对称加密保护大数据，用对方的公钥只加密那把对称密钥。这个"套了一层非对称外皮的对称密钥"就叫数字信封。

流程（以 A 发给 B）：

  1. A 生成一把一次性对称密钥 K，用 K 加密正文（快，管大数据）；
  2. A 用 B 的公钥加密 K（只加密一小段，慢也无所谓）——这就是"信封"；
  3. 把密文 + 加了密的 K 一起发给 B；
  4. B 用自己的私钥解出 K，再用 K 解开正文。

应试动作：背"对称保正文，公钥保钥匙；封谁用谁公钥，拆封谁用谁私钥"。选择题给出流程步骤让你填"用谁的什么钥"，按这句作答。DES/AES/RSA 名字归类题则直接查 2.1 对比表。
