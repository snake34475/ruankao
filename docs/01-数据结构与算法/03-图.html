01.3 图 ★★★ ​

3.0 先认图：从"一对一"到"多对多" ​

线性表是一对一（排队，前一个后一个），树是一对多（族谱，一个爸爸几个孩子），图是多对多——朋友圈里互相是好友、地铁站互相能到达、任务之间互相有依赖，都是"谁都可能认识谁"的关系。

图为什么值得单开一节：树里的"父子"关系规定了层级，所以只有前中后序那么几种走法；图里没有层级，任意两点都可能相连，于是"怎么存、怎么走、怎么找最优解"各自都变成了一类固定题型，也就是软考固定考的六块：存储、遍历、最小生成树、最短路径、拓扑排序、关键路径。

一张图 = 一堆点 + 一堆线，记作 G = (V, E)：V 是顶点（vertex）集合，E 是边（edge）集合。本课反复用下面这张图（叫它 G1，无向、无权、连通、带一个回路）：

        A ─── B
        │     │
        C ─── D ─── E

顶点 V = { A, B, C, D, E }              （5 个顶点）
边   E = { A-B, A-C, B-D, C-D, D-E }    （5 条边，无向边不写箭头）

肉眼验一下：A-B-D-C-A 这一圈首尾相接 → 图里有回路（这正是图与树的区别，树不允许有回路）。

连通分量长什么样——把「连通图」和「不连通图」并排看最清楚：

   连通图 G1（占满全图，只有 1 个分量）         不连通图（脱成 2 片）

        A ─── B                                    A ─── B        C ← 孤立点
        │     │                                    │     │
        C ─── D ─── E                              └──── D

★ 边数公式（必背两条 + 一条反推）：

  1. 无向完全图：n(n−1)/2 条边。n=5 → 5×4/2 = 10 条。
  2. 有向完全图：n(n−1) 条边（每对顶点两个方向的边都要有）。n=5 → 20 条。
  3. 反推：无向图边数最多 n(n−1)/2。边数接近这个上限 = 稠密图；远小于上限 = 稀疏图。这个判别直接决定 3.1 节用哪种存储（稠密用矩阵、稀疏用邻接表）。
扩展知识 · 组合／排列推导：无向边数为什么 ÷2（默认折叠，点开查看）

边数公式背后的原理：为什么无向要 ÷2？（组合 vs 排列）——n(n−1)/2 和 n(n−1) 只差那个「÷2」，两者本质是同一个计数问题的两种数法：从 n 个点里选 2 个，要不要分先后。

先看通用公式（k 个一组）：

  • 组合 C(n,k)（从 n 个里「不分先后」选 k 个）： C(n,k) = n! / (k!·(n−k)!)
  • 排列 P(n,k)（从 n 个里「分先后」选 k 个）： P(n,k) = n! / (n−k)!
  • 两者的桥：P(n,k) = C(n,k) × k!，也就是 C(n,k) = P(n,k) / k!。

代入 k = 2：

  • C(n,2) = n! / (2!·(n−2)!) = n(n−1) / 2　→　n=5：5!/(2·3!) = 120/12 = 10 ✓
  • P(n,2) = n! / (n−2)! = n(n−1)　→　n=5：5!/3! = 120/6 = 20 ✓

对回完全图：

含义该用哪个边数
无向完全图两点之间只有 1 条边，"来去"算同一条组合 C(n,2)（不分先后）n(n−1)/2
有向完全图A→B 与 B→A 是两条不同的边，"选谁当起点"也算区别排列 P(n,2)（分先后）n(n−1)

关键的一步：P(n,2) = C(n,2) × 2!，乘这个 2! = 2，正是无向公式里那个「÷2」的来历——无向把来、回两条折叠成一条，所以要除以 2。口诀：无向 ÷2（不分来去）、有向不 ÷2（来去两条）。

顺手钉死一个易混点：C(n, n−1) 不等于 n(n−1)。C(n, n−1) = C(n, 1) = n（"选 n−1 个"等价于"挑 1 个不要"，就 n 种）。完全图公式用的是 C(n,2)，不是 C(n, n−1)。

★ 度数定理（每年都有它的题）：无向图中所有顶点的度数之和 = 2e（e 是边数）。理由很朴素：一条边有两个端点，它给两头的度数各加 1。

  • 用 G1 验算：度数 2+2+2+3+1 = 10（A2、B2、C2、D3、E1），边数 5 → 10 = 2×5 ✓
  • 反向用（这是常见考法）："某无向图有 10 个顶点、每个顶点的度都是 4，问边数" → 度数和 = 40 = 2e → e = 20。
  • 推论（握手定理）：度数为奇数的顶点个数必为偶数。所以"给一组度数问能不能画出图"的题，第一步就数奇数度的点有几个——奇数个就直接不存在。
  • 有向图版本：入度总和 = 出度总和 = 边数（每条边恰好贡献一个入度和一个出度）。

易错点：连通 ≠ 完全。连通要求"能走到"，完全要求"直接有边"。完全图一定是连通图；连通图不必是完全图（G1 连通，但 A 和 E 之间没有直连边，所以不是完全图）。题目常把这两句换着说法让你判对错。

3.1 存储结构：邻接矩阵 vs 邻接表 ​

要解决的问题：图（点和线）怎么放进内存？两条路——把所有"谁和谁相邻"记成一张表格（矩阵），或者给每个顶点各挂一张"我的邻居"清单（链表）。

邻接矩阵：一张 n×n 的表 ​

n 个顶点就开 n×n 的二维数组，A[i][j] = 1 表示顶点 i 到顶点 j 有边，0 表示无边。G1 的邻接矩阵（顶点顺序按 A、B、C、D、E）：

        A  B  C  D  E
   A [  0  1  1  0  0 ]     ← A 与 B、C 相邻
   B [  1  0  0  1  0 ]     ← B 与 A、D 相邻
   C [  1  0  0  1  0 ]     ← C 与 A、D 相邻
   D [  0  1  1  0  1 ]     ← D 与 B、C、E 相邻
   E [  0  0  0  1  0 ]     ← E 只与 D 相邻

读法：第 i 行第 j 列为 1 ⇒ 顶点 i 与顶点 j 之间有边。行号列号的对应关系靠"顶点顺序表"记着（这里第 1～5 行分别是 A～E）。

三个可以直接考的结论：

  1. 无向图的矩阵一定对称（A 与 B 有边 ⇔ B 与 A 有边），主对角线全是 0（自己跟自己不算相邻）。
  2. 某一行上 1 的个数 = 该顶点的度。D 那行有 3 个 1 → D 的度是 3 ✓ 这也是"数度"最快的算法。
  3. 若把 1 换成边的权值 → 就是带权图的邻接矩阵（无边处记 ∞ 或 0，看题目约定）。

有向图不对称，反例先说清：若边是有向的，比如 A→B 存在、B→A 不存在，那么第 A 行 B 列为 1、第 B 行 A 列为 0 → 矩阵不对称。于是有这条判别：矩阵不对称 ⇒ 一定是有向图；矩阵对称 ⇒ 可能是无向图，也可能是"有向图但两个方向恰好都有边"（参考资料里的原话："不对称的矩阵一定是有向图，对称的矩阵可能是有向图"）。

代价：空间 O(n²)。G1 只有 5 条边却开了 25 格，浪费；顶点多时（如 1000 个顶点、10 条边）几乎全是 0，浪费更严重。优点是查"两点是否相邻"是 O(1)（直接看格子的值），以空间换时间。

邻接表：每个顶点一条"邻居清单" ​

开一个一维数组存 n 个顶点，每个顶点后面挂一条链表，链表里存它的所有邻接顶点。G1 的邻接表：

   [0] A → B → C ∧
   [1] B → A → D ∧
   [2] C → A → D ∧
   [3] D → B → C → E ∧
   [4] E → D ∧
  • 空间 O(n+e)：n 个顶点各一个表头 + 每条边在两头的链表中各出现一次（无向图），所以"边节点"总数 = 2e。G1：5 个表头 + 10 个边节点 = 15 个节点。
  • ★ 固定考点（参考资料原话）："有向图的邻接表有 n+e 个点，无向图的邻接表有 n+2e 个点。"有向图每条边只在一个链表里出现一次，所以是 n+e。这个 n+e / n+2e 是选择题的固定考法。
  • 缺点是判断两点是否相邻要从头扫链表（O(度) 而不是 O(1)）。

两种存储的正面对比（背下来） ​

对比项邻接矩阵邻接表
空间O(n²)O(n+e)
判断两点是否相邻O(1)O(n)（要扫链表）
适合的图稠密图（边接近 n(n−1)/2）稀疏图（边很少）
无向图存法对称矩阵，存一份或两倍每条边在两个链表各出现一次（2e）
数的度数扫一行 O(n)扫自己的链表 O(度)
存带权图矩阵元素直接放权值链表节点多带一个权值字段

手算口诀：稠密用矩阵、稀疏用邻接表；矩阵好查（O(1)）费空间，邻接表省空间查得慢。

还有两个"见过就行"的存储（软考偶尔在选项里出现，知道名字和用途即可）：

  • 十字链表：有向图的邻接表改良版，一条边只存一次又能同时顺着"出边"和"入边"找，专门服务有向图求入度/出度。
  • 邻接多重表：无向图的邻接表改良版，同样让每条边只存一份（邻接表里无向边要存两次），便于删除边。

应试动作：

  • 认题特征：题目给一个矩阵问"这是哪种存储/某顶点的度是多少/图是否连通"，就看行内 1 的个数（度）、是否对称（无向）。
  • 背什么：O(n²) vs O(n+e)、n+e vs n+2e、无向完全图边数 n(n−1)/2、度数和 = 2e。
  • 哪些靠算：给邻接表算某点的度、给矩阵算边数——都是"数 1"的活，别慌，慢慢数。

3.2 遍历：DFS 与 BFS（选择题必有，案例题也用） ​

要解决的问题：从某个顶点出发，怎样把整张图每个点恰好走一遍？

树为什么不用操心这个？因为树没有回路，顺着走就能不重不漏。图里有回路（G1 里 A-B-D-C-A 就是一圈），走法不当就会原地转圈。所以图遍历比树遍历多了一个必需装备：visited 标记数组，走过的点打标记，遇到打过标记的点就跳过。忘掉 visited 是本节最容易犯的错（也是判断题里最爱设计的陷阱）。

两种走法，区别只在"优先照顾哪个方向的邻居"：

DFS（深度优先遍历，Depth-First Search）：一条路走到黑 ​

策略：访问当前顶点 → 挑一个还没访问过的邻居钻进去 → 继续往下钻 → 直到某个顶点周围全是"已访问"，回退到上一个还有未访问邻居的顶点，继续钻。实现靠栈（递归写法用的就是系统栈）。

用 G1 从 A 出发（邻居按邻接表顺序取，字母小的先取）：

   G1 邻接表：  A→B→C   B→A→D   C→A→D   D→B→C→E   E→D
步动作栈（顶在右）已访问（输出序）
1A 无路可退，先访问 A、压栈AA
2A 的第一个未访问邻居 B → 访问 B、压栈A BA B
3B 的第一个未访问邻居 D → 访问 D、压栈A B DA B D
4D 的第一个未访问邻居 C → 访问 C、压栈A B D CA B D C
5C 的邻居 A、D 都访问过了 → 无路可走，弹栈回退到 DA B DA B D C
6回到 D，找它下一个未访问邻居 E → 访问 E、压栈A B D EA B D C E
7E 的邻居 D 已访问 → 无路可走，连续弹栈回退到 A，栈空，结束（空）A B D C E

DFS 序列：A B D C E

两个必须看懂的细节：

  • 第 5 步弹栈时 C 不再输出。弹栈只是"退回去找别的路"，不是"重新访问"。C 只在第 4 步被输出一次。
  • 回退的粒度是"顶点"不是"边"：C 走不通，一次退到最近的一个"还有未访问邻居"的顶点（这里是 D），不是退一步就停。

BFS（广度优先遍历，Breadth-First Search）：一圈一圈往外扩 ​

策略：先把起点的所有邻居访问完，再访问邻居的邻居……实现靠队列（先进先出，保证同层先来先服务）。

同样从 A 出发：

步动作队列（头在左）已访问（输出序）
1A 入队[A]
2出队并访问 A，把 A 的未访问邻居 B、C 入队[B, C]A
3出队并访问 B，把 B 的未访问邻居 D 入队[C, D]A B
4出队并访问 C，C 的邻居 A、D 都已访问/已在队 → 不入队[D]A B C
5出队并访问 D，把 D 的未访问邻居 E 入队[E]A B C D

BFS 序列：A B C D E

★ BFS 的关键实现细节：标记 visited 要在入队的那一刻就打，不能等出队。否则第 3 步 D 入队后，第 4 步处理 C 时看到 D 还没"被访问"（只是排队），会把 D 重复入队。判断题常拿这里做考点。

为什么 D 会被重复入队？因为"等出队才打标"留出了空窗期：D 入队时没打标记，它还挂在队列里排队。等到出队 C、C 检查邻居 D 时，标记数组里查不到 D，就误以为 D 没见过，把第二个 D 塞了进去——队列从 [C, D] 变成 [D, D]，D 就被访问了两遍。一句话记死：重复份数 = 出队前先被它邻居处理的次数；入队即打标，就是把重复份数固定成 1。

两个可以直接考的结论：

  1. 遍历序列不唯一，因为"先钻哪个邻居"没有硬性规定。所以题目若给出邻接表 + 起点 + 邻居顺序，序列才是唯一的——题干一般都会强调"按邻接表顺序访问"。反过来，"下面哪个序列不可能是某个图的 DFS/BFS 序列"这类题，要靠"同层内任意、跨层有约束"去筛。
  2. 复杂度只和存储结构有关，与 DFS/BFS 无关：矩阵 O(n²)、邻接表 O(n+e)。记住这句原话，选择题很喜欢用它做选项。
  3. 非连通图一次遍历只能走完一个连通分量；要访问全部顶点，就得对每个未访问顶点各起一次遍历 → 调用遍历的次数 = 连通分量个数。

  • 认题特征：给一个图/邻接表问"从 V1 出发的 DFS 序列"，或给序列问"是否是 DFS 序列"。看到"深度/一条路走到黑"选 DFS（栈），看到"逐层/由近及远"选 BFS（队列）。
  • 手算技巧：DFS 在草稿上画出递归的走向箭头（进去 →、回退 ←），比盯代码快；BFS 就老老实实画队列的进出。
  • 背什么：栈 ↔ DFS、队列 ↔ BFS；无权图最短路径只能靠 BFS。

3.3 最小生成树：Prim 与 Kruskal ​

要解决的问题：n 座城市要铺通信线路，任意两城能互通即可（不要求直连），怎么铺总造价最低？

这个问题有两个隐含要求，正是"生成树"的定义：要连通（否则有的城市联系不上）、要最省（能连通 n 个点最少只要 n−1 条边，多铺一条都是浪费）——再不允许有回路（有回路就说明多铺了一条线）。

生成树的四个特征（说三个就能推出第四个）：含全部 n 个顶点、恰好 n−1 条边、连通、无回路。

最小生成树（MST，Minimum Spanning Tree）：带权图中"边权之和最小"的那棵生成树。

  • ★ 权值和唯一，但树本身可能不唯一：当图里有权值相同的边时，可选的方案不止一种，但最小权值和是唯一的。这句话选择题直接考。
  • 找法思路：不管哪种算法，都是贪心——每一步都挑当前最小的边，区别只在"从哪里开始挑"。

Kruskal（克鲁斯卡尔）：加边法——"把边按长短排队，短的先上，成环就跳过" ​

一步都不用画树，纯排序 + 查环：

结果：MST = {BC 1, AC 2, CD 3, DE 4}，权值和 = 1+2+3+4 = 10，4 条边 = n−1 ✓，无回路 ✓，覆盖 A～E ✓

查环三问：先把"候选边 / 判断 / 是否选中"的顺序理顺（读表格时最容易绕晕的就是这个词序）：

  • 候选边：还没处理、排队的边。处理顺序 = 权值从小到大（1→2→3→4→5）。它只决定"先看谁"，不保证一定被选。
  • 判断：用已选中的边问一条候选边的两个端点"连没连通"。
  • 是否选中（决定，由判断推出）：两端不连通 → 选 ✔（顺带把它们接通）；两端已连通 → 跳过 ✘（加了必成环）。

一句话因果别搞反：先判断"连没连接上"，才决定"选不选"——判断是依据，"是否选中"是结果。

图上有边 ≠ 两端连通：原图上画的线只是"候选"，在没被选中之前一律不作数。"连通/不连通"只能用"已选中的边"来搭路判断。所以第 1 步开始时一条边都还没选，B、C 虽然原图上有条权 1 的线，彼此仍是孤立点 → 不连通 → 才选中 B-C。

权重管排序、连通管取舍：权重决定"谁先被判断"，但不保证被选；A-B 权重 4 不小，却因 A、B 已连通、加了会成环而被跳过，就是这个道理。

反例前置（最容易错的一步）：第 4 步 A-B 权 4 比 D-E 的 4 一样小，看着都该选——但 A 和 B 此时已经通过 A-C-B 连通了，加上 A-B 就形成回路 A-B-C-A，而生成树不许有回路，所以必须跳过。很多同学"见小的就选"，就错在这一步。Kruskal 唯一要动脑的地方就是查环：只要一条边的两个端点已经连通，就跳过。

Prim（普里姆）：加点法——"从一棵树苗开始，每次接一个最近的顶点进来" ​

Prim 不排序边，而是维护一个"已经长成的树"的顶点集合 S：

先分清"树内 / 树外"（一句话：树内 = 已经接进生成树的点，树外 = 还没接进来的点）。以第 2 步 S = {A, C} 为例：A、C 已被选中，B、D、E 还没被选中，于是 A、C 在"树内"，B、D、E 在"树外"：

   ┌────────────┐   ←── 虚线：树内/树外的分界 ──→   ┌──────────────────┐
   │  树内 S     │                                  │  树外             │
   │(已选进树)   │                                  │(还没选进树)       │
   │   A    C    │                                  │   B    D    E     │
   └────────────┘                                  └──────────────────┘

"从 S 连到集合外的所有边" = 一头在树内、一头在树外的桥（跨过虚线的边）：A-B 4、A-D 5、C-B 1、C-D 3。判断一条边算不算候选，只看它的两端是否一个在树内、一个在树外：

  • 一个树内、一个树外 → 桥，进候选比大小；
  • 两头都在树内（如 A-C 2，或某个点后来入树后的 A-B）→ 树内旧线，不算候选（自动消失，不是"查环"，而是"身份不够格"）；
  • 两头都在树外 → 等以后再说。

Prim 不用查环：因为候选桥的另一头永远是"第一次进树的新点"，它在树内没有任何其他连接，所以不可能围成环。成环的边（两端都在树内）根本不进候选。

易错点：Prim 第 2 步"从 S 连到集合外的边"要包括 S 里所有点发出的边（A-B 4 和 C-B 1 都要列出来），只盯新接进来的 C 会漏掉 A-B，可能选错。Prim 是"整个集合对外的最短边"，不是"新点的最短边"。

3.4 最短路径：BFS（无权）与 Dijkstra（带权） ​

BFS = Breadth-First Search，广度优先搜索（即广度优先遍历，3.2 已详述：按层一圈圈向外扩，用队列）。这里"近"指经过的边数最少，无权图最短路径只能靠它。 Dijkstra = 迪杰斯特拉，以发明者 Edsger Dijkstra 命名的算法（人名，无英文全称缩写）。这里"近"指边权之和最小，用于带权图。

要解决的问题：从一点到另一点怎么走最近？注意分两种"近"：

  • 无权图：边没有权值，"近"= 经过的边数最少 → 用 BFS（3.2 已述：BFS 第一次到达某点时的层数就是最少边数）。
  • 带权图（网）：边上带距离/花费/时间，"近"= 权值之和最小 → 用 Dijkstra（迪杰斯特拉）。

Dijkstra 的思路：贪心，每轮"认定"一个点 ​

一句话：每轮从"还没确定的点"里挑出当前距离最小的那个，宣布它的最短距离已定，然后用它去更新（松弛）所有邻居的距离。

  • "松弛"（relax）= 试着用新确定的点做中转：若 起点的距离 + 这条边的权 < 邻居原来的距离，就改小它。"松弛"这个词会出现在题干里，要知道它就是"试一试能不能更短"。
  • 直觉：既然所有边权都是正的，那么当前离起点最近的那个点，不可能再有别的更短路线绕到它（绕路只会花更多）——所以可以放心"认定"。这就是贪心法的立足点。

   顶点从左到右排：V1  V2  V3  V4  V5       所有箭头一律只能「从左指向右」（无环）

反向验算（必须做）：V1 到 V5 的其他可能路线：

  • V1→V2→V4→V5 = 4+7+2 = 13 > 12 ✗
  • V1→V3→V4→V5 = 6+5+2 = 13 > 12 ✗
  • V1→V3→V5 = 6+9 = 15 ✗ 所以 12 确实是最小的 ✓

这一轮最值得看的是 V3：V1 到 V3 明明有直达边权 6，但第 1 轮经 V2 中转只需 4+1 = 5，于是 d(V3) 从 6 被改小成 5。这就是"松弛"的价值，也说明了为什么每轮都要重新挑最小——不能一开始就把"直达边的权值"当成最终答案。

两个固定考点 ​

  1. Dijkstra 不能处理负权边（选择题几乎年年出）。 反例（就三个点，一眼看懂）：
    V1 ══1══▶ V2        V1 ══2══▶ V3        V3 ══(−2)══▶ V2
    真实最短路径：V1→V3→V2 = 2 + (−2) = 0。 但 Dijkstra 第 1 轮会挑中 V2（d=1）并宣布它已确定；第 2 轮才处理 V3，发现 V1→V3→V2 只要 0，比已宣布的 1 更小——算法却不会再回头改。负权边破坏了"当前最近的点不可能被绕路超越"这个贪心前提，所以 Dijkstra 失效。
  2. Floyd（弗洛伊德）求"多源"最短路径：一次算出任意两点之间的最短路径（Dijkstra 是单源：只算一个源点到其他所有点）。Floyd 是动态规划思想，三重循环实现；它可以处理负权边，但同样不能处理负权回路。 记法：单源 Dijkstra（贪心）、多源 Floyd（动态规划）。这句对照几乎每年以选项形式出现。

应试动作：

  • 认题特征：给带权有向/无向图问"源点到各点的最短距离""哪条是最短路径" → Dijkstra 表格法（画一列表格逐轮填）。
  • 手算纪律：每轮必须重新扫描所有未确定的点选最小，别凭直觉跳步；每轮松弛完把距离写清楚，便于回查。
  • 背什么：Dijkstra 是贪心、不能负权；Floyd 是多源、可负权不能负环；无权图最短路用 BFS。
  • 哪些靠算：具体的最短距离与路径必须自己算一遍（本例 12），光看答案记不住。

3.5 拓扑排序（AOV 网） ​

要解决的问题：做事情有先后依赖——"先打地基才能砌墙""先修课程 A 才能修课程 B"。怎么把一堆有依赖关系的活动排成一个合法的执行顺序？

AOV 网（Activity On Vertex Network，"顶点表示活动"的网）：顶点表示活动，有向边表示活动之间的先后约束（A→B 表示 A 必须排在 B 前面）。要求这张有向图没有回路（有回路意味着"A 要在 B 前、B 又要 A 在 A 前"，矛盾）——没有回路的有向图叫 DAG（有向无环图）。

拓扑排序：把 AOV 网的所有顶点排成一个线性序列，使得每条边都从序列的前面指向后面（若图中有 Vi→Vj 的路径，序列里 Vi 必须排在 Vj 之前）。

做法：反复挑"入度为 0"的点 ​

入度 = 有多少条边指向这个顶点（数指向它的箭头条数，不是数别人），所以入度为 0 = 没有任何前置活动——这种活现在就能干。步骤：

  1. 找一个入度为 0 的顶点，输出它；
  2. 删除它的所有出边（相当于"这件活干完了，它解锁了后面的活"）；
  3. 重复 1～2，直到所有顶点都输出。判环看两个等价信号：① 找不到入度为 0 的点（剩下的点入度都 ≥ 1）；② 输出的顶点个数 < 顶点总数。任一出现就说明有环，排序失败。

演算一遍（AOV：A→B、A→C、B→D、C→D、D→E）：

   A ──→ B ──┐
   │         ↓
   └──→ C ──→ D ──→ E

   各点入度：A 0、B 1、C 1、D 2、E 1
步本轮可输出的点（未输出、入度为 0）本轮输出（任选一个）删掉它的出边后，入度变化
1AA删掉 A→B、A→C 两条边，于是 B、C 的入度从 1 变 0
2B、CB（也可先输出 C）删掉 B→D，于是 D 的入度从 2 变 1
3CC删掉 C→D，于是 D 的入度从 1 变 0
4DD删掉 D→E，于是 E 的入度从 1 变 0
5EE无出边，结束

这张表有四处容易读错，先钉死：

  • 第 2 列不累计，只记"还没输出、且入度为 0"的点（= 现在就能开工的活）。注意 A 输出之后入度仍然是 0（我们只删了它的出边，没人给它加过入边），所以若按"所有入度为 0 的点"去累计，每一步都会把 A 带上，而且第 2 步和第 3 步会完全一样（都是 A、B、C），看不出"这一步能干什么"。已输出的点不再进入第 2 列。
  • "删掉 A→B"指的是删除这条边，不是删除顶点 A 或 B。A 已经排进序列，它当初提出的"我必须排在你们前面"这条约束随之解除，所以要把它发出去的箭头撤掉。教材标准写法是"删除该顶点及其所有出边"，与"只删出边"在算入度时等价——A 的入度为 0，本来就没有入边可删。两种说法都行，但无论用哪种，"本轮可输出的点"都只在未输出的点里找。
  • 入度是"指向我的边的条数"。指向 B 的边本来只有 A→B 这一条，删掉它，B 的入度就从 1 变成 0。这就是"删边导致入度减 1"的全部因果，中间没有别的路径。
  • "任选一个"之所以都行：两个入度为 0 的点之间不可能有边相连（只要有一条边，其中一个的入度就会 ≥ 1），所以它们互不约束，先输出谁都不违反任何规则。这正是"拓扑序列不唯一"的根源。

三条结论（选择题原话考） ​

  1. 拓扑序列不唯一：没有先后约束的点之间可以任意换位置。
  2. 图中有环 → 拓扑排序做不下去（会出现"所有剩下的点入度都 ≥ 1"的死局）。工程上正用它来检测循环依赖（比如 Makefile/编译系统报"circular dependency"）。
  3. 深度优先遍历（见 3.2 节）的"退出顺序"倒过来，也是一种合法的拓扑序列。道理：DFS 退出的时刻，某个点后面能到达的点都已经先退出了，所以把"退出顺序"倒过来看，就是"被依赖的排后面"，正好满足拓扑序。

★ 第 3 条最容易记反，单独拆开讲清。难点在"逆序"两个字没说清是对谁的逆序。用本节的图（A→B、A→C、B→D、C→D、D→E）各跑一遍：

一句话记：DFS 的退出顺序本身就是逆拓扑序，倒过来才是拓扑序。"每次取出度为 0 的点"求的是同一类东西，同样要倒过来才是拓扑序。

易错点：

  • 拓扑排序只关心入度（谁没有被依赖），别看去度去。判"是否能完成拓扑排序"用入度法最稳。
  • 拓扑排序不是排序算法（不比较大小），它只解决"先后约束"，和第五节那些排序是两码事。名字里的"排序"指的是把"部分有序"拉成一条"完全有序"的线性序列——不是按大小排，而是给出一个合法的先后次序。
  • 题干给的"先后关系"要转成边的方向："A 必须在 B 之前完成" ⇒ 边 A→B（从"前"指向"后"），画反了整题就反了。

应试动作：

  • 认题特征：题目出现"先后顺序/前置任务/课程安排/能否完成"，或直接问"下列哪个是合法拓扑序列"。
  • 判别"某个序列是否合法"的最快方法：对着题图的每条边检查一次"起点是否排在终点前面"，有一条不满足就非法。（一句话口诀："图中 A→B，序列中 A 在 B 前面；A 和 B 没有关系，序列中 A 可前可后。"）
  • 背什么：入度法三步；有环则无拓扑序；DFS 的退出顺序倒过来可行（退出顺序本身是逆拓扑序，别记反）。

3.6 关键路径（AOE 网）★★★（计算题大户） ​

要解决的问题：整个工程最快多久能完工？哪些活动一天都不能拖（拖了就拖累整体工期）、哪些活动可以摸鱼（拖几天不影响总工期）？

AOE 网（Activity On Edge Network，"活动在边上"的网）：边表示活动（边权 = 活动工期），顶点表示事件（事件的"发生"= 它所有前置活动都已完成的状态）。

  • 源点：入度为 0 的顶点，代表工程开始；汇点：出度为 0 的顶点，代表工程结束。
  • 与 AOV 网的区别一句话：AOV 边只表示先后（顶点是活动），AOE 边既表示先后又带工期（边是活动）。AOV 用来排顺序，AOE 用来算工期。

★ 读这一节卡住的人，九成卡在同一件事上：把"事件"和"活动"混了。 先把这两句话分清：

  • 顶点（事件）是一个"时刻"——"地基打完了"这个瞬间。它没有时长，只有"第几天发生"。所以 ve、vl 都是时刻。
  • 边（活动）是一段"过程"——"打地基"这件事本身，它有工期。e、l 是这条边的开工时刻。

一句话：ve、vl、e、l 全都是"几点"，只有边权是"几天"。 这条混了，后面四个量全都会用错。

★ 关键路径 = 从源点到汇点的最长路径，它的长度 = 整个工程的最短工期。

"最长"为什么反而是"最短工期"（这是本节的"动机"，理解了才不别扭）：汇点要"发生"，它前面所有的活动都得干完；而最长的那条链上一个活动都省不掉，工期不可能比它短。同时，按这条最长链去安排进度，其余活动都能塞进这个时间窗内完成，所以这个时间刚好够。上下夹住，于是最长路径长度 = 最短完工时间。

四个量、两趟推（每个事件一个 ve/vl，每个活动一个 e/l）：

"怎么算"看不懂，基本都是缺了下面这段因果——四个公式，每个都能用一句话推出来：

  • ve(v) 顺推取 max：事件 v 要"发生"，必须等所有指向它的活动都干完。每条入边给一个候选时刻 = 前驱的 ve + 该活动工期。这些候选里最晚的那个才是"全都干完了"的时刻，所以取 max。 最常见的错法：把各条入边的候选值相加（把 3+4 和 5+7 再加起来得 19）。这是错的——指向 v 的那些活动是并行进行的，不是串行，时间不该累加。"全都干完"看的是最后一个完成的时刻，也就是候选值里最大的那个。
  • vl(v) 逆推取 min：事件 v 最迟能拖到什么时候，由它的每条出边分别卡一道上界。若 v 在 t 发生、后继 u 的 vl(u) 已经定死，这条活动又必须在 vl(u) 前完工，于是 t ≤ vl(u) − 该活动工期。每条出边都卡一道，最紧的那道说了算，所以取 min。
  • e(a) = 起点的 ve：活动 a 从事件 u 出发，u 最早能在 ve(u) 发生，a 最早也就能在 ve(u) 开工——"最早开工"就是"起点最早发生"，不用再加任何东西。 注意 ve(u) 和 e(a) 数值相同，但不是同一个量：ve(u) 是顶点的属性（u 最早第几天发生），e(a) 是边的属性（a 最早第几天开工）。一个 ve(u) 会复制给从 u 出发的所有边，所以同一顶点的多条出边，e 完全相同；而指向 u 的那些入边，它们的 e 由各自的起点决定，与 ve(u) 毫无关系。想成发令枪：事件 u 发生 = 枪响，从 u 出发的所有活动同时听到枪响起跑，所以它们的 e 都等于 ve(u)。
  • l(a) = 终点的 vl − 工期：活动 a 必须让终点事件 v 不晚于 vl(v) 发生；而 a 自己要从开工一路干到完工，得花掉"工期"这么多天，所以它最迟必须在 vl(v) − 工期 开工。注意是"终点的 vl"减工期，不是起点的 vl（这是最常错的一处）。
  • 余量 = l − e：就是"最迟"和"最早"之间的缝隙，也就是这条活动能拖几天。余量 0 = 一天都不能拖 = 关键活动。

两句话背下来：顺推是"要等别人"，所以取 max；逆推是"要留给别人"，所以取 min。

★ 时间余量（松弛时间，slack）= l(a) − e(a)，余量为 0 的活动就是关键活动，把它们首尾相接就是关键路径。

三个直觉锚点（公式记不住时就想这三句）：

  1. ve 是"最早"，vl 是"最晚"。把每个事件想成时间轴上的一个点，ve 和 vl 就是两个时刻，两点之间的缝就是"可以晃悠的空间"。
  2. ve 顺推、vl 逆推。顺推从源点（第 0 天）走向汇点，算"最早"；逆推从汇点（= 总工期）走回源点，本质是"倒排工期"——总工期已经定死，每个事件最晚必须哪天发生就被倒着推出来了。
  3. 关键路径上的事件，ve 和 vl 完全重合（余量 0）；不重合的事件就有富余。活动同理：l(a) − e(a) = 0 才是关键活动。

于是关键路径有两种等价判定，做题时正好互为验算：

  • 定义法：从源点到汇点的最长路径，其长度 = 最短工期（也就是 ve(汇)）；
  • 余量法：所有余量为 0 的活动连成的通路（关键活动必然首尾相接构成一条源点到汇点的通路）。

三条必考结论 ​

  1. 关键路径可能不止一条。多条关键路径时，所有关键活动都长在关键路径上，但某条关键路径上的活动未必在另一条上，于是有了结论 2。
  2. 缩短工期必须压缩"所有关键路径的公共关键活动"。只压缩某一条关键路径上的活动，另一条关键路径长度不变，总工期纹丝不动。
    • 用本例看：a1 有余量 1，压缩它（哪怕压到 0）工期仍是 8；压 a6 才有用。
  3. 关键路径可能因"压过头"而转移：把某条关键路径压到比另一条短，最长路径就换人了，工期不再继续缩短——所以"压关键活动一定能缩短工期"这句话只在"压公共活动且没压过头"的前提下成立。选择题里"缩短任一关键活动都能缩短工期"是错的（见课后题 15）。

易错点清单：

  • 顺推取 max、逆推取 min，别记反（顺推是"要等所有前置做完才能开始"，所以取最大；逆推是"必须给所有后续留够时间"，所以取最小）。
  • l(a) = 终点的 vl 减工期。写成"起点的 vl"或"加工期"都错。
  • ve 和 vl 是事件（顶点）的量，e 和 l 是活动（边）的量，两张表别混。而且这四个量全是"时刻"（第几天），只有边权是"时长"（多少天）——ve 读作"最早第几天能开始"，不是"最早要花几天"。
  • 时间余量为 0 才是关键活动（余量不为 0 的活动还有缓冲）。

应试动作：

  • 认题特征：题干出现"AOE 网/工期/最早发生/最迟开始/时间余量" → 立刻画两张表（ve 表、vl 表），再列活动表算 e、l、余量。
  • 手算纪律：每张表算完做一次自检——ve(源)=0、vl(源)=0、vl(汇)=ve(汇)、关键活动首尾相接构成一条源→汇通路，四条全过基本就没算错。
  • 背什么：四个量的定义与"顺 max 逆 min"、余量 0 即关键、"压缩要压公共关键活动"。
  • 哪些靠算：任何一道关键路径题都必须动手列表，凭直觉猜最长路径在 4 个以上的活动时几乎必错。

跨课联动：软件工程部分（03-软件工程基础.md）里的甘特图、项目工期、总时差（松弛时间）与本节是同一套东西，只是那边用 ES/EF/LS/LF 的记号表示，本质完全一致——在这里算熟，那边直接得分。

内容一句话抓手最常考的判别点
