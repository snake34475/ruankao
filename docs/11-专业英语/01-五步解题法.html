11.1 五步解题法：不要从第一个空开始硬翻 ★★★ ​

1.1 第一步：扫读主题 ​

先用 20–30 秒读首句、末句和重复出现的名词，回答：“这段在讲什么？”

例如反复出现 requirements, stakeholders, traceability, test cases，主题大概率是需求工程；反复出现 model, training data, prediction, overfitting，主题就是机器学习。

知道主题后，大脑会自动缩小词义范围。model 在 AI 文章中通常是“模型”，在软件工程中也可能是“开发模型”，不能一看到就只译成“模特”。

1.2 第二步：先判词性，再看词义 ​

空格前后的结构会直接淘汰一半选项：

线索空格常需什么例子
a/an/the + ___名词，或形容词+名词an interface
be + ___形容词、过去分词或现在分词is reliable
to + ___动词原形to reduce cost
can/must/should + ___动词原形can detect errors
___ + noun形容词或名词作定语secure channel
verb + ___名词/代词作宾语，或副词修饰动词improve quality
one of the + ___复数名词/最高级+复数名词one of the methods

反例前置：句子 The system can ___ failures. 中，若选项有 detection（名词）和 detect（动词），即使两个都认识，也只能选 detect。情态动词 can 后必须接动词原形。

1.3 第三步：检查固定搭配 ​

专业英语里很多答案不是“意思勉强通顺”就行，而是搭配固定：

搭配含义
be responsible for对……负责
depend/rely on依赖
comply with遵守、符合
consist of由……组成
prevent A from doing B防止 A 做 B
protect A from/against B保护 A 免受 B
be divided into被分成
contribute to有助于、导致
result in导致某结果
result from由某原因引起
be compatible with与……兼容
have access to有权/能够访问
in terms of在……方面
rather than而不是

反例：The failure results ___ data loss. 应填 in，因为后面是结果；Data loss results ___ the failure. 才填 from，因为后面是原因。口诀：result in 去结果，result from 找来源。

1.4 第四步：寻找逻辑信号 ​

关系常见信号词做题动作
转折but, however, although, while, whereas前后意思通常相反或对比
因果because, since, therefore, thus, so, as a result找原因与结果
递进moreover, furthermore, in addition后句延续同方向
举例for example, such as, including后面解释前面的类别
换言in other words, that is前后近义解释
条件if, unless, provided that判断条件成立与否
对照rather than, instead of, on the other hand排除相反项

例：The algorithm is accurate; however, it is computationally ___. however 表示转折，前面夸“准确”，后面通常指出缺点，故应考虑 expensive（计算开销大），而不是 efficient。

1.5 第五步：代回全文，做三项检查 ​

每空选完后，不要立刻交卷。把答案代回去检查：

  1. 语法是否完整；
  2. 专业结论是否正确；
  3. 全段逻辑是否自洽。

如果两个词都通顺，优先选能与上下文形成复现或照应的词。例如前文说 users report problems quickly，后文出现 shortens the feedback ___，通常选 cycle，因为快速报告问题会缩短反馈周期。

1.6 完整演示：把五步走完一整篇 5 空题 ​

练习全篇：先自己试做下面这篇（不列选项先想一遍词性与意思），再对照"思考痕迹"。这篇同时也作为本课"真题标杆"短文的范本。

短文（主题：软件测试）：

Software testing is the process of finding defects before software is delivered to users. A well-designed test case consists of input values, the environment in which they run, and the expected (1), so that an actual result can be compared with it. Good test suites cover normal inputs as well as (2) cases, such as boundary values and invalid data. Because a defect discovered late is far more (3) to fix, testing is carried out throughout the life cycle instead of only at the end. Automated tests can be executed repeatedly at low cost, which is why teams keep a (4) test suite to ensure that recent changes do not (5) already-working behavior.

逐空思考痕迹（每一次动手前先背口诀：扫主题—判词性—看搭配—找逻辑—代回读）：

  • (1) A. output　B. quickly　C. implemented　D. removable 先判词性：the expected ____＝"定冠词 + 形容词 + 空"，所以空里应填名词。四个选项只有 output（输出结果）是名词；quickly 是副词、implemented/removable 都是分词/形容词。→ 选 A。
  • (3) A. expensive　B. portable　C. automatic　D. shared 找逻辑：句首 Because 是因果信号，"后期才发现的缺陷"通常是修复成本更高，所以选 expensive（昂贵的）。它是形容词，也满足 far more + 形容词 + to fix 的结构。→ 选 A。
  • (5) A. break　B. encrypt　C. compile　D. measure 判词性：do not ____ already-working behavior，情态/助动词 do 后应接动词原形；四个都能作动词原形，再看语义——"确保最近改动不破坏已正常工作"，break（破坏）最贴。→ 选 A。
  • (2) A. unusual　B. encrypted　C. affordable　D. broken 先判词性：____ cases 是"形容词 + 名词"的结构，四个都能当形容词。这时不要硬猜词义，用逻辑与共现：normal inputs as well as ____ cases, such as boundary values and invalid data——as well as 表示加一种有别于正常的情况，后面举例"边界值、非法数据"，所以选 unusual（不寻常的）。encrypted（加密的）与测试用例边界无关，affordable/broken 均无该语境。→ 选 A。
  • (4) A. regression　B. routing　C. symmetric　D. remote这一步示范"先跳过空"：如果刚看完前几句一时判断不了，不要耗时间，先标号跳过，做完后面再回来。最后一句 ensure that recent changes do not break already-working behavior（确保近期改动不破坏已工作的行为），正是回归测试要防的事，固定术语是 regression test suite（回归测试套件）。其余 routing（路由）、symmetric（对称的）、remote（远程的）都无法与 test suite 组成此专业搭配。→ 回到 (4) 选 A。

代回检查：把 A、A、A、A、A 逐个代回读一遍——每空语法完整、专业结论正确、段落逻辑自洽（先讲测试目的→测试用例构成→覆盖正常与非常规→因因果强调尽早测试→自动化与回归）。五步收工。

应试动作：(1)(2)(3) 靠判词性 + 找逻辑，(4) 靠搭配 + 先跳过 + 代回读，(5) 靠判词性。把它们分别标到这类题上，就能在两分钟内做完一组 5 空。
