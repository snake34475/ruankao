06.7 HTML、WWW 与网络命令 ★

WWW 三要素

万维网（WWW）由三样东西撑起来，三者名字要能配对：

要素 作用 关键词
URL（统一资源定位符） 给每个资源一个全球唯一"门牌号" 协议://主机:端口/路径
HTML（超文本标记语言） 写网页的语言，用标签标记内容与结构 标签、超链接
HTTP 浏览器与 Web 服务器之间传输网页的协议 请求/响应，默认 80 端口

例：http://www.example.com:8080/exam/index.html——协议 http，主机 www.example.com，端口 8080（省略时 HTTP 默认 80），路径 /exam/index.html。

URL 与域名：从右向左看层级 ★★

URL 的通用形式可写为：

协议://主机名:端口/路径?查询参数

以 https://www.example.com:443/search?q=network 为例：

部分 内容 作用
协议 https 规定浏览器与服务器怎样通信
主机名 www.example.com 指定要访问的网络主机
端口 443 指定主机上的服务进程；HTTPS 默认端口，可省略
路径 /search 指定服务器上的资源或处理入口
查询参数 q=network 把附加条件交给服务器

域名按点分层，越靠右层级越高。以 www.example.com 为例，从右向左看：

.（根域，通常省略）
└── com        顶级域
    └── example  注册域/二级域
        └── www    主机名标签

日常题目常把完整的 www.example.com 称为主机名（完整限定域名）。https 不是主机名，/search 也不是；看到“URL 中的主机”就取 :// 后、端口或第一个 / 前的部分。

反例演示：把 www 单独答成完整主机名通常不够；它只是域名最左侧的主机标签，离开 example.com 无法全球唯一定位。

DNS：域名怎样变成 IP，故障怎样判断 ★★

人容易记 www.example.com，网络转发却依靠 IP。DNS 的任务是把域名解析成 IP 地址。浏览器通常先查本机缓存；没有结果再向配置的 DNS 服务器查询，拿到 IP 后才建立传输层连接。

常见现象可以这样定位：

现象 优先怀疑 判断依据
能访问某公网 IP，却打不开任何域名 DNS 配置或解析故障 IP 连通说明基本链路可用，失败集中在“名字变 IP”
同网段能通，所有外网 IP 都不通 默认网关/路由 本地链路正常，跨网第一跳失败
IP 和域名都不通，网关也 ping 不通 本机配置、网卡、链路或网关 还没到 DNS 阶段
只有一个网站打不开，其他网站正常 该站服务器、该域名记录或访问策略 不能据此断定本机 DNS 整体损坏

nslookup 域名用于直接检查 DNS 解析；ping IP与ping 域名组合测试，能帮助区分“网络不通”还是“只解析失败”。注意：部分服务器会禁用 ping，因此 ping 不通不能单独证明网站服务宕机，题目若给出多条现象要综合判断。

HTTP 请求：GET 与 POST 怎么区分 ★★

HTTP 采用“请求—响应”模式。浏览器先发送请求行、首部和可选的消息体，服务器再返回状态、首部和内容。考试常比较 GET 与 POST：

对比项 GET POST
典型用途 获取/查询资源 提交数据、创建或修改资源
参数常见位置 URL 查询串，如 ?page=2 请求体
收藏与分享 带查询参数的 URL 易收藏、分享 请求体不会随普通书签保存
缓存 更适合缓存 通常不按普通查询缓存
典型场景 搜索、查看列表 登录表单、提交订单、上传数据

最重要的反例：“POST 的参数不出现在地址栏，所以 POST 天然加密”——错。GET 和 POST 都只是 HTTP 方法；若使用明文 HTTP，传输内容都可能被窃听。需要保密性与完整性必须使用 HTTPS。

应试动作：题干出现“获取、查询、可收藏 URL”优先选 GET；出现“提交表单、改变服务器状态、请求体”优先选 POST。不要把“参数位置”误记成“是否加密”。

静态网页、动态网页与浏览器职责 ★★

  • 静态网页：服务器通常直接返回已保存的 HTML/CSS/图片文件；同一资源对不同访客的主体内容基本相同。
  • 动态网页：服务器根据请求参数、登录用户、数据库内容等在运行时生成结果，例如查询成绩、购物车和订单页面。服务器可能使用 PHP、Java、Python 等程序处理，但发给浏览器的最终结果仍通常是 HTML、JSON、图片等可传输内容。
  • 客户端动态效果：JavaScript 也可在浏览器中修改页面或再次请求数据。它和“服务器端动态生成”不是同一位置的处理，但都能让页面随操作变化。

浏览器不是只“显示 HTML”：它先解析 URL、借助 DNS 找 IP、建立连接、发送 HTTP 请求，再解析 HTML/CSS、执行必要脚本并渲染页面。服务器负责处理请求和返回资源，浏览器负责解释与呈现收到的内容。

故障链定位口诀：先地址，再解析；再连接，再请求；有响应，看状态；有内容，看渲染。

  1. URL 格式或主机名写错：请求还没找到正确目标。
  2. DNS 失败：域名无法变成 IP。
  3. TCP/端口连接失败：服务器未监听、网络路径或防火墙可能有问题。
  4. HTTP 返回 404：已联系服务器，但请求资源不存在；这不是 DNS 故障。
  5. 服务器返回正常而页面显示异常：再查 HTML/CSS/JavaScript 或浏览器兼容问题。

HTML 常识（考选择题的粒度）

  • HTML 用标签写文档，形如 <标签名>…</标签名>，浏览器负责解析 HTML 并渲染成页面；HTML 是标记语言，不是编程语言。
  • 超链接：<a href="http://www.example.com">链接文字</a>——考题问"网页中建立超链接的标签"答 <a>（href 属性）。
  • 常见标签识别：<html> 根标签；<head> 头部信息（标题等，不显示在正文）；<body> 正文；<img src="…"> 插入图片；<br> 换行；<p> 段落。
  • 浏览器访问网页的完整链路：URL → DNS 把域名解析成 IP → 与服务器端口建立 TCP 连接 → 发 HTTP 请求 → 服务器返回 HTML 等内容 → 浏览器解析并渲染。HTTP 默认 80，HTTPS 默认 443。

常用网络命令（偶尔考一道常识题）

命令 用途
ping 测试与目标主机的连通性（基于 ICMP）
ipconfig（Windows） 查看本机 IP 配置；ipconfig /all 还显示 MAC 地址、DNS、DHCP 租约等
tracert 跟踪到目标沿途经过的路由路径
netstat 查看本机的网络连接与端口占用状态
nslookup 手动查询 DNS 解析结果
arp 查看/维护 IP 地址与 MAC 地址的对应表

应试动作：① WWW 三要素配对（URL 门牌、HTML 语言、HTTP 协议）；② 能从 URL 圈出协议、完整主机名、端口、路径和参数；③ 会用“IP 能通、域名不通”识别 DNS 故障，用“同网能通、外网不通”检查网关；④ GET/POST 看用途与参数位置，不能拿它们判断是否加密；⑤ 命令按用途配对背：连通性 ping、路径 tracert、本机配置 ipconfig、连接状态 netstat、解析检查 nslookup。
