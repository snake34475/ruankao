06.1 网络分层模型 ★★★ ​

为什么要分层 ​

网络通信是一个庞大的问题：比特怎么变成电信号、相邻设备怎么传数据、跨网络的两个程序怎么可靠对话……一口气解决无从下手。于是把整个通信过程按职责切成若干层，每层只干一类事、只跟上下层打交道——这和软件工程里"模块化、高内聚低耦合"是同一个思想（见 03-软件工程基础.md 第三节）：层次 = 模块，层间接口 = 模块接口。分层的直接好处：各层独立演进、出问题可以定位到层、不同厂商设备按同一分层标准互通。

OSI 七层模型（必背顺序与职责） ​

OSI 是国际标准化组织提出的理论参考模型，从下往上共 7 层。考试最爱考：层名顺序、每层干什么、每层的协议、每层的设备。

层号层名职责（一句话）数据单位（PDU）代表协议代表设备
7应用层直接为用户程序提供服务数据 / 报文HTTP、FTP、SMTP、DNS、DHCP网关
6表示层数据格式转换：加密/解密、压缩/解压、编码转换数据 / 报文——
5会话层建立、管理、终止会话（对话的"开场与散会"）数据 / 报文——
4传输层端到端可靠/不可靠传输，用端口号区分应用TCP 段 / UDP 数据报TCP、UDP—
3网络层寻址与路由（按 IP 地址选路径），跨网转发分组（包、IP 数据报）IP、ICMP、ARP路由器
2数据链路层相邻节点间成帧、差错控制、按 MAC 地址转发帧以太网协议、PPP网桥、交换机
1物理层比特流变成电/光信号在介质上传输比特—中继器、集线器

层名口诀：从下往上——物数网传会表应（联想："悟数网，传会表应"：先悟出数据的网络传输，再"会上表应"——开会、表演、回应，从下到上越来越"面向应用"）。

记层职责的抓手：物理层管"信号"，链路层管"相邻两站"（MAC），网络层管"全程寻路"（IP），传输层管"程序到程序"（端口），会话/表示/应用三层合起来管"应用怎么说话"。

PDU 与封装：同一份数据为什么一路改名字 ★★ ​

PDU（Protocol Data Unit，协议数据单元）就是“某一层眼里的完整数据”。发送时，每层都把上层交下来的内容当作自己的“货物”，再加上本层控制信息；因此同一份网页数据会随着下行不断换包装、换名字：

text
应用数据
  ↓ 加 TCP/UDP 首部（源/目的端口等）
TCP 段 / UDP 数据报
  ↓ 加 IP 首部（源/目的 IP 等）
IP 分组（包）
  ↓ 加帧首部和帧尾（源/目的 MAC、差错检测等）
数据帧
  ↓ 编码成信号
比特流

接收方按相反方向逐层解封装：比特 → 帧 → 分组 → 段/数据报 → 应用数据。每层只检查并拆掉自己的包装，再把里面的内容交给上一层。

为什么不能只加一个总首部？ 因为各层解决的问题不同：链路层的 MAC 负责“这一跳交给谁”，网络层的 IP 负责“最终主机在哪里”，传输层的端口负责“最终交给哪个程序”。把职责分开后，更换局域网技术时不必改应用程序。

反例演示：

  1. “数据链路层的数据单位是分组”——错。链路层是帧，网络层才是分组；看到交换机、MAC 就联想到帧。
  2. “路由器转发时，源和目的 IP 每一跳都要改”——通常错。普通路由转发中端到端的源/目的 IP 保持不变，但帧的源/目的 MAC 会随下一跳重写；经过 NAT 时 IP/端口才可能被转换。

应试动作：把“比特—帧—分组—段—数据”按物理层到应用层背熟；题干出现“封装顺序”就按发送方向从上往下写，出现“解封装”就反过来。

TCP/IP 四层模型（实际在用的模型） ​

互联网实际采用 TCP/IP 四层模型，它与 OSI 的对应关系每年可能考一题，必须能画出来——先在下面这张"并入图"上看清谁并给了谁，再对照表格：

TCP/IP 四层对应 OSI 的层协议举例
应用层应用 + 表示 + 会话（三层合一）HTTP、FTP、SMTP、DNS、DHCP、TELNET
传输层传输层TCP、UDP
网际层（网络层）网络层IP、ICMP、ARP
网络接口层数据链路层 + 物理层以太网、PPP

判断口诀：看到 TCP/UDP → 传输层；看到 IP/ICMP/ARP → 网际层；其余有名有姓的"应用协议"（HTTP、FTP、SMTP、DNS、DHCP、TELNET……）→ 应用层。OSI 里的表示层功能（加密压缩）在 TCP/IP 里归入应用层实现。

各层设备与"两个域"（高频辨析） ​

设备工作层次能否隔离冲突域能否隔离广播域
集线器（Hub）物理层不能（所有端口共享一条"路"，一起抢）不能
交换机（二层）数据链路层能（每个端口一个冲突域）不能（默认全网一个广播域）
路由器网络层能能（广播到路由器就被拦下）
  • 冲突域：多个设备同时发信号会"撞车"的范围。集线器把大家拴在一条路上，撞车照旧；交换机每个端口独享带宽，撞车只可能发生在"一条线一个设备"内部（即不存在）。
  • 广播域：一个广播帧能扩散到的范围。交换机收到广播帧会转发给所有其他端口（广播域不变大也不变小），路由器收到广播帧不转发（广播域被切断了）。

反例演示：

  1. "交换机隔离广播域"——错。交换机只隔离冲突域；要隔离广播域得上路由器（或划 VLAN）。
  2. "集线器工作在数据链路层"——错。集线器只认识电信号、不认识 MAC 地址，是纯物理层设备。
  3. "路由器根据 MAC 地址转发"——错。路由器根据 IP 地址（第三层地址）查路由表转发；按 MAC 转发的是交换机。

应试动作：① 七层顺序与四层对应关系背死，考法是"XX 协议/设备属于哪一层"的秒答题；② 设备三件套对应（集线器—物理层、交换机—链路层、路由器—网络层）加"两个域"的隔离能力表；③ 判断依据记牢：按 MAC 转发=链路层，按 IP 转发=网络层，按端口交付进程=传输层。
