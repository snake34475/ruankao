05.3 死锁 ★★★

死锁是什么、为什么会发生

若干进程互相要对方手里的资源，谁都拿不齐、谁都不放手，全体卡死——这就是死锁。发生死锁必须同时满足四个必要条件（背名称+含义，选择题考配对）：

条件 含义 破坏它的预防策略
互斥 资源一次只能一个进程用 无法破坏（资源物理特性决定）
请求和保持（保持和等待） 占着资源还去申请新的 一次性申请全部资源（静态分配）
不剥夺 别人不能抢走已分配的资源 允许强行剥夺
环路等待 形成"你等我、我等你"的环形链 资源有序分配法（全系统资源统一编号、按序申请）

处理策略四层次：死锁预防（破坏四条件之一）→ 死锁避免（银行家算法，动态判断分配后是否安全）→ 死锁检测与解除（资源图化简）。破坏"互斥"做不到，破坏其余三个都能预防。

死锁资源数公式（★★★ 必考计算）

  • 通用形式：m 个进程、每个进程最多需要 w 个同类资源、系统共有 n 个资源——
    • 不可能发生死锁的最小资源数：n = m×(w−1) + 1（等价条件：n ≥ m(w−1)+1 时必不死锁）；
    • 可能发生死锁的最大资源数：n = m×(w−1)（n ≤ m(w−1) 时可能死锁，不是必然）。
    • 推导思路：最坏情况是每个进程都拿到 w−1 个还差 1 个、把资源占光——此时共 m(w−1) 个资源全被占着，人人等资源，死锁；只要再多 1 个资源，就有人能凑齐跑完并释放，死锁解开。
  • 代入算例：3 个进程各需 4 个资源：不可能死锁的最小 n = 3×(4−1)+1 = 10；n = 9 时可能死锁（3 个进程各持 3 个，全占光）。
  • 手算口诀："每进程先扣 1，乘完再加 1"。

反向题型（给 n 求 w）：3 个进程共享 10 个资源，每个进程最多申请 i 个，问"可能发生死锁的最小 i"——令 3×(i−1) ≥ 10，i−1 ≥ 3.34，i ≥ 4.34，取整数 i = 5。（i = 4 时 3×3 = 9 < 10，按鸽笼原理必有一个进程能拿到 4 个而完成，不死锁。）

进程资源图与"化简"（★★）

动机：死锁检测要回答"当前这批进程是否已死锁"。进程资源图用圆圈表示进程、方块表示资源：进程→资源的有向边 = 申请，资源→进程的边 = 已分配。化简 = 模拟"让能跑完的进程跑完并归还资源"，看能否全清空。

判定四步模板（背下来直接套）：

  1. 列剩余：每种资源空闲量 = 总量 − Σ各进程已占该资源；
  2. 判阻塞：申请量 > 空闲量的进程是阻塞结点，先放一边；
  3. 执行归还：找申请量 ≤ 空闲量的进程（非阻塞），模拟它跑完并把它占用的全部资源交还空闲池，标记已化简；
  4. 循环 / 下结论：重复 2–3 步直到全化简 → 非死锁；某轮再也找不到可化简进程而仍有未化简者 → 死锁。

代入算例：R1 总量 2、R2 总量 2。P1 占 R1×1、还申请 R1×1；P2 占 R1×1、R2×1、还申请 R2×1。

  • 剩余：R1 空闲 = 2 − (P1 占1 + P2 占1) = 0；R2 空闲 = 2 − (P2 占1) = 1；
  • P1 申请 R1 需 1、空闲 0 → 阻塞；P2 申请 R2 需 1、空闲 1 → 可化简；
  • P2 跑完归还 R1×1、R2×1 → 空闲 R1 = 1、R2 = 2；此时 P1 申请 R1 需 1 ≤ 空闲 1 → 化简。全部化简 → 非死锁。

反例演示（易错）：① 有环未必死锁——要把环和"申请是否卡死"合起来看，能化简就不是死锁；② 一次化简会改变空闲量，每一步都要重刷剩余再判阻塞，不能拿最初的状态一路判到底。

银行家算法（★★★）

动机：预防策略太死板（一次性分配浪费资源），银行家算法更聪明——每次分配前先假装分出去，看看能不能找到一个让所有进程都跑完的顺序（安全序列）：找得到就真分，找不到就不分。银行放贷同理：放钱前先算"这笔放出去后，是否还能让所有贷款人最终都还上钱"。

判定步骤（五步模板，背下来直接套）：

  1. 算每个进程的需求 Need = 最大需求 − 已分配；
  2. 算剩余可用 Available = 资源总量 − 各进程已分配之和；
  3. 在未完成进程中找"Need ≤ Available"的进程，让它执行完并归还全部已分配资源（Available += 它的 Allocation），标记完成；
  4. 重复第 3 步，直到所有进程完成（→ 安全，执行顺序即安全序列）或找不到任何可满足的进程（→ 不安全，拒绝本次分配）；
  5. 若判断"某进程再申请 X 个能否满足"：先试探性地把 X 从 Available 划给它、Need 减 X，再走一遍第 2–4 步；不安全则回滚并拒绝。

代入算例：资源总量 10。P1 最大 5、已分 3（Need 2）；P2 最大 7、已分 2（Need 5）；P3 最大 6、已分 2（Need 4）。Available = 10 − (3+2+2) = 3。

  • Need ≤ 3 的只有 P1（Need 2）→ P1 先跑，归还后 Available = 3+3 = 6；
  • 此时 P2（Need 5 ≤ 6）、P3（Need 4 ≤ 6）都能跑 → 安全序列有 P1→P2→P3 和 P1→P3→P2 两条。

反例演示（易错）：① 只要找到一条安全序列就算安全，不要求唯一（但做题时若四个选项里三条都不通，剩下的那条就是答案）；② "不安全" ≠ "已死锁"，只是"可能死锁"，银行家算法宁可错杀不肯冒险；③ 算 Available 时忘了用"总量减已分配"，直接拿 Need 求和比较——必错。

应试动作：① 死锁资源数公式"每进程先扣 1 乘完再加 1"正反两个方向都要会算；② 四条件与破坏策略配对（一次性分配→破坏请求和保持；有序分配→破坏环路等待）；③ 银行家五步模板背熟，安全序列判定题在草稿上列表（Need / Available 两列）逐步推，每步检查"Need ≤ Available"。
