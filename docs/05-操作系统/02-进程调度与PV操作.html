05.2 进程调度与 PV 操作 ★★★

为什么要算周转时间

用户交一个作业给系统，最关心的就是"多久能跑完"。周转时间衡量这个：从到达到完成的全部等待 + 运行时间。调度算法不同，周转时间不同——考题就是给几个作业的到达/运行时间，让你按某算法排顺序再求平均周转时间。

公式三件套

  • 通用形式：周转时间 = 完成时刻 − 到达时刻；平均周转时间 = 各作业周转时间之和 ÷ 作业数；带权周转时间 = 周转时间 ÷ 实际运行时间。
  • 代入算例：作业 J1 时刻 0 到达、需运行 4；J2 时刻 1 到达、需运行 3；J3 时刻 2 到达、需运行 1。按先来先服务（FCFS）单道顺序执行：J1 在 0–4 完成，周转 = 4−0 = 4；J2 在 4–7 完成，周转 = 7−1 = 6；J3 在 7–8 完成，周转 = 8−2 = 6。平均周转时间 = (4+6+6)/3 = 16/3 ≈ 5.33。
  • 手算口诀：先列表填"开始时刻、完成时刻"两列（完成 = 上一个完成时刻与本作业到达时刻中较大者 + 运行时间），再用"完成减到达"一列竖式扫下去。

常考调度算法

算法 规则 特征词
FCFS 先来先服务 按到达顺序 "先来先服务"
SJF 短作业优先（非抢占） 可运行作业中挑运行时间最短的 "短作业优先""平均周转时间最短"

反例演示（易错）：SJF 非抢占时，时刻 0 只能从已到达的作业里挑短的，不是全场谁短谁先。上例改按 SJF：t=0 只有 J1 已到 → 仍先跑 J1（0–4）；t=4 时 J2(需 3)、J3(需 1) 都在等 → 挑短的 J3（4–5，周转 5−2 = 3）；再跑 J2（5–8，周转 8−1 = 7）。平均 = (4+3+7)/3 = 14/3 ≈ 4.67 < 5.33 ✓（SJF 平均周转更短，这正是它的卖点）。若错把 J3 提到最前面先跑，就掉进"未到达就运行"的陷阱。

应试动作：背公式"周转 = 完成 − 到达"；SJF 题每一步都先检查"该时刻这个作业到了没有"；选项给分数（16/3、14/3）时别慌，保留分数或算到两位小数即可。

第四节 进程同步与互斥：PV 操作 ★★★（必考）

为什么要互斥：临界资源

两个进程同时往同一台打印机上输出，纸上的内容就会交错成一团乱码。像打印机这种同一时刻只允许一个进程使用的资源叫临界资源，进程中访问临界资源的那段代码叫临界区。注意区分：临界资源必须互斥使用；普通共享资源（如可重入的代码）允许多进程同时用。

临界区管理的四条准则（选择题考过名称与含义）：有空即进、无空则等、有限等待、让权等待（进不了临界区就释放 CPU，避免"忙等"）。

信号量与 PV：一个会"记账"的变量

信号量 S 是一个特殊变量，本质是资源账本：S > 0 表示还剩 S 个资源可用；S = 0 表示资源刚好用光、无人排队；S < 0 的绝对值 = 排队等资源的进程数。

  • P(S)（申请）：S 减 1；若 S < 0，本进程阻塞进等待队列。
  • V(S)（释放）：S 加 1；若 S ≤ 0（说明有人在排队），唤醒一个等待进程。

初学者最容易问："不就是个加减法吗，为什么要绑定阻塞/唤醒？"——因为判断和等待必须一步完成：如果"先查 S 再决定等不等"分成两步，两个进程可能同时查到"还有 1 个"然后都进去，互斥就破了。PV 把"查账 + 排队/叫号"做成了不可拆的整体。

初值怎么定（核心结论）：

模型 信号量含义 初值
互斥（多进程抢同一资源） 资源数量 = 资源数（1 台打印机 → 1；3 台同类打印机 → 3）
同步（前者做完了后者才能做） "前者已完成"这个消息 一般为 0
前趋图 每条有向弧一个信号量 全为 0

信号量取值范围题（公式三件套）：

  • 通用形式：n 个进程共享 k 个同类资源，S 初值 k，则 S 的最大值 = k，最小值 = k − n（负到"全部进程都在排队"为止）。
  • 代入算例：10 个进程共享 3 台打印机：最大 3，最小 3 − 10 = −7，即 S ∈ [−7, 3]。
  • 手算口诀："上界是初值，下界是初值减进程数"。

前趋图配 PV：套路题（★★★）

前趋图刻画"哪些任务必须等哪些任务做完才能开始"（思想与数据结构的拓扑排序一致，见 第 01 课「图」 第 3.5 节；与软件工程的关键路径网络图也同源）。

规则（背死）：

  1. 图中有几条有向弧，就定义几个信号量（每条弧一个，初值全为 0）；
  2. 每条弧的起点（前趋任务）末尾做 V（"我做完了"），终点（后继任务）开头做 P（"等我的前置完成"）；
  3. 一个任务有几条入弧，开头就要连续做几个 P；有几条出弧，末尾就连续做几个 V。

代入算例：弧为 A→B、A→C、B→D、C→D 共 4 条 → 信号量 S1～S4，初值均为 0：

A: 执行; V(S1); V(S2);
B: P(S1); 执行; V(S3);
C: P(S2); 执行; V(S4);
D: P(S3); P(S4); 执行;

反例演示（易错）：把 V 写在弧的终点、P 写在起点——顺序反了：变成"后继先 V 报信、前趋再 P 等待"，而信号量初值是 0，前趋 P 时会永远阻塞，整张图谁都跑不起来。记住口诀："V 在前驱末，P 在后继初"。另一易错点：同步信号量与互斥信号量混用初值——同步（前趋图）初值 0，互斥初值 = 资源数，二者不能抄混。

生产者-消费者：互斥 + 同步组合题

动机：一个进程往缓冲区放数据（生产者），一个进程从缓冲区取（消费者）。缓冲区格子是临界资源（同一时刻只容一个放/取），同时还有两条先后关系：缓冲区满时生产者要等消费者取走，缓冲区空时消费者要等生产者放入。因此至少三类信号量：

  • 互斥 mutex，初值 1，保护"进出缓冲区（放/取）"这段临界区；
  • 同步 empty，初值 = 缓冲区格数（还剩几个空位）；
  • 同步 full，初值 0（已放入几格数据）。

同步为什么"先 P 后 V"（核心，必背）：同步信号量记的是"资源余量"，用前先 P（检查、不够就等），用后 V（归还）——这与互斥只在初值上不同。而且同步的 P 必须放在互斥的 P 之前：若反了，缓冲区满时生产者占着 mutex 去等 empty，消费者却要 mutex 才能取出、腾出空位 → 互相等 = 死锁。

代入算例：缓冲区可放 5 格，初态全空。

semaphore mutex=1, empty=5, full=0;
生产者：P(empty);   // 先申请空位，满则等
        P(mutex);   // 再进临界区
        放入数据;
        V(mutex);
        V(full);    // 通知多了一格数据
消费者：P(full);    // 有数据才取，空则等
        P(mutex);
        取出数据;
        V(mutex);
        V(empty);   // 归还一个空位

口诀："同步 P 在前、互斥 P 在后，V 成对跟各自操作后"。

反例演示（易错）：① 把 P(mutex) 提到 P(empty) 之前（见上"为什么"），缓冲区满即死锁；② empty 初值误设 0（空位应是缓冲区容量 5，不是 0）；③ 生产者也写 P(full)/V(empty)（把消费者的同步抄反，会在空缓冲时误等）。

应试动作：① 互斥 → 初值 = 资源数；同步/前趋 → 初值 0；② 取值范围 = [初值−进程数， 初值]；③ 前趋图按"弧数 = 信号量数、V 起点末、P 终点初"机械填写，填完逐弧检查一遍"每条弧恰好一个 V 和一个 P"。这种题若以小问嵌在案例大题里（历史上考过整道大题），按同一套路做。并发互斥的思想与数据库的锁机制同源，可对照 02-数据库系统.html 的并发控制一节。
