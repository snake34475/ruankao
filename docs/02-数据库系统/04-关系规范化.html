02.4 关系规范化 ★★★

为什么要规范化

一张大表什么都往里塞，会出现三种病：数据冗余（系主任跟着每个学生重复存）、修改麻烦（换主任要改几百行）、插入/删除异常（还没招生的系插不进来、最后一个学生毕业系主任信息也跟着没了）。规范化的目的就是拆表，把这些病一步步消掉。

函数依赖（判断范式的唯一工具）

X→Y 读作"X 决定 Y"：知道 X 就能唯一确定 Y。三种关键形态（设 K 是候选键）：

  • 完全依赖：Y 依赖整个 K，去掉 K 中任何一个属性都不行。例：(学号, 课程号)→成绩。
  • 部分依赖：Y 依赖 K 的一部分就够了。例：(学号, 课程号)→姓名，其实学号→姓名——部分依赖是病。
  • 传递依赖：X→Y、Y→Z 且 Y 不决定 X，则 Z 传递依赖 X。例：学号→系名→系主任——传递依赖是病。

先把几个容易混的“键”分清：

  • 超键：能决定全部属性的属性集，可以含多余属性；
  • 候选键：不含多余属性的最小超键，可能不止一个；
  • 主键：人为从候选键中选一个作为主要标识；
  • 主属性：出现在任一候选键中的属性；其余是非主属性；
  • 全码：整个关系模式的全部属性合在一起才构成候选键，即所有属性都是主属性且缺一不可。

反例演示（易错）：若候选键有 AB 和 AC，主属性是 A、B、C 的并集，不是只看被选作主键的 AB 而把 C 误判为非主属性。范式判断看的是所有候选键，不是只看主键。

范式判定：一级一级"消病"

范式 要求 一句话判定
1NF 属性不可再分（数据库默认满足） 所有属性都是原子值
2NF 消除部分依赖 每个非主属性都依赖整个候选键
3NF 再消除传递依赖 非主属性不间接依赖候选键
BCNF 每个决定因素都必须是候选键 比 3NF 更严：主属性也不能有依赖毛病

判定四步法（背流程，别背定义）：

  1. 找候选键（见下）；
  2. 列出所有"决定→被决定"；
  3. 看有没有非主属性只依赖候选键一部分 → 有则最高 1NF；
  4. 再看有没有非主属性靠别的非主属性中转 → 有则最高 2NF；都没有 → 3NF；若还有主属性被非主属性决定 → 不到 BCNF。

把判定压成一张“谁依赖谁”表：

观察到的依赖 造成什么问题 最高可能停在哪
非主属性依赖组合候选键的一部分 部分依赖 1NF
非主属性经另一个非主属性间接依赖候选键 传递依赖 2NF
决定因素不是超键，但右部是主属性 允许满足 3NF，不满足 BCNF 3NF
每个非平凡依赖的决定因素都是超键 无上述问题 BCNF

快判 1：候选键只有一个属性时，不可能存在“对候选键一部分”的依赖，因此只要满足 1NF 就自动满足 2NF。

快判 2：如果所有属性都是主属性，就没有“非主属性的部分依赖或传递依赖”，因此至少满足 3NF；但决定因素若不是超键，仍可能不到 BCNF。

例：R(A,B,C)，F={AB→C，C→B}。候选键有 AB 和 AC，所以 A、B、C 全是主属性，R 满足 3NF；但 C→B 的决定因素 C 不是超键，因此不满足 BCNF，最高为 3NF。

主属性也会部分依赖，但不会把关系打回 1NF：上例候选键 AC 中，主属性 B 由 C 单独决定，即 B 对候选键 AC 存在部分依赖。2NF 的检查对象是非主属性，所以该依赖不违反 2NF；它真正违反的是更严格的 BCNF 条件。不要见到“部分依赖”四个字就机械判 1NF，先看被决定者是不是非主属性。

反例演示（易错）：R(学号, 姓名, 系, 系主任)，学号→姓名、学号→系、系→系主任。候选键是学号（单属性），不可能有部分依赖（键只有一个属性，"一部分"还是它自己），所以它直接就是 2NF；但学号→系→系主任是传递依赖，所以最高 2NF，不是 3NF。最常见的错误就是把"有冗余"当成"不是 2NF"——单属性键的表不存在部分依赖，第一步就能跳过。

候选键怎么求（案例题必考）

候选键的严格工具是属性闭包。属性集 X 在函数依赖集 F 下能推出的全部属性，记作 X⁺。若 X⁺ 等于关系的全部属性，则 X 是超键；再逐个删除 X 中属性，删谁都不能推全，X 才是候选键。

闭包算法（通用形式）：

  1. 初始化 X⁺ = X；
  2. 反复扫描每条函数依赖 Y→Z：若 Y ⊆ X⁺，就把 Z 加入 X⁺；
  3. 一轮扫描后不再增加属性时停止；
  4. 与属性全集比较，再做“逐个删除”最小性检查。

手算口诀：先把自己圈进去；左边已齐，就收右边；一轮没新增，才算停。

Armstrong 三条公理是闭包推导的依据：

  • 自反律：若 Y⊆X，则 X→Y；
  • 增广律：若 X→Y，则 XZ→YZ；
  • 传递律：若 X→Y 且 Y→Z，则 X→Z。

考试常直接使用三条派生规则：分解（X→YZ 可推出 X→Y、X→Z）、合并（X→Y 且 X→Z 可推出 X→YZ）、伪传递（X→Y 且 WY→Z，可推出 WX→Z）。

完整演算：R(A1,A2,A3,A4,A5,A6)，F={A1→A3，A1A2→A4，A5A6→A1，A3A5→A6，A2A5→A6}，求一个候选键。

  1. 从未出现在任何依赖右部的属性是 A2、A5，它们无法由其他属性推出，必须进入每个候选键；
  2. 初始化 (A2A5)⁺={A2,A5}；
  3. 用 A2A5→A6，加入 A6；
  4. 用 A5A6→A1，加入 A1；
  5. 用 A1→A3，加入 A3；
  6. 用 A1A2→A4，加入 A4；
  7. 闭包已是 {A1,A2,A3,A4,A5,A6}，故 A2A5 是超键；去掉 A2 或 A5 都无法推全，因此 A2A5 是候选键。

反向验证：只用 A2 时没有任何依赖可启动；只用 A5 也无法启动，两个属性都不可删除，最小性成立。

启发式口诀：从未在依赖右部出现的属性，必在每个候选键里。但这只是起点，不是答案；必须继续算闭包并检查最小性。

例：R(A,B,C,D)，F = {A→B, B→C, D→B}。右部出现过的：B、C。从未出现在右部的：A、D。验证 AD：A→B，B→C，D→B → 可推出 A、B、C、D 全部 → 候选键 = AD（ABD 虽也能决定全部，但含多余属性，是超键不是候选键）。

分解后怎么检查：无损连接与保持函数依赖

规范化不是“拆得越碎越好”。拆完必须过两道门：

  1. 无损连接：分表自然连接后能准确还原原关系，不丢行，也不产生原来不存在的假行；
  2. 保持函数依赖：原来的约束能在各分表内部检查，不必把表连接起来才能验证。

二元分解 R→R1、R2 的常用无损快判是：公共属性 R1∩R2 能否函数决定 R1 或 R2 的全部属性，即检查 (R1∩R2)→R1 或 (R1∩R2)→R2 是否成立。

例：R(A,B,C)，F={A→B}，分为 R1(A,B) 与 R2(A,C)。公共属性是 A，且 A→AB 成立，所以分解无损。

反例：仍是 R(A,B,C)，若分为 R1(A,B) 与 R2(B,C)，公共属性是 B，但由 F 只能知道 A→B，推不出 B→AB 或 B→BC，因此不能判为无损，实际可能连接出假行。

保持依赖不等于无损：两者是不同检查项。3NF 综合算法通常可以兼顾无损和保持依赖；BCNF 分解保证无损，但可能牺牲某些依赖保持。案例题若只问“能否还原原表”，答无损；若问“能否分别在单表内检查全部约束”，答保持函数依赖。

应试动作：背四步判定法 + "右部不出现的属性进候选键"；考"最高属于第几范式"时从低往高验，卡在哪级就答前一级。
