02.4 关系规范化 ★★★ ​

为什么要规范化 ​

一张大表什么都往里塞，会出现三种病：数据冗余（系主任跟着每个学生重复存）、修改麻烦（换主任要改几百行）、插入/删除异常（还没招生的系插不进来、最后一个学生毕业系主任信息也跟着没了）。规范化的目的就是拆表，把这些病一步步消掉。

函数依赖（判断范式的唯一工具） ​

先分清记号：假设有一张选课(学号, 课程号, 姓名, 成绩)表。表是“选课”，学号、课程号、姓名、成绩是表的属性（可理解为字段或列）。X、Y 不是表名，也不是某一行里的具体值，而是用来代指属性或属性的组合；例如 X 可以是“学号”，也可以是“(学号, 课程号)”，Y 可以是“姓名”。K 也代表属性组合，但特指这张表的一个候选键：凭它能唯一确定一行，且去掉其中任何一个属性就不行。若同一学生选同一课程只记一条记录，则本例的 K = (学号, 课程号)。

X→Y 读作“X 决定 Y”（Y 函数依赖于 X）：在这张表的业务规则下，任意两行只要 X 相同，Y 就必须相同。例如同一学号总对应同一姓名，所以 学号→姓名；只知道学号不能确定成绩，因为同一学生不同课程的成绩可以不同，而同时知道学号和课程号才能确定该次选课的成绩。这里比较的是列的取值规律，箭头两边写的是属性，不是“表决定表”，也不是某个具体值指向另一个值。

认箭头口诀：X 相同则 Y 必须相同；抓到一行“同 X 不同 Y”，这个箭头就作废。

看下图中的三条记录。X、Y、K 是给列或列的组合起的代号；S01、C01、张三、86 才是各行里的具体值。

text
                 选课表（每行是一条记录）
        X = 学号      课程号       Y = 姓名      成绩
第 1 行    S01          C01          张三          86
第 2 行    S01          C02          张三          92
第 3 行    S02          C01          李四          78

X → Y：第 1、2 行的学号同为 S01，姓名也同为张三。
X 不能决定成绩：第 1、2 行学号相同，成绩却不同。
K = (学号, 课程号)：两列合起来标识一条选课记录。
K → 成绩：同时给定学号和课程号，才能确定这次成绩。

图中的三行只是帮助看懂规则；判断函数依赖仍要依据业务约束，不能只因这几行恰好没有冲突，就认定某个箭头成立。

选课大表(学号, 姓名, 系, 系主任, 课程号, 成绩)，业务规则：每名学生只有一个系，每个系只有一位系主任；每名学生每学期选同一门课只记一条成绩。

于是有四个依赖：学号→姓名、学号→系、系→系主任、(学号,课程号)→成绩。候选键是 (学号, 课程号)——只靠学号定不了成绩，只靠课程号定不了是谁的分数。把这张表的依赖关系画成一张“谁决定谁”的图（方框是属性，箭头是函数决定，不代表数据在流动）：

对照上图，三种形态可以这样认：

形态看图怎么认本图例子是不是病
完全依赖必须从虚线框（整个 K）出发才能走到它(学号,课程号)→成绩正常

记忆口诀：半个键能定，就是部分依赖；绕一脚中转，就是传递依赖。

先分清几个“键” ​

先把几个容易混的“键”分清。以学生表 学生(学号, 身份证号, 姓名, 系) 为例：每个学生有唯一的学号和身份证号，知道其中任意一个，就能确定这一行的全部属性。

它们不是并列关系，而是一层套一层，见下图：

名称怎么判断本例中的结果
超键能确定整行；允许含多余属性学号、(学号, 姓名) 都是
候选键能确定整行，且删掉其中任何属性就不行学号、身份证号
主键从候选键中选一个作主要标识假设选 学号
主属性出现在任一候选键中的单个属性学号、身份证号；姓名、系 是非主属性
全码全部属性合在一起才是候选键此学生表不是全码，见下例

嵌套口诀：超键包候选，候选挑主键；主属性不问被选没被选，只看进没进过候选键。

再逐个检查几个属性组合。这里“能确定整行”只按上面声明的业务规则判断，不能只看当前表里是否碰巧没有重复值。

属性组合能确定整行吗有多余属性吗属于什么
学号能没有超键、候选键；本例选它作主键
身份证号能没有超键、候选键；没有被选为主键
(学号, 姓名)能有，删掉姓名仍能确定整行超键，但不是候选键
姓名不能，同名学生可能有多位不适用不是键

所以每个候选键都是超键，但超键不一定是候选键；主键只是被选中的那个候选键。“主属性”说的是属性本身：身份证号即使没被选作主键，仍因出现在候选键中而是主属性。

全码另看一个例子：设 选课记录(学号, 课程号, 学期) 中，一名学生对同一门课在同一学期只记一条记录。学生可在不同学期重修同一课程，所以 (学号, 课程号) 不够；同一学期可选多门课，所以 (学号, 学期) 不够；同一课程同一学期可有多名学生，所以 (课程号, 学期) 也不够。若没有其他能决定属性的业务规则，必须三个属性一起才能确定一条记录，此时 (学号, 课程号, 学期) 是全码。学生表即使把四个属性全放在一起，也能确定整行，但学号一个就够了，所以它的全部属性只是超键，不是全码。

反例演示（易错）：若候选键有 AB 和 AC，主属性是 A、B、C 的并集，不是只看被选作主键的 AB 而把 C 误判为非主属性。范式判断看的是所有候选键，不是只看主键。

范式阶梯：一级一级往上爬 ​

四级范式就是给上面选课大表“逐级看病、逐级动手术”，每级只消一种病：

爬梯口诀：一格一值是 1NF，整个键靠是 2NF，不借他口中转是 3NF，决定个个是超键才是 BCNF。

范式要求一句话判定
1NF每格是单个原子值不把多个同类值塞在一格
2NF消除部分依赖每个非主属性都依赖整个候选键
3NF再消除传递依赖非主属性不间接依赖候选键
BCNF每个非平凡依赖的决定因素都必须是超键比 3NF 更严：主属性也不能有依赖毛病

下面每一级配一张“病灶 → 手术 → 痊愈”图，所有图共用同一张选课大表和同一组数据，对照着看。

第一关：1NF，每格只准一个值 ​

先过 1NF 这一关。 1NF（第一范式）要求每个字段的每一格只存一个可按当前业务使用的值，不能把一组同类值塞进一格。这里的“不可再分”是相对于业务而言：学号 S01 虽能拆成字符，但业务把它当一个编号，仍是原子值；C01、C02 若表示两门选修课，就不是一个课程号。

上图拆完只是入门：1NF 只检查值是否原子，不保证已经消除重复或函数依赖问题。拆成两行后，(学号, 课程号) 成了组合候选键，学号→姓名 这种“半个键就能定”的依赖开始成为下一级的检查对象。

第二关：2NF，非主属性不能只靠半个键 ​

第三关：3NF，非主属性不能借道中转 ​

看拆完的学生表 (学号, 姓名, 系, 系主任)：候选键是单属性 学号，没有部分依赖问题（单属性键不可能有“半个键”），2NF 已满足。但 学号→系、系→系主任，系主任是借道系这个非主属性才依赖上学号的——传递依赖病，见下图：

手术口径一句话：把中转列单独成表，让它自己当主键。“招一个新系但还没有学生”能插进系表了，“王五换系”只改一行——插入/删除异常与冗余同时消失。

第四关：BCNF，所有“决定因素”都必须是超键 ​

3NF 只管非主属性的毛病；BCNF 把检查范围扩大到每一条依赖：只要 X→Y 成立（Y 不属于 X），X 就必须是超键。换句话说，任何一列都不许被“不是键的东西”决定。

用一张新表“排课”演示。业务规则：每名学生对每门课配有一个任课教师；每位教师只带一门课（一门课可以有多名教师）。

学号课程号教师
S01C01甲老师
S02C01甲老师

依赖有两条：(学号,课程号)→教师（业务规则）；教师→课程号（教师只带一门课）。候选键有两个：(学号,课程号) 和 (学号,教师)——因为知道学号和教师就能推出课程号，验证闭包 (学号,教师)⁺ = {学号,教师,课程号} 推全。于是三列全是主属性，没有非主属性可言，3NF 的两病（部分/传递）都无从谈起——它是 3NF。但 教师→课程号 的决定因素“教师”不是超键（只知教师定不了是哪个学生的记录），BCNF 被违反：

抽象版就是常见考题的原型：R(A,B,C)，F={AB→C, C→B}，对应“学号=A、课程号=B、教师=C”。候选键 AB 和 AC，全主属性、满足 3NF；C→B 的决定因素 C 不是超键，最高 3NF。

判定流程与易错点 ​

判定四步法（先确认满足 1NF，再按此流程检查更高范式）：

  1. 找候选键（见下）；
  2. 列出所有“决定→被决定”；
  3. 看有没有非主属性只依赖候选键一部分——有则最高 1NF；
  4. 再看有没有非主属性靠别的非主属性中转——有则最高 2NF；都没有则 3NF；若还有主属性被非主属性决定——不到 BCNF。

把判定压成一张“谁依赖谁”表：

观察到的依赖造成什么问题最高可能停在哪
非主属性依赖组合候选键的一部分部分依赖1NF
非主属性经另一个非主属性间接依赖候选键传递依赖2NF
决定因素不是超键，但右部是主属性允许满足 3NF，不满足 BCNF3NF
每个非平凡依赖的决定因素都是超键无上述问题BCNF

快判 1：候选键只有一个属性时，不可能存在“对候选键一部分”的依赖，因此只要满足 1NF 就自动满足 2NF。

快判 2：如果所有属性都是主属性，就没有“非主属性的部分依赖或传递依赖”，因此至少满足 3NF；但决定因素若不是超键，仍可能不到 BCNF。

主属性也会部分依赖，但不会把关系打回 1NF：上例候选键 AC 中，主属性 B 由 C 单独决定，即 B 对候选键 AC 存在部分依赖。2NF 的检查对象是非主属性，所以该依赖不违反 2NF；它真正违反的是更严格的 BCNF 条件。不要见到“部分依赖”四个字就机械判 1NF，先看被决定者是不是非主属性。

反例演示（易错）：R(学号, 姓名, 系, 系主任)，学号→姓名、学号→系、系→系主任。候选键是学号（单属性），不可能有部分依赖（键只有一个属性，“一部分”还是它自己），所以它直接就是 2NF；但学号→系→系主任是传递依赖，所以最高 2NF，不是 3NF。最常见的错误就是把“有冗余”当成“不是 2NF”——单属性键的表不存在部分依赖，第一步就能跳过。

4NF 与 5NF（超纲，一句话了解）：4NF 消除“多值依赖”——如一张表同时记录一名学生的多门课和多个互不相关的爱好，重复冗余不是函数依赖造成的，4NF 要求继续拆表；5NF 消除“连接依赖”，针对三个以上属性共同构成键、拆成两两组合仍还原不了的情形。软考大纲只要求到 BCNF，选择题若出现“4NF”，凭“消除多值依赖”这个印象选即可。

候选键怎么求（案例题必考） ​

候选键的严格工具是属性闭包。属性集 X 在函数依赖集 F 下能推出的全部属性，记作 X⁺。若 X⁺ 等于关系的全部属性，则 X 是超键；再逐个删除 X 中属性，删谁都不能推全，X 才是候选键。

先认清下面的记号：X、Y、Z 都表示一组属性；Y→Z 表示已知 Y 就能确定 Z；X⁺ 读作“X 的闭包”，计算时用它记录从 X 出发已经推出的属性。⊆ 读作“包含于或等于”：Y ⊆ X⁺ 表示 Y 中的每个属性都已经在 X⁺ 里，例如 {A1,A2} ⊆ {A1,A2,A3}。满足这个条件，才能用 Y→Z 把 Z 收进闭包。

闭包算法（通用形式）：

  1. 初始化 X⁺ = X；
  2. 反复扫描每条函数依赖 Y→Z：若 Y ⊆ X⁺，就把 Z 加入 X⁺；
  3. 一轮扫描后不再增加属性时停止；
  4. 与属性全集比较，再做“逐个删除”最小性检查。

手算口诀：先把自己圈进去；左边已齐，就收右边；一轮没新增，才算停。

Armstrong 三条公理是闭包推导的依据：

  • 自反律：若 Y⊆X，则 X→Y；
  • 增广律：若 X→Y，则 XZ→YZ；
  • 传递律：若 X→Y 且 Y→Z，则 X→Z。

考试常直接使用三条派生规则：分解（X→YZ 可推出 X→Y、X→Z）、合并（X→Y 且 X→Z 可推出 X→YZ）、伪传递（X→Y 且 WY→Z，可推出 WX→Z）。

完整演算：R(A1,A2,A3,A4,A5,A6)，F={A1→A3，A1A2→A4，A5A6→A1，A3A5→A6，A2A5→A6}，求一个候选键。

  1. 从未出现在任何依赖右部的属性是 A2、A5，它们无法由其他属性推出，必须进入每个候选键；
  2. 初始化 (A2A5)⁺={A2,A5}；
  3. 用 A2A5→A6，加入 A6；
  4. 用 A5A6→A1，加入 A1；
  5. 用 A1→A3，加入 A3；
  6. 用 A1A2→A4，加入 A4；
  7. 闭包已是 {A1,A2,A3,A4,A5,A6}，故 A2A5 是超键；去掉 A2 或 A5 都无法推全，因此 A2A5 是候选键。

把每次新收进来的属性排成一条推导链，可以看出闭包为何不能只扫一轮：

text
起点 {A2,A5}
  │ A2A5→A6
  ▼
{A2,A5,A6}
  │ A5A6→A1
  ▼
{A1,A2,A5,A6}
  │ A1→A3，再由 A1A2→A4
  ▼
{A1,A2,A3,A4,A5,A6} = 全部属性

第二步得到 A1 后，原先不能使用的 A1→A3 和 A1A2→A4 才变得可用；每次有新增属性，都要继续扫描依赖。

反向验证：只用 A2 时没有任何依赖可启动；只用 A5 也无法启动，两个属性都不可删除，最小性成立。

启发式口诀：从未在依赖右部出现的属性，必在每个候选键里。但这只是起点，不是答案；必须继续算闭包并检查最小性。

例：R(A,B,C,D)，F = {A→B, B→C, D→B}。右部出现过的：B、C。从未出现在右部的：A、D。验证 AD：A→B，B→C，D→B → 可推出 A、B、C、D 全部 → 候选键 = AD（ABD 虽也能决定全部，但含多余属性，是超键不是候选键）。

分解后怎么检查：无损连接与保持函数依赖 ​

规范化不是“拆得越碎越好”。拆完必须过两道门：

  1. 无损连接：分表自然连接后能准确还原原关系，不丢行，也不产生原来不存在的假行；
  2. 保持函数依赖：原来的约束能在各分表内部检查，不必把表连接起来才能验证。

二元分解 R→R1、R2 的常用无损快判是：公共属性 R1∩R2 能否函数决定 R1 或 R2 的全部属性，即检查 (R1∩R2)→R1 或 (R1∩R2)→R2 是否成立。

例：R(A,B,C)，F={A→B}，分为 R1(A,B) 与 R2(A,C)。公共属性是 A，且 A→AB 成立，所以分解无损。

反例：仍是 R(A,B,C)，若分为 R1(A,B) 与 R2(B,C)，公共属性是 B，但由 F 只能知道 A→B，推不出 B→AB 或 B→BC，因此不能判为无损，实际可能连接出假行。

保持依赖不等于无损：两者是不同检查项。3NF 综合算法通常可以兼顾无损和保持依赖；BCNF 分解保证无损，但可能牺牲某些依赖保持。案例题若只问“能否还原原表”，答无损；若问“能否分别在单表内检查全部约束”，答保持函数依赖。
