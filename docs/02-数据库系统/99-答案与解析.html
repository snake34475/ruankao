02.10 答案与解析

课后考题答案

1. B 外模式就是某类用户看到的局部数据逻辑（典型实现即视图）。概念模式是全体逻辑，内模式/存储模式是物理层。★ 对应关系直接背。

2. B 存储结构变化发生在内模式，靠模式/内模式映像屏蔽 → 物理独立性。易错点：把"逻辑独立性"跟"存储"联想到一起——恰好相反，逻辑独立性屏蔽的是逻辑结构（表定义）的变化。

3. B 一门课只属一个教师、一个教师可授多门课 → 教师:课程 = 1:n。易错点：见到"多门"就选 m:n——必须两边都可多才是 m:n，这里课程一侧只能一个教师。

4. C m:n 联系必须单独建关系模式，主键 = 学生主键 + 课程主键组合，联系自身的属性（成绩）也放这里。并入任一端都会造成学号重复存储、学号失去主键资格。

5. D 行数：自然连接行数取决于同名属性上相等的元组如何配对，不能确定（最少可能 0 行）；列数 = 4+6−1 = 9。所以选"行数不确定、9 列"。易错点：列数算成 10（忘了去掉一份重复列）或行数答 15（那是笛卡尔积的行数）。

6. B 选择 σ 挑行，投影 π 挑列。口诀：σ 像筛子筛行，π 两条竖线切列。

7. A 能唯一标识元组且无多余属性正是候选键的定义。超键只要求"能唯一标识"（可含多余属性）；主属性是包含在任一候选键中的属性，不是属性集；外键是引用他表主键的属性。

8. A 右部出现过的属性：B（A→B）、C（B→C）、B（D→B）——即 B、C。从未出现在右部的：A、D → 先试 AD：A→B，B→C，D→B，闭包 = A、B、C、D 全部 → 候选键 = AD。再看其余三个为何只是超键：ABD 闭包虽也是 ABCD，但 B 可由 A 推出（A→B），去掉 B 剩 AD 仍能推全 → B 是多余属性；ACD 同理，C 可由 A→B→C 推出，去掉 C 剩 AD 仍推全 → C 多余；ABCD 显然更冗余。候选键 = 无多余属性的"最小"超键，四个选项里只有 AD 满足。

9. B 候选键 = 学号（单属性）→ 不存在部分依赖，直接满足 2NF；但学号→系→系主任是传递依赖 → 达不到 3NF。最高 2NF。易错点：因"有冗余"误判 1NF——单属性键的表第一步就不可能有部分依赖。

10. D 范式是逐级加严的包含链：1NF ⊃ 2NF ⊃ 3NF ⊃ BCNF。BCNF ⇒ 3NF 成立（C 对），反过来 3NF 不一定到 BCNF（D 错，反例：存在主属性被非主属性决定的情况）。A、B 是标准定义。

11. B 聚合条件只能写 HAVING：GROUP BY 课程号 HAVING AVG(成绩)>=80。WHERE 在分组前执行，彼时 AVG 还没算出来，A 语法错误。D 把成绩当分组列，会把每个分数各成一组，不符合"按课程"。

12. B GRANT 授予、REVOKE 收回。DROP 是删除对象（DDL），DENY 不是软考教材标准关键词。

13. C 读到"未提交、随后被回滚"的数据 = 脏数据（读脏数据）。区分：不可重复读是"本事务两次读之间被别人提交的修改弄得不一致"；丢失修改是两个都提交导致一个写被覆盖。

14. B 两段锁协议：先统一加锁、后统一放锁 → 保证可串行化；但两个事务可能互相持有对方要的锁（T1 锁 A 等 B，T2 锁 B 等 A）→ 不能避免死锁。A、C、D 均为典型错误表述。

15. B 故障恢复口诀：已提交 REDO（重做），未提交 UNDO（撤销）。未完成的事务做了一半，必须撤销抹掉。ROLLBACK 是事务运行期间的主动回滚操作，不是恢复策略本身。

案例题答案

问题 1（E-R 图描述）： 实体三个：代表团、运动员、比赛项目。

  • 代表团—运动员：1:n 的"组成"联系；
  • 运动员—比赛项目：m:n 的"参赛"联系，联系属性：成绩。 （画图时：三个矩形 + 两个菱形；"参赛"菱形上挂"成绩"椭圆。）

问题 2（关系模式）：

  • 代表团(团编号, 团名, 团所在地)
  • 运动员(运动员编号, 姓名, 团编号) ← 1:n 联系，把 1 端主键"团编号"并入 n 端作外键
  • 比赛项目(项目编号, 项目名称)
  • 参赛(运动员编号, 项目编号, 成绩) ← m:n 联系单独建表

"参赛"表的主键 =（运动员编号，项目编号）组合键——单靠任何一端都无法唯一标识一行（同一运动员参加多个项目、同一项目多名运动员）。

问题 3（SQL）：

-- (1) 建参赛表
CREATE TABLE 参赛 (
    运动员编号  CHAR(8),
    项目编号    CHAR(6),
    成绩        SMALLINT,
    PRIMARY KEY (运动员编号, 项目编号),
    FOREIGN KEY (运动员编号) REFERENCES 运动员(运动员编号),
    FOREIGN KEY (项目编号)   REFERENCES 比赛项目(项目编号)
);

-- (2) 各代表团总分，保留 300 分以上
SELECT 代表团.团编号, 代表团.团名, SUM(参赛.成绩) AS 总分
FROM 代表团
JOIN 运动员 ON 代表团.团编号 = 运动员.团编号
JOIN 参赛   ON 运动员.运动员编号 = 参赛.运动员编号
GROUP BY 代表团.团编号, 代表团.团名
HAVING SUM(参赛.成绩) >= 300;

（要点：三表连接取全路径代表团→运动员→参赛；GROUP BY 带上团编号防止两个代表团重名被并成一组；聚合条件进 HAVING。）

-- (3) 建视图
CREATE VIEW vHighScore AS
SELECT 运动员.运动员编号, 运动员.姓名, 比赛项目.项目名称
FROM 运动员
JOIN 参赛 ON 运动员.运动员编号 = 参赛.运动员编号
JOIN 比赛项目 ON 参赛.项目编号 = 比赛项目.项目编号
WHERE 参赛.成绩 >= 95;

补充题答案

1. A⁺={A,B,C,D,E}，A 是候选键；C⁺={C}，C 不是候选键。

演算 A⁺：初始 {A}；A→BC，加入 B、C；B→D，加入 D；已有 C、D，可用 CD→E，加入 E；闭包达到全集。A 是单属性，无法再删，故为候选键。反向验证 C⁺：只有 C 时，CD→E 缺 D，其余依赖左部也不满足，没有新属性可加入，故停在 {C}。

2. 候选键为 AB、AC；主属性为 A、B、C；最高为 3NF。

(AB)⁺=ABC，且 A⁺、B⁺都推不全，所以 AB 是候选键。(AC)⁺ 中由 C→B 得到 B，故为 ABC；A⁺、C⁺都推不全，所以 AC 也是候选键。全部属性都出现在某个候选键中，都是主属性，因此至少满足 3NF；但依赖 C→B 中，C 不是超键，违反 BCNF，故最高 3NF。这也反向验证了“全属性皆主属性不代表一定是 BCNF”。

3. A。

分解 A 的公共属性是 A，且 A→AB，所以公共属性能决定 R1，分解无损。分解 B 的公共属性是 B，而由 F={A→B} 推不出 B→AB 或 B→BC，不能用该条件判为无损。

4. 4 行、3 列。

公共值 x 在 R 中出现 2 行，在 S 中出现 2 行，产生 2×2=4 个组合；y、z 互相配不上。列数为 2+2−1=3，属性是 A、B、C。用实际枚举四个组合可反向核对行数。

5. SQL 如下：

SELECT S.Sname
FROM Student AS S
WHERE EXISTS (
    SELECT 1
    FROM SC
    WHERE SC.Sno = S.Sno
      AND SC.Cno = 'C02'
);

SC.Sno = S.Sno 把内层记录与“当前外层学生”绑定。若省略，只要全校任意一人选了 C02，子查询对每个学生都为真，会错误返回全校学生。

6. A。

S 与 S 相容，所以 T2 可再申请 S 锁；S 与 X 不相容，X 锁必须等待。矩阵中唯一的“相容”格就是 S-S。

7. D。

同一范围查询的结果集新增了满足条件的行，属于幻读。不可重复读通常指已存在的同一行字段值改变；脏读必须涉及未提交数据。

8. 系统故障；REDO T1、UNDO T2。

断电但磁盘未损坏属于系统故障。T1 已提交，其结果必须保留，故 REDO；T2 未提交，半成品必须消失，故 UNDO。反向检查：恢复后数据库只应体现已提交事务。

9. 分片透明；可用性。

“怎样水平切块”描述分片规则，属于分片透明；站点失效后仍能借助其他副本服务，描述系统抗单点故障，体现可用性。后者问的是特性，不是复制透明。

精华题答案

1. 视图属于外模式；索引属于内模式 视图是用户局部视图（外模式级，典型实现）；索引是物理存储组织（内模式级）。这题考"具体事物 → 归哪一层"：用户看到的逻辑 = 外模式，磁盘组织细节 = 内模式。

2. 列数 = 3 + 2 − 1 = 4 列（R 的 A、B、C 三列加 S 的 D 列，公共属性 B 只留一份）。 行数最多 = 2×3 = 6 行（R 的每行 B 值恰好都能在 S 中配上时，最多达到笛卡尔积水平；若 B 值全对不上则 0 行）。

3. R 最高属于 2NF 候选键 = 仓库号（单属性）→ 无部分依赖 → 满足 2NF；仓库号→城市→地区编号是传递依赖 → 不到 3NF。 分解到 3NF：仓库(仓库号, 仓库面积, 城市) 和 城市(城市, 地区编号)。

4. 候选键 = E 右部出现过的属性：B、D、A、C；从未出现在右部的只有 E。试 E：E→A，A→B，B→C，C→D → 闭包 = ABCDE，全部推出 → E 单属性即候选键。（验证：E→A→B→C→D，链式全推。）

易错点：答案不是 "AE"。AE 也能推出全部属性（A→B→C→D，再加 E），但它含冗余属性——E 一个人就够了，A 是多余的。候选键的定义是不含冗余属性的最小超键，能少一个就少一个，多出来的那个只能叫超键。反向也要查一遍：A 行不行？A→B→C→D 只能推出 A、B、C、D，推不出 E，所以 A 不是候选键。本题唯一候选键 = E。

5. 发生丢失修改时，A 的错误终值可能是 100 或 70；正确终值应为 120 或 140（取决于串行顺序） 错误终值举例：T1 读 A=50 → T2 读 A=50 → T1 写回 70 → T2 写回 50×2=100，T1 的 +20 被覆盖丢失；另一交错 T2 先写 100、T1 再写 70，则 T2 的结果丢失。正确终值：先 T1 后 T2 串行 = (50+20)×2 = 140；先 T2 后 T1 = 50×2+20 = 120——两种都符合事务语义，但丢失修改哪种都得不到。此题演示"丢失修改 = 一个事务的写被另一个事务的写覆盖"。

6. SQL 答案：

-- (1) 嵌套查询
SELECT Sname FROM Student
WHERE Sno IN (SELECT Sno FROM SC WHERE Cno = 'C02');

-- (2) 选课超过 3 门
SELECT Sno FROM SC
GROUP BY Sno HAVING COUNT(Cno) > 3;

-- (3) 授权（可转授）
GRANT SELECT ON SC TO U1 WITH GRANT OPTION;

要点：(2) 聚合条件进 HAVING；(3) WITH GRANT OPTION 是"允许转授"的固定写法。

7. 前者是不可重复读，后者是读脏数据 "两次读结果不同"：两次读之间别的已提交事务改了数据；"读到未提交"：读到的事务随后可能回滚。判断窍门：看干扰事务提交没有——提交了 → 不可重复读；没提交（后回滚）→ 脏读。
