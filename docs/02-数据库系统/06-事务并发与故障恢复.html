02.6 事务、并发控制与故障恢复 ★★ ​

事务与 ACID ​

事务是"要么全做、要么全不做"的一组操作。经典例子：转账 = A 扣 100 + B 加 100，两个 UPDATE 必须同生共死。

性质含义靠什么保证
原子性 Atomicity全做或全不做故障恢复（UNDO）
一致性 Consistency事务前后数据都处于正确状态原子性 + 隔离性共同效果
隔离性 Isolation并发事务互不干扰并发控制（锁）
持久性 Durability提交后永久生效故障恢复（REDO/日志）

考法："转账中途断电，钱不能凭空消失"体现原子性；"提交后断电重启数据仍在"体现持久性。

并发带来的四类错误（反例各背一个） ​

两个事务 T1、T2 同时操作 A=100：

  1. 丢失修改：T1 和 T2 都读 A=100，T1 加 10 写回 110，T2 减 5 写回 95——T1 的修改被覆盖丢了（应是 105）。
  2. 不可重复读：T1 读 A=100，T2 把 A 改成 200 并提交，T1 再读 A 变 200——同一事务内两次读结果不同。
  3. 读脏数据：T1 把 A 改成 200（还没提交），T2 读到 200；T1 随后回滚，A 恢复 100——T2 读到的 200 是"脏"的，根本没生效过。
  4. 幻读：T1 第一次查询“成绩≥90 的学生”得到 3 行；T2 插入一名 95 分学生并提交；T1 用同一条件再查得到 4 行——像凭空多出一行“幻影”。

不可重复读与幻读都表现为“两次查询不同”，区别在对象：前者是已有同一行的字段值变了，后者是满足条件的行数增减了。口诀：丢改是写被盖，脏读是读未交，不可重复是同一行变，幻读是结果集增减行。

封锁与两段锁协议 ​

  • S 锁（共享锁/读锁）：持锁事务可以读，其他事务还可加 S 锁一起读，但不能加 X 锁写。
  • X 锁（排他锁/写锁）：持锁事务可以读写，其他事务不能再加 S 或 X 锁。

相容矩阵必须会看：行表示“已有锁”，列表示“新申请锁”。

已有锁 \ 新申请S 锁X 锁
S 锁相容不相容
X 锁不相容不相容
  • 两段锁协议：事务分两阶段——先扩展阶段（只加锁不放锁），后收缩阶段（只放锁不加锁）。一旦释放了第一把锁，就不能再申请新锁。
  • 遵守两段锁协议 → 调度可串行化，即并发结果等价于某一种串行顺序执行；但它不能避免死锁。

反例：T1 先锁 A 再等 B，T2 先锁 B 再等 A，两者都处于扩展阶段、都可能符合两段锁，却形成循环等待。因此固定结论是：两段锁保证可串行化，不保证不死锁。

选择题若给出调度并问是否可串行化，简化做法是尝试把所有冲突操作的先后关系画成“事务箭头”：若 T1 必须在 T2 前，同时又推出 T2 必须在 T1 前，形成环，就不能等价为串行调度；无环则可按拓扑顺序串行化。

故障恢复：先分故障，再定 REDO/UNDO ​

故障类型题干识别词影响范围主要恢复手段
事务故障单个事务越界、死锁被撤销、逻辑错误某个事务利用日志 UNDO 该事务
系统故障断电、操作系统崩溃、数据库进程崩溃内存内容丢失，磁盘通常未坏从检查点和日志执行 REDO/UNDO
介质故障磁盘损坏、盘块不可读、数据库文件毁坏持久化数据受损装入备份，再用归档日志 REDO

反例演示（易错）：断电通常属于系统故障，不等于磁盘介质已经损坏；“磁盘磁头损坏导致数据文件不可读”才是介质故障。系统故障靠日志即可恢复，介质故障必须先有备份作底。

依靠日志（先写日志、后写数据库）+ 检查点。系统重启后扫描日志：

  • 事务已提交（BEGIN 后有 COMMIT）→ REDO 重做（结果应该生效，重放保证落盘）；
  • 事务未提交（只有 BEGIN 没有 COMMIT）→ UNDO 撤销（做了一半的必须抹掉）。

口诀：提交了就重做（REDO），没提交就撤销（UNDO）。检查点的作用是记录当时的恢复起点和活跃事务，使恢复时不必从日志开头全量扫描；不能机械理解为“检查点之前的一切都不用管”，跨越检查点但尚未结束的事务仍要结合日志处理。

日志片段若显示 T1 有 COMMIT、T2 只有 BEGIN 和若干写操作，那么恢复动作就是 REDO T1、UNDO T2。反向核对语义：提交的结果必须保持，未提交的半成品必须消失。

分布式数据库：四特性与四种透明性 ​

先分清两类问题：“系统本身有什么特点”问特性；“用户不必知道什么细节”问透明性。

特性白话含义题干识别词
共享性各站点的数据能被全局用户共享跨节点共同访问数据
自治性每个站点能独立管理本地数据库本地独立控制、独立运行
可用性某站点故障时可使用其他站点或副本继续服务单点故障后系统仍可用
分布性数据物理存放在网络中的多个场地多节点、不同地域存储

四种透明性则按“用户被屏蔽的细节”识别：

透明性用户不必知道关键词
分片透明（最高层）一张全局表如何横向或纵向分块分片、分块规则
复制透明同一数据复制了几份、更新哪些副本副本、复制份数
位置透明数据或副本位于哪个站点地址、节点、场地位置
局部映像透明/逻辑透明（最低层）局部 DBMS 的数据模型和操作语言异构数据库、模型转换

易错对比：“表被怎样切成几块”是分片透明；“某一块放在哪座机房”是位置透明；“同一块存了三份”是复制透明。不要把“分片”误当成物理位置。

应试动作：ACID 四个词背全称；四类并发错误能看描述对号入座；S/X 锁只记住“S-S 唯一相容”；“两段锁 → 可串行化但可能死锁”背成一句；故障题先分事务/系统/介质，再套 REDO/UNDO；分布式题先判断问的是“特性”还是“透明性”。
