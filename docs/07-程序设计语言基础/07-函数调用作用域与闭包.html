07.7 函数调用、作用域与闭包 ★★★

动机：函数想用主调方的数据，有两条路——把值复印一份带过去（传值），或把地址/引用（钥匙）递过去直接操作原件（传址/引用）。复印本改坏了不影响原件；钥匙能真改房子。

对比项 传值调用 传址/引用调用
形参拿到什么 实参的值（副本） 实参的地址（原件本身）
形参改变影响实参吗 不影响（单向传递） 影响（双向传递）
实参可以是 变量、常量、表达式均可 只能是变量（必须是地址；常量和表达式没有地址可取）

记忆口诀：传值复印本，改了不还乡；传址寄钥匙，改屋真变样。另一条判断规则：传值的实参随意（常量、表达式都行），传址的实参必须是变量。

反例演示：① 传值调用下 f(a) 里把形参改成 100，函数返回后 a 纹丝不动——想通过参数"带出"结果却用了传值，是初学者最常见 bug；② 引用调用写 f(a+1, b) 直接编译报错/无意义——a+1 是表达式，没有地址可传。

8.1 专题：传值/传址追踪（完整步骤）

考场四步法：

  1. 标记身份：传值参数在旁边标"副本"，传址参数直接标"= 实参"（形实一体）。
  2. 逐句执行：按语句顺序更新形参；每次用到传址参数，写的就是实参的新值（前一句可能刚改过它）。
  3. 同步回写：传址参数每变一次，立即同步到对应实参，防止最后漏记。
  4. 双法验证：先按逐步追踪得出一套结果，再反向验证——传址调用整体等价于"把函数体里的形参名全部替换成实参名后在主调方原地执行一遍"，按这个视角重算一次，两法结果一致才定稿。

例 1（基础对比）：procedure f(x, y) { x = x + 2; y = x + y; }，调用 f(a, b)，初始 a=1, b=3。

传值调用 传址调用
执行 x = x+2 x 副本：1→3 a = 1+2 = 3
执行 y = x+y y 副本：3+(3)=6 b = 3+3 = 6（x 此刻已是 3）
函数返回后 a=1, b=3（原件没动） a=3, b=6

反向验证（传址版）：形参换名后函数体即 a = a+2; b = a+b，原地执行 a=3、b=3+3=6 ✓ 与追踪一致。

例 2（顺序陷阱）：procedure g(x, y) { x = x + y; y = x + y; }，调用 g(a, b)，初始 a=2, b=5。

  • 传值：副本 x=2, y=5 → x=7，y=7+5=12；返回后 a=2, b=5（不变）。
  • 传址：a = 2+5 = 7；接着 y = x+y 用的是新 x：b = 7+5 = 12。

反向验证（传址版）：换名后即 a = a+b; b = a+b → a=7, b=7+5=12 ✓。易错点：第二句若拿旧值算成 b=2+5=7 就错了——传址下第一句已经把 a 改成 7，后续语句必须用新值。

例 3（一值一引用）：procedure mix(value x, ref y) { x=x+1; y=x+y; }，调用 mix(a,b)，初始 a=2、b=5。

  • x 是副本：x=2+1=3，a 仍为 2；
  • y 与 b 是同一变量：y=x+y=3+5=8，所以 b 变为 8；
  • 返回后 a=2、b=8。

反向验证：把值参数 x 换成临时副本 x_copy=2，引用参数 y 换成 b，函数体成为 x_copy=x_copy+1; b=x_copy+b，仍得 a=2、b=8。

例 4（别名陷阱 f(a,a)）：procedure f(ref x, ref y) { x=x+1; y=x+y; }，初始 a=2，调用 f(a,a)。

此时 x、y 不是两个独立格子，而是同一个 a 的两个别名：

  1. x=x+1 → a=3；
  2. y=x+y → 等价于 a=a+a，两边读到的都是当前值 3 → a=6。

若误把 x、y 当成独立副本，会算出 x=3、y=5，这既没有反映引用调用，也漏掉二者指向同一地址。别名题的最稳方法就是形参全部替换成实参名：a=a+1; a=a+a。

8.2 静态作用域与动态作用域：同一段代码为什么可能输出不同

作用域决定某个名字在什么位置可见；当内外层有同名变量时，还要决定一次引用究竟绑定哪一个声明。

x = 1

procedure P() {
    print(x)
}

procedure Q() {
    local x = 2
    P()
}

Q()
  • 静态作用域（词法作用域）：看程序文本中 P 定义在哪里。P 定义在全局层，附近的 x 是全局 x=1，所以输出 1。C、C++、Java、Python 等主流语言采用此思路；
  • 动态作用域：看运行时 P 由谁调用。调用链是 Q→P，沿链先遇到 Q 的局部 x=2，所以输出 2。

反例演示（易错）：静态作用域不是“永远找全局变量”，而是从引用位置按文本嵌套层次由内向外找最近声明；本例恰好 P 的定义层外侧只有全局 x。动态作用域也不是“运行时再看变量类型”，它看的是调用链，别与动态类型混淆。

8.3 闭包：函数离开定义现场后仍带着外部变量

闭包可以理解成“函数代码 + 它引用的词法环境”。例如：

function makeCounter() {
    n = 0
    function next() {
        n = n + 1
        return n
    }
    return next
}

c = makeCounter()
c()  // 1
c()  // 2

makeCounter 已经返回，但 next 仍能访问并更新外层 n；第一次调用后 n 变 1，第二次在同一个变量基础上变 2。它保存的是外部变量的绑定与环境，不是每次调用都重新拿一张“n=0 的照片”。

反例演示（易错）：若把闭包误解成“保存初始值快照”，就会认为两次 c() 都返回 1；实际同一个闭包保留状态，依次返回 1、2。若再次执行 d=makeCounter()，d 拥有另一套独立的 n，第一次 d() 仍返回 1。

应试动作：① 传值标“副本”，传址直接换成实参名；同一实参传给多个引用形参时先标“别名”；② 静态作用域看定义处的文本嵌套，动态作用域看运行时调用链；③ 闭包认准“函数 + 外部词法环境”，连续调用可保留状态。追踪题必须逐句使用最新值，再用换名法重算。
