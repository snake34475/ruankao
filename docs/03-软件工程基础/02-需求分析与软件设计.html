03.2 需求分析与软件设计 ★

2.1 需求工程的四个过程

需求获取 → 需求分析 → 需求规格说明（定义）→ 需求验证（确认）（背顺序）。

需求分析的任务是"找出系统要实现什么功能"——只回答做什么，不回答怎么做。所以"确定模块内部算法""设计数据库表结构"都不属于需求分析（属于设计阶段），这是真题的一种问法。

需求验证指检查需求规格说明书是否正确、一致、完整（三个词连读记）。

2.2 需求的分类（两个层次，别混）

按抽象层次分三层：

层次 视角 例子
业务需求 整体（组织为什么做这个系统） "提升线上订单占比到 60%"
用户需求 用户视角（用户想干什么） "我要能在线查订单进度"
系统需求 计算机化视角（机器怎么界定） 见下面三类

系统需求内部再分三类（这一层才是选择题的主战场）：

类别 含义 识别特征 例子
功能需求 系统做什么 动词 + 对象（查询、统计、导出） "系统应能按日期导出销售报表"
性能需求（非功能需求） 做得怎么样 含数字指标：响应时间、吞吐量、并发数、可靠性 "响应时间不超过 2 秒"
设计约束 必须遵守的外部条件 "必须用…""必须符合…标准" "必须部署在国产操作系统上""须符合等保三级"

应试动作：判断口诀——有数字的"多快好省"归性能，有"必须/须符合"的归设计约束，其余动词句归功能需求。

2.3 结构化分析的产出：四件套（必背清单）

结构化分析（SA）做完之后，交出来的东西是四件，考题常问"下列不属于结构化分析结果的是"：

产出 作用 一句话
一套分层的数据流图（DFD） 功能建模——描述数据怎么流动、被怎么加工 "系统的功能地图"
一本数据词典（DD） 给 DFD 中每个数据流、数据存储、数据项下精确定义 "把图上的名字翻译成人能懂的定义"
一组小说明（加工逻辑说明） 描述 DFD 里每个加工内部的处理逻辑 "加工肚子里的算法"
补充材料：E-R 图 描述数据之间的关系 "数据的静态结构"

动机：为什么光有 DFD 不够？因为 DFD 里的"订单""客户信息"只是名字，谁也不知道里面究竟有哪几个字段——没有数据词典，图中的名字就没有精确含义；同理 DFD 里的"审核"这个加工是个黑盒子，没有小说明就不知道它按什么规则审核。图 + 词典 + 说明，才是完整的一份分析结果。

2.4 软件设计的四项活动（顺序不能乱）

需求想清楚了，进入设计。设计的四项活动是一条有先后依赖的链：

活动 做什么 依据
① 体系结构设计 定义软件系统各主要部件之间的关系（先搭骨架） 需求 + 经验
② 数据设计 基于 E-R 图确定文件系统结构与数据库表结构 E-R 图
③ 接口设计（人机界面设计） 软件内部、软件与操作系统间、软件与人之间如何通信 体系结构
④ 过程设计 把结构部件转换成过程描述——确定各部件内部的算法与内部数据结构 前两项结果

考试问法："确定模块内部算法与数据结构属于哪个活动"→ 过程设计（不是体系结构设计，体系结构只管部件之间的关系）。"基于 E-R 图确定表结构"→ 数据设计。

2.5 加工逻辑的三种描述工具（判定表是重点）

光有 DFD，加工内部是个黑盒；小说明就是用来"打开黑盒"的。描述工具三种：结构化语言、判定表、判定树。

为什么需要判定表：当某个加工的一组动作依赖多个逻辑条件的取值组合时，用自然语言写必然又长又漏（"如果是会员且金额够…如果是会员但金额不够…如果不是会员但金额够…"），判定表能把条件组合与应做的动作一一对平，不漏一种组合。

判定表的四个部分（用双线分割成四个区域）：

区域 内容
左上 条件定义
右上 条件取值的组合（每一列 = 一条规则）
左下 动作定义
右下 在各种取值组合下应执行的动作

完整例子（打折规则：会员且金额≥200 打 9 折；金额≥200 或会员打 95 折；其余不打折）：

条件 / 动作 规则 1 规则 2 规则 3 规则 4
是会员？ Y N Y N
金额 ≥ 200？ Y Y N N
动作 打 9 折 ✓
打 95 折 ✓ ✓
不打折 ✓

验算这张表对不对：4 列 = 2 个条件各取真假共 2² = 4 种组合，无遗漏无双算 ✓。逐列核对规则——(Y,Y)=会员且够钱 → 9 折 ✓；(N,Y)=非会员但够钱 → 命中"金额≥200"→95 折 ✓；(Y,N)=会员但钱不够 → 命中"是会员"→95 折 ✓；(N,N) 两条都不命中 → 不打折 ✓。

判定树是判定表的变形，把条件按层级展开：

用户是否会员？
├─ 是 ── 订单金额 ≥ 200 元？
│        ├─ 是 → 打 9 折
│        └─ 否 → 打 95 折
└─ 否 ── 订单金额 ≥ 200 元？
         ├─ 是 → 打 95 折
         └─ 否 → 不打折

两者对照：判定树更直观、易理解易用；判定表在条件组合多时更严密、不易漏。口诀"树好看、表不漏"。

结构化语言则是用 IF…THEN…ELSE、WHILE…DO 这类受限的伪代码写，规则同上例：

WHILE (收到出库申请)
DO
    查询会员信息 AND 查询订单金额;
    IF (是会员 AND 金额 ≥ 200)
    THEN 打 9 折;
    ELSE
        IF (金额 ≥ 200 OR 是会员)
        THEN 打 95 折;
        ELSE 不打折;
        ENDIF
    ENDIF
    生成结算单;
ENDDO

应试动作：① 背"分层 DFD + 数据词典 + 小说明 + E-R 图"四件套；② 记设计四活动的依据（数据设计靠 E-R 图、过程设计管算法）；③ 判定表只需记住"四区域 + 每列一条规则 + 列数 = 2ⁿ"，考题问列数就直接算 2 的条件数次方。
