03.1 软件开发模型与方法 ★★ ​

1.1 为什么有多种模型 ​

不同项目的需求清晰度和风险高低差别巨大：需求写得一清二楚的项目不需要反复确认，需求说不清的项目硬按部就班走完设计才发现做错了。开发模型的区别就是"怎么安排'想清楚'和'动手做'的顺序"。认模型题的关键是抓题干特征词。

1.2 先分清「方法」和「模型」 ​

这两个词真题里都出现，且常被混问。开发方法回答"用什么思想去理解系统"，开发模型回答"阶段按什么顺序排"。同一个方法可以用不同模型落地（面向对象方法既能用喷泉模型也能用 UP）。

开发方法核心思想一句话识别
结构化方法用户至上、自顶向下逐步求精；严格区分工作阶段（每阶段有任务和结果）；强调开发的整体性、全局性；开发过程工程化、文档资料标准化"自顶向下、逐步求精、阶段严格"
原型法先给用户一个能跑的原型，边用边改"先做出来给用户看"
面向对象方法把系统看成一组互相作用的对象；关键是建立一个全面、合理、统一的模型；分析、设计、实现三阶段界限不明确"三阶段界限模糊、复用性好"
面向服务方法把功能包装成松耦合的服务；抽象级别分三层：操作 → 服务 → 业务流程"三层抽象、服务组合"

考试特征："三阶段界限不明确"只能选面向对象方法（这句话反过来也考："面向对象方法与结构化方法的最大区别"）；"抽象级别为操作、服务、业务流程"只能选面向服务方法。

1.3 开发模型全景（不只有四种） ​

按"想清楚"和"动手做"的排法分两大族：顺序型（一次走完，不回头）与迭代演化型（反复小圈走）。

模型核心特征适用场景题干特征词
瀑布模型线性顺序，每阶段结束有评审，文档驱动需求明确且稳定的项目"需求明确""一次通过、阶段评审"
V 模型瀑布的升级：把测试与开发阶段一一对应挂起来（下面的 4.1 节给对应表）强调测试贯穿始终的项目"测试与开发阶段对应""测试贯穿始终"
增量模型需求切成一片片分批交付，第一个增量常是核心产品可以分期上线、想让核心先稳定的项目"分批交付""先核心后扩展"
原型模型（属演化模型）先快速做一个可运行的原型给用户确认，再正式开发需求不明确、用户说不清，且规模不太大不太复杂"快速构建演示""用户确认后再开发"
螺旋模型（属演化模型）瀑布 + 原型 + 每圈都做风险分析，多圈迭代大型、复杂、高风险项目"风险分析""多轮迭代"
喷泉模型各阶段迭代无间隙（不像瀑布那样阶段分明）；以用户需求为动力、以对象为驱动面向对象的开发"迭代无间隙""对象驱动"
统一过程 UP三大特点：用例驱动、以架构为中心、迭代和增量；四阶段：初始 → 细化 → 构建 → 交付中大型面向对象项目"用例驱动""以架构为中心""四个阶段"
敏捷族（Scrum / XP …）短迭代、拥抱变化、可工作软件优先需求多变、小团队、快速上线"每日站会""冲刺""结对编程""测试驱动"

记忆抓手：

  • 演化模型是一族，包含原型模型与螺旋模型——题干说"属于演化模型的是"要能选原型/螺旋；
  • 喷泉模型的"无间隙"对应面向对象，与瀑布"严格分阶段"正好是一对反义；结构化方法的"严格区分工作阶段"就配瀑布/结构化，别配喷泉；
  • UP 的用例驱动 + 以架构为中心这句连读，是选择题的原话级考点。

1.4 敏捷族六个成员（认名字 + 抓一句特征） ​

敏捷方法一句话特征
极限编程 XP4 大价值观、5 大原则、12 个最佳实践（结对编程、测试驱动开发、持续集成、重构、小型发布…）——工程实践最多
水晶法 Crystal以人为本：每个项目都需要一套不同的策略、约定与方法论；项目质量和开发人员素质提高，过程质量也随之提高
开放式源码开发人员在地域上分布很广
Scrum（并列争球法）把每 30 天一次的迭代称为一个"冲刺周期"，按需求优先级实现；多个自组织和自治的小组并行递增实现产品
功能驱动开发 FDD首席程序员与"类"程序员，人尽其用
自适应软件开发 ASD核心是三个非线性、重叠的阶段：猜测、合作、学习
敏捷统一过程 AUP采用"大型连续"和"小型迭代"原理构建系统

Scrum 与 XP 要能区分（最高频的一对）：Scrum 是管理框架（产品负责人、Sprint 冲刺、每日站会、回顾会）；XP 是工程实践（结对编程、测试驱动开发 TDD、持续集成、重构、小型发布）。题干问"结对编程属于"→ XP；问"每日站会属于"→ Scrum。

1.5 反例演示（易错三处） ​

  1. 原型不是最终产品——抛弃型原型确认完需求就扔掉；考题说"原型可作为最终系统交付"即错。
  2. 螺旋模型不是"更花哨的瀑布"——它区别于一切传统模型的核心就是每圈迭代都加入风险分析；选项里没有风险分析的螺旋描述都是干扰项。
  3. 瀑布模型的"缺点"考法——直到后期才能看到可运行软件、需求变更代价大；不是"没有文档"（瀑布恰恰文档最全，它是文档驱动的）。
  4. 甘特与 PERT 的优缺点不能互串（详见第七节）——"不能反映依赖关系"是甘特的缺点、"不能反映并行关系"是 PERT 的缺点，这两个形容词一换就是错项。

应试动作：背四个特征词对应（明确→瀑布 / 不明确→原型 / 高风险→螺旋 / 多变→敏捷），考试就是配对题；再单独背两条"原话级"结论——面向对象 = 三阶段界限不明确、UP = 用例驱动 + 以架构为中心 + 迭代和增量。
