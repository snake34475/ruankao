03.3 模块化设计：内聚、耦合与模块原则 ★★★ ​

3.0 为什么要"高内聚、低耦合" ​

软件要拆成模块，拆法有好坏：一个模块内部干的事越相关（内聚越高），越容易看懂、改起来越不容易牵连别处；模块之间越独立（耦合越低），一个模块改动对别的影响越小。"高内聚、低耦合"就是这两条经验的一句话版。内聚看模块内部，耦合看模块之间——先分清这个方向再背排序。

3.1 模块设计的六条原则（真题的"下列错误的是"常客） ​

内聚与耦合只回答了"模块怎么拆才算好"里的一个维度。完整的模块设计原则是六条，其中三条专考：

① 保持模块的大小适中

  • 过大：内部可能揉进不同类型的功能，需要进一步划分，尽量让各模块功能单一；
  • 过小：系统复杂度反而增加，模块之间的调用过于频繁，降低了模块的独立性。
  • 结论：模块规模不是越小越好——"模块规模越小越好"是真题的固定错项。

② 深度、宽度适中

  • 深度 = 软件结构中模块的层数。层数过多 → 说明有些模块设计得过于简单，应考虑合并。
  • 宽度 = 软件结构中同一层次上模块总数的最大值。影响宽度最大的因素是模块的扇出。宽度越大系统越复杂。

③ 扇入、扇出系数要合理

  • 扇入 = 该模块的直接上级模块的个数（有多少个模块调用它）；
  • 扇出 = 该模块的直属下级模块的个数（它调用了多少个模块）；
  • 原则是"多扇入、少扇出"：扇入大 = 复用性好（很多模块都用它，改好一处全都受益）；扇出小 = 该模块自身比较独立、不牵动一大片。经典的错项写法是反过来写"多扇出、少扇入"。

④ 模块的作用域应该在控制域之内（最绕、最爱考）

  • 控制域 = 这个模块本身以及所有直接或间接从属于它的模块的集合；
  • 作用域 = 受该模块内一个判定所影响的所有模块的集合；
  • 要求：判定的影响范围必须落在该模块能控制的范围内。

违反时的样子与改法（一眼看懂）：

        M（主控）
       /  \
      A    B        判定 P 写在 A 里面，
     (P)             但 P 的结果要影响兄弟模块 B

A 的控制域 = {A}   ← A 没有下级，管不到 B
A 的作用域 = {B}   ← P 影响的是 B
{B} ⊄ {A}  → 违反！A 只能在算完之后把结果当参数往外传，耦合被迫升高

改法二选一：把判定 P 上移到 M（此时 M 的控制域 = {M, A, B} ⊇ {B} ✓）；或者把被影响的模块 B 下移到 A 之下。

⑤ 功能应该是可预测的 模块的功能要单一、结果要可预期。反例：一个模块的输出取决于某个全局变量的当前值，同样的入参可能返回不同结果，调用者无法预知——这就是"功能不可预测"，属设计缺陷。"模块的功能应该是不可预测的"是真题的固定错项。

⑥ 高内聚、低耦合：见 3.2、3.3。

3.2 内聚七级（从低到高，必须背顺序） ​

级别名称含义一句话识别
1偶然内聚（巧合内聚）动作之间毫无关系，凑在一起（如"为了省事把几个无关函数塞一个模块"）"没什么关系，硬凑"
2逻辑内聚逻辑上相似但功能用途无关（如一个模块按参数分别执行打印输入/打印输出）"相似但无关"
3时间内聚（瞬时内聚）动作无关，但必须在同一时间（同一时间间隔内）执行（如初始化模块）"同一时间"
4过程内聚动作关系不大，但必须按特定次序执行"按次序但无实质关系"
5通信内聚各动作对同一数据进行操作（如对同一份数据先读后存再打印）"围绕同一数据"
6顺序内聚前一个动作的输出正好是后一个动作的输入（必须顺序执行）"接力棒"
7功能内聚所有部分合起来完成单一功能（如计算利息），协同工作缺一不可"就是一个功能"

3.3 耦合七级（从高到低，必须背顺序） ​

级别名称含义一句话识别
1内容耦合一个模块直接访问另一个模块的内部数据或代码；或不经正常入口转入内部；或两块代码重叠；或一个模块有多个入口"掀开别人内脏"
2公共耦合多个模块通过同一公共数据环境（全局数据结构，如一个大数组、一个公共文件）传递信息"共用一个大仓库"
3外部耦合多个模块访问同一全局简单变量（不是数据结构），且不是通过参数表传递"共用一个全局变量"
4控制耦合传递的信息中含控制信号（如开关标志决定对方走哪个分支）"传的是命令不是数据"
5标记耦合通过参数表传递记录信息/数据结构（而非简单变量）"传一整条记录"
6数据耦合通过参数表传递简单数据"传一个数"
7非直接耦合两模块之间没有直接关系，联系完全通过主模块的控制和调用实现"各干各的，上级牵线"

3.4 反例演示（最易混四组） ​

  1. 逻辑内聚 vs 偶然内聚：动作之间"有点相似"（都跟打印/输入输出沾边）→ 逻辑内聚；"完全没关系"→ 偶然内聚。判别标准是相似性是否存在。
  2. 时间内聚 vs 过程内聚：都是"关系不大硬放一起"，区别在约束是"同时"还是"先后"——初始化必须一起做 = 时间；必须按某次序执行 = 过程。
  3. 公共耦合 vs 外部耦合：共用的是数据结构（一整个数组/记录/文件）→ 公共耦合；只是简单变量（一个全局计数器）→ 外部耦合。
  4. 标记耦合 vs 数据耦合：参数传的是一条记录/结构（整个学生信息）→ 标记耦合；只是一个简单变量（学号这一个数）→ 数据耦合。

再强调一处易错：耦合的数据类三项（控制 > 标记 > 数据）排序时，"传记录"比"传简单变量"耦合高——因为在传递的内容里，前者包含了后者的全部信息，改记录结构会牵连更多模块。

应试动作：① 两个排序必须能默写——内聚从"凑（偶然）"到"专（功能）"，耦合从"掀内脏（内容）"到"不认识（非直接）"；② 做题先抓题干关键词（同一时间/同一数据/接力/命令/记录/变量/全局）对号入座；③ 模块原则题抓三个"反向错项"——"越小越好""多扇出少扇入""功能不可预测"，见到就选它错。
