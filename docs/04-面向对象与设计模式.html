04 面向对象与设计模式

分值地位：选择题约 5–7 题 + 案例题「UML 建模」一道大题（补用例/类名/关系，约 15 分）。设计模式每年稳定考 2–4 题，是"背了就得分"的典型考点。

学习目标：读完讲义后，你能——① 分清封装/继承/多态、重载/重写；② 认出 UML 各图及其要素、类图六种关系；③ 背下 23 种设计模式的分类和"意图一句话"，给场景选出模式；④ 按套路补全 UML 案例题。

第一节 面向对象基本概念 ★

四大基石与"为什么"

  • 封装：把数据和对数据的操作捆在一起（类），对外只暴露接口、隐藏实现细节。动机：使用者不必知道内部怎么实现，内部改动不波及外部——和数据库三级模式的"隔离变化"是同一个思想。
  • 继承：子类自动拥有父类的属性和方法，并可扩展。动机：共同点写一遍（放父类），差异点写在子类——消除重复。
  • 多态：同一消息发给不同对象，各自做出不同响应。动机：调用方写一段代码（面向父类/接口），加新子类时调用方一行都不用改——否则就得写满 if 类型==... else if ...，每加一种类型都要回头改调用方。
  • 消息：对象之间通过发送消息（调用操作）通信。

重载 vs 重写（必考对比）

重载 overload 重写 override
位置 同一个类里 子类覆盖父类方法
签名 方法名相同，参数列表必须不同 方法名、参数列表完全相同
绑定时机 编译期根据参数选方法 运行期根据实际对象类型（多态的基础）

反例演示（易错）：只改返回值类型、参数完全相同——既不是重载也不是重写，是编译错误（重载要求参数不同）；子类方法参数列表与父类不同，那就成了重载（新方法），父类版本没有被覆盖，用父类引用调用时执行的还是父类版本——这是"以为重写了、其实重载了"的经典陷阱。

应试动作：抓两个判别词——"同类不同参 = 重载；子类同签名 = 重写"。考题常给一段代码问"输出什么"：父类引用指向子类对象，调用被重写的方法 → 执行子类版本。

第二节 UML 图 ★★★（案例题必考）

九（十）种图先分静态、动态

类别 图 一句话用途 认图特征
静态（结构） 类图 类的属性、操作及类间关系 矩形分三格：类名/属性/操作
对象图 某一时刻的对象快照 名字带下划线
构件图 代码构件之间的依赖 构件符号（带两个小凸起）
部署图 软件到物理节点的映射 立方体（节点）
包图 模型分组 文件夹形状
动态（行为） 用例图 系统功能与参与者 小人（参与者）+ 椭圆（用例）

通信图 同顺序图内容，强调对象间链接 对象间连线标消息序号
状态图 单个对象的状态随事件转换 圆角矩形（状态）+ 箭头（转换）

反例演示（易错）：状态图和活动图长得像，区别在——状态图描述一个对象因事件引起的状态变迁，必须以"事件"为转换条件；活动图描述业务流程步骤，支持并发分支（分叉/汇合），不关心某个对象。另外顺序图 vs 通信图：内容等价、侧重不同——顺序图突出时间顺序，通信图突出对象间链接结构。

类图的六种关系（案例题 + 选择题双考）

关系 符号 含义 例子
泛化（继承） 空心三角实线 is-a 猫 → 动物
实现 空心三角虚线 类实现接口 类 → 接口
关联 实线（可带多重性 1、1..*） 长期的结构关系 读者—借阅记录
聚合 空心菱形实线 整体—部分，部分可独立存在 雁群 — 雁
组合 实心菱形实线 整体—部分，同生共死 鸟 — 翅膀
依赖 虚线箭头 使用关系（参数、局部变量） 类方法里临时用到另一个类

记忆法：菱形在整体一端；空心菱形"散了还能活"（聚合），实心菱形"一荣俱荣一损俱损"（组合）；虚线都是"弱关系"（实现是弱化的继承、依赖是弱化的关联）。

用例图的三种关系（选择题常考）

  • 包含 include：基用例必须执行另一个用例（虚线箭头 + <<include>>）——"借书前必须登录"。
  • 扩展 extend：可选、条件触发的行为（虚线箭头 + <<extend>>）——"超额时弹出逾期提示"（不超额就没有）。
  • 泛化：用例的一般化/特殊化。

反例演示：方向别画反——include 箭头从基用例指向被包含用例；extend 箭头从扩展用例指向基用例。判断窍门：必经之路用 include，可选支线用 extend。

应试动作：① 背"静态五图 + 动态五图"归属；② 六种关系认符号（三角=继承实现、菱形=整体部分、虚线=弱）；③ include/extend 按必经/可选判断。

第三节 设计模式 ★★★（每年 2–4 题）

23 种模式的分类框架（先背骨架）

模式按目的分三类——这本身就回答了"为什么有 23 种"：创建型管"对象怎么造出来"（5 种）、结构型管"对象怎么组装起来"（7 种）、行为型管"对象怎么交互分工"（11 种）。

口诀（自编，按序号背）：

  • 创建型 5：单原工抽建（单例、原型、工厂方法、抽象工厂、构建器）
  • 结构型 7：适桥组外装享代（适配器、桥接、组合、外观、装饰器、享元、代理）
  • 行为型 11：责命解迭中，备观状策模访（职责链、命令、解释器、迭代器、中介者、备忘录、观察者、状态、策略、模板方法、访问者）

23 种意图速查表（背"意图一句话 + 速记词"）

创建型（管出生）：

模式 意图一句话 速记词
Singleton 单例 保证一个类只有一个实例，提供全局访问点 唯一实例
Prototype 原型 通过拷贝原型来创建新对象 克隆
Factory Method 工厂方法 定义创建对象的接口，由子类决定实例化哪个类 动态生产对象
Abstract Factory 抽象工厂 创建一系列相关对象，无需指定具体类 成系列生产
Builder 构建器 复杂对象的构建过程与表示分离，分步构造 分步组装

结构型（管组装）：

模式 意图一句话 速记词
Adapter 适配器 转换接口，使原本不兼容的类协同工作 转换接口
Bridge 桥接 把抽象与实现分离（两个维度），使它们独立变化 继承树拆两维
Composite 组合 把对象组成树形结构表示"整体—部分"，单个和组合对象使用一致 树形目录
Facade 外观 给复杂子系统提供一个统一的高层接口 统一窗口
Decorator 装饰器 动态地给对象附加职责，比继承灵活 附加职责
Flyweight 享元 共享大量细粒度对象，节省内存 共享细粒度
Proxy 代理 为对象提供一个替身以控制对它的访问 间接访问

行为型（管交互）：

模式 意图一句话 速记词
Chain of Responsibility 职责链 请求沿处理者链条传递，直到被处理 传递职责
Command 命令 把请求封装成对象，支持撤销、日志、排队 请求变对象
Interpreter 解释器 给定语言文法，用解释器解释句子 解释语言
Iterator 迭代器 顺序访问聚合元素而不暴露内部表示 逐个访问
Mediator 中介者 封装对象间交互，各对象不必显式互相引用 中介转达
Memento 备忘录 保存对象状态，需要时恢复 存档恢复
Observer 观察者 一对多依赖，状态变化时通知所有依赖者 订阅—通知
State 状态 对象在状态改变时改变行为 状态变行为变
Strategy 策略 封装一系列算法，使它们可互相替换 算法可换
Template Method 模板方法 父类定算法骨架，某些步骤延迟到子类 骨架在父类
Visitor 访问者 不改动类的前提下给类添加新操作 外加操作

高频 8 种：用生活场景锁死（单例、工厂方法、观察者、策略、适配器、装饰器、代理、桥接）

模式 场景联想 认题特征词
单例 系统配置管理器、连接池、打印管理器 "全局唯一""只能有一个"
工厂方法 日志工厂按配置决定生成文件日志还是数据库日志 "子类决定创建哪种对象"
观察者 微信公众号更新，所有粉丝收到推送；事件监听器 "一对多""通知""订阅"
策略 排序算法可换（快排/归并）、支付方式可换（微信/支付宝） "算法可互换""封装算法族"
适配器 国标插头转美标插座；老系统接口包装成新接口 "接口不兼容""转换"
装饰器 给咖啡动态加奶、加糖（不加子类爆炸）；Java IO 流包装 "动态添加职责"
代理 房产中介带看房（控制访问）、图片懒加载、远程调用桩 "控制访问""延迟/远程/安全"
桥接 形状（圆/方）× 颜色（红/蓝）两个维度独立扩展，不用 2×2 个子类 "两个变化维度""抽象与实现分离"

反例演示（最易混三组）：

  1. 装饰器 vs 代理：都包一层对象，区别在意图——装饰器给对象加功能（层层包出不同组合），代理是控制访问（功能不变，管你能不能/何时访问）。
  2. 适配器 vs 外观：适配器是"一个接口转成另一个接口"（一对一改造）；外观是"一堆子系统接口收敛成一个入口"（多合一简化）。
  3. 桥接 vs 装饰器：桥接拆的是两个独立变化的结构维度（形状×绘制方式）；装饰器是同一维度上叠加功能。

应试动作：① 背三分类数字"5/7/11" + 口诀；② 速查表每个模式的"速记词"必须条件反射——考试 80% 是"场景/意图 → 模式名"的配对；③ 三组易混对按"意图"区分。

第四节 案例题专攻：UML 建模（约 15 分）

案例一般是"文字说明 + 用例图/类图/顺序图挖空"，三种小问固定套路：

套路一：补用例图——参与者、用例、include/extend

  1. 参与者：名词且"谁在使用系统/系统服务谁"（读者、管理员、外部系统）；
  2. 用例：系统为参与者完成的一件完整的事（动词短语：借书、还书、缴费）；
  3. 挖空补关系：句子里"必须先/一定要"→ include；"如果…就/可选"→ extend；两种"某类参与者…"→ 用例泛化。

套路二：补类图——名词变类、关系按语义套

  1. 说明中的核心名词 → 类（读者、图书、借阅记录）；数字与规则 → 属性（可借数量）；
  2. 关联：一个读者可有多条借阅记录 → 读者 1 — 1..* 借阅记录；
  3. 聚合/组合：整体部分且"能否独立存在"判空心/实心菱形；
  4. 泛化：句中出现"XX 分为 A、B、C"或"A 类读者、B 类读者都可…" → 抽父类；
  5. 多对多时中间挂关联类（学生—课程之间挂"选课记录"——与第 2 课 m:n 转关系模式同构）。

套路三：补顺序图/状态图——消息按时间排、状态按事件转

  1. 顺序图挖消息：按说明句子的先后顺序填消息名，注意返回消息（虚线箭头）；
  2. 状态图挖状态：状态 = 名词（空闲/占线），转换线上标事件；起点实心圆、终点带圈圆；
  3. 模式识别小问：说明里出现"多种通知方式可切换"→ 策略；"状态变化通知订阅者"→ 观察者；"创建过程复杂分步"→ 构建器——套路与第三节速记词完全一致。

二、案例题（UML 建模，模拟真题风格）

阅读下列说明，回答问题 1 至问题 3。

【说明】某图书馆系统支持读者在线借还图书：

  • 读者使用系统前必须先完成身份登录；
  • 读者可查询图书并借书；若读者存在逾期未还记录，系统给出拒绝提示（没有逾期则不会有此提示）；
  • 借书成功后生成借阅记录，系统在应还日期前通过短信或邮件提醒读者（提醒方式可由系统配置切换）；
  • 一名读者可有多条借阅记录，一本图书可对应多条借阅记录；借阅记录记录所涉图书与读者。

问题 1：用例"借书"与"登录"、"拒绝提示"分别是什么关系？说明理由。

问题 2：画出（或文字描述）核心类图：读者、图书、借阅记录三类，标注关系与多重性。若系统还要求"读者分为学生读者和教师读者"，类图应如何扩展？

问题 3：提醒功能"短信或邮件方式可由系统配置切换"，最适合采用哪种设计模式？说明理由。

课后考题答案

1. C 封装 = 数据 + 操作捆绑、隐藏实现。继承是获得父类特征；多态是同一消息不同响应；重载是同名不同参的方法。

2. B 重载 = 同类中方法名同、参数列表不同、编译期绑定；重写 = 子类同签名覆盖父类方法、运行期绑定。A 把两者的特征说反了；D 错——参数不同就不叫重写了。

3. B 运行期按实际对象类型绑定 → 执行子类版本，这正是多态。C 错在那是重载的绑定方式（编译期看参数）。

4. C 静态（结构）图：类图、对象图、构件图、部署图、包图；状态图、活动图、顺序图、用例图都是动态（行为）图。部署图虽然画的是物理节点，但描述的是结构归属 → 静态。

5. B 鸟与翅膀同生共死（翅膀不能离开鸟独立存在）→ 组合 = 实心菱形。雁群与雁这种"散了还能活"才是空心菱形（聚合）。

6. B "必须先执行"→ include（包含）。extend 是可选/条件触发；泛化是同类用例的一般化。

7. A 同步消息实线实心箭头（发送者停下等返回）；返回用虚线箭头。粗横线是活动图的分叉/汇合，小人是参与者（用例图）。

8. C 结构型 7 种：适配器、桥接、组合、外观、装饰器、享元、代理 → 装饰器在其中。策略、命令属行为型，单例属创建型。

9. B "请求封装成对象 + 撤销/日志/排队" = 命令模式速记词。备忘录是"存档恢复状态"，职责链是"沿链传递直到处理"。

10. A "树形 + 整体部分 + 使用一致" = 组合模式。桥接是抽象与实现两维分离；享元是共享细粒度对象。

11. C "一对多依赖 + 状态变化通知" = 观察者速记词。中介者是"通过中介交互、不显式引用"；状态是"状态变行为变"。

12. A "转换接口、使不兼容类协同" = 适配器。代理是控制访问不加接口转换；装饰器加职责不转接口。

13. B "动态附加职责" = 装饰器速记词。代理意图是控制访问。

14. C "算法可运行时切换" = 策略模式。模板方法是骨架在父类步骤留子类（结构固定）；状态是状态驱动的行为变化（不由客户随意切换算法）。

15. A "仅一个实例 + 全局访问点" = 单例速记词。

案例题答案

问题 1：

  • "借书" → "登录"：<>（包含）——说明中"使用系统前必须先完成身份登录"，登录是借书的必经步骤，基用例（借书）指向被包含用例（登录）。
  • "拒绝提示" → "借书"：<>（扩展）——说明中"若读者存在逾期未还记录，系统给出拒绝提示（没有逾期则不会有）"，是条件触发的可选行为，扩展用例（拒绝提示）指向基用例（借书）。

问题 2：

读者 1 ── 1..* 借阅记录          图书 1 ── 1..* 借阅记录
  • 读者—借阅记录：1 : 1..* 的关联（一名读者可有多条记录，每条记录只属于一名读者）；
  • 图书—借阅记录：1 : 1..* 的关联（一本书可对应多条借阅记录，每条记录只涉及一本书）；
  • 借阅记录是关联类：它把"读者"和"图书"的多对多借还关系落到具体记录上（与第 2 课 m:n 转关系模式同构）。
  • 若增加"读者分为学生读者和教师读者"：增加"读者"的两个子类（学生读者、教师读者），与"读者"之间画泛化（空心三角指向读者），公共属性上移到父类。

问题 3：策略（Strategy）模式。 理由：短信提醒、邮件提醒是一族可互换的算法，系统按配置动态选择其一——正是"封装一系列算法、使它们可以互相替换"的意图。实现上定义统一的提醒接口，短信/邮件各做一个具体策略，配置决定注入哪个策略；将来新增"钉钉提醒"只需加一个策略类，调用方不改（呼应第一节多态的动机）。

精华题答案

1. 分类：创建型——Singleton、Factory Method、Prototype；结构型——Adapter、Bridge、Composite；行为型——Observer、Strategy、Command、Memento。按口诀核对：创建 5 / 结构 7 / 行为 11。

2. ① 享元（Flyweight）——"共享细粒度对象省内存"，棋子共享、位置外提；② 代理（Proxy）——图片对象作为替身控制对真实图片的访问，"延迟加载"是代理的典型应用；③ 职责链（Chain of Responsibility）——请求沿处理者链传递直到被处理，任一环节可截住；④ 命令（Command）+ 备忘录（Memento）——若考"操作封装成对象支持撤销"选命令；若考"恢复到先前状态选快照"则是备忘录。本题"撤销上一步操作"最标准的答案是命令模式（撤销机制由命令对象支持）。

3. ① 聚合（雁离了雁群还能活，空心菱形）；② 组合（翅膀同生共死，实心菱形）；③ 依赖（方法内临时使用，虚线箭头）；④ 实现（类—接口，空心三角虚线）。

4. f(int) 与 f(String) 是重载（同类、同名、参数不同、编译期按参数绑定）；子类的 f(int) 是重写（同签名覆盖父类版本）。多态体现：父类引用 p = new 子类(); p.f(5); 执行的是子类的 f(int)（运行期按实际对象类型绑定）；而 p.f("x") 编译期就绑定到 f(String)。若子类写的是 f(double)，那既没重写也没参与多态——它是子类的新重载方法，父类引用 p 无法直接调到它。

5. 看转换线上标的是什么：状态图的箭头上标事件（事件驱动一个对象的状态迁移，有明确的起点/终点伪状态），活动图的箭头上是动作/活动且出现泳道、分叉汇合（并发）；再问"这图描述的是单个对象还是一段业务流程"——单对象用状态图，流程用活动图。

6. "发布文章"与"保存草稿"是 <>（必经步骤，箭头从发布文章指向保存草稿）；"定时发布"是 <>（勾选才发生，箭头从定时发布指向发布文章）。口诀：必经 include、可选 extend；include 从基用例指出去，extend 从扩展用例指回来。
