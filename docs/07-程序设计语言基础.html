07 程序设计语言基础

分值地位：选择题约 3–5 题（第二梯队稳定得分点）。本课一般不对应独立案例大题，但正规式与有限自动机、传值/传址调用是选择题里的高频题，套路固定、练熟即送分；编译阶段顺序几乎每年都碰。

学习目标：读完讲义后，你能——① 说清程序设计语言的数据、运算、控制、传输四类基本成分；② 背下编译六个阶段的顺序、可选阶段与各阶段产物；③ 在语法树、前中后缀表达式之间互换，并完成最左/最右推导；④ 给正规式快速判串、用子集法理解 NFA 确定化；⑤ 逐步追踪传值/传址、别名参数和静态/动态作用域；⑥ 秒答各语言特点与错误分类。

第一节 语言处理程序：编译与解释 ★★★

动机：计算机 CPU 只认识机器码（0/1 指令），而我们写的是高级语言（C、Java、Python…）。中间必须有一个"翻译程序"把高级语言翻译成机器能执行的东西。按翻译方式不同，分两大流派：

对比项 编译方式 解释方式
代表语言 C、C++、Pascal、Fortran Python、PHP、JavaScript、Ruby
翻译过程 整本翻译：源程序一次性翻译成目标程序（机器码） 逐句翻译：边解释边执行，翻译一句执行一句
是否生成目标程序 生成 不生成
执行效率 高（运行时不再翻译） 低（运行时还要翻译）
灵活性/可移植性 差（目标程序绑定具体机器） 好（源程序拿到哪都能跑）
翻译程序是否参与执行 编译器不参与执行 解释器参与执行

共同点：两种方式都要做词法分析、语法分析、语义分析——别以为解释器就"不分析"，它只是不生成目标程序。

记忆口诀：编译"先翻完再念"，解释"边念边翻"——像拿到一本外文书：编译是请人整本翻译好再读，解释是请个翻译坐在旁边念一句你听一句。

Java / C# 是特殊流派（选择题爱考）：它们先编译成中间代码（Java 字节码 / .NET 中间语言），再由虚拟机（JVM / CLR）解释或即时编译执行——"先编译后解释"。正因为中间代码与平台无关、各平台各有虚拟机，Java 才能"一次编写，到处运行"。

反例演示：判断题「解释方式也会生成与源程序等价的目标程序」——错。这是本考点最常见的陷阱选项；解释器从头到尾不产出可独立执行的目标程序。反向陷阱「编译方式执行效率比解释方式低」——错，编译是"先翻完再念"，运行时零翻译开销，效率更高。

应试动作：背对比表的三行——①是否生成目标程序（编译生成、解释不生成）②执行效率（编译高）③可移植性（解释好）。考场上题干不会出现"流派"这种词，直接给"某语言程序需先翻译成目标程序后执行""逐句翻译执行"等描述让你归类。

第二节 程序设计语言的基本成分 ★★★

动机：不同语言的写法看起来差别很大，但任何程序都绕不开四个问题：数据长什么样、数据怎么算、执行顺序怎么走、数据怎样进出程序。教材把这四件事概括为数据、运算、控制和传输成分。选择题常把其中一个换成“语法/编译/存储”等干扰词。

基本成分 解决的问题 常见内容 最小例子
数据成分 程序处理什么 数据类型、变量、常量、数据结构 int age、Python 列表
运算成分 数据怎样变化 算术、关系、逻辑、位、赋值运算 total = price * count
控制成分 语句按什么顺序执行 顺序、选择、循环 if、for、while
传输成分 数据怎样进入、离开或跨过程传递 输入/输出、参数、返回值、文件与网络读写 read()、print()、return

反例演示（易错）：“整数、字符、布尔”属于数据成分，不是运算成分；if 决定走哪条路径，属于控制成分；+、&&、赋值号描述数据上的操作，才属于运算成分。题目问“可计算问题的程序都能由哪三种控制结构描述”，答顺序、选择、循环，不要把函数调用当第四种基本控制结构。

2.1 数据成分：类型决定“能存什么、能做什么”

数据类型不只是规定占多少空间，还规定取值范围和允许的运算。例如布尔值可以做逻辑运算，整数可以做取模；字符串能拼接，却不能直接参与数值除法。第三节编译知识中的“类型不合法”之所以能在语义分析阶段发现，就是因为类型带着运算规则。

C/C++ 常见基本类型有整数、浮点、字符、布尔、枚举和指针。Python 高频容器要按两个维度分：

类型 是否有序 是否可变 是否允许重复 取元素方式
list 列表 是 可变 是 下标
tuple 元组 是 不可变 是 下标
str 字符串 是 不可变 是 下标
set 集合 否 可变 否 不能按位置下标
dict 字典 按插入次序保存键值对 可变 键不可重复 键

反例演示：tuple 不可变，表示不能把其中某个位置重新赋值，不等于“元组里引用的可变对象永远不会变化”；考试只考第一层结论，记作“字符串、元组不可变；列表、集合、字典可变”。集合去重且不靠位置取值，不能因为打印时看见某个顺序就把它当列表。

2.2 运算成分：同一个符号要结合类型理解

  • 算术运算：+ - * / %；
  • 关系运算：< <= == != >= >，结果通常是布尔值；
  • 逻辑运算：and/or/not 或 &&/||/!；
  • 位运算：按二进制位与、或、异或、移位；
  • 赋值运算：把计算结果写回变量。

Python 中 + 对数字表示相加，对字符串或列表表示拼接；* 对数字表示乘法，对字符串或列表可表示重复。例如 [1,2]+[3]=[1,2,3]，'ab'*2='abab'。这不是符号“随便变义”，而是运算符根据操作数类型选择对应操作。

2.3 控制成分：所有流程都能拆成三种结构

  1. 顺序：从上到下依次执行；
  2. 选择：条件为真走一支，为假走另一支；
  3. 循环：条件满足时重复一段操作。
顺序：A → B → C
选择：条件 ─真→ A
           └假→ B
循环：条件 ─真→ A ─┐
           ↑       │
           └───────┘；假→ 离开

2.4 传输成分：不只是键盘输入和屏幕输出

传输成分负责数据在不同边界之间移动：用户与程序之间有输入/输出，文件与程序之间有读/写，调用者与函数之间有参数和返回值，网络两端之间有发送/接收。例如 x=read() 把外部数据送入程序，return result 把函数结果送回调用者。

反例演示（易错）：赋值 x=x+1 是运算成分，因为数据只在程序内部被计算并写回变量；return x 才是把结果跨越函数边界传回调用者。不要看到“数据发生变化”就一律选传输，关键看是否跨越输入输出或过程边界。

应试动作：背“四成分 = 数据、运算、控制、传输”和“三结构 = 顺序、选择、循环”。题干给 Python 类型时按“是否可变、是否有序、是否去重、怎样取值”四问排除；题干给 +、* 时先看操作数类型，再判断实际运算。

第三节 编译的六个阶段 ★★★

动机：为什么翻译不一步到位，要分六个阶段？因为"读懂一段话"本身就是分层的：先认字（词法），再看句子通不通（语法），再理解意思对不对（语义），最后才落笔翻译（中间代码→优化→目标代码）。分层后每个阶段只管一件事，出错也好定位——你在第 2 阶段就发现"句子结构不对"，不必等到最后生成机器码才发现。

阶段 输入 → 输出 干什么 依据/工具 理论考点
① 词法分析 源程序字符流 → 记号流（单词符号序列） 从左到右逐个扫描字符，识别出关键字、标识符、常数、运算符、分隔符 正规式、有限自动机 词法错误
② 语法分析 记号流 → 语法树 按语法规则把单词组成语法单位，检查结构合法性（如 if…end if 配对、括号匹配） 自顶向下：递归下降、预测分析；自底向上：移进-归约 语法错误
③ 语义分析 语法树 类型检查等静态语义检查（如对浮点数做取余、运算对象类型不合法） 符号表辅助 静态语义错误
④ 中间代码生成 语义分析结果 → 中间代码 生成与具体机器无关的中间形式 常用形式：后缀式、语法树、三地址码、四元式 四元式 (运算符， 对象1， 对象2， 结果)
⑤ 代码优化 中间代码 → 更优的中间代码 提高效率（删冗余、提公共子表达式等） — —
⑥ 目标代码生成 中间代码 → 目标程序 转成低级语言代码，与硬件系统结构密切相关（寄存器分配等） — —

六阶段不是每个编译器都必须逐项拥有：词法、语法、语义分析和目标代码生成是基本阶段；中间代码生成与代码优化可以省略。省略优化只会使目标程序可能不够快，不代表不能正确运行。

目标程序常见三种形式：

  • 绝对指令代码：地址已经确定，可直接装入固定位置执行；
  • 可重定位指令代码：地址尚可调整，装入或链接时再确定实际位置；
  • 汇编指令代码：还需汇编程序进一步翻译成机器指令。

反例演示（易错）：“代码优化是必需阶段”错误；优化服务于效率，不决定源程序语义是否正确。“汇编代码属于中间代码”也错误，教材把它列作目标代码形式之一；常见中间代码是后缀式、语法树、三地址码和四元式。

顺序口诀：词法 → 语法 → 语义 → 中间 → 优化 → 目标（"认字 → 组句 → 懂意 → 打草稿 → 改稿 → 定稿"）。另外符号表贯穿编译全程，记录各符号（变量、函数）的信息，辅助语义检查和代码生成。

中间代码举例（四元式）：对 x := y + z * 60：

(*, z, 60, t1)   ← 先算乘法，结果放临时变量 t1
(+, y, t1, t2)   ← 再算加法
(:=, t2,  , x)   ← 赋值

中间代码"中间"的意义：它站在高级语言和机器语言之间，与机器无关——前端（词法/语法/语义）只管"读懂"，产出到中间代码为止；后端（优化/目标代码）才管"搬到具体机器上"。换一种 CPU，前端原封不动，只改后端。

错误分类（必考表格，背熟）：

类别 发现时机 例子
词法错误 编译时（词法分析阶段） 使用了语言字符集以外的非法字符、单词拼写错误、标点符号错误（如误用中文标点）
语法错误 编译时（语法分析阶段） 括号不匹配、缺少分号、if…end if 不配对、表达式中缺少操作数
静态语义错误 编译时（语义分析阶段） 运算符与运算对象类型不合法（如对浮点数做取余、整型与字符串相加）
动态语义错误 运行时 除数为零、数组下标越界、陷入死循环、无效指针引用

反例演示（最易混的两组）：①「拼写错误 vs 缺分号」——单词拼错、用了中文标点属于词法错误；缺分号、缺括号、缺操作数属于语法错误（涉及语言结构）。②「编译时 vs 运行时」——除零、下标越界编译器查不出来（它不知道运行时下标是多少），所以叫动态错误；死循环也是运行时才暴露。

应试动作：① 背死六阶段顺序和三个"输入→输出"（字符流→记号流→语法树→中间代码→目标程序）；② 错误四分类给例子能归类——判断窍门先问"编译时能发现吗"，再按词法（字符级）/语法（结构级）/静态语义（类型级）定位；③ 记住自顶向下=递归下降/预测分析，自底向上=移进-归约。

第四节 表达式：前缀、中缀、后缀 ★★（与第 1 课联动）

这一节第 1 课（01-数据结构与算法.html 第一节 1.2）已详细讲过中缀转后缀的"傻瓜法"（按优先级加满括号，运算符搬到自己那对括号的右边）。这里给速查表和前缀补全：

表达式 运算符位置 例子（(a+b)*c−d） 特点
中缀 两操作数中间 (a+b)*c−d 人习惯，需括号和优先级
后缀（逆波兰式） 两操作数后面 ab+c*d− 计算机求值最方便，无括号
前缀（波兰式） 两操作数前面 −*+abcd 无括号，考试较少考

4.1 语法树遍历与三种表达式

表达式树把“谁先算”直接画成父子关系：内部结点是运算符，叶子是操作数。对 (a+b)*c：

        *
       / \
      +   c
     / \
    a   b

同一棵树用不同遍历顺序读，就得到三种等价写法：

遍历 访问次序 结果 表达式
先序 根—左—右 * + a b c 前缀 *+abc
中序 左—根—右 a + b * c，按树补括号 中缀 (a+b)*c
后序 左—右—根 a b + c * 后缀 ab+c*

为什么中序必须按树补括号：若只把中序字符机械写成 a+b*c，常规优先级会先算 b*c，与树中“先算 a+b”矛盾。树已经规定运算结构，中缀式必须用括号把这层结构保留下来。

反例演示（易错）：有人把这棵树的后缀写成 bc+a*。按后缀规则还原：bc+ 先得到 (b+c)，再与 a 相乘，实际是 (b+c)*a，不是 (a+b)*c。错误版本不是“顺序差一点”，而是换了一棵树、改变了运算含义。

应试动作：见“给语法树求表达式”直接套：先序=前缀，中序=中缀，后序=后缀；中序读完按树补括号。写完把后缀用栈还原一次，确认每个运算符吃到的左右子树正确。

转前缀的傻瓜法：同样先加满括号，把运算符搬到自己那对括号的左边。例：(a+b)*c−d → (((a+b)*c)−d) → +ab 变 +ab，(+ab)c 变 *+abc，整体减 d → −*+abcd。

后缀求值（必考，完整步骤）：从左到右扫，操作数进栈；遇运算符弹出栈顶两个数计算——先弹出的是右操作数——结果再进栈。例：后缀 8 2 3 * − 4 +：

读到 动作 栈
8, 2, 3 依次进栈 8, 2, 3
* 弹 3、弹 2，算 2×3=6，进栈 8, 6
− 弹 6、弹 8，算 8−6=2，进栈 2
4 进栈 2, 4
+ 弹 4、弹 2，算 2+4=6 6

结果 6。反向验证：该后缀对应中缀 8−2*3+4 = 8−6+4 = 6 ✓。

为什么编译器爱用后缀做中间代码：第三节说过中间代码常用形式里就有"后缀式"——扫后缀式时每个运算符出现时它的操作数一定已在栈里，一遍扫完，不需要优先级表和括号。

反例演示：后缀求值时先弹的是右操作数，减法除法顺序不能反。8 6 − 是 8−6=2；若先弹的当左操作数就算成 6−8=−2，错。

应试动作：① 中缀转后缀用"加满括号搬右边"，转前缀"搬左边"；② 求值时先弹的当右操作数；③ 考题给后缀式求值，用栈表逐步算，算完还原成中缀验一遍。

第五节 文法与语法树 ★★

动机：语法分析"按语法规则组句"，这条规则的形式化描述就是文法。

一个形式文法是四元组 G = (V, T, S, P)：

成分 名称 含义
V 非终结符 不是语言的最终组成部分，是"占位符"（如 <句子>、S、A）
T 终结符 语言的最终组成部分（如 a、b、关键字）
S 起始符 推导从它开始（S ∈ V）
P 产生式 替换规则，形如 A → α（用右部替换左部）

例：文法 S → aSb | ε。从 S 出发反复推导：S ⇒ aSb ⇒ aaSbb ⇒ aabb。它描述的语言是 {aⁿbⁿ | n≥0}——非终结符 S 像"待填的坑"，终结符 a、b 才是最终结果。

5.1 推导、句型与句子

  • α ⇒ β：使用一次产生式，把 α 中某个非终结符替换后得到 β，称为直接推导；
  • α ⇒* β：经过零次或多次推导得到；
  • 句型：从起始符 S 能推导出的符号串，可以同时含终结符和非终结符；
  • 句子：不再含非终结符的句型，即全部由终结符组成；
  • 语言 L(G)：文法 G 能生成的全部句子的集合。

反例演示（易错）：在文法 S→aSb|ε 中，aaSbb 是句型，但不是句子，因为 S 这个“待填坑”还没消失；aabb 才是句子。判断时不要看它“像不像单词”，只看是否还含非终结符。

5.2 最左推导与最右推导：只改变替换顺序

设文法：

S → AB
A → aA | a
B → bB | b

目标串 aabb 的最左推导（每一步只替换最左边的非终结符）：

S ⇒ AB ⇒ aAB ⇒ aaB ⇒ aabB ⇒ aabb

目标串的最右推导（每一步只替换最右边的非终结符）：

S ⇒ AB ⇒ AbB ⇒ Abb ⇒ aAbb ⇒ aabb

两条推导的中间句型不同，但终点都是 aabb。反向核对：A 只能生成一个或多个 a，B 只能生成一个或多个 b，因此任何句子都应是“若干 a 后接若干 b”；aabb 符合，而 abab 不可能由该文法生成。

判串三步法：① 从 S 开始；② 每一步明确写出使用哪条产生式，不允许凭空换字符；③ 最终必须消掉全部非终结符并恰好得到目标串。若目标串的开头、结尾已经违反产生式结构，可先快速排除。

闭包与正则闭包（公式三件套）：

  • 通用形式：正则闭包 A⁺ = A¹ ∪ A² ∪ …（1 个或多个 A 连接）；闭包 A* = A⁰ ∪ A⁺（在正则闭包基础上加上 A⁰ = {ε}，ε 是空串）。
  • 代入算例：A = {ab} 时，A⁺ = {ab, abab, ababab, …}；A* = {ε, ab, abab, …}——只多一个空串 ε。
  • 手算口诀："加 1 乘 0"——+ 表示 1n 个（不含空串），* 表示 0n 个（含空串）。

5.3 语法推导树

从起始符 S 出发按产生式展开：根是 S，内部结点是非终结符，叶子从左到右拼起来就是句子。上例 aabb 的树可写成：

          S
        /   \
       A     B
      / \   / \
     a   A b   B
         |     |
         a     b

叶子从左到右为 a a b b，与目标串一致；树的左、右子树也分别满足 A、B 的产生式。教学图反向检查：每个内部结点展开出的孩子必须恰好等于某条产生式右部，不能为了凑目标串随意添叶子。

重要结论：常见的程序设计语言（C、Java 等）的语法规则通常是上下文无关文法——选择题直接考这个结论。

应试动作：① 四元组各成分一句话定义；② 能区分“仍含非终结符的句型”与“只含终结符的句子”；③ 题目指定最左/最右推导时，每步只换对应一侧的非终结符；④ 背“程序语言通常用上下文无关文法”。闭包公式放在本节是为了服务正规式，口诀仍是“加 1 乘 0”。

第六节 正规式与正规集 ★★★

动机：词法分析阶段要识别"什么样的字符串算一个标识符、什么样的算一个整数"——这种单词的模式就用正规式（正则表达式）描述。它是描述字符串集合的最简工具。

6.1 三种运算与优先级

正规式只有三种基本运算（按优先级从高到低）：

运算 符号 含义 例
闭包 * 重复 0 次或多次（优先级最高） a* = {ε, a, aa, aaa, …}
连接 ·（常省略） 依次拼接（次高） ab = {ab}
或 ` ` 二选一（最低）

公式三件套（以 (a|b)* 为例）：① 通用形式——闭包作用于括起来的整体，表示括号内串的任意次拼接；② 代入算例——(a|b)* = {ε, a, b, ab, ba, aab, abb, …}，即所有由 a、b 组成的串（含空串）；③ 手算口诀——先算 *（闭包），再算连接，最后算 |；想改变顺序就加括号。

常用正规式速查表（背熟，考题基本不出这张表）：

正规式 表示的正规集
ab 仅 {ab}
`a b`
a* {ε, a, aa, aaa, …}（任意多个 a，含空串）
`(a b)*`
`a(a b)*`
`(a b)*abb`
`(a b)*aa(a

反例演示（三组经典混淆，逐组看会错在哪）：

  1. ab* ≠ (ab)*。ab* 中 * 只作用于 b（闭包优先级最高）：{a, ab, abb, abbb, …}——一个 a 后跟任意多个 b；(ab)* 是 {ε, ab, abab, …}。若把 ab* 误当成 (ab)*，就会得出"abb 属于 (ab)*"的错误结论——按 (ab)* 逐块切分 abb：第一块 ab，剩下 b 不够一块，切不动 → 不属于。
  2. a|b* ≠ (a|b)*。a|b* = {a} ∪ {ε, b, bb, …}——单个 a，或若干个 b；绝没有 ab、ba 这种混合串。
  3. 「以 abb 结尾」≠「含有 abb」。(a|b)*abb 要求串最后三个字符恰好是 abb；若多写一段成 (a|b)*abb(a|b)*，就放宽成"中间只要出现过 abb"——此时 abba（以 a 结尾）也会被匹配。边界条件差一段闭包，集合就完全不同。

6.2 专题：给正规式判串（完整判定步骤）

考场四步法：

  1. 翻译：把正规式翻译成大白话——"以什么开头 / 以什么结尾 / 中间任意 / 至少含什么"。
  2. 首尾筛查：先用开头、结尾条件快速淘汰选项（最快）。
  3. 分块回代：对存活选项，把串按正规式结构切分——闭包部分逐字符核对是否都在字母表内，| 部分逐位二选一。
  4. 反向验证：把选中的串按"开头块 + 闭包块 + 结尾块"重新拆一遍，确认每块都能对上号，且没有剩余字符没归属。

例（完整演算）：正规式 r = (a|b)*aa(a|b)*，判断哪个串属于 L(r)。

  1. 翻译：所有含有连续两个 a（子串 aa） 的 a、b 串。
  2. 首尾筛查：首尾无限制（两端都是 (a|b)*），此步淘汰不了，直接进第 3 步。
  3. 分块回代：
    • ababa：逐字符找 aa——a、ab、aba…均无相邻两个 a → 不属于 ✗
    • baab：中间 baab，含 aa → 候选 ✓
    • abab：无 aa ✗
    • abba：无 aa ✗
  4. 反向验证：baab = (a|b)* 取 b ＋ aa ＋ (a|b)* 取 b，三块拼回恰好是 baab，无剩余字符 ✓。

结论：只有 baab 属于 L(r)。注意第 3 步找"连续 aa"是看相邻两个字符，别隔位看。

给串选正规式（反过来问）同样用四步法：先看待匹配串的结构特征（开头/结尾/含什么），再逐个选项检查——特别警惕"形似但范围不同"的选项，用上面第 6.1 节的反例 1、2 的切分法排除。

6.3 两类真题变体：由式找规律、由语言选式

变体一：给正规式，问整个集合的共同特征。

例：0*(10*1)*0* 表示什么？

  1. 最外两段 0* 允许开头、结尾出现任意多个 0；
  2. 中间每个 10*1 块固定贡献 两个 1，两者之间可夹任意多个 0；
  3. 整块再取 *，可以重复 0 次、1 次、2 次……；
  4. 因而 1 的总数只能是 0、2、4、6……，即1 出现偶数次的所有 0、1 串。

代串验证：000 取中间块 0 次，属于；101 有两个 1，属于；11001 有三个 1，不属于。反例：不能把它误读成“长度为偶数”，101 长度 3，却有两个 1，仍属于该语言。

变体二：给语言定义，选择正规式。

“所有至少含一个 1 的 0、1 串”可写成：

0*1(0|1)*

第一个固定 1 保证“至少一个”；它前面只能是 0，所以由 0* 承担；第一个 1 之后可以再出现任意 0/1，由 (0|1)* 承担。也可写成 (0|1)*1(0|1)*，两者都描述“某处至少出现一个 1”，但选择题以选项实际给法为准。

排除法：为每个候选式各找一个“应当接受的串”和“应当拒绝的串”。例如“至少一个 1”必须接受 1、001、1010，必须拒绝 ε、0、000；一个选项只要在这几条上出错即可淘汰，不必穷举整个语言。

应试动作：背熟速查表 + 三组反例。考场上题干给一个正规式四个串，30 秒流程：翻译成大白话 → 首尾筛 → 存活者分块回代 → 反向拼回验证。若问集合规律，就数每个重复块固定贡献几个字符；若给语言选式，就用“应接收/应拒绝”的最小测试串排除。"给状态图写正规式"用第七节的方法。

第七节 有限自动机：DFA 与 NFA ★★★

动机：正规式描述了单词的"模式"，但程序怎么执行这个模式？有限自动机（FA）就是正规式的"可执行版本"——词法分析器内部就是一台有限自动机在逐字符扫描。正规式和自动机描述能力等价，可互相转换。

7.1 定义与五元组

自动机 M = (S, Σ, δ, s₀, Z)：

成分 含义
S 有限状态集
Σ 有穷输入字母表（每个元素一个输入字符）
δ 转换函数：当前状态 + 输入字符 → 下一状态
s₀ 唯一初态（s₀ ∈ S）
Z 终态集（可空）

状态转换图：圆圈是状态，箭头标输入字符表示转移，双圈（或打星）是终态。

识别规则：从初态出发，逐个读入字符串的字符沿箭头走；读完整个串恰好停在终态，则该串被自动机接受（识别）；中途走不动或读完不在终态，则不接受。

含 ε 的快判：如果初态本身也是终态，那么即使一个字符都不读，空串 ε 也已经停在终态，因此自动机接受 ε。若初态上还有能回到终态的循环，则通常识别“0 个或多个”某类片段；看到“初态=终态”先检查选项是否漏掉空串。

反例：不能因为状态图里“有一条 a 边”就断言最短串一定是 a。若初态画成双圈，长度为 0 的 ε 已经被接受，a 只是另一个可能的串。

DFA vs NFA（必考区别）：

确定有限自动机 DFA 不确定有限自动机 NFA
转移函数 单值对照：一个状态面对一个输入符号，转移到的状态唯一确定 面对同一输入符号可转移到多个状态（一个集合），可有 ε 转移（不读字符就跳）
识别能力 与 NFA 等价 与 DFA 等价（NFA 可用子集法确定化成 DFA）

注：DFA 是 NFA 的特例；两者识别的语言类相同（都恰好是正规式能描述的语言）。这与第 1 课（01-数据结构与算法.html）里算法的"确定性"是同一种思想——DFA 每一步走向唯一，模拟它就是照表走。

7.2 专题：判定自动机接受哪些串（完整步骤）

考场三步法：

  1. 列转移表：把每个状态对每个输入字符的走向列成表（题干给状态图就照图抄表）。
  2. 逐步走串：从初态开始，对候选串逐字符查表，每步写出当前状态；中途出现"该状态对该字符无转移"则立即拒绝。
  3. 终态核对 + 反向验证：读完整个串看是否停在终态；再用该自动机对应的语言特征（先根据几条路径归纳出"以××开头/结尾"等规律）反向检查一遍，两条路结论一致才落笔。

例（完整演算）：DFA 状态转移表如下（q₀ 为初态，q₂ 为唯一终态）：

状态 输入 0 输入 1
→q₀ q₀ q₁
q₁ q₀ q₂
*q₂ q₀ q₂

先归纳语言：观察——只有"连续读入两个 1"才能从 q₀ 经 q₁ 到达 q₂；到了 q₂ 之后读 1 停在 q₂、读 0 回 q₀。所以接受的是以 11 结尾的 0、1 串（等价正规式 (0|1)*11）。

逐步走串（判 1011）：q₀ --1--> q₁ --0--> q₀ --1--> q₁ --1--> q₂。读完停在终态 q₂ → 接受 ✓。

反向验证：1011 以 "11" 结尾，与归纳的语言特征一致 ✓。再判 1101：q₀ --1--> q₁ --1--> q₂ --0--> q₀ --1--> q₁，读完停在 q₁ 非终态 → 拒绝；反向看 1101 以 "01" 结尾，不一致才对（它确实不以 11 结尾）✓。两条路结论吻合。

给状态图写正规式：先归纳语言（看什么路径能从初态走到终态、走终态前必须经过什么），再用速查表（第六节）把特征写成正规式——以"以 11 结尾"为例：前面任意 (0|1)* ＋ 结尾固定 11，得 (0|1)*11。写完拿一个被接受的串和一个被拒绝的串各回代验一次。

7.3 子集法：把 NFA 的“一次多路”变成 DFA 的“集合状态”

NFA 面对一个输入可以同时走向多个状态；DFA 不允许多选。子集法的核心不是丢掉某条路，而是把“NFA 此刻所有可能状态的集合”当成 DFA 的一个新状态。

通用步骤：

  1. 取 NFA 初态的 ε-闭包（只走 ε 边能到达的全部状态）作为 DFA 初态；
  2. 对一个集合状态和输入字符 x，让集合中每个 NFA 状态都走一次 x，把所有结果取并集；
  3. 再对结果取 ε-闭包，得到下一个 DFA 集合状态；
  4. 遇到新集合就加入表中，反复处理，直到不再出现新集合；
  5. 集合中只要含 NFA 的任一终态，该集合就是 DFA 终态。

最小演算：NFA 状态为 {q0,q1}，q0 是初态、q1 是终态，字母表 {a}；转移为 δ(q0,a)={q0,q1}、δ(q1,a)=∅，且没有 ε 边。

DFA 集合状态 输入 a 后各状态的去向 并集结果 是否终态
{q0}（初态） q0→{q0,q1} {q0,q1} 否
{q0,q1} q0→{q0,q1}，q1→∅ {q0,q1} 是（含 q1）

得到的 DFA 有两个集合状态：读入第一个 a 后进入终态，以后每读 a 都留在终态，所以识别 a+（一个或多个 a）。反向验证：ε 停在 {q0} 非终态，不接受；a、aa、aaa 都进入或留在 {q0,q1}，接受。

反例演示（易错）：不能从 {q0,q1} 随便挑 q0 的去向当结果，必须把集合内所有状态的去向取并集；也不能把“含终态”误写成“集合必须只剩终态”，只要包含 q1 就是接受状态。

应试动作：① 背 DFA/NFA 区别一句话——"DFA 单值、NFA 多值（可含 ε），能力等价"；② 初态也是终态时立刻检查 ε；③ 判串逐字符走，子集法逐集合取并集，集合含任一原终态就标终态；④ 给图写正规式时用“逐字符走 + 归纳语言”双重验证。

第八节 函数调用、作用域与闭包 ★★★

动机：函数想用主调方的数据，有两条路——把值复印一份带过去（传值），或把地址/引用（钥匙）递过去直接操作原件（传址/引用）。复印本改坏了不影响原件；钥匙能真改房子。

对比项 传值调用 传址/引用调用
形参拿到什么 实参的值（副本） 实参的地址（原件本身）
形参改变影响实参吗 不影响（单向传递） 影响（双向传递）
实参可以是 变量、常量、表达式均可 只能是变量（必须是地址；常量和表达式没有地址可取）

记忆口诀：传值复印本，改了不还乡；传址寄钥匙，改屋真变样。另一条判断规则：传值的实参随意（常量、表达式都行），传址的实参必须是变量。

反例演示：① 传值调用下 f(a) 里把形参改成 100，函数返回后 a 纹丝不动——想通过参数"带出"结果却用了传值，是初学者最常见 bug；② 引用调用写 f(a+1, b) 直接编译报错/无意义——a+1 是表达式，没有地址可传。

8.1 专题：传值/传址追踪（完整步骤）

考场四步法：

  1. 标记身份：传值参数在旁边标"副本"，传址参数直接标"= 实参"（形实一体）。
  2. 逐句执行：按语句顺序更新形参；每次用到传址参数，写的就是实参的新值（前一句可能刚改过它）。
  3. 同步回写：传址参数每变一次，立即同步到对应实参，防止最后漏记。
  4. 双法验证：先按逐步追踪得出一套结果，再反向验证——传址调用整体等价于"把函数体里的形参名全部替换成实参名后在主调方原地执行一遍"，按这个视角重算一次，两法结果一致才定稿。

例 1（基础对比）：procedure f(x, y) { x = x + 2; y = x + y; }，调用 f(a, b)，初始 a=1, b=3。

传值调用 传址调用
执行 x = x+2 x 副本：1→3 a = 1+2 = 3
执行 y = x+y y 副本：3+(3)=6 b = 3+3 = 6（x 此刻已是 3）
函数返回后 a=1, b=3（原件没动） a=3, b=6

反向验证（传址版）：形参换名后函数体即 a = a+2; b = a+b，原地执行 a=3、b=3+3=6 ✓ 与追踪一致。

例 2（顺序陷阱）：procedure g(x, y) { x = x + y; y = x + y; }，调用 g(a, b)，初始 a=2, b=5。

  • 传值：副本 x=2, y=5 → x=7，y=7+5=12；返回后 a=2, b=5（不变）。
  • 传址：a = 2+5 = 7；接着 y = x+y 用的是新 x：b = 7+5 = 12。

反向验证（传址版）：换名后即 a = a+b; b = a+b → a=7, b=7+5=12 ✓。易错点：第二句若拿旧值算成 b=2+5=7 就错了——传址下第一句已经把 a 改成 7，后续语句必须用新值。

例 3（一值一引用）：procedure mix(value x, ref y) { x=x+1; y=x+y; }，调用 mix(a,b)，初始 a=2、b=5。

  • x 是副本：x=2+1=3，a 仍为 2；
  • y 与 b 是同一变量：y=x+y=3+5=8，所以 b 变为 8；
  • 返回后 a=2、b=8。

反向验证：把值参数 x 换成临时副本 x_copy=2，引用参数 y 换成 b，函数体成为 x_copy=x_copy+1; b=x_copy+b，仍得 a=2、b=8。

例 4（别名陷阱 f(a,a)）：procedure f(ref x, ref y) { x=x+1; y=x+y; }，初始 a=2，调用 f(a,a)。

此时 x、y 不是两个独立格子，而是同一个 a 的两个别名：

  1. x=x+1 → a=3；
  2. y=x+y → 等价于 a=a+a，两边读到的都是当前值 3 → a=6。

若误把 x、y 当成独立副本，会算出 x=3、y=5，这既没有反映引用调用，也漏掉二者指向同一地址。别名题的最稳方法就是形参全部替换成实参名：a=a+1; a=a+a。

8.2 静态作用域与动态作用域：同一段代码为什么可能输出不同

作用域决定某个名字在什么位置可见；当内外层有同名变量时，还要决定一次引用究竟绑定哪一个声明。

x = 1

procedure P() {
    print(x)
}

procedure Q() {
    local x = 2
    P()
}

Q()
  • 静态作用域（词法作用域）：看程序文本中 P 定义在哪里。P 定义在全局层，附近的 x 是全局 x=1，所以输出 1。C、C++、Java、Python 等主流语言采用此思路；
  • 动态作用域：看运行时 P 由谁调用。调用链是 Q→P，沿链先遇到 Q 的局部 x=2，所以输出 2。

反例演示（易错）：静态作用域不是“永远找全局变量”，而是从引用位置按文本嵌套层次由内向外找最近声明；本例恰好 P 的定义层外侧只有全局 x。动态作用域也不是“运行时再看变量类型”，它看的是调用链，别与动态类型混淆。

8.3 闭包：函数离开定义现场后仍带着外部变量

闭包可以理解成“函数代码 + 它引用的词法环境”。例如：

function makeCounter() {
    n = 0
    function next() {
        n = n + 1
        return n
    }
    return next
}

c = makeCounter()
c()  // 1
c()  // 2

makeCounter 已经返回，但 next 仍能访问并更新外层 n；第一次调用后 n 变 1，第二次在同一个变量基础上变 2。它保存的是外部变量的绑定与环境，不是每次调用都重新拿一张“n=0 的照片”。

反例演示（易错）：若把闭包误解成“保存初始值快照”，就会认为两次 c() 都返回 1；实际同一个闭包保留状态，依次返回 1、2。若再次执行 d=makeCounter()，d 拥有另一套独立的 n，第一次 d() 仍返回 1。

应试动作：① 传值标“副本”，传址直接换成实参名；同一实参传给多个引用形参时先标“别名”；② 静态作用域看定义处的文本嵌套，动态作用域看运行时调用链；③ 闭包认准“函数 + 外部词法环境”，连续调用可保留状态。追踪题必须逐句使用最新值，再用换名法重算。

课后考题答案

1. C 编译是"先整本翻译成目标程序，再直接运行目标程序"，执行时编译器不参与，效率高（A 反了）；解释器逐句翻译执行、不生成目标程序（B 反了）；两种方式都要做词法、语法、语义分析（D 反了）。易错点：B 是最常见陷阱——"解释也要分析，但不产出目标程序"。

2. B 词法分析：字符流 → 记号流；语法分析的输出才是语法树（C）；目标代码是最后阶段产物（D）。记忆链：字符流→记号流→语法树→中间代码→目标程序。

3. A 固定顺序：词法④ → 语法② → 语义⑤ → 中间代码① → 优化⑥ → 目标代码③。B 把优化提到中间代码之前（没有中间代码，优化什么？）；C 词法语法颠倒（先认字才能组句）；D 语义跑到语法前面（不懂结构怎么查语义）。口诀：词法语法语义，中间优化目标。

4. D 下标越界要等运行时才知道实际下标是多少，编译器无法发现——动态语义错误。同类的还有除数为零、死循环。凡是"运行时才暴露"的都选动态语义错误。

5. C 静态语义错误 = 类型类错误且编译时能查：对浮点数做取余是运算对象类型不合法。A、B 是语法错误（结构问题）；D 是动态语义错误（运行时）。判断窍门：编译时+类型有关 → 静态语义；编译时+结构有关 → 语法；运行时 → 动态语义。

6. D 常用中间代码四种：后缀式、语法树、三地址码、四元式——它们都与具体机器无关。汇编指令代码是目标代码级的东西，不是中间代码。

7. A 逐步演算（傻瓜法：加满括号，运算符搬到自己那对括号右边）： (a+b)*c-(d-e) → (((a+b)*c)-(d-e))；a+b → ab+；(ab+)*c → ab+c*；d-e → de-；最后整体减法：ab+c* ＋ de- ＋ - → ab+c*de--。 反向验证：按"每个运算符吃掉前面紧挨的两块"读 ab+c*de--——+ 吃 a、b 得 a+b；* 吃 (a+b)、c；- 吃 d、e 得 d−e；最后一个 - 吃 (a+b)c 与 (d−e)——恰为原式 ✓。 B 读出来是 a+bc−(d−e)（* 抢先作用于 b、c）；C 读出来是 (a+b)c−de；D 读出来是 (a+b)−(c−d)*e，均与原式不符。

8. B 翻译：(a|b)*aa(a|b)* = 两端任意、中间含连续 aa 的 a、b 串（速查表第 7 行）。A、C 错在把"含 aa"窄化成"开头/结尾是 aa"——baab 含 aa 但既不以 aa 开头也不以 aa 结尾，却在集合中；D 更是无关。反向验证：baab = b＋aa＋b，三块拼回无剩余 ✓。

  • D 1110：q₀ --1--> q₁ --1--> q₂ --1--> q₂ --0--> q₀，停在 q₀ ✗ 反向验证：该 DFA 的语言是"以 11 结尾的 0、1 串"（见第七节例题）；C 1011 以 11 结尾 ✓，A 以 01 结尾、B 以 10 结尾、D 以 10 结尾，均不符。两条路结论一致。

13. B ②④正确：传值传的是副本，实参给常量表达式都行，但形参改动不会影响实参（①错，单向）；引用调用双向传递（④对），但实参必须是变量——常量和表达式没有地址可传（③错）。记忆口诀：传值复印本（单向、实参随意），传址寄钥匙（双向、实参须变量）。

14. B 逐句追踪（引用调用：x 即 a，y 即 b）：

  • 初始 a=6, b=2
  • x = 2*x → a = 2×6 = 12
  • y = x - y → b = 12 − 2 = 10（x 必须用新值 12） 反向验证：换名后函数体即 a = 2*a; b = a - b，原地执行 a=12、b=12−2=10 ✓。 A 是传值调用的结果（原件不动）；C 错在第二句没用新 x；D 错在第一句没执行。易错点：传址追踪每句都用当前最新值。

15. A Prolog 是逻辑推理型语言（用于专家系统、数据库），不是面向对象语言——A 的对应关系错误，选它。B、C、D 均为正确对应。易错点：Lisp（函数式/AI）与 Prolog（逻辑推理）都沾"人工智能"，但"函数式"标签专属 Lisp，"逻辑推理"标签专属 Prolog，别互换。

案例 1

问题 1（p 传值 = 副本；q 引用 = y 本身）：

语句 p（副本） q（=y） x y r
初始 5 3 5 3 —
q = q - p 5 3−5=−2 5 −2 —
p = p - q 5−(−2)=7 −2 5 −2 —
return p — — 5 −2 7

结果：r=7，x=5，y=−2。 反向验证：q 引用即"函数体中 q 全部换成 y"：y = y−x → y=−2；p 是副本不受影响，p=5−(−2)=7，返回 7；x 从未被引用绑定，保持 5 ✓。

问题 2（都传值，p、q 均为副本）：

语句 p q x y r
初始 5 3 5 3 —
q = q - p 5 −2 5 3 —
p = p - q 7 −2 5 3 —
return p — — 5 3 7

结果：r=7，x=5，y=3。反向验证：全是副本，主调方 x、y 纹丝不动 ✓。

问题 3：两次返回值恰好相同（返回值只依赖形参自身的算术，与传递方式无关），但引用调用把对形参的修改带回了实参（y 由 3 变 −2），传值调用完全不影响实参——本质区别：传的是"复印本"还是"原件本身（地址）"，即数据能否双向流动。

案例 2

问题 1：观察转移表：从 q₀ 想到达终态 q₂，唯一入口是 q₁ --b--> q₂；而到 q₁ 只能靠读 a（q₀ --a--> q₁ 或 q₁ --a--> q₁）；q₂ 读 a 回 q₁、读 b 回 q₀（一旦读 b 彻底清零，必须重新积累）。所以接受的是所有以 ab 结尾的 a、b 串。 等价正规式：(a|b)ab。 反向验证：拿 aab（∈L）回代正规式——(a|b) 取 a、结尾 ab，拼回 aab ✓；拿 abb（∉L）检验——它以 bb 结尾，不满足"以 ab 结尾" ✓。

问题 2（逐字符列轨迹）：

串 轨迹 结论
aab q₀ --a--> q₁ --a--> q₁ --b--> q₂ 停在终态，接受 ✓
abb q₀ --a--> q₁ --b--> q₂ --b--> q₀ 停在 q₀，拒绝 ✗
abab q₀ --a--> q₁ --b--> q₂ --a--> q₁ --b--> q₂ 停在终态，接受 ✓
baab q₀ --b--> q₀ --a--> q₁ --a--> q₁ --b--> q₂ 停在终态，接受 ✓

反向验证：aab、abab、baab 都以 ab 结尾，abb 以 bb 结尾——与"以 ab 结尾"的语言特征一致 ✓。

问题 3：变成了 NFA（不确定有限自动机）。依据：DFA 要求转移函数是单值对照——一个状态面对一个输入符号只有唯一后继；改成"q₁ 或 q₂ 均可"后，同一状态同一输入对应一个状态集合，这正是 NFA 的定义特征。（NFA 与 DFA 识别能力等价，可用子集法把这台 NFA 确定化。）

补充题答案

1. B

>= 对数据进行关系比较，属于运算成分；if 决定执行路径，属于控制成分；print 把数据送到程序外部，属于传输成分。判断时看它解决的是“怎么算、怎么走、怎么进出”哪一个问题。

2. C

列表、集合、字典可修改；元组和字符串不可按位置改写。集合不允许重复，也不能依赖位置下标取元素；字典按键取值，键不限定为整数。反例验证：s={1,1,2} 的有效元素只有 1、2，不会保留两个 1。

3. C

目标程序可以是绝对指令代码、可重定位指令代码或汇编指令代码。中间代码生成和代码优化可省略；省略优化只可能影响效率，不必然影响正确性。目标代码生成要考虑指令集、寄存器等硬件细节，与具体机器密切相关。

4. 前缀式 / - a b + c d，写紧凑形式为 /-ab+cd；后缀式 a b - c d + /，写紧凑形式为 ab-cd+/。

前序按“根—左—右”先读 /，再读左子树 -ab，再读右子树 +cd；后序按“左—右—根”得到 ab-、cd+，最后放 /。按后缀还原：ab- 是 (a-b)，cd+ 是 (c+d)，最后 / 合成 (a-b)/(c+d)，与题面一致。

5. B

aabb 可由 S 推导且已不含非终结符，因此既是句型也是句子。aaSbb、aSb 都可推导得到，所以是句型；但仍含 S，不是句子。句子的判据不是“含有终结符”，而是“只含终结符”。

6. 最左推导：

S ⇒ AB ⇒ aAB ⇒ aaB ⇒ aabB ⇒ aabb

每一步都替换当前最左边的非终结符。A 只能生成一个或多个连续的 a，B 只能生成一个或多个连续的 b，所以语言结构必为 a+b+；abab 在出现 b 后又出现 a，不符合“所有 a 在前、所有 b 在后”，无法生成。用产生式逐步尝试也会发现 B 阶段只能继续产生 b。

7. B

每个 10*1 块贡献两个 1，整块重复任意次，因此 1 的总数是 0、2、4……。外侧 0* 允许任意前后零。反例：101 长度为 3 但有两个 1，属于该语言，故“长度为偶数”的 C 错。

8. B

初态同时是终态，所以一个字符都不读的 ε 被接受；每读一个 a 又回到 q0，因此 a、aa、aaa…… 也全部接受，语言为 a*。A a+ 漏掉了 ε。

9. 可达集合状态为 {q0} 和 {q0,q1}；初态是 {q0}，终态是 {q0,q1}；语言为 a+。

从 {q0} 读 a 得 {q0,q1}；从 {q0,q1} 读 a，要把 q0 的 {q0,q1} 与 q1 的空集取并，仍为 {q0,q1}。集合含 q1 即标为终态。ε 停在非终态 {q0}，不接受；读至少一个 a 后进入终态并一直自环，所以恰为一个或多个 a。

10.（1）静态作用域输出 1，动态作用域输出 2。（2）a 最终为 6。

静态作用域看 P 的定义处：P 定义在全局层，绑定全局 x=1；动态作用域沿调用链 Q→P 查找，先遇到 Q 的局部 x=2。

f(a,a) 中 x、y 都是 a 的别名：第一句 x=x+1 使 a 从 2 变 3；第二句 y=x+y 等价于 a=a+a，左右读到的当前值均为 3，所以 a 变 6。用形参换名法得到 a=a+1; a=a+a，反向计算仍为 6。

2. A 先归纳语言：p₂（终态）只接受"刚连续读了两个 a"（p₀ --a--> p₁ --a--> p₂）；在 p₂ 再读 a 停在 p₂、读 b 回 p₀ 清零重来。所以语言 = 以 aa 结尾的 a、b 串 → (a|b)*aa。 反向验证各选项：B a(a|b)*a 只要求首尾是 a——串 aba 满足 B 但不被自动机接受（p₀a→p₁b→p₀a→p₁ 非终态），B 范围偏大；C (a|b)*a 只要结尾是 a——ba 满足 C 但自动机不接受（p₀b→p₀a→p₁）；D aa(a|b)* 只要开头 aa——aab 满足 D 但自动机不接受（p₀a→p₁a→p₂b→p₀）。只有 A 与自动机语言完全重合。 （注意本题机器与案例 2 的机器形状相同、语言不同——案例 2 的"入口"是读 b，本题"入口"是读 a，归纳时看清到达终态的最后一步用什么字符。）

4. A 引用调用（p≡x，q≡y）逐句追踪：

  • 初始 x=4, y=1
  • p = p + q → x = 4+1 = 5
  • q = p - q → y = 5−1 = 4（p 用新值 5）
  • 返回 p × q = 20。结果 x=5、y=4。 传值调用：p=4、q=1 均为副本 → p=5，q=5−1=4，返回 5×4=20；x=4、y=1 不动。 两次返回值相同（返回值只依赖形参自身的算术，与传递方式无关），实参只有引用方式被改动。反向验证：引用调用等价于"形参换名原地执行"：x=x+y; y=x−y → x=5、y=5−1=4 ✓。B"返回值不同"无根据；C 错在引用调用下 y 已改为 4 仍写 1；D 错在第一句 p=p+q 已把 x 改为 5 仍写 4。
