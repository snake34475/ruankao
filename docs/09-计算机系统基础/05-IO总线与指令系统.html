09.5 I/O、总线与指令系统 ★★★ ​

7.1 CPU 怎样与外设交换数据 ​

方式谁盯设备CPU 负担适用特点
程序查询CPU 反复查询最大，忙等简单、低速
中断设备就绪后通知 CPU不必忙等，但每次传送仍需 CPU 处理低中速、事件驱动
DMADMA 控制器在主存与外设间成批传送很小，CPU 只做初始化与结束处理高速、批量
通道/I/O 处理机专用部件执行 I/O 程序更小大型系统、多设备

DMA 的关键不是“完全不经过主存”，恰好相反，它让外设与主存直接成批交换数据，只是在传送期间暂时取得总线控制权，减少 CPU 逐字搬运。

7.2 中断过程 ​

简化顺序：

  1. 设备发出中断请求；
  2. CPU 通常在当前指令执行完后响应；
  3. 保存断点和现场；
  4. 根据中断向量找到中断服务程序入口；
  5. 执行中断服务程序；
  6. 恢复现场，返回原程序。

中断向量 = 中断服务程序的入口地址（或形成入口地址的信息）。断点是原程序被打断后应继续执行的位置，二者不是一回事。

7.3 总线分类 ​

按传送内容：

  • 数据总线：传数据，通常双向；
  • 地址总线：传地址，通常由 CPU 向外，宽度决定可寻址空间；
  • 控制总线：传读/写、中断、总线请求等控制信号。

若地址总线有 32 根，按字节编址，可寻址单元数为 2^32，空间为 2^32 B = 4 GiB。

按范围可分芯片内总线、系统总线、外部/通信总线；按传送方式可分串行和并行。并行不是永远更快：线路较长、频率较高时，多根线的时序偏差和串扰会限制速度，现代高速外设常用高速串行链路。

应试动作：题干出现“CPU 忙等”选查询，“设备通知 CPU”选中断，“主存与高速外设批量直传”选 DMA。“中断服务入口”选中断向量；地址线 n 根、按字节编址就写 2^n B。

第八节 指令、寻址方式与 RISC/CISC ★★★ ​

8.1 寻址方式：指令里的地址字段究竟装了什么 ​

设指令地址字段为 A，寄存器 R 的内容记为 (R)，主存单元 A 的内容记为 (A)，EA 为有效地址。

寻址方式操作数/有效地址一句话识别
立即寻址操作数 = A指令里就是数
直接寻址EA=A，操作数=(A)指令里是一次地址
间接寻址EA=(A)，操作数=((A))先从内存取地址，再取数
寄存器寻址操作数=(R)寄存器里就是数
寄存器间接寻址EA=(R)，操作数=((R))寄存器里是地址
相对寻址EA=(PC)+A相对当前程序位置
基址寻址EA=(基址寄存器)+A基地址加偏移
变址寻址EA=A+(变址寄存器)数组首址加下标

例：A=100，(100)=500，(500)=36：

  • 立即寻址得到 100；
  • 直接寻址得到 500；
  • 间接寻址得到 36。

反例：直接寻址不是“直接拿到操作数”，而是直接拿到操作数的地址；真正把操作数写在指令中的是立即寻址。寄存器间接寻址也不是操作数在寄存器，而是操作数的地址在寄存器。

有效地址算例：相对、基址、变址别混 ​

  • 相对寻址：若 (PC)=1000，地址字段 A=40，则 EA=1000+40=1040。程序整体搬家后 PC 随之改变，位移 40 不变，适合分支与位置无关代码。
  • 基址寻址：若基址寄存器内容为 2000，位移 A=120，则 EA=2000+120=2120。基址常由系统设置，便于程序或存储区域重定位。
  • 变址寻址：若数组首址 A=5000，变址寄存器内容为 12，则 EA=5000+12=5012。变址值常随循环变化，适合访问数组元素。

三者表面都是“加法”，区别在谁是稳定基准、谁会变化：相对看 PC，基址看程序/区域起点，变址看数组下标或偏移。

考试默认速度排序通常写：

立即寻址 ＞ 寄存器寻址 ＞ 直接寻址 ＞ 间接寻址

这里“＞”表示通常更快。立即数已随指令取入，寄存器寻址只访问寄存器；直接寻址要额外访问一次主存取操作数；间接寻址通常先去主存取有效地址，再去主存取操作数，额外访存最多。若题面明确给出某体系结构的周期数，应按题面数据计算。

8.2 RISC 与 CISC ​

对比RISC（精简指令集）CISC（复杂指令集）
指令数量与格式少、格式较规整/常定长多、常变长
寻址方式少多
单条指令功能较简单，多数可快速完成功能复杂，周期差异大
访存Load/Store：通常只有装入/存储指令访问内存多种指令可直接访问内存
寄存器通用寄存器多相对较少
控制实现常用硬布线，利于流水线常用微程序控制
编译器更依赖优化编译指令本身表达力强

反例：“RISC 指令少，所以程序一定更短”是错的。完成同一复杂任务，RISC 可能需要更多条简单指令；它追求的是规则、快速、易流水化，不是源程序或机器码条数必然更少。

流水线辨析：CISC 并非“绝对不能使用流水线”，现代 CISC 处理器同样会采用流水、译码和内部微操作等技术；只是 RISC 的定长、规整指令和较少寻址方式让分段更均匀，更容易高效流水化。因此题目问“更适合流水线”选 RISC，问“能否使用流水线”时不能断言 CISC 完全不能。

口诀：RISC：少、齐、快，多寄存器，Load/Store，硬布线，爱流水；CISC 反过来。

应试动作：题干出现“定长、少寻址、多寄存器、Load/Store、硬布线、易于流水”就锁定 RISC；“复杂指令、多寻址、可变长、微程序”锁定 CISC。注意“更适合流水线”不等于“另一类绝对不能流水”。
