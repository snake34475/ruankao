04.6 高频设计模式与易混对照 ★★★ ​

模式场景联想认题特征词
单例系统配置管理器、连接池、打印管理器"全局唯一""只能有一个"
工厂方法日志工厂按配置决定生成文件日志还是数据库日志"子类决定创建哪种对象"
观察者微信公众号更新，所有粉丝收到推送；事件监听器"一对多""通知""订阅"
策略排序算法可换（快排/归并）、支付方式可换（微信/支付宝）"算法可互换""封装算法族"
适配器国标插头转美标插座；老系统接口包装成新接口"接口不兼容""转换"
装饰器给咖啡动态加奶、加糖（不加子类爆炸）；Java IO 流包装"动态添加职责"
代理房产中介带看房（控制访问）、图片懒加载、远程调用桩"控制访问""延迟/远程/安全"
桥接形状（圆/方）× 颜色（红/蓝）两个维度独立扩展，不用 2×2 个子类"两个变化维度""抽象与实现分离"

代理的三种细分（选择题出现过）：远程代理（为不同地址空间的对象提供本地代表，负责编码请求）、虚拟代理（缓存信息，延迟创建开销大的对象，如图片懒加载）、保护代理（检查调用者权限）。看到"权限/延迟/远程"三个字眼，就归到代理的对应细分里。

4.4 模式的角色名（案例题第五题 Java/C++ 填空的命门）★★ ​

案例题第五题常给一段 Java/C++ 代码 + 一张类图让你填空，填的就是角色名（如 interface Observer、class Subject）。所以高频模式的角色名必须能中英对照写出来。下面按三分类分组列出，箭头 → 表示"抽象到具体"，斜杠 / 表示并列角色：

创建型（5）

  • 抽象工厂：AbstractFactory（抽象工厂，声明创建产品的抽象方法）→ ConcreteFactory（具体工厂，实现方法并生成具体产品）；AbstractProduct（抽象产品，为一种产品声明接口）→ Product（具体产品）；Client（客户，用抽象产品与抽象工厂生成对象）。
  • 工厂方法：Product（产品接口）→ ConcreteProduct（真实产品）；Creator（工厂角色，声明工厂方法）→ ConcreteCreator（真实工厂，返回产品实例）。
  • 原型：Prototype（抽象原型，定义克隆自己的接口）→ ConcretePrototype（实现 clone、返回自身拷贝）；Client 调 p = prototype.clone()。
  • 单例：Singleton 自己——私有的静态唯一实例变量 + 公有的静态获取方法（getInstance()），构造方法私有化。
  • 构建器：Builder（抽象建造者，为各部件指定抽象接口）→ ConcreteBuilder（具体建造者）；Director（指挥者，按步骤指挥建造）；Product（被构建的复杂对象）。

结构型（7）

  • 适配器：Target（目标抽象类，客户要用的标准接口）；Adapter（适配器，调另一个接口做转换）；Adaptee（被适配者，需要接入的实际接口）；Client。
  • 桥接：Abstraction（抽象类，维护一个 Implementor 引用）→ RefinedAbstraction（扩充的抽象类）；Implementor（实现类接口，只给基本操作）→ ConcreteImplementor（具体实现类）。
  • 组合：Component（成员父类，统一接口含 Add/Remove/GetChild）→ Leaf（叶子，无子节点）／ Composite（组合类，持子部件列表并递归调用）。
  • 装饰器：Component（部件接口）→ ConcreteComponent（被装饰者）；Decorator（装饰抽象类，持有一个 Component，接口与之一致）→ ConcreteDecorator（加具体职责，内部调 super.operation()）。
  • 外观：Facade（外形类，知道哪些子系统负责哪些请求，把客户请求转给相应子系统）；Subsystem（子系统类，实现功能，不知道也不引用 Facade）。
  • 享元：Flyweight（抽象享元，接受外部状态）→ ConcreteFlyweight（含内部状态）／ UnsharedConcreteFlyweight（不共享的具体享元）；FlyweightFactory（轻量级工厂，按 key 从池中取或新建）。
  • 代理：Subject（抽象实体接口，为 RealSubject 与 Proxy 定义相同的接口）→ RealSubject（真实对象）／ Proxy（代理，持有 RealSubject 引用，控制访问）。

行为型（11）

  • 职责链：Handler（传递者接口，持有后继者引用）→ ConcreteHandler（能处理就处理，否则转发给后继）；Client。
  • 命令：Command（抽象命令，声明执行接口）→ ConcreteCommand（把接收者与动作绑定）；Invoker（调用者，触发 execute）；Receiver（接收者，知道如何执行关联请求）；Client。
  • 解释器：AbstractExpression（抽象表达式，定义 Interpret(Context)）→ TerminalExpression（终结符表达式，每个终结符一个实例）／ NonTerminalExpression（非终结符表达式）；Context（场景，含解释器的全局信息）。
  • 迭代器：Iterator（First/Next/CurrentItem/IsDone）→ ConcreteIterator（遍历时跟踪聚合中的当前位置）；Aggregate（定义创建迭代器的接口）→ ConcreteAggregate。
  • 中介者：Mediator（抽象中介者，定义同事间通信的统一接口）→ ConcreteMediator（掌握并维护各同事对象的引用）；Colleague（同事类，与别的同事通信必经中介者）。
  • 备忘录：Memento（备忘录，保存原发器在某一时刻的状态）；Originator（原发器，创建备忘录并可用它恢复自己）；Caretaker（管理者，负责保存备忘录）。
  • 观察者：Subject（被观察对象，提供绑定/分离观察者的接口）→ ConcreteSubject（具体被观察对象，状态改变时通知）；Observer（定义更新接口）→ ConcreteObserver（持 ConcreteSubject 引用）。
  • 状态：Context（情景类，持有具体状态实例，把请求委托给状态）；State（抽象状态，封装与某状态相关的行为）→ ConcreteState（具体状态类）。
  • 策略：Strategy（抽象策略，定义所有策略的公共接口）→ ConcreteStrategy（封装具体算法）；Context（上下文，持有 Strategy 引用）；Client。
  • 模板方法：AbstractClass（抽象类，定义算法骨架并声明若干基本方法）／ ConcreteClass（子类实现某些步骤）。
  • 访问者：Visitor（为每个 ConcreteElement 声明一个 Visit 操作）→ ConcreteVisitor；Element（定义 Accept(Visitor)）→ ConcreteElement；ObjectStructure（对象结构类，遍历元素）。

背法建议：不要死背这一长串，而是抓三个"通用套路"——① 抽象 + 具体成对出现（抽象工厂/具体工厂、抽象产品/具体产品）；② 谁持有谁决定控制权（代理持 RealSubject、装饰器持 Component、状态持 State、职责链持 successor、上下文持 State、组合持子部件列表）；③ 客户只认抽象（Client 永远通过抽象接口打交道，这就是依赖倒置原则在模式里的落地）。考场上即使记不住确切名字，按"抽象 X / 具体 X / 客户"的命名规律写，往往也能得分。

4.5 易混组对照（案例题给理由时用得上） ​

  1. 装饰器 vs 代理：都包一层对象，区别在意图——装饰器给对象加功能（层层包出不同组合），代理是控制访问（功能不变，管你能不能/何时访问）。
  2. 适配器 vs 外观：适配器是"一个接口转成另一个接口"（一对一改造）；外观是"一堆子系统接口收敛成一个入口"（多合一简化）。
  3. 桥接 vs 装饰器：桥接拆的是两个独立变化的结构维度（形状×绘制方式）；装饰器是同一维度上叠加功能。
  4. 策略 vs 状态：结构几乎一样（都委托给一个接口），但客户能不能选是分水岭——策略是客户主动选算法（想换就换）；状态是对象自己随条件转换，客户通常不指定（且状态之间常互相触发迁移）。
  5. 命令 vs 备忘录（撤销题的正主）：支持"撤销"的机制是命令（把操作封装成对象，命令里存了执行所需的信息，提供 undo()）；备忘录是保存/恢复对象状态快照。若题目问"把请求封装成对象从而支持撤销/排队/日志"→ 命令；问"保存对象某一时刻的状态以便以后恢复"→ 备忘录。真题里两者常同框出现，看题干强调的是"操作"还是"状态"。
  6. 工厂方法 vs 抽象工厂：都造对象，区别在单一还是系列——工厂方法造一个产品（由子类决定），抽象工厂造一整个产品族（一族相关对象，如"Windows 风格的按钮+滚动条"）。

应试动作：① 背三分类数字"5/7/11" + 口诀；② 速查表每个模式的"速记词"必须条件反射——考试 80% 是"场景/意图 → 模式名"的配对；③ 易混对按"意图"区分；④ 高频模式的角色名要能默写英文（服务案例题填空）。
