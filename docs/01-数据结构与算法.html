01 数据结构与算法

分值地位：选择题 8–10 题（第一大块）+ 案例题「算法设计」一道大题（约 15 分）。这是全卷最重要的一课。

学习目标：读完讲义后，你能——① 前中后序遍历互推；② 手算哈夫曼树、散列表、关键路径；③ 背下八大排序的复杂度与稳定性表；④ 会做案例题算法填空。

第一节 线性表、栈与队列

1.1 线性表：顺序存储 vs 链式存储

线性表就是"一排元素"。两种存法：

对比项 顺序存储（数组） 链式存储（链表）
内存 连续一片 每个节点散落 + 指针连接
按位置访问第 i 个 O(1) 直接算地址 O(n) 要从头数过去
插入/删除一个元素 O(n)（后面全要挪） O(1)（改指针即可，找到位置不算）
空间 需预估容量，可能浪费 按需分配，但每个节点多一个指针开销

★ 记忆口诀：数组「查得快、插删慢」，链表「插删快、查得慢」。选择题几乎每年考这组对比。

链表变种（知道结构即可）：

  • 单链表：只有 next 指针，只能从头往后找。
  • 循环链表：尾节点 next 指回头节点，可"绕圈"遍历。
  • 双向链表：每个节点有 prior 和 next，可前后两个方向找。

1.2 栈：后进先出（LIFO）★

栈像一个只有一口的羽毛球筒：后放进去的先拿出来。

必考应用（三个都要会，表达式求值是重中之重）：

① 表达式求值——中缀转后缀（逆波兰式）

先弄清三个名词：

  • 中缀：我们平时写的式子，运算符夹在两个操作数中间，如 a+b*c。
  • 后缀（逆波兰式）：运算符写在两个操作数后面，如 abc*+。计算机按从左到右顺序扫一遍就能算，不需要括号。
  • 前缀（波兰式）：运算符写在前面，如 +a*bc，考试较少考。

手算中缀→后缀的傻瓜法（不看代码版）：按运算优先级给式子加满括号，再把每个运算符搬到自己那对括号的右边，最后去掉所有括号。

例 1：a+b*c → 加括号得 a+(b*c) → 运算符 * 搬到 (bc)*，+ 搬到整对括号右 → a(bc)*+ → 去括号得 abc*+。

为什么要转后缀？运算符会"失去意义"吗？

不会。你看到 a+b*c 觉得意义清楚，是因为脑中默认了两条约定：① 优先级（* 高于 +）② 运算符写在两个操作数中间。也就是说，中缀式的意义不在式子本身，而在读者脑子里的约定里。后缀式只是换了一套规则——每个运算符"吃掉"它前面紧挨着的两个东西——意义一点没少，只是把约定搬进了位置。

按这条规则读 abc*+：遇到 * 拿前面最近的 b、c 相乘，遇到 + 拿 a 和刚才的乘积相加——算出来恰好就是 a+(b*c)，一个字都没丢。对比着看：

中缀 后缀 运算符的作用对象
a+b ab+ 一样，都是 a 和 b
a+(b*c) abc*+ + 作用于 a 和 b*c
(a+b)*c ab+c* * 作用于 a+b 和 c

注意后两行：中缀里必须靠括号才能区分的两个式子，后缀 abc*+ 和 ab+c* 天然不同——运算顺序被运算符的位置唯一确定，连括号都省了。

计算机为什么偏爱后缀：扫中缀式时遇到 + 不能马上算（右边可能藏着优先级更高的 *），得回头预判；而扫后缀式时，每个运算符出现时它的两个操作数一定已经在栈里，从左到右一遍扫完，不需要优先级表、不需要括号、不需要回溯。这就是编译器用逆波兰式做中间代码的原因，也是软考爱考它的原因。

例 2（带括号，考试更爱出）：a*(b+c)-d → 加括号 ((a*(b+c))-d) → b+c 变 bc+；a*(bc+) 变 abc+*；整体减 d 变 abc+*d-。所以后缀是 abc+*d-。

易错提醒：搬运算符时，"前面紧挨着的两个东西"不是两个单字母，而是已经成型的一整块，且左块在前、右块在后，内部顺序不动。例 2 中 a*(bc+) 的 * 作用于左块 a 和右块 bc+，所以写成 a(bc+)* → abc+*（写成 bc+a* 就成了 (b+c)a，操作数顺序反了，遇到减法除法必错）；减号的左操作数是整块 abc+*、右操作数是 d，所以 - 放在整个式子最末尾（写成 abcd+*- 读出来是 a-(b(c+d))，错的）。

后缀式怎么求值：从左到右扫，遇到操作数进栈，遇到运算符就弹出栈顶两个数计算（先弹出的是右操作数！），结果再进栈。例：后缀 ab+c*，先 a、b 进栈，遇到 + 弹 b、a 得 a+b 进栈，遇到 * 与后面的 c 相乘。

② 函数递归调用：系统用栈保存每层调用的参数、局部变量和返回地址，函数返回时弹栈。所以「递归太深会栈溢出」；考题问"递归调用是利用什么实现的"→ 答栈。

③ 括号匹配：从左到右扫字符串，左括号进栈；遇到右括号就弹栈顶看是否配对（{ 对 }），栈空或配不上就是错；扫完栈必须为空才合法。例：{[()]} 合法；{[}]——遇到 } 时栈顶是 [，配对失败。

★ 卡特兰数：出栈序列有多少种

问题：n 个元素按 1,2,…,n 顺序进栈（进栈和出栈可交替进行），最终出栈序列共有多少种？

答案 = 卡特兰数 Cₙ = C(2n, n)/(n+1) = (2n)! / ((n+1)!·n!)。

  • 会不会直接考公式计算？会。选择题常见考法两种：① 直接问"4 个元素依次进栈，出栈序列有几种"→ 套公式算 14；② 给一组序列问"哪个是不可能出现的出栈序列"（这种不套公式，靠模拟）。考场只需背三样，30 秒内出答案：① 数列前几项（n=0～5：1, 2, 5, 14, 42, 132），最常考的 n=3/4/5 直接对答案；② 通项公式 C(2n,n)/(n+1)，防它出稍大的 n 现算（如 n=6：C(12,6)/7 = 924/7 = 132）；③ 组合数手算口诀（见下方"公式怎么算"）。另外：同源问题（n 对括号合法匹配数、n 个节点能构成的二叉树棵数）用同一个公式，题干不会出现"卡特兰"三个字，看到这几类问法要能认出来；而"给具体序列问可不可能"的题不套公式，用栈模拟即可。

扩展（冷知识，了解即可）：卡特兰数以比利时数学家卡特兰（Catalan，1838 年研究括号匹配）得名，但最早见于清代蒙古族数学家明安图1730 年代《割圜密率捷法》中的推导（比欧洲早约 20 年），欧拉 1751 年也独立发现过——属于"以研究者命名、但非最早发现者"的典型例子。

公式怎么算（以 n=3 为例）：C(6,3)/(3+1) = 20/4 = 5 种。（这和通项式 (2n)!/((n+1)!·n!) 是一回事：C(6,3)/4 = 6!/(3!·3!)÷4 = 6!/(4!·3!)，因为 4! = 4×3!，只是 4 并进阶乘的写法不同。）其中 C(6,3) 是"从 6 个里选 3 个"的组合数，通用公式 C(m,n) = m! / (n!·(m−n)!)，手算口诀：分子从 m 往下连乘 n 个数，分母从 n 往下连乘 n 个数——因为分母里的 (m−n)! 恰好把分子 m! 末尾多余的因子约掉了。例：C(6,3) = (6×5×4)/(3×2×1) = 120/6 = 20。这 5 种用 A、B、C 演示如下（每一步要么"进栈"要么"出栈"）：

出栈序列 过程
ABC A进A出，B进B出，C进C出（进一个出一个）
ACB A进A出，B进C进，C出B出
BAC A进B进，B出A出，C进C出
BCA A进B进，B出，C进，C出A出
CBA 三个全进栈，再依次弹出

注意 CAB 不可能：C 第一个出，说明 A、B 都还在栈里，且 B 压在 A 上面，只能先 B 后 A，不可能先 A。

判断"某个出栈序列是否可能"的通用方法（必须练熟）：按顺序模拟——元素 1,2,3,… 依次进栈，每进一个就检查：栈顶是不是目标序列当前要出的元素？是就弹出，重复检查；不是就继续进栈。若最后发现"要出的元素被压在栈底够不着"，该序列不可能。 例：判断 312（元素 1,2,3，出栈序 3,1,2）：要出 3 → 把 1、2、3 全进栈 → 弹 3 ✓；下一个要出 1，但栈顶是 2 → 不可能。

卡特兰数还有一堆"同源问题"（答案同为卡特兰数，选择课示偶尔出现）：n 对括号的合法匹配数、n 个节点能构成的不同二叉树棵数、n+1 个数相乘的不同加括号方式。

1.3 队列：先进先出（FIFO）

队列像排队买票：先来的先走。应用：操作系统任务调度、打印队列、BFS（图的广度优先遍历）。

★ 循环队列判满判空（每年可能考一题）

题干会直接出现 front、rear、循环、取模、牺牲一个单元这些词。下面用容量 m=5 的队列把它们逐个画出来看懂。

第 1 步：front 和 rear 各指哪一格？

  • front（队头指针）：指着当前第一个元素，出队时它往前走。
  • rear（队尾指针）：指着下一个能放新元素的空位——它不指任何元素！这是最容易看错的地方。

空队列，两针重叠在下标 0；入队 a（a 放进 rear 指的 0 号格，rear 前移）；再入 b、c：

      0     1     2     3     4
   ┌─────┬─────┬─────┬─────┬─────┐
   │     │     │     │     │     │
   └─────┴─────┴─────┴─────┴─────┘
      ↑
  front=rear   ← 两针重叠 = 空

      0     1     2     3     4
   ┌─────┬─────┬─────┬─────┬─────┐
   │  a  │     │     │     │     │
   └─────┴─────┴─────┴─────┴─────┘
      ↑     ↑
    front  rear

      0     1     2     3     4
   ┌─────┬─────┬─────┬─────┬─────┐
   │  a  │  b  │  c  │     │     │
   └─────┴─────┴─────┴─────┴─────┘
      ↑                   ↑
    front               rear

口诀：入队 = 先把元素放进 rear 指的格子，rear 再前移；出队 = 先取走 front 指的元素，front 再前移。

第 2 步：为什么需要"循环"？——因为"假溢出"

接着出队 a、b（front 走到 2），再入队 d、e，rear 走到 4：

      0     1     2     3     4
   ┌─────┬─────┬─────┬─────┬─────┐
   │     │     │  c  │  d  │  e  │
   └─────┴─────┴─────┴─────┴─────┘
                  ↑           ↑
                front        rear

再想入队，rear 就要走到 5 号格——可 5 号格不存在！而 0、1 号格明明空着。这种"队头前面空着却报满"叫假溢出。

解决办法：把数组首尾粘起来变成一个环。rear 走过 4 号格，沿"回头路"绕回 0 号格继续放：

   0 ──► 1 ──► 2 ──► 3 ──► 4
   ▲                       │
   └───────────────────────┘

第 3 步：取模 %m 就是"钟表绕圈"

钟表 11 点再过 2 小时是 1 点——没有 13 点，因为 13−12=1。取模 = 除以 m 取余数 = 超过 m−1 就绕回去。m=5 时，0,1,2,3,4 就是一个只有 5 个刻度的钟面：

  • rear=4 时再入队：(4+1)%5 = 5%5 = 0（5 除以 5 商 1 余 0），绕回 0 号格；
  • 公式里 % m 的唯一作用就是把绕过头的下标折回来，没有其他含义。

第 4 步：牺牲一个格子——为了分清"空"和"满"

假如不牺牲：放满 m 个元素时，rear 绕一整圈又撞回 front，出现 front == rear；可空队列也是 front == rear。空和满两个状态长得一模一样，程序无法区分。

于是约定：rear 最多走到 front 的下一格就停，中间永远留一个空格当"隔离带"。接着上面继续入队 f（f 绕圈放进 0 号格，rear=1），再想入 g 时：

      0     1     2     3     4
   ┌─────┬─────┬─────┬─────┬─────┐
   │  f  │     │  c  │  d  │  e  │
   └─────┴─────┴─────┴─────┴─────┘
            ↑     ↑
          rear  front

判满：(rear+1)%5 = (1+1)%5 = 2 == front → 满！格 1 明明空着也不能放——它就是牺牲的隔离带。此后：

  • 空 = 两针重叠 front == rear；
  • 满 = rear 停在 front 的下一格 (rear+1)%m == front。

两个条件永远不撞脸。代价：容量 m 的循环队列最多只能存 m−1 个元素（选择题考过这个坑！）。

操作 公式 记忆
入队（rear 前进） rear = (rear+1) % m 先把新元素放进 rear，再后移
出队（front 前进） front = (front+1) % m 先取走 front 的元素，再后移
判空 front == rear 两个指针重叠 = 空
判满 (rear+1) % m == front rear 追到 front 的下一格 = 满
元素个数 (rear − front + m) % m 加 m 是防负数，再取模防越界

元素个数公式的推导：正常情况 rear 在 front 前面，个数 = rear − front；但绕圈后 rear 可能"反超"到 front 后面（下标反而小了），出现负数。+m 先把负数拉成正，%m 把绕圈的情况折算回来。用上面的满状态验算：(1−2+5)%5 = 4 ✓（正好 4 = m−1 个）。

例题完整走一遍（m=5，牺牲一格法）：初始 front=rear=0（空）。

  1. 入队 a、b、c：a→格 0、b→格 1、c→格 2，rear=3（见第 1 步第三张图）。个数 (3−0+5)%5=3 ✓。
  2. 出队 2 次：取走 a（front→1）、取走 b（front→2）。front=2 指 c，格 0、1 空出。
  3. 入队 d：d→格 3，rear=4。入队 e：e→格 4，rear=(4+1)%5=0，绕圈！个数 (0−2+5)%5=3 ✓：
      0     1     2     3     4
   ┌─────┬─────┬─────┬─────┬─────┐
   │     │     │  c  │  d  │  e  │
   └─────┴─────┴─────┴─────┴─────┘
      ↑               ↑
    rear            front
  1. 入队 f：先判满 (0+1)%5=1 ≠ 2，不满 → f 绕圈放进 0 号格，rear=1。个数 (1−2+5)%5=4 ✓。
  2. 再想入队 g：判满 (1+1)%5=2 == front(2) → 满！格 1 空着也不能放——牺牲的隔离带（见第 4 步的图）。此时 c,d,e,f 共 4 = m−1 个，已是上限。

补充：区分空满还有另外两种办法（选择题考过"哪种方法可以/不需要牺牲空间"）：

补充 1：设标志位法（不牺牲空间）

先想清楚 front == rear 为什么分不清空满：中间状态（有 1～m 个元素）两针必然错开，只有两个瞬间会追平——

  • rear 绕一整圈追上 front → 刚好塞满（最后一步是入队）；
  • front 绕一整圈追上 rear → 刚好取空（最后一步是出队）。

位置上完全一样，唯一的区别是"刚才干的事"。所以加一个标志位 lastOp 记录最后一次操作，追平时看它即可。

举例（容量 4，从空队开始连续入队 A～D，再连续出队 4 次）：

初始：空
   0   1   2   3
 ┌───┬───┬───┬───┐
 │ · │ · │ · │ · │   lastOp = 出队(初始)
 └───┴───┴───┴───┘
   ↑  front=rear=0 → 相等+出队 ⇒ 判「空」

入队 A、B、C、D 后（rear 绕回 0）：
 ┌───┬───┬───┬───┐
 │ D │ A │ B │ C │   lastOp = 入队
 └───┴───┴───┴───┘
   ↑  front=rear=0 → 相等+入队 ⇒ 判「满」

再出队 4 次（front 绕回 0）：
 ┌───┬───┬───┬───┐
 │ D │ A │ B │ C │   lastOp = 出队（逻辑上已取空）
 └───┴───┴───┴───┘
   ↑  front=rear=0 → 相等+出队 ⇒ 判「空」

一模一样的 front=rear=0 出现两次，一次判满、一次判空——全靠标志位。

int queue[4], front = 0, rear = 0;
int lastOp = DEQUEUE;          // 初始当作出队 → 空队

void enqueue(int x) {
    queue[rear] = x;
    rear = (rear + 1) % 4;
    lastOp = ENQUEUE;          // 每次入队后打标记
}
int dequeue(void) {
    int x = queue[front];
    front = (front + 1) % 4;
    lastOp = DEQUEUE;          // 每次出队后打标记
    return x;
}
// 队空：front == rear && lastOp == DEQUEUE
// 队满：front == rear && lastOp == ENQUEUE

口诀：逢满必入，逢空必出——追平那一刻，最后一步是入队就是满，是出队就是空。

补充 2：记元素个数法（最直观）

另设计数器 count：入队 +1、出队 −1，count==0 为空、count==m 为满。同样不牺牲空间，代价也是多一个变量，且比标志位好懂——判断时根本不用看 front/rear 是否重叠。

方法 判空 / 判满 队列可用空间 代价
牺牲一格 front==rear 空；(rear+1)%m==front 满 m−1 格（浪费 1 格） 无
标志位 重叠 + 标志 = 入队则满 / 出队则空 m 格全用 多 1 个变量

第二节 树与二叉树 ★★★

2.1 基本性质（选择题最爱直接考结论）

二叉树：每个节点最多两个孩子，且分左右。先在一棵具体的树上把术语认全（这棵树后面反复用）：

            A          ← 根节点（没有父节点）
           / \
          B   C       ← A 的左孩子、右孩子
         / \  \
        D   E  F      ← D、E、F 都没有孩子，是叶子
  • 根：最顶上的 A；叶（叶子节点）：没有孩子的 D、E、F。
  • 度：一个节点的孩子个数。A、B 的度为 2，C 的度为 1，叶子度为 0。
  • 层：根是第 1 层，往下逐层 +1（A 第 1 层，B/C 第 2 层，D/E/F 第 3 层）。
  • 深度 / 高度：默认按"经过的边数"算——D 的深度 = A 走到 D 经 2 条边；树的高度 = 根到最深叶子的边数（上图 = 2）。个别教材按"节点数"算（结果差 1），题干会说明，看清即可。

性质的"为什么"（理解了才不用死背）：

  1. 第 i 层最多 2^(i-1) 个节点：每往下走一层，每个节点最多分裂成 2 个，所以每层最多是上一层的 2 倍——1、2、4、8……第 i 层即 2^(i-1)。

  2. 深度 k 最多 2^k − 1 个节点：把每层拉满求和 1+2+4+…+2^(k−1)。这个和有个特点：再加一项 2^k 就整体翻倍，所以和 = 2^k − 1（如 1+2+4=7=8−1）。

  3. 叶子数 n0 = 度为 2 的节点数 n2 + 1（考过无数次，完整推导一遍）：

    先认识符号：n0、n1、n2 是把树上所有节点按"孩子个数"分类后，每一类的实际个数（不是最大值）——

    • n0 = 度为 0 的节点个数 = 叶子数（没有孩子）；
    • n1 = 度为 1 的节点个数（只有一个孩子）；
    • n2 = 度为 2 的节点个数（两个孩子都齐）。

    例如 7 个节点的满二叉树：n0=4、n1=0、n2=3。

    先破一个典型误解："n2 个节点每人生 2 个孩子，叶子不该是 n2×2 吗？"——不对，孩子 ≠ 叶子。 n2×2 算出的是"孩子总数"，但孩子自己一旦又生了孩子，就从叶子变成了内部节点。看反例：

              A            ← 度 2（分叉①）
         / \
        B   C          ← B 度 2（分叉②）；C 没孩子 → 叶子
       / \
      D   E            ← D、E 没孩子 → 叶子
    • A、B 度为 2 → n2=2；C、D、E 是叶子 → n0=3。检验：3 = 2+1 ✓，而 n2×2=4 ✗。
    • n2×2=4 数的是孩子总数（B、C、D、E 共 4 个），其中 B 自己当了爸爸、不是叶子——"出生人数" ≠ "绝后人数"。

    直觉推导（记住这个就不用背）：从根出发若人人只生一个孩子（整条 n1 链），走到底只有 1 个叶子（此时 n2=0，n0=1，公式成立）。每出现一个度为 2 的节点，就是把链上某个节点分岔成两支：一个潜在叶子变成两个，叶子净多 1 个。分叉 n2 次 → 叶子 = 1 + n2。口诀：分叉一次，叶子多一。n1 完全不参与——度为 1 的节点只把链拉长，叶子不多不少。

    代数推导（掰"边"）：

    • 从"人数"数：n = n0 + n1 + n2（三类节点各数一遍）；
    • 从"边"数：每个节点头顶恰好一条边（根除外），所以边数 = n − 1；每条边都从父亲长出来，度为 1 的节点长 1 条、度为 2 的长 2 条，所以边数 = n1 + 2·n2；
    • 两式相等：n0 + n1 + n2 − 1 = n1 + 2·n2，两边消掉 n1 → n0 = n2 + 1（和 n1 无关）。
    • 用上面反例树验证：n=5，人数式 5 = 3+0+2 ✓；边数式 5−1 = 0+2×2 = 4 ✓。

    应试动作：背结论 n0 = n2 + 1；题干给"5 个度为 2 的节点"问叶子数，直接 5+1=6——不需要知道 n1 和总节点数。

  4. n 个节点的完全二叉树深度 = ⌈log₂(n+1)⌉。

满二叉树 vs 完全二叉树（选择题爱考"给一棵树判断是不是完全二叉树"）：

满二叉树 = 每一层都塞满。每层节点数 1、2、4、8……，深度 k 的满二叉树恰好 2^k − 1 个节点，一层不多不少：

深度 3 的满二叉树（7 个节点）
            A
          /   \
         B     C        ← 第 2 层：2 个，满
        / \   / \
       D   E F   G      ← 第 3 层：4 个，满

完全二叉树 = 只有最后一层可以缺，且只能缺最右边。从上到下、从左到右数，节点必须连续不跳号；缺可以，但缺的只能是"最右边几个"，左边不能空：

完全二叉树 ✓                      不是完全二叉树 ✗
        A（满）                        A（满）
      /   \                          /   \
     B     C（满）                  B     C（满）
    / \   /                        / \     \
   D   E F     ← 只缺右边 G、H    E   F     G   ← B 的左孩子 D 缺了，
                                                  左边空、右边在 → 断档

判断口诀：从左往右数，只能右边缺席，左边不许空。

为什么要有"完全二叉树"这个概念：它是长得最"紧凑"的形状——按层序编号塞进数组不留空洞，这正是堆能用数组存的原因：

完全二叉树：  数组 [A][B][C][D][E][F]   ← 编号 1~6 连续，无浪费
非完全二叉树：数组 [A][B][C][?][F][G]   ← 位置 4（D）空洞，浪费
满二叉树 完全二叉树
定义 每层都满 仅最后一层可缺最右边若干
节点数 恰好 2^k − 1 1 ～ 2^k − 1 之间任意值
关系 满是完全的特例（取到最大值） 完全不一定满

易错点：中文教材的"满二叉树"（每层全满）对应英文 Perfect Binary Tree；英文 Full Binary Tree 指"每个节点有 0 或 2 个孩子"，和中文"满"不是一回事——软考按中文教材口径考。另注意题干描述"叶子只出现在最下两层""最后一层从左到右连续"都是在暗示完全二叉树。

★ 完全二叉树的顺序存储下标关系（选择题直接考）：把完全二叉树按层序（从上到下、从左到右）编号存进数组，下标从 1 开始：

树：        A(1)
           /   \
          B(2)  C(3)
         /  \  /
        D(4) E(5)F(6)
  • 公式里的 i 是什么：i 指「当前节点在数组里的编号」，也就是它按层序排到了第几号（编号从 1 开始，根 A = 1）。算谁的孩子，就把谁的编号代入 i。比如算 B 的孩子们时，令 i = 2（B 是 2 号），于是左孩子 = 2×2 = 4（D）、右孩子 = 2×2+1 = 5（E）；算 C 时令 i = 3，左孩子 F = 2×3 = 6。
  • 通用公式：左孩子 = 2i，右孩子 = 2i+1，父节点 = ⌊i/2⌋。用上面的例子验证：B 是 2 号，左孩子 D 恰是 2×2=4 号、右孩子 E 是 5 号；C 是 3 号，左孩子 F 是 6 号。
  • 为什么恰好是倍数：按层序编号，每层排满时总数是 2^层 − 1，下一层从头接着编——父与长子之间正好隔开"一整层的名额"，编号差了一倍，所以左孩子 = 2i。
  • i > ⌊n/2⌋ 的节点全是叶子。例：n=10 个节点，最后一个非叶节点是 5，建堆从它开始。
  • 这也是堆排序"用数组存树"的原理（第五节建堆公式 ⌊n/2⌋ 就是从这来的）。

2.2 遍历 ★★★（必考，选择题 + 案例题都会出）

三种遍历的"序"说的是根被访问的时机：

遍历 顺序 记法
前序 根 → 左 → 右 根在前
中序 左 → 根 → 右 根在中
后序 左 → 右 → 根 根在后

别死背三种"序"，想象"绕树走一圈"就全通了。

从根出发，贴着树的左侧走，把整棵树的外围绕一圈回到根。你会发现每个节点都被路过三次：第一次是从上面来（经过它的上方）、第二次是走完它左边绕回来（经过它的下方）、第三次是走完它右边绕回来（经过它的上方）。约定在不同次路过时记下节点，就得到三种遍历：

  • 第 1 次路过时记 → 前序
  • 第 2 次（下方）路过时记 → 中序
  • 第 3 次（离开）路过时记 → 后序

用 2.1 的那棵树实际走一圈（每步都记录，三个"记录本"分别得到三种序）：

三本记录：前序 ABDEC、中序 DBEAC、后序 DEBFCA。同一个"绕圈"动作，只因记录时机不同，就得到三种序——这就是三个定义的全部秘密。

为什么"下方"那一次恰好是中序：中序 = 左 → 根 → 右。走完左子树绕回节点，正是"左"结束的时刻，此刻记它，结果自然是"左在前、根居中"。前序（一到达就记，根跑在左右前面）、后序（离开才记，根落在最后）同理。

用递归的话说也相通：第 1 次到达 = 递进去，第 3 次离开 = 归出来；"递"时记是前序、"归"时记是后序、递归完左边回头时记是中序。

核心解题法（必须练熟）：

  • 前序第一个是根，后序最后一个是根，中序里根把树切成左右两半。
  • 已知「前序 + 中序」或「后序 + 中序」可唯一还原二叉树；「前序 + 后序」不能唯一确定（无法分左右），这是经典陷阱题。
  • 还原步骤：从遍历序列中找根 → 中序里分左右子树 → 对左右子树递归重复。

还原例题一步步看：前序 ABDEC，中序 DBEAC。

第 1 步：前序第一个 A 是根；中序里 A 把序列切成 DBE | A | C
        A
       / \
      ？   ？      ← 左子树 {D,B,E}，右子树 {C}

第 2 步：左子树 3 个节点，它的前序是 BDE → 第一个 B 是它的根；
        中序 DBE 里 B 的左边 D、右边 E，即 D、E 是 B 的孩子

第 3 步：右子树只剩 C，直接挂上。还原完成：
        A
       / \
      B   C
     / \
    D   E

检验：对还原出的树走一圈——前序 A B D E C ✓，中序 D B E A C ✓，与题目一致。

层序遍历：从上到下从左到右逐层访问，用队列实现（注意：前中后序递归用栈）。可以想成"水波扩散"：根先入队，处理 A 时把 B、C 排进队，处理 B 时把 D、E 排进队……队列的"先进先出"恰好保证了同一层先访问完才轮到下一层。

2.3 线索二叉树

利用二叉链表中的空指针（n 个节点有 n+1 个空指针，想想为什么：2n 个指针域、用了 n−1 条边）：

  • 左孩子为空 → 左指针改为指向该节点在遍历序中的前驱；
  • 右孩子为空 → 右指针改为指向该节点在遍历序中的后继；
  • （按哪种遍历建立线索就叫"X 序线索树"，考试默认说清是哪种。）

例子（中序线索树）：

          A
         / \
        B   C
       / \
      D   E
中序序位：D(1) → B(2) → E(3) → A(4) → C(5)

  • E（叶子，两个指针原本都空着）：左指针改为指向前驱 B，右指针改为指向后继 A。

  • D（叶子，且是中序第 1 个）：没有前驱可指，左指针保持空；右指针指向后继 B。

  • C（叶子，且是中序最后一个）：没有后继可指，右指针保持空；左指针指向前驱 A。

  • B 的两个孩子都在（左 D 右 E）：不加线索。

  • （按哪种遍历建立线索就叫"X 序线索树"，考试默认说清是哪种。）

  • 目的：不借助栈/递归也能按遍历序找前驱后继。

  • 考法：判断"某节点在 X 序线索树中的前驱/后继指向谁"——先写出该遍历序，再按定义套即可。

  • 加线索后为区分"指针指向孩子还是线索"，节点需多存两个标志位 ltag/rtag。

2.4 哈夫曼树与哈夫曼编码 ★★★（几乎年年考）

它解决什么问题：压缩。给文件里的字符分配二进制编码时，字符出现频率天差地别——a 可能出现 5000 次，z 只出现 3 次。如果每个字符都固定占 8 位，等于让"天天用的 a"和"几乎不用的 z"付一样的房租。朴素想法很自然：常用的给短码、少用的给长码，总位数就降下来了。但马上冒出新麻烦：码长不一，读的时候会切错位置。哈夫曼树就是那个"既让常用字拿到短码、又保证读起来不歧义"的标准答案。

先认五个关键词（丢分多半丢在这几个名词上）

① 路径长度：从一个节点往下走到另一个节点，经过的边数（走一条边算 1）。根走到根，路径长度是 0。

② 权（weight）：贴在节点上的一个数字，表示它的"分量"。在哈夫曼编码里，权就是该字符出现的次数（频率）。

③ 带权路径长度 WPL：Σ（每个叶子的权 × 该叶子到根的路径长度）。两个限定必须记牢：只算叶子，乘的是边数不是层次号。

                        *            ← 根（内部节点，权 = 8 + 7 = 15）
                      /   \
                     (8)  *      ← 内部节点，权 = 5 + 2 = 7
                        /   \
                       (5) (2)

  三个叶子：(8) 路径长 1    (5) 路径长 2    (2) 路径长 2
  WPL = 8×1 + 5×2 + 2×2 = 8 + 10 + 4 = 22

图中带括号的 (8)、(5)、(2) 是带权的叶子，星号节点是合并出来的内部节点（它的权值等于两个孩子之和，只是算 WPL 时用不上）。最高频的失分点就在这儿：WPL 求和时只挑叶子，那些 7、15 写在那儿也不许乘路径长——用非叶节点求和是另一套算法（见后面结论 4），两套不能混着用。

④ 哈夫曼树：在所有"叶子权值恰好是给定这组数"的二叉树里，WPL 最小的那一棵（因此也叫最优二叉树）。

⑤ 前缀码：任何一个字符的编码，都不是另一个字符编码的开头。所有的二进制编码只要满足这条，就能从左往右一路读下去、不会切错。（为什么必须满足，后面有反例。）

构造过程：拿权 {1, 2, 3, 4} 走一遍

规则一句话：每轮从森林里挑权值最小的两棵树，合并成一棵新树（新根权值 = 两者之和），再放回森林。重复到只剩一棵。

时刻 0   森林 = { (1)  (2)  (3)  (4) }       ← 四棵单节点树，全是叶子

时刻 1   挑最小的两个（1 和 2）→ 合并，新根权 = 1 + 2 = 3

              3
             / \
           (1) (2)                          森林 = { 3, (3), (4) }

时刻 2   现在的数是 3、3、4 —— 最小的两个是"两个 3"（新 3 与原 3）

                6
              /   \
             3    (3)
            / \
          (1) (2)                           森林 = { 6, (4) }

                /    \
               6     (4)
              / \
             3  (3)
            / \
          (1) (2)

                 /      \
               (3)       7          ← 权 4 到了第 2 层，权 3 却还在第 1 层

4 右 1 1 4×1 = 4
3 左 → 右 01 2 3×2 = 6
1 左 → 左 → 左 000 3 1×3 = 3
2 左 → 左 → 右 001 3 2×3 = 6

WPL = 4×1 + 3×2 + 1×3 + 2×3 = 19。 第二种方法验算：WPL = 所有非叶节点权值之和 = 3 + 6 + 10 = 19 ✓ 它的含义：这 4 个字符一共出现 10 次（1+2+3+4），用这套编码只需要 19 位；定长编码 4 个字符要 2 位，同样 10 次要 20 位。只省 1 位——因为 {1,2,3,4} 这组权太均匀了，权值越悬殊，哈夫曼的收益越大。下一个例子正好演示这一点。

再看一个"像真题"的例子：权 {5, 9, 12, 13, 16, 45}

6 个字符、频率悬殊，这是考题的典型长相。照规则走：

  5 + 9   = 14   →  森林 {12, 13, 14, 16, 45}

WPL = 45×1 + 12×3 + 13×3 + 16×3 + 5×4 + 9×4 = 45 + 36 + 39 + 48 + 20 + 36 = 224 验算：非叶节点权值之和 = 14 + 25 + 30 + 55 + 100 = 224 ✓

两个值得记住的观察：

  • 频率越大码越短：45 只占 1 位，5 和 9 要 4 位。这就是"常用字付低房租"。
  • 收益来自不均衡：6 个字符定长要 3 位，100 次共 300 位；哈夫曼只用 224 位，省掉 25%。

前缀码为什么必须满足，哈夫曼为什么天然满足

译码的方式是从左往右一位一位读，读到凑够某个字符的完整编码，就切一刀、认一个字。

反例：假设编码表是 e=0、a=1、b=01、d=00（随手定的、没有树在背后撑腰），收到一串 0100：

  • 按 e(0) 切：剩下 100 → 没有任何字符的编码是 100，卡住译不下去；
  • 换个切法：01(b) + 00(d) → 读出 bd。

同一串二进制读出两种结果，这就是非前缀码的歧义（b=01 以 e=0 开头，读的时候分不清 0 后面还有没有内容）。

哈夫曼树不会出这种事，因为所有字符都挂在叶子上，而"叶子"的定义就是没有孩子、路到此为止：

叶子 = 编码终点；中间节点不是字符，只是岔路口。

从根走到一个叶子的路径，绝不可能恰好是通往另一个叶子的路径的开头——只要在中间某点就"认出字"了，那个点下面就不会再有路，它也就不是中间节点了。所以这一条反过来说明：字符必须放在叶子上，不能放在中间节点。

四条必背结论（选择题原话考）

  1. n 个叶子的哈夫曼树，节点总数 = 2n − 1，且没有度为 1 的节点。 为什么：每轮合并都是"两棵并成一棵"，新造出来的节点必然有两个孩子 → 所有非叶节点的度都是 2，不存在度为 1 的节点。n 棵单节点树要合并 n−1 次，所以非叶节点共 n−1 个，总数 n + (n−1) = 2n−1。
  2. 权越大的叶子离根越近（路径长度越小）——这是每轮挑最小合并的顺序决定的。
  3. 哈夫曼树不唯一，但 WPL 唯一。 权值相同的叶子可以左右互换、并列最小的几组可以调换合并次序，长出来的形状可能不同，但最小总长是定死的。同理：编码不唯一，但码长分布唯一。考题问"编码是否唯一"答不唯一，问"WPL / 最短码长"答唯一，两者别混。
  4. WPL = 所有非叶节点权值之和（自检神器：用叶子算一遍，再用非叶节点算一遍，两个数必须相等；不等就是合并过程挑错了数）。

应试动作（手算四步，30 秒内）

  1. 把权值抄成升序列表——避免"最小两个"漏挑。
  2. 合并 → 划掉两个 → 写下和 → 把和插回有序列表，逐轮写清楚（草稿纸上一行一轮，别跳步）。
  3. 树从最后一次合并往回拆着画，不要一开始就凭空画树。
  4. 求 WPL 用两种方法互验：叶子求和法 ↔ 非叶节点求和法；两者不等就回第 2 步重查。

补充一句读法：有些教材把"第几层"和"路径长度"混着说——层次从 1 起算时，路径长度 = 层次 − 1。本讲义一律用"路径长度 = 边数"，根为 0。

2.5 平衡二叉树（AVL 树）★（低频，选择题偶尔 1 题）

先把考频说清：这一节不是重点。按考频编排的考前资料里，AVL 只剩一句话定义（"任一结点的左右子树高度之差不超过 1"），真题精选题库里也几乎不单独出它的题。所以别背过程，做到三件事就够：认得出一棵树是不是 AVL、判得出插入点该用哪种旋转、记得住最少节点数公式。真正要花时间的是 2.2 遍历和 2.4 哈夫曼。

它解决什么问题：二叉排序树的效率完全取决于树的形状——按 1、2、3、4、5 的顺序插入，树会退化成一条斜链，查找从 O(log₂n) 掉回 O(n)。AVL 的解法是给树加一条硬规矩：任何节点左右子树的高度差不许超过 1，插完发现违规就旋转修正，把最坏情况重新压回 O(log₂n)。（BST 本身的定义、插入删除、退化过程在第四节 4.4，那里讲得更细。）

两个词必须先认识：

  • AVL 树：任意节点左右子树高度差 ≤ 1 的二叉排序树。两个条件都要满足——先得是 BST，再谈平衡。
  • 平衡因子（BF）：BF = 左子树高度 − 右子树高度，合法取值只有 −1、0、+1 三个。某个节点的 BF 一旦变成 ±2，这棵树就失衡了。（高度按层数算：只有一个节点的子树高 1，空子树高 0——这是教材算 BF 的通用口径。）
【是 AVL】每个节点的 BF 都落在 −1 ~ +1 内

四种旋转怎么记：LL、RR、LR、RL 的字母，第一个字母是插入点相对失衡节点的位置（L=左子树侧，R=右子树侧），第二个字母是再往里的方向。口诀：

  • LL 和 RR（同侧）：做一次"反方向旋转"。LL（全在左边）→ 右旋；RR（全在右边）→ 左旋。想象三个节点排成一条直线，把中间那个提起来当根，树就转平了。
  • LR 和 RL（异侧）：先对中间两个节点做一次旋转（变成 LL/RR），再按同侧规则转一次。口诀：先局部再整体，转两次。

最少节点数：高度为 h 的 AVL 树最少节点数 N(h) = N(h−1) + N(h−2) + 1（N(1)=1, N(2)=2）。

  • 公式怎么来的：要"节点最少"，根占 1 个；一棵子树塞满（高度 h−1），另一棵只求合法（高度只能是 h−2，差 1 是 AVL 的底线，再矮就失衡了）。所以 N(h) = 1 + N(h−1) + N(h−2)。
  • 代入算例：N(3)=N(2)+N(1)+1=2+1+1=4，N(4)=4+2+1=7，N(5)=7+4+1=12。考法："高度为 4 的 AVL 树最少有几个节点？" → 7。

考试怎么问：① 给几棵树问"哪个是 AVL"——数每个节点的 BF，越界的排除；② 给一棵插入后的失衡图问"应采用哪种旋转"——先找离插入点最近的失衡节点，再看插入点落在它的左子树侧还是右子树侧。旋转后的树形很少要求现场画，记住"谁当新根、哪棵子树改挂"就够了。

2.6 B 树与 B+ 树（每年 0–1 题，记住对比即可）

考频先说清：真题目库里几乎没有 B 树的独立题，按考频精炼的考前资料里干脆不提它。所以只做三件事：知道它为什么存在、认得出两张结构图的区别、背下那张对比表。阶数公式、插入分裂过程都不必背。

它解决什么问题：磁盘 I/O。二叉树查找要一层层往下走，每下一层就是一次磁盘访问——100 万条记录，二叉树高度约 20，最坏情况要读 20 次盘。把树"变胖"就解决了：一个节点塞几百个关键字、带几百个孩子，树高压到 3～4 层，磁盘只需读三四次。B 树是被磁盘逼出来的结构，不是为内存设计的。

定义（m 阶 B 树）："阶"就是一个节点最多能有多少个孩子。

  • 每个节点最多 m 个孩子、m−1 个关键字；
  • 除根外每个节点至少有 ⌈m/2⌉ 个孩子（根至少 2 个）；
  • 所有叶子节点都在同一层——这一条让它天然平衡，不需要旋转。

结构图：下面是 3 阶（每个节点最多 3 个孩子、2 个关键字）的两种树。两者的拓扑长得几乎一样，差别只在数据放在哪、叶子连不连：

对比 B 树 B+ 树

为什么数据库索引用 B+ 树不用 B 树（两句就够）：

  1. 内部节点不存数据 → 同样一个磁盘块能装下更多关键字 → 树更矮 → 磁盘访问次数更少；
  2. 叶子串成链表 → "查 10 到 500 之间的记录"顺着链表扫一段就行，B 树得反复回到上层重新往下走。

考试怎么问：给两张图问"哪棵是 B+ 树"（看数据是不是全在最底层、叶子有没有连线）；问"B+ 树叶子节点的作用"（存全部数据 + 串成链表支持范围查询）；问"数据库为什么用 B+ 树"（上面那两句）。都不涉及算法，背表即可。

边数公式背后的原理：为什么无向要 ÷2？（组合 vs 排列）——n(n−1)/2 和 n(n−1) 只差那个「÷2」，两者本质是同一个计数问题的两种数法：从 n 个点里选 2 个，要不要分先后。

先看通用公式（k 个一组）：

  • 组合 C(n,k)（从 n 个里「不分先后」选 k 个）： C(n,k) = n! / (k!·(n−k)!)
  • 排列 P(n,k)（从 n 个里「分先后」选 k 个）： P(n,k) = n! / (n−k)!
  • 两者的桥：P(n,k) = C(n,k) × k!，也就是 C(n,k) = P(n,k) / k!。

代入 k = 2：

  • C(n,2) = n! / (2!·(n−2)!) = n(n−1) / 2　→　n=5：5!/(2·3!) = 120/12 = 10 ✓
  • P(n,2) = n! / (n−2)! = n(n−1)　→　n=5：5!/3! = 120/6 = 20 ✓

对回完全图：

含义 该用哪个 边数
无向完全图 两点之间只有 1 条边，"来去"算同一条 组合 C(n,2)（不分先后） n(n−1)/2
有向完全图 A→B 与 B→A 是两条不同的边，"选谁当起点"也算区别 排列 P(n,2)（分先后） n(n−1)

关键的一步：P(n,2) = C(n,2) × 2!，乘这个 2! = 2，正是无向公式里那个「÷2」的来历——无向把来、回两条折叠成一条，所以要除以 2。口诀：无向 ÷2（不分来去）、有向不 ÷2（来去两条）。

顺手钉死一个易混点：C(n, n−1) 不等于 n(n−1)。C(n, n−1) = C(n, 1) = n（"选 n−1 个"等价于"挑 1 个不要"，就 n 种）。完全图公式用的是 C(n,2)，不是 C(n, n−1)。

★ 度数定理（每年都有它的题）：无向图中所有顶点的度数之和 = 2e（e 是边数）。理由很朴素：一条边有两个端点，它给两头的度数各加 1。

  • 用 G1 验算：度数 2+2+2+3+1 = 10（A2、B2、C2、D3、E1），边数 5 → 10 = 2×5 ✓
  • 反向用（这是常见考法）："某无向图有 10 个顶点、每个顶点的度都是 4，问边数" → 度数和 = 40 = 2e → e = 20。
  • 推论（握手定理）：度数为奇数的顶点个数必为偶数。所以"给一组度数问能不能画出图"的题，第一步就数奇数度的点有几个——奇数个就直接不存在。
  • 有向图版本：入度总和 = 出度总和 = 边数（每条边恰好贡献一个入度和一个出度）。

易错点：连通 ≠ 完全。连通要求"能走到"，完全要求"直接有边"。完全图一定是连通图；连通图不必是完全图（G1 连通，但 A 和 E 之间没有直连边，所以不是完全图）。题目常把这两句换着说法让你判对错。

3.1 存储结构：邻接矩阵 vs 邻接表

要解决的问题：图（点和线）怎么放进内存？两条路——把所有"谁和谁相邻"记成一张表格（矩阵），或者给每个顶点各挂一张"我的邻居"清单（链表）。

邻接矩阵：一张 n×n 的表

n 个顶点就开 n×n 的二维数组，A[i][j] = 1 表示顶点 i 到顶点 j 有边，0 表示无边。G1 的邻接矩阵（顶点顺序按 A、B、C、D、E）：

        A  B  C  D  E
   A [  0  1  1  0  0 ]     ← A 与 B、C 相邻
   B [  1  0  0  1  0 ]     ← B 与 A、D 相邻
   C [  1  0  0  1  0 ]     ← C 与 A、D 相邻
   D [  0  1  1  0  1 ]     ← D 与 B、C、E 相邻
   E [  0  0  0  1  0 ]     ← E 只与 D 相邻

读法：第 i 行第 j 列为 1 ⇒ 顶点 i 与顶点 j 之间有边。行号列号的对应关系靠"顶点顺序表"记着（这里第 1～5 行分别是 A～E）。

三个可以直接考的结论：

  1. 无向图的矩阵一定对称（A 与 B 有边 ⇔ B 与 A 有边），主对角线全是 0（自己跟自己不算相邻）。
  2. 某一行上 1 的个数 = 该顶点的度。D 那行有 3 个 1 → D 的度是 3 ✓ 这也是"数度"最快的算法。
  3. 若把 1 换成边的权值 → 就是带权图的邻接矩阵（无边处记 ∞ 或 0，看题目约定）。

有向图不对称，反例先说清：若边是有向的，比如 A→B 存在、B→A 不存在，那么第 A 行 B 列为 1、第 B 行 A 列为 0 → 矩阵不对称。于是有这条判别：矩阵不对称 ⇒ 一定是有向图；矩阵对称 ⇒ 可能是无向图，也可能是"有向图但两个方向恰好都有边"（参考资料里的原话："不对称的矩阵一定是有向图，对称的矩阵可能是有向图"）。

代价：空间 O(n²)。G1 只有 5 条边却开了 25 格，浪费；顶点多时（如 1000 个顶点、10 条边）几乎全是 0，浪费更严重。优点是查"两点是否相邻"是 O(1)（直接看格子的值），以空间换时间。

邻接表：每个顶点一条"邻居清单"

开一个一维数组存 n 个顶点，每个顶点后面挂一条链表，链表里存它的所有邻接顶点。G1 的邻接表：

   [0] A → B → C ∧
   [1] B → A → D ∧
   [2] C → A → D ∧
   [3] D → B → C → E ∧
   [4] E → D ∧
  • 空间 O(n+e)：n 个顶点各一个表头 + 每条边在两头的链表中各出现一次（无向图），所以"边节点"总数 = 2e。G1：5 个表头 + 10 个边节点 = 15 个节点。
  • ★ 固定考点（参考资料原话）："有向图的邻接表有 n+e 个点，无向图的邻接表有 n+2e 个点。"有向图每条边只在一个链表里出现一次，所以是 n+e。这个 n+e / n+2e 是选择题的固定考法。
  • 缺点是判断两点是否相邻要从头扫链表（O(度) 而不是 O(1)）。

两种存储的正面对比（背下来）

对比项 邻接矩阵 邻接表
空间 O(n²) O(n+e)
判断两点是否相邻 O(1) O(n)（要扫链表）
适合的图 稠密图（边接近 n(n−1)/2） 稀疏图（边很少）
无向图存法 对称矩阵，存一份或两倍 每条边在两个链表各出现一次（2e）
数的度数 扫一行 O(n) 扫自己的链表 O(度)
存带权图 矩阵元素直接放权值 链表节点多带一个权值字段

手算口诀：稠密用矩阵、稀疏用邻接表；矩阵好查（O(1)）费空间，邻接表省空间查得慢。

还有两个"见过就行"的存储（软考偶尔在选项里出现，知道名字和用途即可）：

  • 十字链表：有向图的邻接表改良版，一条边只存一次又能同时顺着"出边"和"入边"找，专门服务有向图求入度/出度。
  • 邻接多重表：无向图的邻接表改良版，同样让每条边只存一份（邻接表里无向边要存两次），便于删除边。

应试动作：

  • 认题特征：题目给一个矩阵问"这是哪种存储/某顶点的度是多少/图是否连通"，就看行内 1 的个数（度）、是否对称（无向）。
  • 背什么：O(n²) vs O(n+e)、n+e vs n+2e、无向完全图边数 n(n−1)/2、度数和 = 2e。
  • 哪些靠算：给邻接表算某点的度、给矩阵算边数——都是"数 1"的活，别慌，慢慢数。

3.2 遍历：DFS 与 BFS（选择题必有，案例题也用）

要解决的问题：从某个顶点出发，怎样把整张图每个点恰好走一遍？

树为什么不用操心这个？因为树没有回路，顺着走就能不重不漏。图里有回路（G1 里 A-B-D-C-A 就是一圈），走法不当就会原地转圈。所以图遍历比树遍历多了一个必需装备：visited 标记数组，走过的点打标记，遇到打过标记的点就跳过。忘掉 visited 是本节最容易犯的错（也是判断题里最爱设计的陷阱）。

两种走法，区别只在"优先照顾哪个方向的邻居"：

DFS（深度优先遍历，Depth-First Search）：一条路走到黑

策略：访问当前顶点 → 挑一个还没访问过的邻居钻进去 → 继续往下钻 → 直到某个顶点周围全是"已访问"，回退到上一个还有未访问邻居的顶点，继续钻。实现靠栈（递归写法用的就是系统栈）。

用 G1 从 A 出发（邻居按邻接表顺序取，字母小的先取）：

   G1 邻接表：  A→B→C   B→A→D   C→A→D   D→B→C→E   E→D
步 动作 栈（顶在右） 已访问（输出序）
1 A 无路可退，先访问 A、压栈 A A
2 A 的第一个未访问邻居 B → 访问 B、压栈 A B A B
3 B 的第一个未访问邻居 D → 访问 D、压栈 A B D A B D
4 D 的第一个未访问邻居 C → 访问 C、压栈 A B D C A B D C
5 C 的邻居 A、D 都访问过了 → 无路可走，弹栈回退到 D A B D A B D C
6 回到 D，找它下一个未访问邻居 E → 访问 E、压栈 A B D E A B D C E
7 E 的邻居 D 已访问 → 无路可走，连续弹栈回退到 A，栈空，结束 （空） A B D C E

DFS 序列：A B D C E

两个必须看懂的细节：

  • 第 5 步弹栈时 C 不再输出。弹栈只是"退回去找别的路"，不是"重新访问"。C 只在第 4 步被输出一次。
  • 回退的粒度是"顶点"不是"边"：C 走不通，一次退到最近的一个"还有未访问邻居"的顶点（这里是 D），不是退一步就停。

BFS（广度优先遍历，Breadth-First Search）：一圈一圈往外扩

策略：先把起点的所有邻居访问完，再访问邻居的邻居……实现靠队列（先进先出，保证同层先来先服务）。

同样从 A 出发：

步 动作 队列（头在左） 已访问（输出序）
1 A 入队 [A]
2 出队并访问 A，把 A 的未访问邻居 B、C 入队 [B, C] A
3 出队并访问 B，把 B 的未访问邻居 D 入队 [C, D] A B
4 出队并访问 C，C 的邻居 A、D 都已访问/已在队 → 不入队 [D] A B C
5 出队并访问 D，把 D 的未访问邻居 E 入队 [E] A B C D
6 出队并访问 E，邻居 D 已访问 → 队空，结束 [] A B C D E

BFS 序列：A B C D E

★ BFS 的关键实现细节：标记 visited 要在入队的那一刻就打，不能等出队。否则第 3 步 D 入队后，第 4 步处理 C 时看到 D 还没"被访问"（只是排队），会把 D 重复入队。判断题常拿这里做考点。

两者对比（这张表要能默写）

DFS 深度优先 BFS 广度优先
走法 一条路走到黑，走不动才回退 一圈一圈向外扩
辅助结构 栈（或递归） 队列
树的对应 相当于树的先根（前序）遍历 相当于树的层序遍历
生活类比 走迷宫贴着墙一直走到底 水波从落水点向外扩散
遍历序列 不唯一（邻居次序不同结果不同） 不唯一
求无权图单源最短路径 不行 可以：BFS 第一次到达某点时的层数就是最少边数
时间复杂度 邻接矩阵 O(n²)、邻接表 O(n+e) 同左

两个可以直接考的结论：

  1. 遍历序列不唯一，因为"先钻哪个邻居"没有硬性规定。所以题目若给出邻接表 + 起点 + 邻居顺序，序列才是唯一的——题干一般都会强调"按邻接表顺序访问"。反过来，"下面哪个序列不可能是某个图的 DFS/BFS 序列"这类题，要靠"同层内任意、跨层有约束"去筛。
  2. 复杂度只和存储结构有关，与 DFS/BFS 无关：矩阵 O(n²)、邻接表 O(n+e)。记住这句原话，选择题很喜欢用它做选项。
  3. 非连通图一次遍历只能走完一个连通分量；要访问全部顶点，就得对每个未访问顶点各起一次遍历 → 调用遍历的次数 = 连通分量个数。

应试动作：

  • 认题特征：给一个图/邻接表问"从 V1 出发的 DFS 序列"，或给序列问"是否是 DFS 序列"。看到"深度/一条路走到黑"选 DFS（栈），看到"逐层/由近及远"选 BFS（队列）。
  • 手算技巧：DFS 在草稿上画出递归的走向箭头（进去 →、回退 ←），比盯代码快；BFS 就老老实实画队列的进出。
  • 背什么：栈 ↔ DFS、队列 ↔ BFS；无权图最短路径只能靠 BFS。

延伸阅读：BFS/DFS 的逐帧动画与实现代码见 hello-algo · 图的遍历（在线可看；离线不影响自足）。

3.3 最小生成树：Prim 与 Kruskal

要解决的问题：n 座城市要铺通信线路，任意两城能互通即可（不要求直连），怎么铺总造价最低？

这个问题有两个隐含要求，正是"生成树"的定义：要连通（否则有的城市联系不上）、要最省（能连通 n 个点最少只要 n−1 条边，多铺一条都是浪费）——再不允许有回路（有回路就说明多铺了一条线）。

生成树的四个特征（说三个就能推出第四个）：含全部 n 个顶点、恰好 n−1 条边、连通、无回路。

最小生成树（MST）：带权图中"边权之和最小"的那棵生成树。

  • ★ 权值和唯一，但树本身可能不唯一：当图里有权值相同的边时，可选的方案不止一种，但最小权值和是唯一的。这句话选择题直接考。
  • 找法思路：不管哪种算法，都是贪心——每一步都挑当前最小的边，区别只在"从哪里开始挑"。

先用一张图把两个算法都跑一遍（G2）

        A ──4── B
        │ ╲     │
        5   2   1
        │     ╲ │
        D ──3── C
        │
        4
        │

   G2 的边（无向）：A-B 4、A-C 2、A-D 5、B-C 1、C-D 3、D-E 4        共 6 条边、5 个顶点

Kruskal（克鲁斯卡尔）：加边法——"把边按长短排队，短的先上，成环就跳过"

一步都不用画树，纯排序 + 查环：

步 候选边（从小到大） 权 判断 是否选中 已选中的边
1 B-C 1 两端不连通 ✔ BC
2 A-C 2 不连通（A 还是孤点） ✔ BC、AC
3 C-D 3 不连通（D 还是孤点） ✔ BC、AC、CD
4 A-B 4 A、B 已经连通（A-C-B）→ 选了会成环 ✘ 跳过 —
5 D-E 4 不连通（E 还是孤点） ✔ BC、AC、CD、DE
— A-D 5 5 已连满 4 条边（n−1=4），结束 — —

结果：MST = {BC 1, AC 2, CD 3, DE 4}，权值和 = 1+2+3+4 = 10，4 条边 = n−1 ✓，无回路 ✓，覆盖 A～E ✓

反例前置（最容易错的一步）：第 4 步 A-B 权 4 比 D-E 的 4 一样小，看着都该选——但 A 和 B 此时已经通过 A-C-B 连通了，加上 A-B 就形成回路 A-B-C-A，而生成树不许有回路，所以必须跳过。很多同学"见小的就选"，就错在这一步。Kruskal 唯一要动脑的地方就是查环：只要一条边的两个端点已经连通，就跳过。

Prim（普里姆）：加点法——"从一棵树苗开始，每次接一个最近的顶点进来"

Prim 不排序边，而是维护一个"已经长成的树"的顶点集合 S：

步 已选顶点集合 S 从 S 连到集合外的所有边 最短的 接进来的点
起始 {A} A-B 4、A-C 2、A-D 5 A-C 2 C
2 {A, C} A-B 4、A-D 5、C-B 1、C-D 3 C-B 1 B
3 {A, C, B} A-D 5、C-D 3 C-D 3 D
4 {A, C, B, D} D-E 4 D-E 4 E（点全到齐，结束）

结果：选中的边 = {AC 2, CB 1, CD 3, DE 4}，权值和 = 10 —— 与 Kruskal 完全一致 ✓

这正是一次"用第二种方法反向验证"：两个算法的思路差得远（一个加边一个加点），却给出同一个权值和 10，说明算对了。考场上若时间允许，用另一个算法复核，比反复验算同一条路更可靠。

易错点：Prim 第 2 步"从 S 连到集合外的边"要包括 S 里所有点发出的边（A-B 4 和 C-B 1 都要列出来），只盯新接进来的 C 会漏掉 A-B，可能选错。Prim 是"整个集合对外的最短边"，不是"新点的最短边"。

两个算法的分工（常考"选哪个算法"）

Prim（普里姆） Kruskal（克鲁斯卡尔）
思路 加点：每次把离树最近的顶点接进来 加边：每次取全图最短的边，成环则跳过
复杂度关键 与顶点数 n 有关（传统实现 O(n²)） 与边数 e 有关（排序 O(e·log e)）
更适合 稠密图（边多，n 小） 稀疏图（边少）
手算感觉 围着"已选集合"一圈一圈找最近的点 把边排成一队，从上往下捡

手算口诀：Prim 加点（对外找最短）、Kruskal 加边（排队捡短的、成环丢掉）；稠密 Prim、稀疏 Kruskal。

应试动作：

  • 认题特征："求最小生成树/最省造价线路" → 立即边列表排序（Kruskal）或标出已选集合（Prim）。
  • 必查三件事：边的条数 = n−1、无回路、覆盖所有顶点。三件都过才算做完（这也是自检口径）。
  • 背什么：MST 权值和唯一、树可能不唯一；Prim 稠密、Kruskal 稀疏。
  • 哪些靠算：给图算 MST 权值和——必须动手画一遍，光看不能得出答案。

3.4 最短路径：BFS（无权）与 Dijkstra（带权）

要解决的问题：从一点到另一点怎么走最近？注意分两种"近"：

  • 无权图：边没有权值，"近"= 经过的边数最少 → 用 BFS（3.2 已述：BFS 第一次到达某点时的层数就是最少边数）。
  • 带权图（网）：边上带距离/花费/时间，"近"= 权值之和最小 → 用 Dijkstra（迪杰斯特拉）。

Dijkstra 的思路：贪心，每轮"认定"一个点

一句话：每轮从"还没确定的点"里挑出当前距离最小的那个，宣布它的最短距离已定，然后用它去更新（松弛）所有邻居的距离。

  • "松弛"（relax）= 试着用新确定的点做中转：若 起点的距离 + 这条边的权 < 邻居原来的距离，就改小它。"松弛"这个词会出现在题干里，要知道它就是"试一试能不能更短"。
  • 直觉：既然所有边权都是正的，那么当前离起点最近的那个点，不可能再有别的更短路线绕到它（绕路只会花更多）——所以可以放心"认定"。这就是贪心法的立足点。

完整演算一遍（G3，有向网，源点 V1）

   顶点从左到右排：V1  V2  V3  V4  V5       所有箭头一律只能「从左指向右」（无环）

   V1 ══4══▶ V2 ══1══▶ V3 ══5══▶ V4 ══2══▶ V5      ← 主干链
   V1 ══6══▶ V3                                     ← 跨一格
   V2 ══7══▶ V4                                     ← 跨一格
   V3 ══9══▶ V5                                     ← 跨一格

初始化：d(V1)=0（起点到自己），有直接边的先写上权值，其余记 ∞。 即 d(V2)=4、d(V3)=6、d(V4)=∞、d(V5)=∞。已确定的集合 S = {V1}。

轮 未确定的点及其当前距离 本轮认定（距离最小者） 松弛动作 松弛后的距离
1 V2=4、V3=6、V4=∞、V5=∞ V2（4） V2→V3：4+1=5 < 6 → 改小；V2→V4：4+7=11 < ∞ → 写上 d(V3)=5、d(V4)=11
2 V3=5、V4=11、V5=∞ V3（5） V3→V4：5+5=10 < 11 → 改小；V3→V5：5+9=14 < ∞ → 写上 d(V4)=10、d(V5)=14
3 V4=10、V5=14 V4（10） V4→V5：10+2=12 < 14 → 改小 d(V5)=12
4 V5=12 V5（12） 没有出边，结束 —

最终结果：d(V1)=0、d(V2)=4、d(V3)=5、d(V4)=10、d(V5)=12。 V1 到 V5 的最短路径 = V1→V2→V3→V4→V5，长度 4+1+5+2 = 12。

反向验算（必须做）：V1 到 V5 的其他可能路线：

  • V1→V2→V4→V5 = 4+7+2 = 13 > 12 ✗
  • V1→V3→V4→V5 = 6+5+2 = 13 > 12 ✗
  • V1→V3→V5 = 6+9 = 15 ✗ 所以 12 确实是最小的 ✓

这一轮最值得看的是 V3：V1 到 V3 明明有直达边权 6，但第 1 轮经 V2 中转只需 4+1 = 5，于是 d(V3) 从 6 被改小成 5。这就是"松弛"的价值，也说明了为什么每轮都要重新挑最小——不能一开始就把"直达边的权值"当成最终答案。

两个固定考点

  1. Dijkstra 不能处理负权边（选择题几乎年年出）。 反例（就三个点，一眼看懂）：
    V1 ══1══▶ V2        V1 ══2══▶ V3        V3 ══(−2)══▶ V2
    真实最短路径：V1→V3→V2 = 2 + (−2) = 0。 但 Dijkstra 第 1 轮会挑中 V2（d=1）并宣布它已确定；第 2 轮才处理 V3，发现 V1→V3→V2 只要 0，比已宣布的 1 更小——算法却不会再回头改。负权边破坏了"当前最近的点不可能被绕路超越"这个贪心前提，所以 Dijkstra 失效。
  2. Floyd（弗洛伊德）求"多源"最短路径：一次算出任意两点之间的最短路径（Dijkstra 是单源：只算一个源点到其他所有点）。Floyd 是动态规划思想，三重循环实现；它可以处理负权边，但同样不能处理负权回路。 记法：单源 Dijkstra（贪心）、多源 Floyd（动态规划）。这句对照几乎每年以选项形式出现。

应试动作：

  • 认题特征：给带权有向/无向图问"源点到各点的最短距离""哪条是最短路径" → Dijkstra 表格法（画一列表格逐轮填）。
  • 手算纪律：每轮必须重新扫描所有未确定的点选最小，别凭直觉跳步；每轮松弛完把距离写清楚，便于回查。
  • 背什么：Dijkstra 是贪心、不能负权；Floyd 是多源、可负权不能负环；无权图最短路用 BFS。
  • 哪些靠算：具体的最短距离与路径必须自己算一遍（本例 12），光看答案记不住。

3.5 拓扑排序（AOV 网）

要解决的问题：做事情有先后依赖——"先打地基才能砌墙""先修课程 A 才能修课程 B"。怎么把一堆有依赖关系的活动排成一个合法的执行顺序？

AOV 网：顶点表示活动，有向边表示活动之间的先后约束（A→B 表示 A 必须排在 B 前面）。要求这张有向图没有回路（有回路意味着"A 要在 B 前、B 又要 A 在 A 前"，矛盾）——没有回路的有向图叫 DAG（有向无环图）。

拓扑排序：把 AOV 网的所有顶点排成一个线性序列，使得每条边都从序列的前面指向后面（若图中有 Vi→Vj 的路径，序列里 Vi 必须排在 Vj 之前）。

做法：反复挑"入度为 0"的点

入度为 0 = 没有任何前置活动——这种活现在就能干。步骤：

  1. 找一个入度为 0 的顶点，输出它；
  2. 删除它的所有出边（相当于"这件活干完了，它解锁了后面的活"）；
  3. 重复 1～2，直到所有顶点都输出（或发现没有入度为 0 的点 → 说明有环，排序失败）。

演算一遍（AOV：A→B、A→C、B→D、C→D、D→E）：

   A ──→ B ──┐
   │         ↓
   └──→ C ──→ D ──→ E

   各点入度：A 0、B 1、C 1、D 2、E 1
步 当前所有入度为 0 的点 本轮输出（任选一个） 删除它的出边后，入度变化
1 A A 删 A→B、A→C → B 变 0、C 变 0
2 B、C B（也可先输出 C） 删 B→D → D 从 2 变 1
3 C C 删 C→D → D 从 1 变 0
4 D D 删 D→E → E 从 1 变 0
5 E E 无出边，结束

得到一个合法拓扑序列：A B C D E（另一个是 A C B D E，只有这两种：A 必须第一、E 必须最后、B 与 C 之间无约束可互换、D 必须夹在 B、C 之后和 E 之前）。

三条结论（选择题原话考）

  1. 拓扑序列不唯一：没有先后约束的点之间可以任意换位置。
  2. 图中有环 → 拓扑排序做不下去（会出现"所有剩下的点入度都 ≥ 1"的死局）。工程上正用它来检测循环依赖（比如 Makefile/编译系统报"circular dependency"）。
  3. 深度优先遍历的逆序也是一种合法的拓扑序列。道理：DFS 退出的时刻，某个点后面能到达的点都已经先退出了，所以把"退出顺序"倒过来看，就是"被依赖的排后面"→ 正好满足拓扑序。（顺带记住另一条：逆拓扑排序是每次取出度为 0 的点输出并删除其所有入边。）

易错点：

  • 拓扑排序只关心入度（谁没有被依赖），别看去度去。判"是否能完成拓扑排序"用入度法最稳。
  • 拓扑排序不是排序算法（不比较大小），它只解决"先后约束"，和第五节那些排序是两码事。
  • 题干给的"先后关系"要转成边的方向："A 必须在 B 之前完成" ⇒ 边 A→B（从"前"指向"后"），画反了整题就反了。

应试动作：

  • 认题特征：题目出现"先后顺序/前置任务/课程安排/能否完成"，或直接问"下列哪个是合法拓扑序列"。
  • 判别"某个序列是否合法"的最快方法：对着题图的每条边检查一次"起点是否排在终点前面"，有一条不满足就非法。（一句话口诀："图中 A→B，序列中 A 在 B 前面；A 和 B 没有关系，序列中 A 可前可后。"）
  • 背什么：入度法三步；有环则无拓扑序；DFS 逆序可行。

3.6 关键路径（AOE 网）★★★（计算题大户）

要解决的问题：整个工程最快多久能完工？哪些活动一天都不能拖（拖了就拖累整体工期）、哪些活动可以摸鱼（拖几天不影响总工期）？

AOE 网：边表示活动（边权 = 活动工期），顶点表示事件（事件的"发生"= 它所有前置活动都已完成的状态）。

  • 源点：入度为 0 的顶点，代表工程开始；汇点：出度为 0 的顶点，代表工程结束。
  • 与 AOV 网的区别一句话：AOV 边只表示先后（顶点是活动），AOE 边既表示先后又带工期（边是活动）。AOV 用来排顺序，AOE 用来算工期。

★ 关键路径 = 从源点到汇点的最长路径，它的长度 = 整个工程的最短工期。

"最长"为什么反而是"最短工期"（这是本节的"动机"，理解了才不别扭）：汇点要"发生"，它前面所有的活动都得干完；而最长的那条链上一个活动都省不掉，工期不可能比它短。同时，按这条最长链去安排进度，其余活动都能塞进这个时间窗内完成，所以这个时间刚好够。上下夹住，于是最长路径长度 = 最短完工时间。

四个量、两趟推（每个事件一个 ve/vl，每个活动一个 e/l）：

量 含义 怎么算
ve(v) 事件最早发生时间 这个事件最早什么时候能发生 源点 ve(源)=0；顺推取 max：ve(v) = max 所有入边 { ve(前驱) + 该活动工期 }
vl(v) 事件最迟发生时间 这个事件最晚什么时候发生还不拖累工期 汇点 vl(汇)=ve(汇)；逆推取 min：vl(v) = min 所有出边 { vl(后继) − 该活动工期 }
e(a) 活动最早开始时间 起点事件一发生它就能开工 e(a) = 起点的 ve
l(a) 活动最迟开始时间 再晚开工就拖累工期 l(a) = 终点的 vl − 该活动工期

★ 时间余量（松弛时间）= l(a) − e(a)，余量为 0 的活动就是关键活动，把它们连起来就是关键路径。

完整算一遍（G4，6 个事件、7 个活动）

       a1=3                 a3=2
  V1 ────────▶ V2 ───────────────▶ V4 ─────a6=2────▶ V6
   │                                ▲                 ▲
   │ a2=2                           │ a4=4            │
   └─────────▶ V3 ──────────────────┘                 │
               │                                      │
               │ a5=3                                 │
               └─────────▶ V5 ───────a7=1─────────────┘

  事件（顶点）：V1 源点、V6 汇点
  活动（边）：a1 V1→V2 =3   a2 V1→V3 =2   a3 V2→V4 =2   a4 V3→V4 =4
              a5 V3→V5 =3   a6 V4→V6 =2   a7 V5→V6 =1

第一趟：顺推求 ve（取 max）

事件 谁指向它 计算 ve
V1（源点） — 规定为 0 0
V2 V1(a1=3) 0+3 3
V3 V1(a2=2) 0+2 2
V4 V2(a3=2)、V3(a4=4) max(3+2=5, 2+4=6) 6
V5 V3(a5=3) 2+3 5
V6（汇点） V4(a6=2)、V5(a7=1) max(6+2=8, 5+1=6) 8

→ 总工期 = ve(V6) = 8。注意 V4 那步必须把所有入边都算上取最大（只用一条会算成 5，这是最常见的错）。

第二趟：逆推求 vl（取 min）

事件 它指向谁 计算 vl
V6（汇点） — 与 ve 相同 = 8 8
V5 V6(a7=1) 8−1 7
V4 V6(a6=2) 8−2 6
V3 V4(a4=4)、V5(a5=3) min(6−4=2, 7−3=4) 2
V2 V4(a3=2) 6−2 4
V1（源点） V2(a1=3)、V3(a2=2) min(4−3=1, 2−2=0) 0

（自检：源点逆推出来必须是 0，不是 0 说明前面算错了。）

第三趟：算每个活动的 e、l、余量

活动 起点 ve（=e） 终点 vl − 工期（=l） 余量 l−e 是否关键
a1 V1→V2 =3 0 4−3 = 1 1 否
a2 V1→V3 =2 0 2−2 = 0 0 ★ 是
a3 V2→V4 =2 3 6−2 = 4 1 否
a4 V3→V4 =4 2 6−4 = 2 0 ★ 是
a5 V3→V5 =3 2 7−3 = 4 2 否
a6 V4→V6 =2 6 8−2 = 6 0 ★ 是
a7 V5→V6 =1 5 8−1 = 7 2 否

关键路径：V1 → V3 → V4 → V6，长度 = 2+4+2 = 8，与 ve(V6) 一致 ✓

反向验算（必做）：从源点到汇点的其他所有路线都不许超过 8——

  • V1→V2→V4→V6 = 3+2+2 = 7 < 8 ✓
  • V1→V3→V5→V6 = 2+3+1 = 6 < 8 ✓ 只有 V1→V3→V4→V6 达到 8，所以关键路径唯一 ✓（关键活动 a2、a4、a6 首尾相接，恰好构成一条从源点到汇点的完整通路，这也是自检口径。）

三条必考结论

  1. 关键路径可能不止一条。多条关键路径时，所有关键活动都长在关键路径上，但某条关键路径上的活动未必在另一条上，于是有了结论 2。
  2. 缩短工期必须压缩"所有关键路径的公共关键活动"。只压缩某一条关键路径上的活动，另一条关键路径长度不变，总工期纹丝不动。
    • 用本例看：a1 有余量 1，压缩它（哪怕压到 0）工期仍是 8；压 a6 才有用。
  3. 关键路径可能因"压过头"而转移：把某条关键路径压到比另一条短，最长路径就换人了，工期不再继续缩短——所以"压关键活动一定能缩短工期"这句话只在"压公共活动且没压过头"的前提下成立。选择题里"缩短任一关键活动都能缩短工期"是错的（见课后题 15）。

易错点清单：

  • 顺推取 max、逆推取 min，别记反（顺推是"要等所有前置做完才能开始"，所以取最大；逆推是"必须给所有后续留够时间"，所以取最小）。
  • l(a) = 终点的 vl 减工期。写成"起点的 vl"或"加工期"都错。
  • ve 和 vl 是事件（顶点）的量，e 和 l 是活动（边）的量，两张表别混。
  • 时间余量为 0 才是关键活动（余量不为 0 的活动还有缓冲）。

应试动作：

  • 认题特征：题干出现"AOE 网/工期/最早发生/最迟开始/时间余量" → 立刻画两张表（ve 表、vl 表），再列活动表算 e、l、余量。
  • 手算纪律：每张表算完做一次自检——ve(源)=0、vl(源)=0、vl(汇)=ve(汇)、关键活动首尾相接构成一条源→汇通路，四条全过基本就没算错。
  • 背什么：四个量的定义与"顺 max 逆 min"、余量 0 即关键、"压缩要压公共关键活动"。
  • 哪些靠算：任何一道关键路径题都必须动手列表，凭直觉猜最长路径在 4 个以上的活动时几乎必错。

跨课联动：软件工程部分（03-软件工程基础.html）里的甘特图、项目工期、总时差（松弛时间）与本节是同一套东西，只是那边用 ES/EF/LS/LF 的记号表示，本质完全一致——在这里算熟，那边直接得分。

第四节 查找 ★★

4.1 五种查找的定位（先看清各自的"前提条件"）

查找这件事的难点不在算法本身，而在前提条件：你手上是一张无序表还是有序表？是顺序存储还是链式存储？数据是静态的还是要频繁插入删除？条件不同，可选的算法完全不同，软考最爱考的就是"哪个方法在这个条件下不能用"。

查找方法 前提条件 平均时间 一句话
顺序查找 无要求（顺序/链式、有序/无序都行） O(n) 一个个比过去，最笨但最万能
二分查找 有序 + 顺序存储（数组） O(log₂n) 每次砍一半
分块查找 块间有序、块内无序 O(√n) 量级 先查索引再查块，二分与顺序的折中
二叉排序树 树是 BST 平均 O(log₂n)，最坏 O(n) 动态查找：插入删除都方便
散列表（Hash） 有哈希函数 O(1)（理想） 直接算出地址，不比较

易错点（第一条就是送分题级别的）：链表不能做二分查找。二分要靠下标跳到"中间元素"，而链表找中间元素只能从头走，砍一半的便宜立刻没了。所以"有序链表用二分查找做 O(log n) 查询"是错的。

4.2 顺序查找与二分查找

  • 顺序查找：从头到尾逐个比。无序表也能用（这是它唯一的优势）。等概率下查找成功的平均查找长度 ASL = (n+1)/2（1+2+…+n 除以 n）。
  • 二分查找（折半查找）：每次取中间元素比较，小就往左半区、大就往右半区，比较一次砍掉一半。O(log₂n)。
    • ★ 最多比较次数 = ⌈log₂(n+1)⌉（等于判定树的深度）。n=15 → ⌈log₂16⌉ = 4 次；n=1000 → ⌈log₂1001⌉ = 10 次。
    • 判定树：把"每次取中间元素"的过程画成树——第一层的中间元素做根，左右两半各自递归。树有几层，最多就比较几次。
    • ASL（成功，等概率）≈ log₂(n+1) − 1。
    • 二分查找的"找不到"也不难判：最后区间为空就是失败；"插入位置"就是最后落幕的那个下标（案例题的二分插入代码常挖这个空）。

判定树长什么样（n=11 的例子）：中间元素是第 6 个，它做根；左边 1～5、右边 7～11 各自再取中间，得到深度 4 的树，⌈log₂12⌉ = 4 ✓

            6
         /     \
        3        9
       / \      / \
      1   5    7   11
       \  /     \  /
        2 4     8 10

应试动作：看到"有序 + 顺序存储 + 求最多比较次数"，直接套 ⌈log₂(n+1)⌉；n 给 2^k−1（如 15、31、63）时答案就是 k，别自己算错。

4.3 分块查找（索引顺序查找）

动机：顺序查找太慢、二分查找又要求全体有序（维护成本高）。折中方案：把表分成若干块，块间有序、块内无序。

  • 分块规则：第一块里所有元素都小于第二块里所有元素，第二块全小于第三块……块内不要求有序。
  • 查找分两步：① 先在索引表（每个块的最大值和块起始位置，是有序的）里确定目标在哪块；② 再在该块内顺序查找。
  • ASL = 索引查找的 ASL + 块内查找的 ASL。n 个元素分成 b 块、每块 s 个（b·s = n），两边都用顺序查找时： ASL = (b+1)/2 + (s+1)/2 = (b+s+2)/2
  • ★ 最优块长 s = √n（这样 b = s = √n 时 b+s 最小），此时 ASL ≈ √n + 1。
    • 代入算例：n=100 → 取 s=10、b=10 → ASL = (10+10+2)/2 = 11 = √100 + 1 ✓
    • n=100 若用顺序查找，ASL = (100+1)/2 = 50.5 → 分块把它降到 11，这就是分块的价值。

应试动作：认题特征——题干出现"索引表/块/分块"，或给一张"块内无序、块间有序"的表问平均查找长度。记两条：总 ASL = 两步 ASL 相加、s=√n 时最优、ASL≈√n+1。

4.4 二叉排序树（BST）★★——动态查找的答案

要解决的问题：顺序表插入删除要搬家（O(n)），链表查找要走路（O(n)）。有没有一种结构，查找像二分那样快，插入删除又像链表那样便宜？答案就是二叉排序树。

定义（也叫二叉搜索树/BST）：一棵二叉树，满足"左子树上所有节点的值 < 根 < 右子树上所有节点的值"，且左右子树各自也是二叉排序树。

★ 最重要的一条性质：对二叉排序树做中序遍历，得到的序列是递增有序的（因为它就是"左 < 根 < 右"）。考法：给一棵树问"中序序列是什么"（直接考），或"这棵树是不是 BST"（中序递增就是）。

查找：从根开始，目标比当前节点小就往左走、大就往右走——一次比较砍掉一整棵子树，同二分一个道理。

插入：按查找的路线一路走到 NULL，把新节点挂在那个空位置上（所以新插入的节点一定是叶子）。

删除（三种情况，按树的形状分），设要删的节点为 p：

  1. p 是叶子：直接摘掉。
  2. p 只有一个孩子：让这个孩子直接顶替 p 的位置（整棵子树搬上去）。
  3. p 有两个孩子：不能简单顶替（两个都得管）。做法是找一个"替身"来占 p 的位置——中序前驱（左子树里最大的那个，即左子树一路往右走到底）或中序后继（右子树里最小的那个），把它的值写到 p 上，然后递归地去删除那个替身节点（替身至多只有一个孩子，于是退回情况 1 或 2，好删）。

完整演算一遍（本例树后续还用来算 ASL）：

            45                    ← 根
          /    \
        24      53
       /  \        \
     12    37       93
  • 删 12（叶子）：直接摘掉，树变成 45 下左子树只剩 37 ✓
  • 删 53（只有一个孩子 93）：让 93 顶替 53，成为 45 的右孩子 ✓
  • 删 24（有两个孩子 12、37）：取中序前驱（左子树里最大）= 37，把 37 写到 24 的位置，再去删原来的 37（它是叶子）。结果：
              45
        /    \
      37      53
     /           \
   12             93
（若改用"中序后继"= 右子树最小，本例右子树只有 37 自己，结果相同；两者都对。）

查找效率：完全取决于树的形状（这是本节最常考的判断）：

  • 最好的形状是平衡（左右差不多高）→ 高度约 log₂n → 查找 O(log₂n)，和二分一样快。
  • 最坏的形状是一条斜链（每个节点只有一个孩子）→ 高度 n → 查找 O(n)，退化成一个链表。
  • 什么时候会退化：按有序顺序依次插入。例：依次插入 1、2、3、4、5，1 是根、2 挂右、3 再挂右……形成一条向右下斜的链，找 5 要比较 5 次。反例记住这一句话就够："BST 最坏时可退化成单支树，查找退化为 O(n)。"
  • ASL 算例（用上面那棵 6 个节点的原始树，等概率）：各节点的比较次数 = 它所在的层数： 45 第 1 层（1 次）、24 和 53 第 2 层（各 2 次）、12、37、93 第 3 层（各 3 次） → ASL(成功) = (1 + 2 + 2 + 3 + 3 + 3) / 6 = 14/6 ≈ 2.33 算法就是"把每个节点的层数加起来除以节点数"——层数 = 查找它的比较次数，这是算 ASL 的通用套路（顺序、二分、BST 都一样）。

和平衡二叉树的关系（联动第二节 2.5 平衡二叉树）：既然形状决定效率，那就强制它平衡——这就是 AVL 树（任意节点左右子树高度差 ≤ 1），插入失衡就旋转修正，把最坏情况从 O(n) 拉回 O(log₂n)。

应试动作：

  • 认题特征："左小右大""中序递增""无序插入后建树"→ 立刻画树，千万别只在脑子里想。
  • 必背三条：中序递增；插入的节点必是叶子；删除有两个孩子的节点要用中序前驱/后继顶替。
  • 算 ASL：数层数求平均；问最好/最坏情况就答"平衡时 log₂n / 退化成单支时 n"。

延伸阅读：BST 的查找/插入/删除过程与配图见 hello-algo · 二叉搜索树（在线可看；离线不影响自足）。

4.5 散列表（Hash 表）★★（计算题大户）

要解决的问题：前面几种方法最快也要 O(log₂n)，因为它们都在"比较"。能不能不比较？ 能——用哈希函数 H(key) 直接算出关键字该放的位置，一次到位，理想情况查找 O(1)。

哈希函数怎么定：最常用除留余数法 H(key) = key mod p，其中 p 通常取"不大于表长的最大素数"（取素数能让余数分布更均匀）。例：表长 13 → p = 13；表长 12 → p = 11。

冲突与同义词：

  • 冲突：两个不同的关键字算出了同一个地址。
  • 同义词：H(key) 值相同的那些关键字（比如 9 和 17 在 H=k mod 8 下都是 1，它们就是同义词）。

冲突处理方法：

方法 做法 优缺点
线性探测（开放定址） 该位置被占了就往后挪一格、再挪一格……直到有空位 实现简单；会产生"堆积（聚集）"：连续被占的区间越来越长，非同义词也被牵连（见下面算例）
平方探测（开放定址） 依次试 +1²、−1²、+2²、−2²…… 缓解堆积，但可能漏掉空位
再散列（双散列） 冲突时换第二个哈希函数算新地址 分布更好，实现稍麻烦
链地址法 每个位置挂一条链表，冲突的节点都挂在同一链上 无堆积（不同地址互不干扰）、删除方便；链表变长时可改成树
公共溢出区 冲突的一律丢进另一张表 了解即可

★ 装填因子 α = 表中元素个数 / 表长。α 越大冲突越多、ASL 越大——散列表的查找效率取决于 α，而不是表的绝对长度（这句是原话考点：把表长从 100 改成 1000、元素数同比例变化时 ASL 基本不变）。

★ ASL 一定要动手算：ASL(成功) = Σ(每个元素的比较次数) / 元素个数。每个元素的比较次数 = 从它的哈希地址走到它的实际位置，一路上看了几个格子。

算例（同时演示"堆积怎么牵连别人"）：表长 8，H(key) = key mod 8，依次插入 9、17、25、3。

关键字 H(key) 线性探测后的位置 比较次数 说明
9 1 1 1 一次命中
17 1 2 2 位置 1 被占，往后挪
25 1 3 3 位置 1、2 都被占
3 3 4 2 注意：3 本来该待在自己家 3 号位，但 25 占了它 → 被牵连到 4 号位
  • 线性探测：ASL(成功) = (1+2+3+2)/4 = 2。
  • 换链地址法：位置 1 挂链 9→17→25，位置 3 挂链 3 → 各自的比较次数 1、2、3、1 → ASL = (1+2+3+1)/4 = 1.75。
  • 对比出的结论：25 只是一次普通冲突，却把毫不相干的 3 号位置"占"了，害得 3 多比一次——这就是堆积，链地址法没有这个问题，因为每个地址各自成链、互不干扰。

易错点：

  • 算 ASL 时别把"哈希地址"当"存储位置"，实际存放位置要按探测规则一步步推。
  • 线性探测下"某元素查找成功需要比较 k+1 次"里的 k 是它离自己哈希地址的格数（隔 0 格就是 1 次）。
  • 散列表的删除不能直接抹掉（线性探测下会截断别人的探测链），要用"墓碑标记"；链地址法没有这个烦恼——这也是"链地址法删除方便"的由来。

延伸阅读：四种冲突处理方式的实现与对比见 hello-algo · 哈希冲突（在线可看；离线不影响自足）。

5.2 高频判别题：给中间过程猜算法

题目给出一趟或两趟排序后的序列，问是哪种排序。识别特征：

  • 冒泡一趟：从头两两比较，一趟结束后最大（小）元素沉到末尾。
  • 选择一趟：第一个位置换成全序列最小值，其余相对位置基本不动。
  • 插入一趟：前 i+1 个元素局部有序，后面原封不动。
  • 快排一趟：某个元素到了最终位置，它左边全比它小、右边全比它大。
  • 堆排一趟：最大元素到了末尾。

5.3 各排序补充要点

  • 快排：每趟以枢轴为界划分。序列已有序（正序/逆序）时退化到 O(n²)，这是最常考的"最坏情况"。
  • 堆：大顶堆（父 ≥ 子）用于升序排序。建堆从最后一个非叶节点 ⌊n/2⌋ 开始向前调整。
  • 外部排序：数据太大放外存时用多路归并，败者树/最佳归并树（哈夫曼思想）减少 I/O，选择题考过概念。

5.4 三种过程亲手走一遍（"给中间过程判算法"靠它，建堆过程几乎年年考）

5.2 教的是"看特征认算法"，这一节把三种最容易考的过程完整走一遍。考场上要么给你中间过程问算法，要么问"建堆后的序列是什么"，都得靠手上熟练。

快速排序一趟（挖坑法，枢轴取第一个元素）

要解决的问题：怎么用一个元素（枢轴 pivot）把序列切成"左小右大"两半？

做法（左右双指针 + 挖坑）：枢轴先"存起来"，它原来的位置就成了一个空坑，然后

  1. 右指针从右往左找"比枢轴小"的元素，找到就填进左边的坑（它自己原来的位置变成新坑）；
  2. 左指针从左往右找"比枢轴大"的元素，找到就填进右边的坑；
  3. 左右指针相遇时，把枢轴填进最后的坑——枢轴到此彻底归位，左边全比它小、右边全比它大。

序列 [52, 49, 80, 36, 14, 58, 61, 97, 23, 75] 走一趟（枢轴 = 52）：

1 右指针左移找第一个 < 52 的：23（9 号位）→ 填进 1 号坑 [23, 49, 80, 36, 14, 58, 61, 97, _ , 75] 9
2 左指针右移找第一个 > 52 的：80（3 号位）→ 填进 9 号坑 [23, 49, _ , 36, 14, 58, 61, 97, 80, 75] 3
3 右指针继续左移（75、97、61、58 都 > 52），找到 14（5 号位）< 52 → 填进 3 号坑 [23, 49, 14, 36, _ , 58, 61, 97, 80, 75] 5
4 左指针右移（14、36 都 < 52）走到 5 号位与右指针相遇 → 把 52 填进 5 号坑，结束 [23, 49, 14, 36, 52, 58, 61, 97, 80, 75] —

结果：23 49 14 36 | 52 | 58 61 97 80 75 —— 52 落在第 5 位（说明原序列里比它小的恰好 4 个），左半边 4 个数全 < 52 ✓、右半边 5 个数全 > 52 ✓。

★ 判算法的唯一依据：一趟之后枢轴 52 到了它的最终位置。左半区内部谁先谁后，不同教材的交换次序不一样，不必和上表完全一致——所以 5.2 才强调"判别靠枢轴归位 + 两侧大小关系，不必精确模拟每步交换"。

反例前置：选项里若出现"52 还在第 1 位附近"（前面没有 4 个比它小的数），或它左边混进了 > 52 的数，直接排除，不用算。

建堆完成，堆的层序（即数组形态）：97, 76, 65, 38, 49, 13, 27。 自检口诀：逐个检查"父 ≥ 左右孩子"——97 ≥ 76、65 ✓；76 ≥ 38、49 ✓；65 ≥ 13、27 ✓，全过 → 合法大顶堆。

接着取堆顶（第一趟）：堆顶 97 是最大值，与最后一个元素 27 交换（97 归位到数组末尾，从此不再参与），再让 27 从堆顶往下沉：

交换 97 与末尾的 27：              27 下沉：先与 76 换（76 是孩子里最大的），
        27                             49 是 27 换位后孩子们里更大的 → 再与 49 换
      /    \                          → 最终：
    76      65                            76
   /  \    /                            /    \
  38  49  13                          49      65
                                     /  \    /
                                    38  27  13

第一趟结束：已归位的部分是 97（数组末位），剩下的堆是 76, 49, 65, 38, 27, 13（自检：76 ≥ 49、65 ✓；49 ≥ 38、27 ✓；65 ≥ 13 ✓）。重复"换堆顶、下沉调整"共 n−1 趟，就得到升序序列。

易错点：

  • 建堆是从 ⌊n/2⌋ 往前调（自下而上、从后往前），不是从根往下；顺序反了结果就不是堆。
  • 一次交换后，被换下来的小元素往往还要继续往下沉（如 ③ 里的 49、第一趟里的 27），只换一次就收工是错的。
  • 大顶堆排出升序、小顶堆排出降序，别记反。

归并排序的三趟（2 路归并）

规则：把序列看成 n 个长度为 1 的有序段，两两合并成更大的有序段，段长翻倍，重复到只剩一段。

序列 [49, 38, 65, 97, 76, 13, 27]：

趟 分组情况 合并后的序列
第 1 趟 [49][38]、[65][97]、[76][13]、[27] 38 49／65 97／13 76／27 → 38 49 65 97 13 76 27
第 2 趟 [38 49][65 97]、[13 76][27] 38 49 65 97／13 27 76 → 38 49 65 97 13 27 76
第 3 趟 两段合并 13 27 38 49 65 76 97 ✓
  • 趟数 = ⌈log₂n⌉：n=7 → ⌈log₂7⌉ = 3 趟 ✓（与 5.1 表里那句"n 个元素归并趟数 = ⌈log₂n⌉"一致）。
  • 判算法的特征：中间过程"有序段成对出现、段长 1→2→4 翻倍"，而整体并未有序。
  • 归并过程不需要交换，只按段拷贝，但需要 n 长度的辅助数组 → 空间 O(n)，这是它空间代价最大的原因。

小结：三种过程一眼认——

  • 快排：某个元素归位 + 左小右大；
  • 堆排：先是一个合法堆（父 ≥ 子），再看到"最大值跑到了末尾"；
  • 归并：有序段长度翻倍地两两合并。

第六节 算法设计与分析基础

6.0 先补两件基础：算法的五个特性、好算法的标准

算法的五个特性（选择题原话考，五个字要背准）：

特性 含义 反例（哪个不满足）
有穷性 执行有穷步之后必须结束 "不断重复直到满足条件"若永不满足就不算算法
确定性 每条指令含义唯一、无歧义 x = 随机数 不算（结果不确定）
可行性 每步都能用基本运算有限次实现 "求 π 的精确值"不可行
输入 有 0 个或多个输入 "无输入的算法"是合法的（如打印一行字）
输出 至少一个输出 没有任何输出的不能叫算法

易错点：输入可以是 0 个，输出至少 1 个——这两个数字经常被互换着考。程序与算法的区别也只在这条：程序可以不满足有穷性（操作系统就是一个"永不结束"的程序），算法必须满足。

好算法的标准：正确性、可读性、健壮性（对非法输入能处理）、高效性（时间与空间）。题干问"评价算法优劣主要看什么"→ 正确性 + 效率。

6.1 五大算法策略（选择题常考"这是哪种策略"）

策略 核心思想 典型例子
分治法 拆成互相独立的子问题，分别解再合并 二分查找、归并排序、快排、汉诺塔、大整数乘法
动态规划 子问题重叠，用表保存子问题的解（自底向上），要求最优子结构 矩阵连乘、最长公共子序列、0-1 背包、LIS、Fibonacci
贪心法 每步取当前最优，不回溯，不保证全局最优 Prim、Kruskal、Dijkstra、哈夫曼、部分背包
回溯法 深搜 + 试探 + 走不通就退回来（可剪枝） N 皇后、迷宫、子集和、图着色
分支限界 广搜式搜索 + 用"界限"剪枝 旅行商问题（TSP）

★ 动态规划 vs 分治：分治的子问题互相独立（算左边不用管右边）；动态规划的子问题重叠（同一个子问题会被反复用到），所以要用表存下答案避免重复计算。这也是 DP 比"朴素递归"快的唯一原因——比如求 Fibonacci，朴素递归是 O(2ⁿ)，加了记忆表就是 O(n)。 ★ 贪心 vs 动态规划：贪心只走一条路、走了不回头；动态规划考察所有子问题再取最优。所以贪心快但可能错，DP 稳但要多花空间。

动态规划的四个要件（题目问"能否用 DP"时拿这四条对）：最优子结构（大问题的最优解由小问题的最优解拼成）、重叠子问题、状态与状态转移方程、无后效性（当前状态一旦确定，不受后面怎么决策影响）。

下面把五个策略各配一个能亲手算的小例子，考试时要能"给代码说策略、给策略说思路"。

分治：汉诺塔（把"分治"算到底）

规则：n 个盘子从 A 柱移到 C 柱，一次只能挪一个，且任何时候大盘不能压在小盘上。

分治三步：

  1. 分：把"n 个盘子从 A 到 C"拆成三件事：先把上面 n−1 个从 A 挪到 B（中转柱）；
  2. 治：把最大的第 n 个盘从 A 直接挪到 C（就这一下）；
  3. 合：再把 B 上的 n−1 个挪到 C。

递推式：T(n) = 2·T(n−1) + 1，边界 T(1) = 1。

  • 代入算例：T(1)=1 → T(2)=2×1+1=3 → T(3)=2×3+1=7 → T(4)=15……
  • 通项：每次"翻倍再加一"，答案就是 T(n) = 2ⁿ − 1（n=3 时 7 ✓，n=4 时 15 ✓）。
  • 它说明什么：n=64 时约 1.8×10¹⁹ 次——指数级增长的可怕，这就是"O(2ⁿ) 不可做"的直观来源。选择题问"汉诺塔的时间复杂度"答 O(2ⁿ)。

动态规划：0-1 背包（把表亲手填一遍）

问题：背包容量 5，3 件物品（每件只能整个拿或不拿）：A 重 2 值 3、B 重 3 值 4、C 重 4 值 5。求能装的最大价值。

状态：dp[i][j] = 只考虑前 i 件物品、容量为 j 时的最大价值。 状态转移方程（★ 必背）：

dp[i][j] = max( dp[i-1][j] ,                    ← 不放第 i 件
                dp[i-1][j - w[i]] + v[i] )      ← 放第 i 件（前提：j ≥ w[i]）

含义："要么不要它（继承上一行同列），要么要它（腾出 w[i] 的容量，再加上它的价值）"——两者取大。

填表（行 = 只考虑前 i 件，列 = 容量 j 从 0 到 5）：

j=0 j=1 j=2 j=3 j=4 j=5
i=0（无物品） 0 0 0 0 0 0
i=1（只有 A：w2 v3） 0 0 3 3 3 3
i=2（加入 B：w3 v4） 0 0 3 4 4 7
i=3（加入 C：w4 v5） 0 0 3 4 5 7

读答案：dp[3][5] = 7。 反向追出"拿了哪几件"（考点：DP 不只给数值，还能回溯方案）：

  • dp[3][5] = 7 等于 dp[2][5] = 7 → C（第 3 件）没拿；
  • dp[2][5] = 7 = dp[1][5−3] + 4 = 3 + 4 → 拿了 B；
  • dp[1][2] = 3 = dp[0][2−2] + 3 = 0 + 3 → 拿了 A。 → 最优方案 = {A, B}，重量 2+3=5 恰好装满、价值 7 ✓（与表格一致）

易错点：

  • 填表顺序是逐行从左到右（每格只依赖上一行和本行左边的格子），手算时别跳行。
  • j < w[i] 的格子不能"放"，只能继承上一行——初学者最爱在这里瞎算。
  • 时间复杂度 O(n·C)（物品数 × 容量），不是多项式时间里的"n 的多项式"（C 是数值，所以叫伪多项式）。
  • 0-1 背包的滚动数组写法：把二维压成一维 dp[j] 时 j 必须从大到小遍历（否则同一件物品会被重复拿，变成"完全背包"）。这个"从大到小"是案例题的高频空。

贪心：两个反例（说明"贪心为什么不一定最优"）

反例 1——找零钱：面额 {1, 3, 4}，要凑出 6。

  • 贪心的做法：每次拿不超过剩余金额的最大面额 → 拿 4 → 剩 2 → 拿 1 → 拿 1 → 3 枚。
  • 最优解：3 + 3 = 6 → 2 枚。贪心错了 ✓

反例 2——0-1 背包：容量 10，物品 A(重 8 值 80)、B(重 5 值 49)、C(重 5 值 49)。

  • 贪心按"单位价值"排：A 每单位 10 最高 → 先拿 A → 剩余容量 2，B、C 都放不下 → 总价值 80。（B 9.8、C 9.8）
  • 最优解：拿 B + C，重量 5+5=10，价值 49+49 = 98 > 80。贪心又错了 ✓

为什么"部分背包"贪心就对：如果物品可以切碎（比如装金粉），那容量 10 时拿 A(8) 后还能再装 2 单位的 B → 价值 80 + 49×2/5 = 99.6，反而超过了只拿 B+C 的 98，贪心确实最优。 结论（考点）：背包问题可以分割时用贪心，不可分割（0-1）时必须用动态规划。这一句是贪心与 DP 分界线的标准考法。

为什么 Prim/Kruskal/Dijkstra/哈夫曼贪心对：它们的问题结构有"拟阵"性质或特殊性质，能保证局部最优能拼出全局最优——考试不必证明，记住这四个是"贪心但正确"的就行。

回溯：N 皇后（DFS + 剪枝）

问题：n×n 棋盘放 n 个皇后，任意两个不同行、不同列、不同斜线。

回溯的骨架（一段伪代码背下来，案例题填空就是它）：

放第 row 行：
    for 每一列 col:
        若 (row, col) 不冲突:
            摆上皇后            ← 试探
            若 row == n: 输出一个解
            否则 放第 row+1 行   ← 递归深入
            撤掉皇后            ← 回溯（关键！恢复现场）
  • 试探 → 深入 → 撤回三步循环，就是"一条路走到黑，走不通退回来换条路"。
  • 剪枝：一旦当前摆法已经冲突，立刻停（不再往下递归），省掉整棵子树。剪枝越狠越快。
  • 4 皇后只有 2 个解（选择题考过"n=4 时解的数量"）；8 皇后 92 个解。
  • 回溯与图遍历的关系：回溯 = 在"状态空间树"上做 DFS。3.2 节的 DFS 是它在图上的特例，本节是它在"所有可能的选择组合"上的推广——所以两者都用递归 + 恢复现场。
  • 子集和问题：从一堆数里挑出若干使和 = 目标值；做法就是"每个数选择拿/不拿两分支"的 DFS，和 0-1 背包的搜索版同族。

分支限界 vs 回溯（一字之差）

回溯法 分支限界法
搜索方式 深度优先（一条路走到底） 广度优先（一层层扩）
剪枝依据 约束条件（不合法就停） 界限函数（当前活结点若"不可能比已知最优更好"就砍）
目标 找出所有可行解 / 任意一个解 通常求最优解
典型 N 皇后、迷宫、图着色 旅行商问题（TSP）、0-1 背包最优化

记法：回溯很深、限界很广；回溯看"合不合法"、限界看"划不划算"。

6.2 时间复杂度（必考 1–2 题）

常见复杂度从小到大：O(1) < O(log n) < O(n) < O(nlog n) < O(n²) < O(n³) < O(2ⁿ) < O(n!)

怎么"数"出来（不用背公式，数循环）：

  • 单层循环 n 次 → O(n)。
  • 两层嵌套、各 n 次 → 乘起来 O(n²)。三层 → O(n³)。
  • 循环变量每次 ×2 或 ÷2 → 只跑 log₂n 次 → O(log n)。例：for (i=1; i<=n; i*=2) 是 log₂n 次。
  • 一外一内：外 ×2 内 n → O(nlog n)（这就是归并/快排的来源）。
  • 递归：看递推式——T(n)=2T(n−1)+1（汉诺塔）→ O(2ⁿ)；T(n)=2T(n/2)+n（归并）→ O(nlog n)；T(n)=T(n/2)+1（二分）→ O(log n)。
  • 暴力枚举子集/全排列 → O(2ⁿ)、O(n!)。

对照表（考前扫一眼）：

代码特征 复杂度
三条语句、无循环 O(1)
for i=1..n O(n)
for i=1..n 套 for j=1..n O(n²)
while (i<n) i*=2; O(log₂n)
外层 i*=2、内层 j 跑 n O(nlog₂n)
汉诺塔 T(n)=2T(n−1)+1 O(2ⁿ)

★ 渐近记号：O 是上界（增长率不超过 f(n) 的量级）、Ω 是下界、Θ 是精确界（上下界同阶）。选择题常考"O(f(n)) 的含义：增长率不超过 f(n) 的量级"。 易错点：O(2n) 就是 O(n)、O(n²+n) 就是 O(n²)——常数系数和低阶项都要扔掉，只留增长最快的项。

6.3 空间复杂度与递归

  • 空间复杂度看的是额外开销：几个临时变量是 O(1)；开一个长度 n 的数组是 O(n)。
  • 递归的空间 = 递归深度 × 每层开销：快排平均递归深度 log₂n → 空间 O(log₂n)；最坏（已有序）深度退化为 n → 空间 O(n)（第 5.1 节的表里那一列就是这么来的）；归并排序要一个 n 长度的辅助数组 → O(n)。
  • 递归的两面：写起来简洁（树遍历、汉诺塔、回溯全靠它），代价是栈空间和函数调用开销。想改成迭代，就用自己维护的栈（3.2 节 DFS 的栈实现就是这个道理）。
  • 递归三要素（案例题挖空必考）：① 边界条件（什么情况下直接返回）；② 递推式（大问题怎么用小问题表达）；③ 返回值/现场恢复。缺边界条件 → 无限递归 → 栈溢出。

第七节 案例题专攻：算法填空解题套路（约 15 分）

案例第 4 题一般是「一段说明 + C 代码（或伪代码）+ 3～5 个空 + 1 小问」，常考：动态规划、贪心、回溯、字符串处理、链表/树操作。套路如下：

套路一：先读说明再读代码，说明就是答案说明书

题干「说明」部分会用文字描述算法步骤，例如"第 3 步：若 a[i] 大于当前最大值，则更新最大值"。空基本就藏在文字步骤对应的代码行上，照着文字填代码。

套路二：看空的位置判断要填什么

  1. 空在初始化处：常填 0、1、-1、INT_MAX 或数组首元素 a[0]。
  2. 空在循环条件：看循环变量和边界，i < n、j > 0，或动态规划的 i <= n。
  3. 空在 if 内部更新处：动态规划常填递推式 dp[i] = dp[i-1] + xxx；求最大值常填 maxv = a[i]。
  4. 空在递归调用：填递归式，参数看函数定义对应着填，注意返回值 return f(...)。
  5. 空在 return：动态规划常填 dp[n] 或 dp[m][n]。

套路三：代入一个具体例子验证

填完后，用一个 n=2 或 n=3 的小例子手动模拟整段代码，能跑通且结果符合说明，基本就对了。

常见考题模板速记

  • 0-1 背包：dp[i][j] = max(dp[i-1][j], dp[i-1][j-w[i]] + v[i])，j 从大到小滚动数组。
  • 最长公共子序列：字符相等 dp[i][j]=dp[i-1][j-1]+1，否则 max(dp[i-1][j], dp[i][j-1])。
  • Fibonacci / 爬楼梯：f[i] = f[i-1] + f[i-2]。
  • 链表插入：s->next = p->next; p->next = s;（顺序不能反）。
  • 链表删除：p->next = p->next->next;。
  • 二叉树递归遍历：visit(root); f(root->left); f(root->right); 按序对应前中后序。

  • (2) BFS 序列：1 2 3 4 5 队列过程：[1] → 访问 1，2、3 入队 [2,3] → 访问 2，4 入队 [3,4]（3 已在队，不重复入队）→ 访问 3，5 入队 [4,5] → 访问 4（2、5 都已访问/在队）→ 访问 5（3、4 都已访问）。 注意 BFS 与 DFS 只差最后两位：BFS 是"按层"，4 在第 3 层、5 在第 4 层，所以 4 先出；DFS 是一条路走到底，先顺着 3→5 钻下去再回头找 4。
  • (3) 边数 e = 6；度数之和 = 2+3+3+2+2 = 12 = 2e ✓（度数依次为 1 号 2、2 号 3、3 号 3、4 号 2、5 号 2）；该图只有 1 个连通分量（任意两点都能互相到达，是连通图）。 易错点：别漏掉"度数之和一定是偶数"这条自检——若数出来是 11，说明数错了。
