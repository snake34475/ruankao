第 1 题 · 权限收回

课后 12✓ 对
题目
下列 SQL 语句中，用于收回用户权限的是（ ）。　A. GRANT　B. REVOKE　C. DENY　D. DROP
你的答案
B
正确答案
B（REVOKE）

解析　GRANT 授予、REVOKE 收回。口诀：GRANT 用 TO 给出去，REVOKE 用 FROM 收回来。DROP 是删除对象（DDL），DENY 不是软考教材的标准关键词。

第 2 题 · 聚合条件的位置

课后 11✓ 对
题目
实现「查询每门课程的课程号和平均成绩，只保留平均分 80 分以上（含）」的关键子句是（ ）。
A. WHERE AVG(成绩) >= 80　B. HAVING AVG(成绩) >= 80　C. ORDER BY AVG(成绩)　D. GROUP BY 成绩
你的答案
B
正确答案
B

解析　聚合条件只能进 HAVING：GROUP BY 课程号 HAVING AVG(成绩)>=80。A 里 WHERE 比分组先执行，那时 AVG 还没算出来，语法直接报错。这是本课第一高频扣分点。D 把成绩当分组列，会把每个分数各成一组，不符合「按课程」。

第 3 题 · 这是什么并发错误

课后 13✗ 错
题目
事务 T1 修改了数据 A 但尚未提交，事务 T2 读取了 A 的修改值，随后 T1 执行回滚。T2 读到的数据称为（ ）。
A. 丢失的数据　B. 不可重复读的数据　C. 脏数据　D. 幻影数据
你的答案
A（丢失的数据）
正确答案
C（脏数据）

错因　你抓到的现象是「读到的值后来没了」，于是归到「丢失」。但两类错误的分界锚点在最后一步动作。

丢失修改：关键字是「写被写覆盖」——两个事务都写回、都提交了，后写的把先写的盖掉。

读脏数据：特征字是「读到一个从未生效的值」——读的时候对方还没提交，读完对方 ROLLBACK，这个值被作废。

判别锚点：改值者 ROLLBACK → 脏读；改值者 COMMIT → 不可重复读。

本题里 T1 最后是 ROLLBACK，读到的 200 从未生效过，所以是脏读。

第 4 题 · 两段锁协议

课后 14✓ 对
题目
关于两段锁协议，下列说法正确的是（ ）。
A. 保证并发执行不会死锁　B. 保证调度可串行化，但不能避免死锁　C. 保证不会产生读脏数据　D. 要求事务任何时刻都可先加锁再解锁交替进行
你的答案
B
正确答案
B

解析　两段锁把事务切成「先只加锁、后只放锁」两段，保证可串行化；但两个事务可能各持一把对方要的锁（T1 锁 A 等 B、T2 锁 B 等 A），形成循环等待，挡不住死锁。A 是典型错误项。C 错在隔离级别与脏读是另一套机制。

第 5 题 · 未完成事务怎么恢复

课后 15✗ 错
题目
系统故障恢复时，对尚未完成的事务应执行（ ）。　A. REDO　B. UNDO　C. COMMIT　D. ROLLBACK
你的答案
不确定是 B 还是 A
正确答案
B（UNDO）

解析　这题只有一句话的记忆出口：已提交 → REDO，未提交 → UNDO。

恢复时扫日志只看两件事：BEGIN 后面有没有 COMMIT。题目说「尚未完成」，就是只有 BEGIN 没有 COMMIT，是半成品，必须撤销抹掉。A（REDO）方向正好反了——它是给已完成、结果该留存的事务用的。D 的 ROLLBACK 是事务运行期间的主动回滚操作，不是恢复策略本身。

第 6 题 · 锁相容矩阵

补充 6✓ 对
题目
事务 T1 已对数据 A 加 S 锁。此时 T2 对 A 的哪种申请可以立即获准？
A. 只可申请 S 锁　B. 只可申请 X 锁　C. S、X 都可　D. S、X 都不可
你的答案
A
正确答案
A

解析　相容矩阵里只有 S-S 这一个格子是「相容」。已有 S 锁，再加 S 锁允许（一起读），加 X 锁必须等（读写互斥）。记住唯一相容格即可。

第 7 题 · 幻读还是不可重复读

补充 7✗ 错
题目
T1 两次执行相同的范围查询，期间 T2 插入一条满足条件的记录并提交，导致第二次多出一行。这属于（ ）。
A. 丢失修改　B. 读脏数据　C. 不可重复读　D. 幻读
你的答案
C（不可重复读）
正确答案
D（幻读）

错因　不可重复读和幻读都叫「两次结果不同」，区别在对象：

不可重复读：同一行的字段值被改了（读 A 得 100，再读 A 得 200）。

幻读：满足条件的行数增减了（范围查得 3 行，再查得 4 行）。

口诀：同一行变是前者，结果集增减行是后者。

题干是「插入一条满足条件的记录」导致结果集多一行，属于行数变化，故选 D。

第 8 题 · 两种错误分别是什么

精华 7✓ 对
题目
「某个事务对同一数据的两次读取结果不同」与「读到未提交的数据」分别对应哪类并发错误？并说明区分的依据。
你的答案
前者不可重复读，后者脏读。依据：T1 先读到 100，T2 把 A 提交为 200，T1 再读发现变了，所以不能重复读。
正确答案
前者不可重复读，后者读脏数据；依据是干扰事务「提交没有」

解析　两个词都对，依据也基本对。补一处精确表述：不可重复读要求干扰事务提交了（你举的 T2 commit 200 正是如此）；脏读是干扰事务未提交、随后回滚。你的区分依据成立。

第 9 题 · 相关 EXISTS 子查询

补充 5△ 半对
题目
针对 Student(Sno, Sname, Dept)、SC(Sno, Cno, Grade)，把「查询选修 C02 的学生姓名」写成相关 EXISTS 子查询，并说明关联条件为何不能省略。
你的答案
SELECT S.Sname
FROM Student AS S
WHERE exit(                       -- ✗ 关键字拼写错，应为 EXISTS
    SELECT 1
    FROM SC
    WHERE SC.Sno = S.Sno
      AND SC.Cno = "C02"          -- ✗ 应为单引号 'C02'
);

并说明：省掉关联条件 SC.Sno = S.Sno 后，只要有一个学生选了 C02，就会返回所有学生。但不知道为什么会这样。

正确答案
SELECT S.Sname
FROM Student AS S
WHERE EXISTS (
    SELECT 1
    FROM SC
    WHERE SC.Sno = S.Sno
      AND SC.Cno = 'C02'
);

问题一：逻辑骨架全对，SELECT 1、FROM SC、关联条件、EXISTS 结构都对。两处扣分是小硬伤：

  • exit 应为 EXISTS——SQL 里没有 exit，这样写直接语法报错。
  • "C02" 应为 'C02'——标准 SQL 里双引号是标识符名，字符串常量一律用单引号，考试按单引号写才稳。

问题二：为什么省掉关联条件会返回全体

EXISTS 是逐行检查的：WHERE EXISTS (...) 是拿外层的每一行去问子查询「这一行在 SC 里配得上吗」。SC.Sno = S.Sno 就是那个「随外层行移动的指针」——它把子查询和「当前这个学生」绑在一起，问的是「你选了吗」。

一旦这截断掉，子查询问的对象就不再跟着外层的行走，退化成一句与当前学生无关的固定判断：「SC 里有没有任何一行 Cno='C02'」。只要全校有一个人选了 C02，这句就恒为真，于是外层每个学生都被保留，返回全校。

一句话记住：关联子查询里的关联条件，就是那根「随外层行移动的指针」，省不得。

第 10 题 · 丢失修改的终值

精华 5✓ 对
题目
设 A 初值为 50。T1：读 A，A←A+20，写回；T2：读 A，A←A×2，写回。若两事务并发执行且发生「丢失修改」，最终 A 的值可能错误地变成多少？正确值应为多少？
你的答案
可能变成 70 或 100；正确值看顺序，先 T1 是 140，先 T2 是 120
正确答案
错误终值 70 或 100（一个写被覆盖）；正确终值 140（先 T1 后 T2）或 120（先 T2 后 T1）

解析　完全正确。丢失修改 = 一个事务的写被另一个事务的写覆盖，所以哪种正确结果都得不到。

  • 错误终值举例：T1 读 50 → T2 读 50 → T1 写回 70 → T2 写回 100，T1 的 +20 被覆盖；或 T2 先写 100、T1 再写 70，则 T2 的结果丢失。
  • 正确终值：先 T1 后 T2 = (50+20)×2 = 140；先 T2 后 T1 = 50×2+20 = 120。

第 11 题 · 故障类型与恢复动作

补充 8✓ 对
题目
系统日志中 T1 已出现 COMMIT，T2 只有 BEGIN 和更新记录；随后主机断电，但磁盘未损坏。问：故障类型及恢复动作。
你的答案
系统故障；T2 做 UNDO，T1 做 REDO
正确答案
系统故障；REDO T1、UNDO T2

解析　完全正确。断电但磁盘未损坏属于系统故障（不是介质故障——「磁盘磁头损坏导致数据文件不可读」才是介质故障，那需要先有备份打底）。T1 已提交，结果必须保留 → REDO；T2 未提交，半成品必须消失 → UNDO。反向核对语义：恢复后只应体现已提交事务。

第 12 题 · 三小问：嵌套查询 / 分组统计 / 授权

精华 6✗ 错（第 2 小问）
题目
(1) 查询选修了「C02」课程的学生姓名（用嵌套查询）；
(2) 查询选修课程门数超过 3 门的学生学号；
(3) 把查询 SC 表的权限授予用户 U1，并允许其转授。
你的作答

(1) 同第 9 题的 EXISTS 写法（结构对，拼写错）。

(2) SELECT Sno FROM SC
    GROUP BY Cno              -- ✗ 分组列选错
    HAVING Cno > 3;          -- ✗ 裸列不能与数字比较
(3) GRANT SELECT ON SC TO U1 WITH GRANT OPTION;
    REVOKE SELECT ON SC FROM U1;
正确答案
-- (1)
SELECT S.Sname
FROM Student AS S
WHERE EXISTS (
    SELECT 1 FROM SC
    WHERE SC.Sno = S.Sno AND SC.Cno = 'C02'
);
-- 等价写法
SELECT Sname FROM Student
WHERE Sno IN (SELECT Sno FROM SC WHERE Cno = 'C02');

-- (2)  ← 本小问的关键
SELECT Sno FROM SC
GROUP BY Sno HAVING COUNT(Cno) > 3;

-- (3)
GRANT SELECT ON SC TO U1 WITH GRANT OPTION;

第 (1) 小问：逻辑对，扣分同第 9 题（exit、双引号）。用 IN 写也行，两种都是标准答案。

第 (2) 小问：全题最需要记的一处，两处错叠在一起：

  • 分组粒度选错：题干要「每个学生选了几门课」，粒度是学生，分组列必须是 Sno。写 Cno 就变成了「每门课」，整句意思跑偏。
  • HAVING 里用了裸列：分组后每组是一捆行，裸的 Cno 代表不了整组的一个值；要数行数，得用聚合函数 COUNT(Cno)。

认题方法：题干说「每个 X 的门数／平均分／人数」，GROUP BY 就写 X，组条件用聚合函数包住要统计的列。

第 (3) 小问：两句都对。WITH GRANT OPTION 是「允许转授」的固定写法，REVOKE ... FROM 收回也对。介词记牢：给出去用 TO、收回来用 FROM。

第 13 题 · 案例综合：建表 / 三表聚合 / 建视图

案例题·问题 3✗ 错（三小问）
题干
已知表：代表团(团编号, 团名, 团所在地)、运动员(运动员编号, 姓名, 团编号)、 比赛项目(项目编号, 项目名称)、参赛(运动员编号, 项目编号, 成绩)。用 SQL 完成：
  1. 建立参赛表（含主键与外键约束）；
  2. 查询每个代表团的团名及该团运动员所获成绩的总和，只保留总分 300 分（含）以上的代表团；
  3. 建立视图 vHighScore，显示成绩在 95 分（含）以上的运动员编号、姓名和项目名称。

(1) 建参赛表　✗

你的作答
CREATE TABLE 参赛 (
  运动员编号 char(8)              -- ✗ 缺逗号
  项目编号 char(8)                -- ✗ 缺逗号
  成绩 SMALLINT
  PRIMARY KEY (运动员编号，项目编号)   -- ✗ 顿号应为英文逗号
  FOREIGN KEY (运动员 REFRENCE 运动员(运动员编号))  -- ✗ 三段式写坏、拼写错
  FOREIGN KEY (项目编号 REFRENCE 比赛项目(项目编号))
  CHECK (成绩 BETWEEN 0 AND 100)
)
正确答案
CREATE TABLE 参赛 (
    运动员编号 CHAR(8),
    项目编号   CHAR(6),
    成绩       SMALLINT,
    PRIMARY KEY (运动员编号, 项目编号),
    FOREIGN KEY (运动员编号) REFERENCES 运动员(运动员编号),
    FOREIGN KEY (项目编号)   REFERENCES 比赛项目(项目编号),
    CHECK (成绩 BETWEEN 0 AND 100)
);

批注　主要硬伤：① 列定义之间缺逗号；② 主键里用了中文顿号「，」；③ 外键三段式写坏——漏了列名的「编号」，REFERENCES 拼错成 REFRENCE（少一个 S）。固定格式是 FOREIGN KEY (本表列名) REFERENCES 表名(被引列名)，列名写完整。CHECK 那行题目没要求，你加了属于加分不影响，保留没问题。

(2) 三表聚合　✗

你的作答
SELECT 团名，成绩                    -- ✗ 中文逗号；成绩不在代表团表
FROM 代表团
WHERE 团编号 IN （                  -- ✗ 中文括号；三表完全没连接
   SELECT 团编号，SUM(成绩)          -- ✗ IN 子查询只能出一列
   FORM 运动员                       -- ✗ FORM 拼写
   WHERE (
       SELECT 运动员编号，成绩
       FROM 参赛
   )
   GROUP BY 团编号
   HAVING SUM(成绩)>300            -- ✗ 「含」应为 >=
);
正确答案
SELECT 代表团.团编号, 代表团.团名, SUM(参赛.成绩) AS 总分
FROM 代表团
JOIN 运动员 ON 代表团.团编号 = 运动员.团编号
JOIN 参赛   ON 运动员.运动员编号 = 参赛.运动员编号
GROUP BY 代表团.团编号, 代表团.团名
HAVING SUM(参赛.成绩) >= 300;

批注　四个问题叠在一起：

  • 成绩取错表：成绩在「参赛」表里，不在代表团表里，SELECT 团名, 成绩 直接拿不到。
  • 三张表没连接：数据要沿 代表团 → 运动员 → 参赛 逐段 join 才能凑齐，你这里三张表完全没连起来。
  • IN 子查询出了两列：IN 后面的子查询只能出一列（它是拿去做成员判断的集合）。这题本来就不该用子查询，用 JOIN + GROUP BY 直接做。
  • 区间写错：「300 分（含）以上」是闭区间，要写 >= 300，写 > 300 丢掉了等于，正好丢分。

另外 GROUP BY 带上团编号，是防止两个代表团重名被并成一组。

看一下这句查出来的结果长什么样（用一组小数据验证，「300 分含」按 >=300 取）：

团编号团名该团成绩明细总分是否入选
T1飞鹰96, 88, 90, 92366✓ ≥300
T2蓝鲸85, 78, 100, 95358✓ ≥300
T3雪豹6060✗ 出局

最终 SELECT 只出 T1 飞鹰 366、T2 蓝鲸 358 两行——注意这里的「总分」是把该团所有运动员的多条参赛记录全部相加，不是只算一个人的。

(3) 建视图　✗

你的作答
CREATE VIEW vHighScore AS （      -- ✗ AS 后不能加括号
  SELECT 运动员编号, 姓名, 项目名称   -- ✗ 姓名不在比赛项目表
  FROM 比赛项目                     -- ✗ 起点选错
  WHEHE exit(                       -- ✗ WHERE 拼写；嵌套 EXISTS 替代不了连接
     SELECT 1 FROM 运动员 WHERE exit(
        SELECT 1 FROM 参赛
        WHERE 比赛项目.项目编号 = 项目编号   -- ✗ 自等，没有桥接
          AND 运动员.运动编号 = 运动编号
          AND 成绩>95 )                   -- ✗ 「含」应为 >=
  )
)
正确答案
CREATE VIEW vHighScore AS
SELECT 运动员.运动员编号, 运动员.姓名, 比赛项目.项目名称
FROM 运动员
JOIN 参赛     ON 运动员.运动员编号 = 参赛.运动员编号
JOIN 比赛项目 ON 参赛.项目编号 = 比赛项目.项目编号
WHERE 参赛.成绩 >= 95;

批注　三处问题：

  • 格式：CREATE VIEW ... AS 后面直接接 SELECT，不加括号；把整句套进括号是 0 分硬伤。另外 WHEHE 是 WHERE 的拼写错。
  • 列名归属搞反：视图要显示「运动员编号、姓名、项目名称」，这三个列分属运动员表和比赛项目表，你却把 FROM 比赛项目 打头，姓名根本不在那张表里。
  • 双嵌套 EXISTS 替代不了连接，里层的关联条件写成了自己等于自己，没有桥接作用。

建视图的固定骨架是 CREATE VIEW 视图名 AS 查询语句;——视图本身不存数据，只是把一条 SELECT 起名存起来。本题要跨三张表，就沿「运动员 → 参赛 → 比赛项目」逐段 JOIN。

本轮第 4 题 · 相关 EXISTS 子查询

原第 9 题✓ 第二次提交通过
题目
针对 Student(Sno, Sname, Dept)、SC(Sno, Cno, Grade)，把「查询选修 C02 的学生姓名」写成相关 EXISTS 子查询，并说明关联条件为何不能省略。
第 1 次
SELECT S.Sname
FROM Student AS S
WHERE EXISTS (
    SELECT 1
    FROM SC
    WHERE S.Sno = Sno          -- △ 关联条件只写了单侧限定
      AND Cno = 'C02'
);

说明：省掉关联条件后，只要有一个学生选了 C02，就会返回所有学生。结论对，机理没写出来。

第 2 次
SELECT S.Sname
FROM Student AS S
WHERE EXISTS (
    SELECT 1
    FROM SC
    WHERE S.Sno = SC.Sno       -- ✓ 两侧都带前缀
      AND Cno = 'C02'
);

说明：外部每行都去询问子查询；没有关联条件，子查询就与外部无关，成了固定的句子，从而是个常量。

第 1 次的问题　S.Sno = Sno 能跑通，是因为 SQL 解析列名由内向外找：内层 FROM SC 里正好有 Sno，这个裸 Sno 被绑到 SC.Sno，整句等价于 S.Sno = SC.Sno。它靠「内层恰好有同名列」才成立：内层一旦改名，这个裸名就会指向外层，语义翻车；而且阅卷人一眼看不出关联关系，很可能按「没写关联条件」处理。关联条件两侧都要带表名或别名。

第 2 次　SQL 与说明都补到位了，机理说对。只差最后一环收口：这个「常量」若恒为真，外层每一行就都被保留，于是返回全校——把这句补上就是满分表述。

一句话记住：关联子查询里的关联条件，就是那根「随外层行移动的指针」。

有关联条件 → 外层每行得到不同答案；无关联条件 → 所有行共用同一个答案。

本轮第 5 题 · 三小问（嵌套查询 / 分组统计 / 授权）

原第 12 题✗ (2) 未过
题目
(1) 查询选修了「C02」课程的学生姓名（用嵌套查询）；
(2) 查询选修课程门数超过 3 门的学生学号；
(3) 把查询 SC 表的权限授予用户 U1，并允许其转授。
(1) 作答
SELECT S.Sname
FROM Student AS S
WHERE EXISTS (
    SELECT 1
    FROM SC
    WHERE S.Sno = SC.Sno
      AND Cno = 'C02'
);

✓ 对。关联条件两侧带前缀，EXISTS 与单引号都正确——上一轮的两处硬伤已修正。

(2) 第 1 次
SELECT Sno
FROM SC
GROUP BY Sno
HAVING COUNT(Cno>3)        -- ✗ 比较运算符写进了聚合函数的括号里

分组粒度已经对了（知道「每个学生」要按 Sno 分组），错在把 >3 塞进了 COUNT() 里：这样算出来的其实是「选过课的行数」，等价于把「超过 3 门」这个条件整个丢掉。

(2) 第 2 次
SELECT Sno
FROM SC
GROUP Sno                  -- ✗ 漏了 BY，语法报错
HAVING COUNT(Cno) >3       -- ✓ 比较运算符已在括号外

核心错误修正了，但 GROUP BY 漏了一个词，整句仍然是语法错误——这种「会做但写错」最亏。

(3) 第 1 次
GRANT SELECT ON SC TO U1 GRANT OPTIONS      -- ✗ 少了 WITH，OPTION 还加了 S
REVOKE SELECT FROM SC TO U1                 -- ✗ 对象与用户的介词全错位
(3) 第 2 次
GRANT SELECT ON SC TO U1 WITH GRANT OPTION;   -- ✓
REVOKE SELECT ON SC FROM U1;                  -- ✓（题干未要求，写对不扣分）

(2) 的正确写法　比较运算符必须在聚合函数的括号外面，模板固定为 HAVING 聚合函数(列) 运算符 数值：

SELECT Sno
FROM SC
GROUP BY Sno
HAVING COUNT(Cno) > 3;     -- COUNT(*) > 3 也对

括号里只放「要统计哪一列」，先数出每组的门数、再拿这个门数去比大小。同一处错误本轮在 (2) 和下面的第 6 题 (2) 各犯一次，是本轮最该掐掉的习惯。

(3) 的介词对照　对象永远跟 ON，用户是「给出去 TO、收回来 FROM」：

动作对象介词用户介词模板
授予ONTOGRANT 权限 ON 对象 TO 用户
收回ONFROMREVOKE 权限 ON 对象 FROM 用户

「允许转授」是固定短语 WITH GRANT OPTION——有 WITH、OPTION 是单数。

原第 13 题✗ 三小问均未过

(1) 建参赛表 · 三次提交　✗

第 1 次
CREATE TABLE 参赛表(
运动员编号 CHAR(8),
项目编号     CHAR(8),
成绩            SMALLINT,
PRIMARY KEY (运动员编号,项目编号),
FOREIGN (运动员编号) REFRENCES 运动员(运动编号),      -- ✗ 缺 KEY；拼写错；被引列名缺「员」
FOREIGN (项目编号) REFRENCES 比赛项目(项目编号)        -- ✗ 拼写错
)

进步：列定义之间的逗号、主键里的英文逗号都写对了（上一轮的格式硬伤已修）。

第 2 次
FOREIGN KEY (运动员编号) REFRENCES 运动员(运动员编号),  -- 补了 KEY 和「员」，拼写仍错
FOREIGN KEY (项目编号) REFRENCES 比赛项目(项目编号)      -- 拼写仍错
第 3 次
FOREIGN KEY (运动员编号) REFERENCES运动员(运动员编号),   -- ✓ 改对了（中间缺空格，不影响判分）
FOREIGN KEY (项目编号) REFRENCES 比赛项目(项目编号)       -- ✗ 错字从上一行「转移」到这一行

表名 参赛表 也一直未改回题干给的 参赛。

REFERENCES 记法：它由动词 refer 派生——refer + ence = reference，复数 references。读作 re-fer-ences 三个音节，REF 后面那个 e 是 refer 自带的。

REFRENCES（9 个字母，3 个 e）≠ REFERENCES（10 个字母，4 个 e）。

外键固定三段式：FOREIGN KEY (本表列名) REFERENCES 表名(被引表的列名)——三段缺一不可，被引列名要对着题干逐字核对。

另记一条考试习惯　同一个词在一句里出现两次时，改错只改了一处、另一处照旧（本例中错字还在两个外键行之间来回「转移」）。交卷前的自查要扫同类项是否全部改到，而不是改完一处就收工。

(2) 三表聚合　✗

作答
SELECT 代表团.团编号,代表团.团名,SUM(参赛.成绩) AS 总分
FROM 代表团
JOIN 运动员 ON 运动员.团编号 = 代表团.团编号
JOIN 参赛 ON 运动员.运动员编号 = 参赛.运动员编号 
GROUP BY 代表团.团编号,代表团,团名          -- ✗「代表团」是表名不是列名
HAVING SUM(参赛.成绩>=300)                 -- ✗ 比较运算符又写进了括号里

批注　骨架已经立住了：FROM 代表团 JOIN 运动员 JOIN 参赛 这条代表团 → 运动员 → 参赛 的逐段连接路径完全正确——上一轮这里三张表根本没连起来。剩下的两处：

  • 表名当列名：GROUP BY 代表团.团编号,代表团,团名 里的 代表团 是表名，不是列名，语法报错；应为 代表团.团名。
  • 比较运算符位置：SUM(参赛.成绩>=300) 与上一题 COUNT(Cno>3) 是同一个错，实际含义变成了「数一数有多少行成绩 ≥300」。应为 HAVING SUM(参赛.成绩) >= 300。

你问的「GROUP BY 明明写编号就够了，为什么还要加团名」——判断是对的。

加团名不是逻辑需要，而是语法规则：SELECT 里出现的每一个非聚合列，都必须出现在 GROUP BY 里。因为 SELECT 里选了 代表团.团名，所以分组依据里也要列上它；否则「团名」在组内不唯一，DBMS 不知道取哪一行的值。

而「防止两个同名代表团被并成一组」靠的是编号（它是主键，永远唯一），不是团名。两个都写上最稳妥：GROUP BY 代表团.团编号, 代表团.团名。严格说，因为团名函数依赖于主键团编号，MySQL 等允许只写 GROUP BY 代表团.团编号；但考试按「SELECT 里的非聚合列都写进 GROUP BY」这条最保险的规则来。

正确写法：

SELECT 代表团.团编号, 代表团.团名, SUM(参赛.成绩) AS 总分
FROM 代表团
JOIN 运动员 ON 代表团.团编号 = 运动员.团编号
JOIN 参赛   ON 运动员.运动员编号 = 参赛.运动员编号
GROUP BY 代表团.团编号, 代表团.团名
HAVING SUM(参赛.成绩) >= 300;

(3) 建视图　✗

作答

批注　连接路径（参赛 ↔ 比赛项目 ↔ 运动员）与 FROM 参赛 起手都对了，比上一轮进步明显。四处问题：

  • AS 后面直接接 SELECT，不加括号——上一轮已点过，本轮又犯，属 0 分硬伤。
  • 参赛成绩 漏了点号，应为 参赛.成绩。
  • 题干只要「运动员编号、姓名、项目名称」三列，这里多给了一列成绩——按题作答，不要自行加列。

建视图的固定骨架是 CREATE VIEW 视图名 AS 查询语句;——视图本身不存数据，只是把一条 SELECT 起名存起来。跨三张表就沿最短路径逐段 JOIN。从哪张表起手都可以，关键是每一段 JOIN 都要有 ON 把两张表桥起来。
